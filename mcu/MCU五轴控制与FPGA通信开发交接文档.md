# MCU 五轴控制与 FPGA 通信开发交接文档

版本：V1.3 MCU 实施版 · 日期：2026-10-11 · 接收方：MCU 固件开发者、FPGA 接口开发者、上位机开发者

本稿依据用户与协作者确认的现有 F4/F1 控制方式实施。MCU 源码、协议和目录迁移已经落地，软件构建与回归测试见 mcu/reports；真实传感器、运动和 FPGA 联调仍须实板验收。运动控制沿用现有驱动，不新增自动龙门架回零、STEP/DIR 云台或加速度曲线。V1.0 的五轴 STEP/DIR、pitch/roll、纯 IMU 来源和速度遥测约定已撤销。最终内部接口、旧功能封装和硬件初值见 output/MCU_POSE_V2接口实现补充.md。

本系统由 F4 龙门架控制器和 F1 云台控制器共同提供五个逻辑轴：X/Y/Z 由 F4 控制步进驱动，pitch/yaw 由 F1 控制两只串口总线舵机。F1 直接读取两只舵机的角度反馈，再由 F4 汇聚并通过独立 UART 向 FPGA 回传五个参量。**X/Y/Z 来自 F4 的步数估计；pitch/yaw 直接来自 F1 的舵机位置反馈，不再使用 MPU6050 姿态融合（2026-10-20 决定，见第 0 节）。** 上位机负责运动任务、参数管理、显示和记录，不逐包转发 FPGA 所需的实时状态。

本文冻结新增接口规格，软件实现与验证范围见 `mcu/reports/MCU_POSE_V2软件验证.md`。下列 MCU 命令用于新的 PC–F4、F4–FPGA 接口；F4 代理 F1 的内部协议见接口补充稿，F1–舵机继续使用现有 JOHO 厂商协议。已确认的轴向、raw 中心、驱动映射按现有工程保存；新增串口引脚、物理长度换算和姿态标定仍需实物核对。

## 1 职责和交付边界

| 开发方 | 必须完成 |
| --- | --- |
| MCU | F4 的步进脉冲/方向/使能和手动零点流程；F1 的舵机协议、自动回正、MPU6050 驱动与融合；双接口协议、状态/事件、时间戳、故障处理 |

| 链路 | 连接和用途 | 本版约定 |
| --- | --- | --- |
| MPU6050–F1 | **本版不连接、不使用**（2026-10-20 起） | 保留原 I²C 方案作为历史设计；F1 固件不再初始化 I²C1，驱动文件保留但不参与构建 |
| F4–步进驱动器 | 三个逻辑直线轴对应现有 D36A STEP/DIR/EN 通道；龙门架轴由两台电机配对 | F4 定时器产生步进脉冲；不是 FPGA 输出脉冲；龙门架不提供自动回零 |
| F1–总线舵机 | USART3 半双工总线，pitch=ID1、yaw=ID2；读回 raw 位置和报警状态 | 保留现有舵机驱动、270°标定和 `ready` 自动回正 |
| MCU–位置反馈 | F4 使用已输出脉冲估计；F1 使用舵机位置反馈并与 MPU6050 融合 | F4 零点由人工建立；F1 `ready` 完成自动回正后再进行姿态零位标定 |
| F4–F1 | 独立双向 UART，F4 代理云台命令并接收舵机状态 | USART1↔USART1、460800、8N1；内部封装、近似时间映射和本地超时处理见接口补充稿；引脚/电平待实测 |
| F4–FPGA | 独立双向 UART，TX/RX/GND | 固定 460800、8N1；查询、会话、同步双向，运动指令仅来自 PC；不与 PC 控制 UART 并接 |
| PC–F4 | 独立 USB-UART 桥，使用现有 F4 USART3 | 实际 UART 为 115200、8N1；不因本次通信适配强制改成 USB CDC |
| FPGA–MCU 同步线 | 可选 GPIO；首版不作为必接条件 | 电平、方向、引脚、捕获机制经双方确认后再启用 |

裸 UART 必须核对 FPGA IO Bank 与 MCU 的电平；不默认允许 5V，也不把 TTL UART 当作 RS-232。长线或电机干扰导致误码时，在保持报文格式的基础上另行配置差分收发器。F4 应提供独立 PC、F1、FPGA 通信资源并保留现有四路步进通道；F1 保留独立舵机总线并增加 MPU6050 的 I²C 资源。

任务优先级依次保护电机时序/本地限位处理、IMU 数据就绪捕获和采样、姿态融合、FPGA 状态发送、PC 查询/显示。使用中断或 DMA 加有界缓冲；串口打印、日志和 I²C 重试不得阻塞脉冲生成。I²C 超时、FIFO 溢出或漏样须计数，不能把旧样本重新标成新采样。

## 3 五个参量和测量来源

| 参量/数组索引 | 类型和单位 | 状态回传来源 | 运动目标含义 |
| --- | --- | --- | --- |
| X / 0 | i32，归一化坐标的 0.000001 单位 | 已确认手动零点和行程后的脉冲计数估计 | 现有轴 1 的 0..100 目标 |
| Y / 1 | i32，同上 | 同上 | 现有轴 2 的 0..100 目标 |

| pitch / 3 | i32，0.001° | F1 舵机位置反馈减去正对中心后的相对角（mdeg），不使用 MPU6050 | 期望的 pitch |
| yaw / 4 | i32，0.001° | F1 舵机位置反馈减去正对中心后的相对角（mdeg），不使用 MPU6050 | 期望的 yaw |

X/Y/Z 在线整数 `1000000` 表示现有坐标 1.000000，`100000000` 表示满行程 100.000000；`1000mdeg=1°`。现有 F4 没有已确认的 µm 换算，本稿不把归一化坐标冒充物理长度；如需物理长度，协作者根据独立标定实体换算并记录单位。**STATE 不回传速度或加速度；也不新增加速度控制要求。** F4 运动请求保留原有 RPM 参数，F1 保留原有固定运动时间。线上不用 float 或 JSON 表示运动量。无效值在线上填 0，但接收端必须看有效位；导出到 JSON 时无效值为 null，不能显示成有效零位。

五项是机械位置加云台 pitch/yaw 的组合，不能自动当成相机光心完整六自由度位姿。XYZ 的机器零点、正向、丝杆/传动比例以及云台舵机 ID、中心 raw 和方向必须随配置保存。MPU6050 不用于积分获取 XYZ，也不能代替 F4 的步数估计或 F1 的舵机反馈。MPU6050 没有绝对磁航向参考，yaw 在本协议中表示相对 F1 零位的云台轴角度，不宣称绝对地磁航向。

### 3.1 位置和到位判据

X/Y/Z 归一化坐标按现有行程脉冲数换算，使用整数或足够宽的有理数，避免每步舍入积累误差。人工回零及上电/复位后的零点确认建立可用坐标，不证明没有失步。配置行程、`wake` 重连或软件计数为 0 都不能自动证明物理零点可靠；手动零点未确认、行程未正式配置或坐标确定丢失时清除对应有效位。轴 3 原 `state` 使用的临时 2 圈分母只用于旧显示，不得据此在 FPGA 五轴状态中标为有效位置。

pitch/yaw 的舵机目标、舵机读回角和 MPU6050 融合角是不同对象。对外高频状态中的两个角使用舵机优先融合：二者差值超过配置阈值时直接采用舵机角，差值在阈值内时按配置权重加权且舵机权重大于 MPU6050。F1 在 `ready` 两轴自动回正且舵机反馈确认到位后等待 5 s，确认仍静止且传感器数据有效，再标定 MPU6050 当前姿态为零位；此期间拒绝普通云台运动命令，ready/HOME 用于建立零位且不允许重入正在执行的回正流程。不能从收到 ready 或仅发出目标时开始计时。旋转轴动作完成保留现有舵机位置误差/超时判据，不改成纯 IMU 闭环，也不只凭指令发送成功返回到位。

F4 保留现有步数、行程和方向；F1 保留现有舵机 raw 位置、中心值、±60°软件范围、位置模式和报警检查。F1 的舵机位置反馈与 MPU6050 角度先转换到同一 pitch/yaw 零位坐标，并核对两者测量时刻，再按上述阈值和权重融合。零位校准未完成、舵机读回失效/报警、超行程或动作超时按现有错误处理拒绝或终止动作。初次校准完成后的 MPU6050 故障可以使用新鲜有效的舵机反馈回传，并标识降级；不能静默复用旧 IMU 角。价格不作为精度证明，阈值和权重仍须后续独立角度参考调试。

### 3.2 pitch 和 yaw 定义

云台零位下 pitch、yaw 的机械正方向、舵机 ID、中心 raw 和安装关系写入配置。pitch/yaw 对外表示 F1 云台的两个机械轴角度，不把舵机 raw 值直接当作世界坐标，也不把 yaw 当成绝对地磁航向。

MPU6050 对 pitch 的倾斜估计仍使用融合器的重力方向；yaw 的短时变化由陀螺积分参与融合，但长期基准由舵机位置反馈提供。两路数据先通过安装变换和各自零位换算到 mdeg，再执行：

```text
pitch_imu = atan2(-u_B.x, sqrt(u_B.y² + u_B.z²))
yaw_imu   = gyro_fused_relative_yaw
```

pitch_imu 和 yaw_imu 不能在运动中用瞬时加速度或未校准的陀螺数据冒充姿态。减去 F1 保存的 pitch_zero/yaw_zero 后，与舵机读回的 pitch_servo/yaw_servo 比较：若角差超过 fusion_disagreement_mdeg，输出舵机角；否则在同一连续角分支计算 `round((servo_weight*servo + imu_weight*imu)/(servo_weight+imu_weight))`，且 `servo_weight>imu_weight>0`。涉及 yaw 的角差先按最短角差归一，不能跨 ±180°直接平均；实际云台命令范围仍为 ±60°。舵机读回失败时清除相应有效位，不用旧舵机数据作为新测量；MPU6050 超出有效域、失效、过期或与舵机采样不同步时退回舵机反馈并报告来源与降级。

内部融合可使用 Hamilton 四元数 [w,x,y,z]，安装变换和算法版本随 F1 配置保存。六轴器件没有磁航向参考；本版发送的是相对零位的 pitch/yaw 机械轴角度，不发布完整相机→世界 q_wc。FPGA 若需 q_wc，应另行冻结航向参考、平台→相机外参及相应协议扩展。

### 3.3 云台实测能力边界（2026-10-22，实机测量）

以下数字来自 F4+F1 实机联调（F1 舵机总线 460800，编码器 raw 范围 0..4095 对应 270° 行程），
是接入方设置运动指令时应遵守的边界，不是理论推算。

**分辨率与精度**

| 项目 | 实测值 | 说明 |
| --- | --- | --- |
| 反馈分辨率 | **0.0659° / 计数**（4095 计数 / 270°） | 对外 `pitch/yaw` 与 `raw` 皆按此换算 |
| 舵机死区/重复精度 | **±20~30 计数 ≈ 0.5~0.8°** | 小于该净变化量的指令舵机不动作 |
| **最小可执行角度（净变化）** | **≈ 1.5°（约 23 计数）** | 低于此值的指令可能被静摩擦吞掉 |
| **推荐单步步进** | **≥ 3°（约 46 计数）** | 实测稳定动作并可在容差内判定到位 |
| 实测定位误差 | **±0.3~0.5°** | 2.4° 步进实测偏差 12~14 计数 |
| 回中（`/home`）精度 | **±0.5°**（容差 32 计数 = 2.1°） | 机械对中精度；姿态零位使用实际 raw，不影响跟踪 |

**2.4° 步进实测（原始记录）**

| 阶段 | pitch raw | yaw raw | 相对角 |
| --- | --- | --- | --- |
| 回正+零位后 | 1866 | 2415 | −0.989° / +0.659° |
| 命令 +2.4°/−2.4° 后 | 1903 | 2381 | +1.451° / −1.582° |
| 实测位移 | **+37 计数** | **−34 计数** | 理论值 36 计数 |

**编写指令时的注意事项**

1. 目标角是**相对云台零位的绝对角**（mdeg），不是增量；连续步进时每步的净变化应 ≥1.5°，
   否则舵机可能不响应而任务仍返回 `MOTION_DONE`。
2. `MOTION_DONE` 只表示 F1 回到空闲且零位有效，**不保证落在目标角上**；
   需要确认到位请读取 `GET_GIMBAL` 的 `raw`/相对角并与目标比对。
3. 到位容差分两类：居中判定 `32` 计数（2.1°），普通定位 `16` 计数（1.05°）。
   若把定位容差设得小于舵机死区，任务会反复判"未到位"。
4. 一次定位若首次未进入容差，F1 会自动补一次修正动作（目标不变），两次仍不到位才判失败。
5. 需要优于 ±0.3° 的重复定位精度时，只能增加外部编码器构成闭环，
   仅靠调整软件参数无法突破上述机械死区。
## 4 UART 外层报文

接口配置名：`MCU_POSE_V2`，`protocol_profile=0x4D32`，外层 `version=2`。V1.0 的旧稿使用 `MCU_POSE_V1/0x4D31/version=1`；因旋转轴、坐标单位、来源和控制含义已变化，两者不得混解。两个新外部接口使用相同外层结构，但命令权限和流频率不同。C 固件与独立 Python 解码器的软件向量互操作已验证；现有 PC–FPGA 客户端不能直接用于解释本接口，FPGA RTL 与完整 PC 客户端仍需按此冻结规格实施并联调。

```text
55 AA | version:u8 | cmd:u8 | seq:u16 | length:u16 | payload:length | crc16:u16
```

| 全帧偏移 | 字段 | 规则 |
| --- | --- | --- |
| 0 | magic，2B | 固定 55 AA |
| 2 | version，u8 | 本修订稿固定 2；旧版或未知版本不执行 |
| 3 | cmd，u8 | 命令表见第 6 节 |
| 4 | seq，u16 | 请求序号；回应原样回显 |
| 6 | length，u16 | 仅 payload 长度，0～1024；本版每个命令还需核对精确长度 |
| 8 | payload | 字段按后文；不含填充、指针、编译器结构体对齐 |
| 8+length | crc16，u16 | 小端 |

所有多字节整数和定点数小端；i32 为二进制补码。全帧长度为 `10+length`。禁止直接发送编译器默认对齐的 C 结构体，需逐字段编解码或验证紧凑布局。新增长度/版本须通过协议升级，不允许接收端默认忽略多出的字节。

CRC 为 CRC-16/CCITT-FALSE：多项式 0x1021、初值 0xFFFF、不反射、xorout=0。覆盖从 version 到 payload 最后一字节，即全帧 `[2,8+length)`，不含 55 AA 和 CRC 本身。标准检查串 ASCII `123456789` 的结果为 0x29B1。它是错误检测，不是设备认证。

解析器处理半包、粘包、垃圾前缀和载荷内的 55 AA。先核对头和有界长度，再收齐并校验；合法载荷内的包头字节不触发重新同步。坏 CRC、长度或超时则丢弃候选包首字节，再扫描剩余缓存，避免跳过下一合法帧。初始整包接收期限：FPGA 链路 30ms、PC 链路 150ms，从候选 magic 首字节开始，不由零散字节续期；正常发端整帧连续发送。超时参数由能力回应回读。

## 5 身份和会话

`device_id:u64` 为 F4 对外系统身份；`boot_id:u64` 为 F4 跨重启不重复的启动代次，采用持久化递增计数并处理写入中断，不能每次恒为 0。计数存储磨损控制和原子提交是 MCU 交付内容。`session_id:u32` 为接收方选取的非零会话号，PC 和 FPGA 的会话独立；新的会话不得影响另一链路。F1 单独复位必须被 F4 检出，撤销云台标定和角度有效位、取消相关任务并要求重新 ready；F1 旧启动的数据、旧零位及旧时间戳不能继续使用。内部身份/序号映射在 F4–F1 接口补充稿中确定。

除 GET_INFO、OPEN 外，请求 payload 前 12B 固定为 `boot_id:u64 | session_id:u32`，称为上下文。身份不匹配则拒绝动作。PC/FPGA 重连先 GET_INFO，再 OPEN，再回读配置和状态；不能用旧 boot_id 继续运动或拼接状态。

每个链路最多一个未完成的请求事务；请求 seq 从 1 递增到 65535，不在同一会话回绕。超时重发使用相同 seq 和完全相同 payload，默认回应期限 200ms、最多 2 次重试。MCU 每链路缓存最近 16 个事务的请求内容与回应至少 2s：相同请求回原回应，同 seq 不同内容拒绝。低于已接受最大 seq 且不在缓存的请求返回 STALE，不得再次执行。达到 seq 上限后建立新会话；正在运动时 PC 不应主动更换会话。

`motion_id:u32` 由 PC 在当前 boot_id 内递增分配；MCU 保持已接受的最大 motion_id，F1 回正也占用该编号。拒绝重复或更小的新动作编号，OPEN 和会话变化不清零此最大值。GET_STATUS 的 motion_id 返回最近接受的动作号，包括终态，PC 据此分配下一号；它不等于所有并行任务的唯一活动编号。新 PC 会话取代旧会话时，旧会话的未完成任务进入本地通信故障处理，产生 LINK_LOST 终止事件；F4 取消本地任务并暂停 F1 保活，由 F1 自身超时取消动作，不自动续行。

实时 STATE 的 seq 为 sample_seq 低 16 位，EVENT 的 seq 为 event_id 低 16 位，均不占用请求序号空间。响应、状态、事件由 cmd 区分，不只看 seq。

### 6.1 通用回应

RESPONSE payload 前 16B：`boot_id:u64 | session_id:u32 | request_cmd:u8 | result:u8 | detail:u16`，之后为该命令的 data。GET_INFO 的 session_id 为 0；OPEN 回显请求的新 session_id。非法上下文回应使用 MCU 当前 boot_id 和请求的 session_id，接收端不因此自动切换会话。详细错误没有定义时 detail=0。

result：0=OK，1=ACCEPTED（动作已接受，尚未完成），2=BUSY，3=BAD_LENGTH，4=RANGE，5=BAD_CONTEXT，6=UNSUPPORTED，7=NOT_READY，8=CONFLICT，9=FAULT，10=STALE。只有校验正确的报文回应；坏 CRC 不回应。未实现命令返回 UNSUPPORTED，不能伪装 OK。

| 请求 | 成功 data |
| --- | --- |
| GET_INFO | 48B 能力信息，见下表 |
| OPEN | config_version:u32、last_motion_id:u32 |
| GET_CONFIG | 264B 配置，见 6.3 |
| SET_STREAM | actual_rate_hz:u16、reserved:u16=0 |
| GET_STATUS | 96B STATE；内部 boot/session 与回应一致 |
| MOVE_ABS/HOME | motion_id:u32，result=ACCEPTED；终态另发 EVENT |
| ACK_EVENT | event_id:u32 |
| SET_POSE_ZERO | new_config_version:u32、pitch_zero:i32、yaw_zero:i32 |
| GET_COUNTERS | 10 个 u32，见 6.5 |
| HEARTBEAT | 无 |
| GET_RAW_IMU | 32B，见 6.5 |

错误回应不附成功 data。有效协议但不足 12B 的请求可返回 BAD_LENGTH，session_id=0；其他格式错误需计数。

### 6.4.1 已取消的全系统停机接口

新增全系统紧急 STOP 命令及内部转发已取消，外部 0x47、内部 0x23 均保留且返回 UNSUPPORTED，不改派其他用途。移除 stop_mode、STOP 回应和停止确认流程，STATE 不再发出 STOPPING，EVENT 不再发出全系统 STOPPED；保留其旧数值，其他状态和事件号不重排。GET_INFO 固件版本为 2.1，紧急停机能力位清除。

原 F4 按轴 `stop n`、wake 和驱动已有到位失败/报警处理保留。本地通信故障处理不提供可调用的全系统紧急停机接口，也不承诺两块开发板同时停止；具体超时与恢复流程见第 8 节和接口补充稿。

### 6.4.2 手动零点与 F1 自动回正

HOME 不等于 SET_POSE_ZERO。F4 的 X/Y/Z 没有自动回零，人工把机构置于零点并按现有控制流程建立步数坐标；对这些轴收到 HOME 返回 UNSUPPORTED，不伪造 HOME_DONE，包含不支持轴的混合请求整体拒绝且不部分执行。F1 的 HOME 选择 pitch/yaw 两轴，等价于现有 `ready` 回正：两个舵机反馈确认到位后等待 5 s，再完成 MPU6050 姿态零位标定；标定完成前拒绝普通云台 MOVE。回正反馈成功时可记录机械零点成功，姿态有效位需等待标定完成；最终 HOME_DONE 在整套流程成功后发出。通信超时、舵机报警、回正失败会中断本次标定；运动或传感器无效会重启稳定等待，不写入错误零位。SET_POSE_ZERO 仅在已完成 ready、两轴处于标定中心且满足同样等待/稳定条件时执行，不改变 F4 直线轴手动零点；零位成功更新 config_version，下一状态及事件引用新版本。HOME 与标定等待期间 PC 仍须保持控制租约心跳，不能因等待最终完成而停止 HEARTBEAT。

### 6.5 诊断数据

GET_COUNTERS data 按顺序为 10×u32：rx_crc_error、rx_length_error、rx_timeout、rx_context_error、imu_i2c_error、imu_missed_sample、imu_fifo_overflow、state_replaced、event_overflow、control_watchdog_stop。计数按 boot_id 从 0 起，u32 饱和不回绕；前四项与 state_replaced/event_overflow 为本链路计数，其余为全设备计数。

GET_RAW_IMU data：`imu_tick_us:u64 | sample_seq:u32 | config_version:u32 | accel_raw:3×i16 | gyro_raw:3×i16 | temperature_raw:i16 | valid:u8 | reserved:u8=0`，共 32B。raw 为传感器原始计数，valid=1 才有效；量程与温度换算按实际 MPU6050 配置解释。这保留传感器调试通道；“不回传运动速度/加速度”是指取消 STATE 的运动遥测，不删除 MPU6050 六轴原始采样。raw 数据不是 pitch/yaw 的最终融合结果。

## 7 高频状态报文

STATE payload 保持 96B；完整 UART 帧 106B。原速度区替换为舵机反馈时间和保留字节，不再发送速度/加速度。两链路生成同语义状态，但 session_id 使用对应接收方会话。F4 按 200Hz 采样/发布周期生成快照，sample_seq 标识这一周期；FPGA 100Hz 模式每两个周期取一次，PC 取最新完整快照降频且不重新编号。发布频率不证明舵机总线产生同频率新样本，使用 servo_tick_us 区分新旧反馈。

| payload 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | u64 | boot_id |
| 8 | u32 | session_id |
| 12 | u32 | config_version |
| 16 | u32 | sample_seq；每个 F4 采样/发布周期递增，包括因错误未获得有效姿态的周期；不表示每周期都有新舵机反馈 |
| 20 | u32 | status_flags，定义见下文 |
| 24 | u64 | imu_tick_us：F1 捕获 IMU DATA READY 后映射到 F4 单调时基的采样时刻；原采样无效时为 0；非转发/发包时间 |
| 32 | u64 | xyz_tick_us：X/Y/Z 一致性快照时刻 |
| 40 | 3×i32 | x、y、z，归一化坐标的 0.000001 单位；不得解码为 µm |
| 52 | 2×i32 | pitch、yaw，mdeg；F1 舵机优先融合或舵机反馈 |
| 60 | u64 | servo_tick_us：本次使用的有效舵机反馈中最早的 F4 时基采集时刻，无有效反馈时为 0；保留两轴各自采集时刻和偏差上界，不把两次串行读回冒充完全同时 |
| 68 | 12B | reserved，全 0；不发送 vx/vy/vz、角速度或加速度 |
| 80 | u32 | motion_id，最近接受的动作，启动后无动作为 0 |
| 84 | u32 | latest_event_id，无事件为 0 |
| 88 | u8 | axis_present_mask，完整实现为 0x1F |
| 89 | u8 | homed_mask；X/Y/Z 为人工零点已确认位，pitch/yaw 为舵机回标定中心反馈成功位；不表示 MPU 标定一定完成 |
| 90 | u8 | xyz_source：每轴 2bit，X=[1:0]、Y=[3:2]、Z=[5:4]；0 无效、1 步数估计、2 编码器实测、3 保留；高两位 0 |
| 91 | u8 | angle_source：pitch=[1:0]、yaw=[3:2]；每轴 0=无效、1=舵机反馈、2=舵机优先加权融合、3=保留；高四位 0 |
| 92 | u8 | motion_state：0 IDLE、1 MOVING、2 HOMING、3 SETTLING、4 保留不发送、5 FAULT |
| 93 | u8 | pose_quality：0 INVALID、1 INITIALIZING、2 VALID_SERVO_IMU、3 SERVO_FALLBACK；不代表绝对世界航向有效 |
| 94 | u16 | fault_code，见第 8 节 |

status_flags：bit0～4 对应 X/Y/Z/pitch/yaw 有效；bit5 该 IMU 原始采样有效；bit6 本次 F1 ready 后 MPU 零位标定完成；bit7 配置实体已验证；bit8 正在 MOVE/HOME/SETTLING；bit9 本链路曾替换未发送状态；bit10 本链路曾事件溢出；bit11 姿态时戳为轮询/时基映射近似值；其余 0。bit9/10 在本 boot 内粘性保持，计数可查询。bit6 未置位时 pitch/yaw 有效位保持 0，普通云台运动拒绝；标定后 MPU 失效时可仅用有效新鲜舵机反馈，并标识 SERVO_FALLBACK。未配置行程的 XYZ 不因软件位置为 0 而置有效。

DATA READY 捕获与融合计算完成不同；内部需保留 F1 原采样、计算及 F4 接收/发送时刻供测延迟。未接中断或跨 MCU 时基仅能近似时置相应时间标志并保存误差上界，不把转发到达或计算结束冒充采样。保留 xyz_tick_us、imu_tick_us、servo_tick_us，三者不承诺完全同时；内部还需保留两只舵机分别读回的时刻。只在舵机反馈新鲜、两轴采样偏差有界且舵机/MPU 的时基可关联时做加权融合；否则使用仍有效的舵机反馈并标识来源。舵机过期或读回失败时清除相关角有效位，不能重复旧角后改写采样时间冒充新数据。具体舵机过期阈值及 F1→F4 映射策略在内部接口设计中冻结并验证。

sample_seq 按 u32 模运算比较，只有小于 2³¹ 的前向差为更新；过大跳变应重新查询身份。MCU 复位按 boot_id 分流，不能只按 sample_seq 接续。

## 8 事件和故障处理

EVENT payload 固定 40B：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0、8 | u64、u32 | boot_id、该链路 session_id |
| 12 | u32 | event_id，当前 boot 内从 1 递增；耗尽时进入本地故障处理并禁止新运动，要求维护，不回绕复用 |
| 16 | u64 | event_tick_us，事件实际发生时刻 |
| 24 | u32 | motion_id，非运动事件为 0 |
| 28 | u16 | event_type：1 STARTED、2 DONE、3 保留不发送、4 HOME_DONE、5 FAILED、6 FAULT、7 POSE_ZEROED、8 LINK_LOST |
| 30 | u16 | result：0 成功、1 执行失败、2 用户停止、3 控制租约过期/替换 |
| 32 | u32 | config_version |
| 36 | u16 | fault_code |
| 38 | u8 | 本事件 axis_mask |
| 39 | u8 | 事件后的 motion_state |

fault_code：0=NONE、1=IMU_IO、2=IMU_STALE、3=IMU_CALIBRATION、4=LIMIT、5=DRIVER、6=HOME_TIMEOUT、7=MOTION_TIMEOUT、8=CONTROL_LINK_LOST、9=EVENT_OVERFLOW、10=CONFIG、11=ANGLE_NOT_SETTLED。事件保留实际故障，STATE 为当前主故障；多故障细节和恢复记录归 MCU 日志。

事件存储采用共享 64 条有界日志，两链路独立确认进度。OPEN 返回后新接收方从当时仍保留的最早事件开始读取；事件重发保持 event_id、时间和内容不变，只修改该接收方 session_id 并重算 CRC。ACK_EVENT 为累计确认，只能确认连续收到的事件号，不可跳过缺口。MCU 每链路最多每 100ms 重发最早未确认事件，首次发送可立即执行；STATE 保留 latest_event_id 供缺口检测。

日志满时记录 event_overflow、置粘性状态并禁止新运动，进入本地故障处理；保留可回读的故障和最新终态。不得声称溢出后事件记录完整。事件传输不无限阻塞状态流；发送器在当前完整帧结束后选择事件/回应/状态，不打断正在发送的帧。FPGA 链路状态不饥饿超过10ms为目标；PC 的 GET_CONFIG 等大回应在线时间可超过10ms，完整帧结束后发最新状态并按50%长期预算调度。

PC 运动、HOME 和姿态标定等待期间每≤300ms 发有效 HEARTBEAT 或有效控制/查询请求，MCU 以本地时间执行 1000ms 控制租约。无效、错误会话、旧序号重放和 FPGA 请求不续期。超时后 F4 取消本地电机任务、清除尚未发送的 F1 请求和内部重试、暂停 INFO 保活，发 LINK_LOST/终止事件；FPGA 状态仍继续发送。F1 在运动/回正/标定期间超过1000ms未收到有效内部请求时，通过本地超时入口取消动作并进入 FAULT。两端超时分别计时，不承诺同时停止；收到新 PC 心跳不自动清除故障，F1 退出忙状态后需通过 ready/HOME 恢复。控制租约按有效 PC 收包时刻独立计时，不以当前待处理事务占用为由拒绝 HEARTBEAT；现有 wake 的停止语义不能作为周期心跳。

FPGA 链路断开不要求 F4 因此停止普通 XYZ 运动；正在依赖 F1 pitch/yaw 到位的动作若舵机反馈无效、过期或 F1 链路断开，进入本地故障处理并发失败事件。PC 断开后的静止状态采集和 F4→FPGA 状态回传继续运行；控制租约过期时执行上述本地超时流程。

## 9 同步和 FPGA 使用规则

SYNC 的成功回应使用 cmd=0x82，seq 回显请求：`boot_id:u64 | session_id:u32 | sync_id:u32 | fpga_t1_us:u64 | mcu_t2_us:u64 | mcu_t3_us:u64`，共 40B。失败用通用 RESPONSE 返回错误码。

FPGA 记录 t1 为请求首位发出时刻、t4 为完整回应接收结束时刻；MCU 的 t2 为请求 CRC 末字节接收结束时刻，t3 为回应首位发出时刻。实际实现可在 DMA 启动前锁存 t3，但必须测量和记录“锁存到首位”的偏差上界；t2 也不能使用普通任务较晚处理时刻而不记录误差。

FPGA 以每秒一次 SYNC 为初始策略，扣除已知请求/回应串行时间，结合多个样本拟合 `fpga_time=a*mcu_time+b`，保存样本、往返时间、偏移/漂移及不确定度。时戳不精确时使用保守误差区间，不宣称硬件同步。SYNC 只做时钟对应，不改 MCU 时钟、boot_id 或采样时间。可选 GPIO 同步需另行冻结边沿与编号关联，不因 MPU6050 有 FSYNC 引脚就默认已同步。

FPGA 接收时校验版本、长度、CRC、boot/session、config_version、有效标志、序号及位置来源，保存接收时间。新 config_version 出现时先查询配置并保存实体，再用于正式测评；旧样本不能套用当前零位或滤波配置。

姿态缓冲至少保留最近 32 个有效新样本。按图像的采集/曝光参考时刻选择或插值 pitch/yaw，再按源帧锁定；处理帧中途不能替换角度。yaw 插值使用最短角差并处理 ±180° 接缝。未建立时基、舵机反馈年龄超过配置阈值或 F1→F4 映射不确定时，标为未同步/过期；默认暂停动态角度更新并标记降级，不把旧角当新测量。原 20ms 只作为待协作者核对的初始姿态年龄阈值，最终按舵机轮询、F1 链路延迟、运动速度及误差要求验收。

pitch/yaw 两轴仍不足以证明相机完整空间姿态或绝对航向；每帧元数据保存 `pose_representation=gimbal_pitch_yaw`、两角值、XYZ、各角实际测量来源、boot_id、sample_seq、imu_tick_us、servo_tick_us、FPGA 接收时间、同步状态和实际使用角。q_wc 未建立时为 null；yaw 字段表示云台相对零位轴角度，不是绝对磁航向。该姿态采样不自动证明 HDMI 与 RAW 视频同帧配对。

## 10 性能预算与发送队列

| 项目 | 预算 |
| --- | --- |
| STATE | 96B payload + 10B 外层 = 106B/帧 |
| FPGA 200Hz | 21200B/s；8N1 为 212000bit/s；460800 占用约 46.0% |
| 单包纯线时间 | 106×10/460800 ≈ 2.30ms |
| PC 20Hz，桥接 UART 115200 | 2120B/s；占用约 18.4%，另计回应和事件 |
| GET_CONFIG 成功回应 | 264B data + 16B 回应头 + 10B 外层 = 290B；PC 桥接 UART 约 25.2ms |

以上为串行预算，不是端到端实测。FPGA 链路发布目标为 200Hz，新状态正常间隔 5ms；“IMU 数据就绪到 MCU 发出 STATE 末位”初始 P99 目标≤5ms，并测最大值。姿态滤波延迟另行测量，不能包含在纯线时间中宣称已达标。

状态发送每链路只允许“当前正在发送的完整帧 + 一个最新待发快照”。来不及发送时覆盖尚未开始的待发状态并计数，不排队旧姿态；当前帧不可覆盖。事件和回应单独有界保存。主机 UI 按 10～20Hz 刷新即可，正式高频姿态测评从 FPGA 实际使用的样本与关联元数据归档，不靠 UI 刷新次数计采样率。

## 11 MCU 实现顺序和交付验收

按以下顺序交付，每阶段注明实现版本和测试来源。

1. **协议先行**：实现 PC–F4、F4–F1、F4–FPGA 的独立解析、CRC、GET_INFO/OPEN/GET_CONFIG、事务幂等和身份检查，提供新版逐字段编解码向量；保留旧 `wake/measure/set/go/out/state/stop` 与 `ready/go/get` 的语义封装。只模拟报文时明确标记模拟，不冒充真实传感器。
2. **真实 IMU 与融合**：读取器件身份，冻结寄存器/量程/采样/滤波配置并回读；实现静态零偏、安装变换、ready 后 5 s 零位和舵机优先融合；完成正负 pitch/yaw 单轴运动、舵机/IMU 分歧切换、动态加速度干扰和极限角域测试。
3. **真实五轴适配**：确认 F4 三个逻辑轴的 STEP/DIR 正向、驱动细分、行程、手动零点和双电机配对；确认 F1 两个舵机 ID、raw 标定、软限位、位置反馈、自动回正和本地故障处理；实现绝对运动、原按轴停止和各自到位判据。F4 坐标是步数估计，F1 旋转轴完成依据舵机反馈并上报融合来源。
4. **FPGA 直连**：上位机只负责运动任务；验证 200Hz 实时状态、FPGA 独立会话、软件同步和按帧绑定。PC 视频采集/归档忙时，MCU→FPGA 状态不受 PC 转发影响。
5. **故障与长稳**：注入坏 CRC、错误长度、上下文错误、过期请求、重复动作、复位、串口断线、I²C 失败、限位、事件溢出；至少 1 小时边运动边状态回传，保存计数和延迟分布。

## 12 启动联调和待确认配置

冷启动联调流程：F4/F1 校验配置并进入停止态 → MPU6050 初始化/回读/融合初始化 → F4 与 F1 建立身份和内部链路 → PC 和 FPGA 各自 GET_INFO/OPEN → 查询 GET_CONFIG/GET_STATUS 并校验身份 → F1 执行 ready/自动回正，确认到位后等待 5 s 完成姿态零位 → 操作者完成 F4 机械手动零点并提交确认 → FPGA 开始 200Hz 状态及 SYNC → PC 发送运动任务并保持 HEARTBEAT → 两侧接收并确认事件 → PC 归档配置、状态和终态。

F1 pitch/yaw 有效不要求 F4 XYZ 手动零点已确认，F4 XYZ 有效也不代表 F1 姿态已标定；各有效位独立判断。F1 ready 后 5 s 标定未完成时，pitch/yaw 有效位清除且普通云台运动拒绝。禁止在初始化期间用五个零值假装就绪。

开发者在驱动电机前必须完成并提交下表；这些是实物配置缺口，不能自行写成已确认事实。

| 待确认项 | 配置内容 |
| --- | --- |
| MCU 与接口资源 | 型号、SDK、时钟、定时器、两个通信资源、USB 方式、引脚及电平 |
| 五轴机构 | 运动对象是相机还是图卡/平台、XYZ 正向/人工零位、pitch/yaw 物理转轴、关节顺序与安装图 |
| 驱动器和传动 | F4 STEP 最小脉宽、DIR 建立时间、细分、丝杆导程、减速比、每轴方向及故障输出；F1 舵机型号、ID、raw 中心、软限位、运动时间及停机能力 |
| 运动保护 | 每轴行程、F4 RPM 上限、F1 ±60°范围、手动/自动零点流程、限位、本地故障处理、动作最长时间；不新增加速度轨迹 |
