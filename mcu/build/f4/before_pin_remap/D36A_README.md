# STM32F407 + 两块 D36A 四路步进电机

## 当前测试行为

- 芯片沿用工程原有的 STM32F407ZGT6，系统时钟仍为 HSI 16 MHz。
- 上电初始化后，等待 10 秒，四路以 +10 RPM 各转一圈。
- 一圈完成后停止发送脉冲并保持力矩；随后在第 20、30、40 秒再次启动。
- 默认电机为 1.8°、无减速箱，驱动板为 8 细分，因此每圈 200 × 8 = 1600 个脉冲。
- 脉冲频率约 266.667 Hz，周期 3750 us，高低电平各 1875 us；一圈约 6 秒，间歇约 4 秒。
- 四路在同一次主循环内依次启动，存在很小的软件启动时间差，不是严格的硬件同步。
- 只接一块板、一个电机即可测试，其余通道没有电机不影响已连接通道。

**360° 的前提是步距角和细分正确，而且电机没有失步。** 当前没有编码器反馈。
若电机是 0.9°，将 `Core/Inc/d36a_motor.h` 的 `D36A_FULL_STEPS_PER_REV` 改为 `400U`。
若带减速箱，目前的一圈是电机轴一圈，输出轴一圈还要乘减速比。
0.83 A 由板上的拨码决定，软件不设置电流。

## 接线

先断开电源再接线或插拔电机。下表中的 PA0、PC0 等为 STM32 芯片信号名，
请在开发板排针上找对应标注；并非芯片封装的物理脚号。

| 全局电机编号 | 驱动板及通道 | D36A 的 ST | D36A 的 DIR | D36A 的 EN |
| --- | --- | --- | --- | --- |
| 1 | 第一块板通道 1 | ST1 接 PA0 | DIR1 接 PC0 | EN1 接 PC4 |
| 2 | 第一块板通道 2 | ST2 接 PA6 | DIR2 接 PC1 | EN2 接 PC5 |
| 3 | 第二块板通道 1 | ST1 接 PB6 | DIR1 接 PC2 | EN1 接 PC6 |
| 4 | 第二块板通道 2 | ST2 接 PA1 | DIR2 接 PC3 | EN2 接 PC7 |

现在只接第一块板：把前两行的六根控制线全部接上，再接 GND。
电机插在该板任意一个电机接口都能参与测试。
第二块板暂时不接，它对应的 STM32 引脚留空即可。

| 电源或其他引脚 | 本次测试接法 |
| --- | --- |
| STM32 开发板 | USB 供电 |
| D36A Vin+ | 外部 12 V 直流电源正极 |
| D36A Vin- | 外部 12 V 直流电源负极 |
| D36A 控制排针 GND | 必须连接 STM32 GND；以后两块板也必须共地 |
| D36A 控制排针 5V | 不接，这是输出，避免和 USB 供电互相回灌 |
| D36A ADC | 不接，本程序没有电压采样 |
| D36A 的额外 3V3、5V 输出 | 不接 |

信号使用 STM32 的 3.3 V 推挽输出，可直接接 D36A。不要向 STM32 的 GPIO 或 3V3 接入 5 V、12 V。
电机电源由外部电源提供，不能由 STM32 的 GPIO 或 3V3 提供。
电源电流容量应满足电机和风扇需要，0.83 A 是驱动电流档位，不是整板的固定输入电流。

以驱动板背面丝印为准辨认 ST1/ST2、DIR1/DIR2、EN1/EN2，不要仅凭排针朝向猜位置。
EN 高电平使能、低电平休眠。这里的 EN 实际连到芯片 nSLEEP，不能套用其他驱动器的低有效 EN 规则。

电机两组线圈分别接到同一通道的 A+/A-、B+/B-；线色因电机而异。
不确定线序时，断电并把电机从驱动板拔下，用万用表确定两组导通的线圈。
板上两个电机插座的针序不能直接假定相同，请看各自丝印及对应线束。
首次使能时电机可能轻微跳动以建立保持位置，属于上电励磁过程。

## 拨码核对

根据附带用户手册第 12、13 页，ON 表示开关导通，不代表芯片引脚高电平：

| 开关编号 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| 8 细分、0.83 A | ON | OFF | OFF | OFF | ON | ON |

同一块板的两个通道共享这组细分和电流设置。以后第二块板也按相同方式设置。
保持风扇正常工作。停转后仍通电保持力矩，电机及驱动板发热是需要留意的。

## 唯一应用接口

```c
HAL_StatusTypeDef D36A_Control(uint8_t motor, int16_t rpm, uint32_t pulses);
```

- `motor`：1、2、3、4，映射见接线表。
- `rpm`：整数转速，当前允许 -60 到 +60 RPM；正负决定方向，0 表示停止并保持力矩。
- `pulses`：微步脉冲数；非零时达到计数后停转，0 时按指定非零转速连续转动。
- 返回 `HAL_OK` 表示指令已接受，不代表电机已经转完。参数错误返回 `HAL_ERROR`，不会替换已有运动。
- 第一次合法调用检查外设配置、准备四路并等待 2 ms 唤醒，之后接口不等待运动完成。
- 必须在 HAL、系统时钟及 CubeMX 生成的 `MX_GPIO_Init()`、`MX_TIM2/3/4/5_Init()` 完成之后，
  从中断开启的主循环调用，不要从中断服务函数调用。现有 `main.c` 已按此顺序执行。
- 正方向仅表示 DIR 高电平。实际顺逆时针受电机线序和观察方向影响。

```c
#include "d36a_motor.h"

D36A_Control(1, 10, D36A_PULSES_PER_REV);  /* 电机 1 正转一圈 */
D36A_Control(2, -10, D36A_PULSES_PER_REV); /* 电机 2 反转一圈 */
D36A_Control(3, 20, 0);                   /* 电机 3 连续正转 */
D36A_Control(4, -15, 0);                  /* 电机 4 连续反转 */
D36A_Control(3, 0, 0);                    /* 电机 3 停止并保持 */
```

运行中修改指令，会在原来当前脉冲周期结束后生效，避免把高电平截断或在脉冲中途改变方向。
等待期间多次下发时以最后一条为准，不是排队执行。
等待时间最多约一个旧脉冲周期，例如 10 RPM 时约 3.75 ms，1 RPM 时约 37.5 ms。
新指令的脉冲数从新指令生效时重新计算，不包含替换前完成的脉冲。
本程序没有加减速曲线，高负载时突然启动或反转可能失步；先按 10 RPM 空载测试。

## 实现与资源占用

电机运动逻辑在 `Core/Src/d36a_motor.c`，头文件只提供参数和一个应用函数声明。
GPIO、定时器基础配置及 NVIC 由 `FPGA.ioc` 统一管理，通过 CubeMX 生成 `gpio.c`、`tim.c`。
四个中断入口在 CubeMX 生成的 `stm32f4xx_it.c` 中，调用 `HAL_TIM_IRQHandler()`，
再进入驱动中的 `HAL_TIM_PeriodElapsedCallback()` 处理计数，不增加应用调用接口。

| 资源 | 用途 |
| --- | --- |
| TIM2 CH1 / PA0 | 电机 1 STEP |
| TIM3 CH1 / PA6 | 电机 2 STEP |
| TIM4 CH1 / PB6 | 电机 3 STEP |
| TIM5 CH2 / PA1 | 电机 4 STEP |
| PC0-PC3 | 四路 DIR |
| PC4-PC7 | 四路 EN |
| TIM2/3/4/5 更新中断，优先级 1 | 独立计数和执行待处理指令 |
| DBGMCU 对应定时器冻结位 | 调试暂停时冻结 STEP，避免继续多走 |

定时器预分频由 `.ioc` 配置。当前 APB1 定时器时钟为 16 MHz，PSC=15，计数频率为 1 MHz。
驱动首次调用时根据 APB1 时钟及其倍频规则校验四个 PSC，若配置不匹配或定时器未初始化，
返回 `HAL_ERROR`，不会悄悄覆盖 `.ioc` 配置。
使用 PWM2，周期前半段为低、后半段为高，在周期结束的下降沿中断计数并停止，避免多发一个上升沿。
停止时 STEP 强制为低，EN 保持高。
当前 1.8° 配置最高 60 RPM，即每路 1600 Hz。软件另外限制每路最高 3200 Hz，
供 0.9° 配置使用。所有通道定时器周期统一限制在 16 位范围内。

精确计数依赖中断及时执行：当前 60 RPM 下必须在下一次上升沿前（约 312 us 内）处理更新中断。
后续集成其他功能时不要长时间屏蔽中断，也不要加入会长时间抢占这些定时器中断的代码。
启用加倍脉冲数的 0.9° 配置时，该时间缩短为约 156 us。
HSI 频率误差会影响实际转速和时间，但不会改变每次命令的脉冲数。

## CubeMX 配置与后续维护

**全部基础外设配置已同步到 `FPGA.ioc`，并使用本机 CubeMX 6.17 实际重新生成代码验证。**
打开 `.ioc` 可直接看到所有占用引脚及 `D36A_M1_STEP`、`D36A_M1_DIR`、`D36A_M1_EN` 等标签。

| CubeMX 项目 | 当前设置及用途 |
| --- | --- |
| RCC | HSI 16 MHz 直接作为 SYSCLK；AHB、APB1、APB2 均不分频；不使用 PLL |
| SYS | PA13/PA14 保留 SWD；SysTick 为 HAL 毫秒时基 |
| PC0-PC3、PC4-PC7 | DIR、EN 为推挽输出、下拉、低速，上电输出低；EN 初始低使驱动板保持休眠 |
| PA0、PA6、PB6、PA1 | 对应 STEP 的定时器复用推挽、下拉、低速 |
| TIM2/3/4 CH1、TIM5 CH2 | 内部时钟、向上计数、PSC=15、ARR=65535、自动重装载预装载开启 |
| 四路 PWM | PWM2、高有效、初始 CCR=32768、快速模式关闭；初始化后不启动计数 |
| 四路 NVIC | 启用全局中断，抢占优先级 1、子优先级 0，由 CubeMX 生成 IRQHandler 并调用 HAL |
| Project Manager | CMake、按外设生成 `.c/.h`、保留 USER CODE；GPIO 和四个定时器初始化在应用代码之前 |

ARR/CCR 初值只用于基础配置，不代表启动后就会转动。运行时的启动、停止、改速、方向和使能电平
由驱动根据命令设置，包括启用计数中断、改变 ARR/CCR、停止时强制 STEP 为低。
`URS`（禁止软件更新事件被计为脉冲）和 `DBGMCU`（调试暂停时冻结定时器）在本 MCU 的 CubeMX
配置中没有对应选项，因此保留在驱动内并加有注释。它们随自定义驱动文件保留，不会被重新生成覆盖。

后续维护时：

1. 在 CubeMX 修改基础外设配置后 Generate Code，再重新编译。自定义驱动文件、`main.c` 的 USER CODE
   和根目录 CMake 中的自定义源文件条目均会保留。
2. 修改系统时钟时，四个定时器的 `PSC = TIMxCLK / 1000000 - 1`，保持计数频率为 1 MHz。
   例如 APB1 定时器时钟为 84 MHz 时，PSC 应为 83。仅修改时钟而未同步 PSC，驱动会报错。
3. DIR/EN 引脚使用生成的 `D36A_Mx_*_GPIO_Port`、`D36A_Mx_*_Pin` 宏。
   修改 GPIO 位置时保留这些标签；STEP 可以切换同一定时器通道的其他复用引脚。
   若更换定时器或通道，还需同步 `d36a_motor.c` 的 `hardware` 映射。
4. TIM2/3/4/5 全部通道由本驱动独占，不要用其他 HAL 启停函数同时控制它们。
   当前项目只定义一个 `HAL_TIM_PeriodElapsedCallback()`；以后增加其他定时器回调逻辑时，
   在同一回调内按句柄分发，避免重复定义或替换电机回调。HAL 时基继续使用 SysTick。
5. 项目根目录不要创建名为 `tmp` 的文件夹，CubeMX 6.17 生成代码会使用该临时文件名。
   本项目临时资料放在 `build/` 下。
