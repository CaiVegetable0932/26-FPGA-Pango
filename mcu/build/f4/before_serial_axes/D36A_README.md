# STM32F407 + 两块 D36A 四路步进电机

## 当前测试行为

**排线顺序已修正，用户确认电机正常旋转；当前已恢复四路单向一圈验证程序。**
程序直接在 `Core/Src/main.c` 默认执行，沿用原有编译、烧录方式。Debug 和 Release 使用相同逻辑。
正反交替的电池诊断和未上板的 20 步点动程序以块注释保留，默认不执行。

**本次拨码：1-6 号为 ON OFF OFF OFF ON OFF，即 8 细分、0.93 A。**
不能沿用先前整步的 ON ON ON OFF ON OFF，否则实际转速及圈数都会变成预期的 8 倍。
电池的最高输出 6 A 表示供电能力，不是驱动应设置的电机电流，软件也不设置驱动电流。

| 初始化后的时间 | 四路动作 | 预期方向信号 |
| --- | --- | --- |
| 0-10 秒 | 静止保持，不发 STEP | DIR 低 |
| 10-22 秒 | +5 RPM 连续发送 1600 脉冲 | DIR 高 |
| 22-32 秒 | 停止发脉冲，保持约 10 秒 | DIR 仍高 |
| 32-44 秒 | 再次 +5 RPM 连续发送 1600 脉冲 | DIR 仍高 |
| 44-54 秒 | 停止发脉冲，保持约 10 秒 | DIR 仍高 |
| 54 秒之后 | 同方向重复一圈、保持 | DIR 仍高 |

这里的 10 秒是每圈结束后的间歇；5 RPM 一圈约需 12 秒，因此两次启动相隔约 22 秒。
每路使用有限脉冲命令，达到 1600 脉冲后由定时器更新回调停止；主循环负责间隔和下一圈启动。
即使主循环暂时停顿，计数中断正常时也不会无限发脉冲。四路依次下发，有很小的软件启动时间差。
只连接一台电机即可，其余通道空载不影响这台的指令。
按 1.8°、8 细分计算，每次约一圈、用时 12 秒；STEP 为 133.333 Hz、50% 占空比，
高低电平各 3.75 ms。未知电机步距角或失步时不能保证实际 360°，当前没有位置反馈。
停止时 EN 仍高，可能有保持电流的嗡鸣，不要求声音完全消失。

STM32 保持独立 USB 供电，与 D36A 共地；电池正负分别接 D36A Vin+/Vin-，
不连接两板间的 5V。断电撤掉此前 EN/DIR 接 3V3/GND 的临时跳线，恢复下方标准控制接线。
先用电压档确认电池实际输出和极性；标称 12 V 电池的满电电压可能不同，不能仅凭标称值判断。
更换接线、拨码或插拔电机都在断电后进行。主控电源独立并不取消两板的信号共地。

### 万用表测量

使用直流电压档，黑表笔接 D36A GND，红表笔测下表各点，记录静止和转动阶段的读数。
红表笔插电压测量插孔，不能将电流档或电流插孔直接跨接电池两端。
每次测一个点，避免表笔同时碰到相邻排针；建议复位后按时间表重复测量。

| 测量点 | 静止保持 | 正转期间 |
| --- | --- | --- |
| Vin+ 对 Vin- | 电池实际输出，约 12 V | 不应出现明显持续掉压或反复波动 |
| EN1 或 EN2 对 GND | 约 3.3 V | 始终约 3.3 V |
| DIR1 或 DIR2 对 GND | 上电低，首次运动后保持高 | 约 3.3 V |
| ST1 或 ST2 对 GND | 约 0 V | 常规直流平均读数约 1.65 V，因表而异 |

ST 的约 1.65 V 是 0-3.3 V 脉冲的时间平均，不是 MCU 输出 1.65 V 逻辑电平，
也不能仅凭这个读数证明频率或波形正确。若表有适用的 Hz 档，运动期间预期约 133.33 Hz。
EN 在运动时却读到约 1.65 V，或 ST 一直 3.3 V/0 V，应优先检查信号对应关系、共地和接触。
需要确认精确时序时仍应使用示波器或逻辑分析仪；普通万用表可能漏掉很短的电源跌落。
测到静态 12 V 只能说明当时电压正常，不能完全排除启动瞬态或接头压降。

已移除之前的 `D36A_DIAGNOSTIC_TEST` 编译开关和独立 Diagnostic 构建预设。
历史 `build/Diagnostic/` 中的产物不作为本次烧录入口。直接使用原有工程编译、烧录流程。
本次未改变 MCU 的引脚、时钟或基础定时器配置，因此 `FPGA.ioc` 无需调整；
8 细分是驱动板的外部拨码设置，不是 STM32 外设配置。

本次故障已由线序修正解决，见下面记录。以后增加电机时，应逐条确认线束两相配对，
不能因为是厂家附带线束就假定插头针序与 D36A 匹配。

### 最新上板排查记录

**已确认原因：电机线束的两相交错排列，与驱动板的相邻成对排列不匹配。**
按用户此次测量时的端子编号，原线束 1、3 属于 A 相，2、4 属于 B 相；
所用驱动接口需要 1、2 为 A 相，3、4 为 B 相。调整对应关系后，原电池诊断程序已能正常驱动电机旋转。
本次依用户要求恢复单向一圈验证，速度、脉冲数、引脚及拨码不变。

此前曾替换电机、驱动板和线束，仍嗡鸣或小幅摆动；EN/DIR/ST 平均电平符合预期，运行电压约 12 V。
早先按错误端子配对测得 OL，后来重新测量确认上述交错线序。因此不再将此前 OL 记录解释为绕组损坏，
也没有证据把这次故障归因于电源额定电流或固件。电机已正常旋转是用户的上板反馈，尚不代表四台电机全部实测。

### 备用电阻检查

以下步骤供后续新增电机或再次出现异常时使用，本次故障已经解决，不是继续运行前的待办项。
断电检查完整的线束加线圈回路，不依据线色猜测配对。

1. 断开电池和主控 USB，等板上指示灯熄灭。从 D36A 拔下电机四芯插头，电机端保持连接。
   测量对象是拔下来的线束插头金属端子，不能隔着驱动板测线圈电阻。
   拔下前按板上丝印记住对应 A+、A-、B+、B- 的位置，避免翻转插头后弄反。
2. 万用表用电阻档，表笔插 COM 和 V/ohm 孔。先短接表笔记录表笔电阻，再测下表。
   电机型号未知，不指定应有多少欧姆；记录数值比仅听蜂鸣档更有用。
3. 测每相电阻时轻轻活动线束和插头，观察读数是否跳变或变成 OL；不要用粗表笔撑大端子。

| 测量组合 | 预期及记录内容 |
| --- | --- |
| A+ 与 A- | 有限且稳定的电阻，记录具体欧姆数 |
| B+ 与 B- | 有限且稳定，通常与 A 相接近，记录具体欧姆数 |
| A+ 与 B+、A+ 与 B-、A- 与 B+、A- 与 B- | 四组都应不导通，通常显示 OL |

若两组同相也都是 OL，先暂停上电试转，按以下顺序确认测法：

1. 电机和驱动全部断电，表笔离开电路；黑表笔插 COM，红表笔插 V/ohm，选择电阻档。
   只把两支表笔的金属尖互相接触，应该显示接近 0 ohm 的有限数值。
   如果仍是 OL，先检查档位、表笔插孔及表笔自身，暂不解释电机测量结果。
2. 短接正常后，确认是在测从 D36A 拔下的线束端，且线束另一端仍插在电机上。
   电机已拔出后再测 D36A 板上空插座，不能得到电机线圈电阻。
   探针必须接触插头内金属端子；不要靠加力将粗探针塞入小孔，以免损坏触点。
3. 仍全部 OL 时，若电机端可插拔且触点可安全接触，断电拆下线束，分别测电机自身四个触点
   的六种组合，以及线束各芯两端的通断。正常四线两相电机应有两组有限电阻；
   正常独立四芯线束应能找到四条近零电阻的通路，不凭插头观察方向假定端子顺序。
   这样才能区分电机端、线束和接触问题；无需再拆开电机内部。

某相 OL、两相阻值明显不同或活动线束时断续，需要继续定位该相线圈、压接或接触；
两相测量正常可降低上述问题的嫌疑，不能证明驱动上电后两相电流一定正常。
不能用交换同一线圈两端的方法修复已确认配对的缺相问题；同一相反接通常只会改变转向。

测完先切回电压档，再断电接回电机并上电。若再次异常，可记录 D36A 电源端 Vin+ 对 Vin- 的读数，
以及板上 5V、3V3 对 GND 的电压，后两项对应厂家排查手册第 4 页的电源检查。
若万用表具有适合 3.3 V 信号的 Hz 档，在驱动板所用通道的 ST 对 GND 测运动段频率，预期约 133.33 Hz；
只有直流档平均约 1.65 V 不能确认频率、脉冲幅度及毛刺。无 Hz 档时跳过该项，不据此判断故障。
测量期间保持同一固件、拨码及接线条件，便于比较结果。

### 固定使能与方向的对照

先完成上方正常接线测量。若仍怀疑 EN/DIR 线路，可保持现有固件，
断电后做以下单通道对照。不要手动碰触 ST，继续由 STM32 提供确定的脉冲。

| D36A 通道 1 输入 | 对照接法 |
| --- | --- |
| EN1 | 从 PC2 断开，改接 D36A 自身的 3V3 输出 |
| DIR1 | 从 PA4 断开，改接 D36A 自身的 GND |
| ST1 | 保持接 STM32 PA5 |
| GND | 保持与 STM32 GND 相连 |

电机必须接通道 1 对应的电机插座；使用通道 2 时输入名称全部换成 EN2/DIR2/ST2，
原 EN/DIR 控制线分别为 PC3/PA2，ST2 接 PA1。不要混用通道。
PA4、PC2（或 PA2、PC3）必须与上述外部固定电平断开，不能把它们的推挽输出直接接到电源或地。
主控继续独立供电，两板只共地；保持 8 细分、0.93 A，不同时改变电源或电机。
由板上电源固定 EN、DIR 的接法参考附带故障排查手册第 6 页。
本对照将 DIR 固定为低，电机应始终沿该电平方向运动；即使恢复正反交替程序也不能再用它验证反转。

若这样能逐步转动，应回查原 EN/DIR 线路或控制端定位；若仍不转，仍需测量 ST、
实际供电和驱动输出，不能用上述替换结果单独判定电机损坏。
对照结束先断电，撤掉 EN/DIR 固定电平连接，再恢复原 STM32 接线。

### 调试器观察

`main.c` 内增加文件私有的 `volatile` 结构体 `d36a_diagnostic`，可在调试器观察窗口展开：

| 成员 | 用途 |
| --- | --- |
| `firmware_tag` | 当前单向一圈程序的标记 `0xD36A1001`，核对实际下载版本 |
| `uptime_ms` | 最近一次主循环读取的 HAL 毫秒时间，复位后从头计时 |
| `phase` | 默认只出现 0=上电保持、1=正转、2=正转后保持；3、4 留给正反交替诊断 |
| `phase_elapsed_ms` | 当前软件阶段经过的毫秒数 |
| `commanded_rpm` | 上电为 0，首次运动后为 +5，保持阶段保留原值 |
| `pulse_commands_per_motor` | 每路已接受的目标脉冲总数，每次下发一圈立即加 1600 |
| `moves_started` | 已接受的运动段数，约在 10 秒首次变为 1，32 秒变为 2 |
| `error_motor` | 正常为 0；某路接口返回失败时记录该路编号，随后进入 Error_Handler |
| `reset_csr` | main 入口保存的 RCC CSR 原始值，随后清除复位标志供下次启动辨认 |

计数和阶段反映软件命令和经过时间，不是对驱动输入脉冲或电机位移的测量。
`phase` 切到保持仅表示预计一圈用时已过，实际发脉冲停止由驱动计数决定。
上电或下载本来就会产生复位标志，
不能仅凭一次 BOR/POR 标志判定掉压；需结合运行时间、计数是否反复重置及调试器的复位操作判断。
单步或断点会中断实际运行节奏，观察运动时让程序连续运行。

### 保留的诊断程序

原单向一圈程序已恢复，无需手工取消注释。正反交替诊断保留为 `Saved battery loop`。
如需恢复该诊断，所有切换位置都在 `main.c` 的 USER CODE 区域内：

1. 保留当前 STARTUP、PAUSE、MOVE、INTERVAL 和 RPM 宏，8 细分、0.93 A 拨码也不变。
2. 在 `USER CODE BEGIN 1` 中启用注释保留的 `next_motor_rpm` 局部变量。
3. 用 `Saved battery loop` 块内的循环替换 `Active normal loop`，保留其后的公共阶段统计代码，
   不能同时执行两个循环。
4. 更新 `firmware_tag` 区分固件，并同步 main 主机测试的方向及阶段预期，再编译、烧录。

该诊断上电等待 10 秒，以 5 RPM 转一圈约 12 秒，停约 10 秒，然后反向重复。

20 步短段测试也保留在 `Saved short-burst settings`、`Saved short-burst loop` 及局部变量注释中。
要恢复它，需同时启用这些部分、停用单向一圈循环及阶段统计，并断电把拨码改回整步、0.93 A。

## 接线

先断开电源再接线或插拔电机。下表中的 PA5、PC2 等为 STM32 芯片信号名，
请在开发板排针上找对应标注；并非芯片封装的物理脚号。

本接线表已按 `pic/` 中的 M144Z-M4 开发板实拍重新分配，**取代此前所有接线表，PA0 不再使用**。
定位方向：背面朝向自己，与当前 `IMG20260919121822.jpg` 一致，SD 卡座在上、SWD 插座在下。
第一块 D36A 的六根控制线集中在左下方排针，第二块板的六根控制线集中在右侧中部。
同一通道的三根线在邻近的两到三行内，不是把丝印数字相邻误当成排针位置相邻。

当前实拍见 [主控背面接线](pic/IMG20260919121822.jpg)。请根据丝印找到对应排针，
翻到开发板正面看时左右会反转；实拍记录的是当前接线，不是每根线都已通过测量确认的接线图。

| 1 | 第一块板通道 1 | ST1 接 PA5 | DIR1 接 PA4 | EN1 接 PC2 |
| 2 | 第一块板通道 2 | ST2 接 PA1 | DIR2 接 PA2 | EN2 接 PC3 |

电机插在该板任意一个电机接口都能参与测试。
第二块板暂时不接，它对应的 STM32 引脚留空即可。

| D36A 控制排针 GND | 必须连接 STM32 GND；以后两块板也必须共地 |
| D36A 控制排针 5V | 不接，这是输出，避免和 USB 供电互相回灌 |
| D36A ADC | 不接，本程序没有电压采样 |
| D36A 的额外 3V3、5V 输出 | 不接 |

信号使用 STM32 的 3.3 V 推挽输出，可直接接 D36A。不要向 STM32 的 GPIO 或 3V3 接入 5 V、12 V。
电机电源由外部电源提供，不能由 STM32 的 GPIO 或 3V3 提供。
电源电流容量应满足电机和风扇需要，0.83 A 是驱动电流档位，不是整板的固定输入电流。

以驱动板背面丝印为准辨认 ST1/ST2、DIR1/DIR2、EN1/EN2，不要仅凭排针朝向猜位置。
EN 高电平使能、低电平休眠。这里的 EN 实际连到芯片 nSLEEP，不能套用其他驱动器的低有效 EN 规则。

电机两组线圈分别接到同一通道的 A+/A-、B+/B-；线色因电机而异。
不确定线序时，断电并把电机从驱动板拔下，用万用表确定两组导通的线圈。
板上两个电机插座的针序不能直接假定相同，请看各自丝印及对应线束。
首次使能时电机可能轻微跳动以建立保持位置，属于上电励磁过程。

本次已修复线束的对应关系如下。编号仅沿用用户此次测量视角，其他线束或翻转插头时不能照搬编号，
应以实际导通的两相和驱动板 A+/A-、B+/B- 丝印为准。

| 所用驱动接口 | 原线束端子 | 用户标记 |
| --- | --- | --- |
| 1 / A+ | 1 | A+ |
| 2 / A- | 3 | A- |
| 3 / B+ | 2 | B+ |
| 4 / B- | 4 | B- |

即将原线束中间两根交换。断电从修正后的驱动端线束插头测量，1-2 和 3-4 应各有有限电阻，跨相应不导通。
新增的每台电机及每条线束都应单独核对，不能假定与已修好的这一条相同。

### 电流调整与嗡鸣排查

**先断电，再调拨码或插拔电机。** 1-3 号按正在运行的程序选择整步或 8 细分，见上表。
调电流只调整 4、5、6 号。ON 是拨向开关标有 ON 的一侧，不要按开发板摆放方向判断上下。
手册第 13 页表 2-3 的完整电流表如下，按电流从小到大排列：

| 手册标称等效电流 | 4 / CUR1 | 5 / CUR2 | 6 / CUR3 |
| --- | --- | --- | --- |
| 0.55 A | ON | ON | ON |
| 0.59 A | ON | ON | OFF |
| 0.70 A | ON | OFF | ON |
| 0.77 A | ON | OFF | OFF |
| 0.83 A（原设置） | OFF | ON | ON |
| 0.93 A | OFF | ON | OFF |
| 1.22 A | OFF | OFF | ON |
| 1.44 A | OFF | OFF | OFF |

选择档位前确认电机型号、额定相电流及其标注口径；不能把电源适配器的额定电流当作电机额定相电流。
表中沿用手册的“等效电流”名称，不自行换算成峰值或 RMS，也不是整板从电源吸取的电流。
在电流口径匹配且不超过电机额定值的前提下，才逐档增加：0.83 -> 0.93 -> 1.22 -> 1.44 A。
例如额定相电流为 1.0 A 时先试 0.93 A，不再升至 1.22 A；型号或额定值未知时，先核实再加流。
每次断电换档后先空载试运行，确认风扇转动，观察电机及驱动板温升；温升异常或出现保护停机应断电检查。
两通道共用电流设置，以后同板接两台不同电机时要同时满足两台电机的允许电流。

**嗡鸣不等于电流不足，也不能证明 STEP 已到达驱动板。** 当前以 5 RPM、8 细分连续脉冲验证，
不保证解决线序、供电或负载导致的问题。按下面顺序检查：

1. 去掉轴上的机械负载，在轴上做标记；烧录后运行而非停在调试断点，等待首次 10 秒延时结束。
   观察接下来约 12 秒是否累计旋转，再观察约 10 秒保持阶段，避免将保持阶段误判为堵转。
2. 断电并将电机线束从驱动板拔下，用万用表电阻档辨认两组线圈。
   四线电机同一线圈的两根线应有有限且稳定的电阻，不同线圈间应不导通。
   一组接该通道 A+/A-，另一组接 B+/B-，同时检查插头接触，不能仅凭线色猜配对。
3. 检查 D36A 与 STM32 共地、ST/DIR/EN 对应正确；当前 EN 应约为 3.3 V。
   在运动的约 12 秒内，用示波器或逻辑分析仪在 D36A 的 ST 输入处测量：
   约 0-3.3 V、133.333 Hz、高低电平各 3.75 ms，每段 1600 个脉冲；DIR 在该段内保持不变。
   普通万用表直流档预期读到 ST 约 1.65 V，但无法确认脉冲是否正确；
   同样不能靠测 A+/A- 的平均电压判断驱动是否正常。
4. 在电机尝试启动时测 D36A Vin+ 对 Vin- 的电压，检查外部电源是否限流或明显掉压，
   同时核对板上 5 V、3.3 V 电源。现有接线方案使用外部 12 V 电源。
5. 在上述正常且电机额定值允许时再按表逐档增加电流。空载仍只振不转时，
   应继续查线圈、连接器、驱动通道或电机故障，不要用最大电流掩盖问题。

### 没有仪表时的独立步进检查

若电机、线束和 D36A 是厂家明确配套的一套，先保留原线序，断电检查插头是否插到底、
端子是否退针即可。不要在没有测量依据时随意换线。

可以利用 STEP 上升沿有效的特性，做一个脱离 STM32 的手动步进试验。
以下接法依据用户手册第 11 页和故障排查手册第 6 页；手动产生电平变化是为了替代测试脉冲，
接触抖动可能产生多个脉冲，因此只能判断是否能向一个方向累计转动，不能用于精确计数。

1. 断开 D36A 的 12 V 电源和 STM32 的 USB 电源，拆下两板之间的所有连线。
   电机使用已经核对并修正线序的线束。下面以通道 1 为例；若接在通道 2，ST1/DIR1/EN1 全部换成 ST2/DIR2/EN2。
2. 断电状态下把 1-6 号拨码临时设成 **ON、ON、ON、OFF、ON、OFF**，
   即整步、0.93 A，使单步位移更容易观察。
3. 用 D36A 自身的电源输出连接：EN1 接板上 3V3，DIR1 接板上 GND。
   另一根杜邦线一端接 ST1，另一端先接板上 GND。此时这些输入不能再连接 STM32 输出。
4. 给 D36A 接通 12 V，等待约 1 秒。保持 EN 和 DIR 不动，
   将 ST1 那根线的自由端在 GND 和 3V3 之间交替连接，每处停留约半秒，重复 10-20 次。
   不要把 GND 与 3V3 直接短接；只使用标有 3V3 的输出，不使用 5V 或 12V。
   在轴上做一个可见标记，观察角度是否向同一方向逐渐累积。
5. ST 固定接高或低电平都不会持续转动，需要反复产生低到高的变化。
   测试期间不带电插拔电机，也不带电改变拨码。出现异常发热时停止试验。
6. 完成后先断电，再按接线表接回 STM32，并恢复当前一圈验证所需的 8 细分、0.93 A，
   即 ON、OFF、OFF、OFF、ON、OFF。此手动试验不修改固件或 `.ioc`。

若能明显向一个方向累计转动，说明这套电源、驱动通道和电机至少能完成上述整步低速运动，
下一步应回查 STM32 的控制接线和 STEP 输出，以及恢复 8 细分后的表现；
这不能证明原来的连续微步运动、动态供电或负载能力一定正常。
若仍然只振不转，由于手动接触的脉冲质量不确定，先用当前 main 中的诊断程序复查，
再结合替换电源、驱动板或电机的结果定位。
每次只替换一项，并保持其余连接和设置不变；尚不能仅凭该现象判定某个器件损坏。

## 唯一应用接口

```c
HAL_StatusTypeDef D36A_Control(uint8_t motor, int16_t rpm, uint32_t pulses);
```

- `motor`：1、2、3、4，映射见接线表。
- `rpm`：整数转速，当前允许 -60 到 +60 RPM；正负决定方向，0 表示停止并保持力矩。
- `pulses`：微步脉冲数；非零时达到计数后停转，0 时按指定非零转速连续转动。
- 返回 `HAL_OK` 表示指令已接受，不代表电机已经转完。参数错误返回 `HAL_ERROR`，不会替换已有运动。
- 第一次合法调用检查外设配置、准备四路并等待 2 ms 唤醒，之后接口不等待运动完成。
- 必须在 HAL、系统时钟及 CubeMX 生成的 `MX_GPIO_Init()`、`MX_TIM2/3/4/5_Init()` 完成之后，
  从中断开启的主循环调用，不要从中断服务函数调用。现有 `main.c` 已按此顺序执行。
- 正方向仅表示 DIR 高电平。实际顺逆时针受电机线序和观察方向影响。

```c
#include "d36a_motor.h"

D36A_Control(1, 10, D36A_PULSES_PER_REV);  /* 电机 1 正转一圈 */
D36A_Control(2, -10, D36A_PULSES_PER_REV); /* 电机 2 反转一圈 */
D36A_Control(3, 20, 0);                   /* 电机 3 连续正转 */
D36A_Control(4, -15, 0);                  /* 电机 4 连续反转 */
D36A_Control(3, 0, 0);                    /* 电机 3 停止并保持 */
```

运行中修改指令，会在原来当前脉冲周期结束后生效，避免把高电平截断或在脉冲中途改变方向。
等待期间多次下发时以最后一条为准，不是排队执行。
等待时间最多约一个旧脉冲周期，例如 10 RPM 时约 3.75 ms，1 RPM 时约 37.5 ms。
新指令的脉冲数从新指令生效时重新计算，不包含替换前完成的脉冲。
本程序没有加减速曲线，高负载时突然启动或反转可能失步；当前用 5 RPM 空载验证，
每圈后保持约 10 秒，再同方向启动。

## 实现与资源占用

电机运动逻辑在 `Core/Src/d36a_motor.c`，头文件只提供参数和一个应用函数声明。
GPIO、定时器基础配置及 NVIC 由 `FPGA.ioc` 统一管理，通过 CubeMX 生成 `gpio.c`、`tim.c`。
四个中断入口在 CubeMX 生成的 `stm32f4xx_it.c` 中，调用 `HAL_TIM_IRQHandler()`，
再进入驱动中的 `HAL_TIM_PeriodElapsedCallback()` 处理计数，不增加应用调用接口。

| 资源 | 用途 |
| --- | --- |
| TIM2 CH1 / PA5 | 电机 1 STEP |
| TIM5 CH2 / PA1 | 电机 2 STEP |
| TIM3 CH1 / PA6 | 电机 3 STEP |
| TIM4 CH1 / PB6 | 电机 4 STEP |
| PA4、PA2、PB5、PB11 | 电机 1-4 的 DIR |
| PC2、PC3、PG8、PB10 | 电机 1-4 的 EN |
| TIM2/3/4/5 更新中断，优先级 1 | 独立计数和执行待处理指令 |
| DBGMCU 对应定时器冻结位 | 调试暂停时冻结 STEP，避免继续多走 |

定时器预分频由 `.ioc` 配置。当前 APB1 定时器时钟为 16 MHz，PSC=15，计数频率为 1 MHz。
驱动首次调用时根据 APB1 时钟及其倍频规则校验四个 PSC，若配置不匹配或定时器未初始化，
返回 `HAL_ERROR`，不会悄悄覆盖 `.ioc` 配置。
使用 PWM2，周期前半段为低、后半段为高，在周期结束的下降沿中断计数并停止，避免多发一个上升沿。
停止时 STEP 强制为低，EN 保持高。
当前 1.8° 配置最高 60 RPM，即每路 1600 Hz。软件另外限制每路最高 3200 Hz，
供 0.9° 配置使用。所有通道定时器周期统一限制在 16 位范围内。

精确计数依赖中断及时执行：当前 60 RPM 下必须在下一次上升沿前（约 312 us 内）处理更新中断。
后续集成其他功能时不要长时间屏蔽中断，也不要加入会长时间抢占这些定时器中断的代码。
启用加倍脉冲数的 0.9° 配置时，该时间缩短为约 156 us。
HSI 频率误差会影响实际转速和时间，但不会改变每次命令的脉冲数。

## CubeMX 配置与后续维护

**全部基础外设配置已同步到 `FPGA.ioc`，并使用本机 CubeMX 6.17 实际重新生成代码验证。**
打开 `.ioc` 可直接看到所有占用引脚及 `D36A_M1_STEP`、`D36A_M1_DIR`、`D36A_M1_EN` 等标签。

| CubeMX 项目 | 当前设置及用途 |
| --- | --- |
| RCC | HSI 16 MHz 直接作为 SYSCLK；AHB、APB1、APB2 均不分频；不使用 PLL |
| SYS | PA13/PA14 保留 SWD；SysTick 为 HAL 毫秒时基 |
| PA4、PA2、PB5、PB11；PC2、PC3、PG8、PB10 | DIR、EN 为推挽输出、下拉、低速，上电输出低；EN 初始低使驱动板保持休眠 |

| TIM2/3/4 CH1、TIM5 CH2 | 内部时钟、向上计数、PSC=15、ARR=65535、自动重装载预装载开启 |

| 四路 NVIC | 启用全局中断，抢占优先级 1、子优先级 0，由 CubeMX 生成 IRQHandler 并调用 HAL |
| Project Manager | CMake、按外设生成 `.c/.h`、保留 USER CODE；GPIO 和四个定时器初始化在应用代码之前 |

ARR/CCR 初值只用于基础配置，不代表启动后就会转动。运行时的启动、停止、改速、方向和使能电平
由驱动根据命令设置，包括启用计数中断、改变 ARR/CCR、停止时强制 STEP 为低。
`URS`（禁止软件更新事件被计为脉冲）和 `DBGMCU`（调试暂停时冻结定时器）在本 MCU 的 CubeMX
配置中没有对应选项，因此保留在驱动内并加有注释。它们随自定义驱动文件保留，不会被重新生成覆盖。

本次恢复验证仅修改 `main.c` 的 USER CODE 应用逻辑，不改变引脚、时钟或定时器基础配置，
因此 `.ioc` 无需变更。5 RPM 使用的 ARR=7499、CCR=3750 由现有驱动在接收命令时计算并设置。
当前 `MOTOR_TEST_STARTUP_MS` 为上电等待 10000 ms，`MOTOR_TEST_PAUSE_MS` 为每圈后的间歇 10000 ms，
`MOTOR_TEST_MOVE_MS` 为一圈用时 12000 ms，`MOTOR_TEST_INTERVAL_MS` 为两次启动间隔 22000 ms。
每次命令发送 `D36A_PULSES_PER_REV`（1600）个脉冲，避免无限运动或覆盖未完成的一圈。

后续维护时：

1. 在 CubeMX 修改基础外设配置后 Generate Code，再重新编译。自定义驱动文件、`main.c` 的 USER CODE
   和根目录 CMake 中的自定义源文件条目均会保留。
2. 修改系统时钟时，四个定时器的 `PSC = TIMxCLK / 1000000 - 1`，保持计数频率为 1 MHz。
   例如 APB1 定时器时钟为 84 MHz 时，PSC 应为 83。仅修改时钟而未同步 PSC，驱动会报错。
3. DIR/EN 引脚使用生成的 `D36A_Mx_*_GPIO_Port`、`D36A_Mx_*_Pin` 宏。
   修改 GPIO 位置时保留这些标签；STEP 可以切换同一定时器通道的其他复用引脚。
   若更换定时器或通道，还需同步 `d36a_motor.c` 的 `hardware` 映射。
4. TIM2/3/4/5 全部通道由本驱动独占，不要用其他 HAL 启停函数同时控制它们。
   当前项目只定义一个 `HAL_TIM_PeriodElapsedCallback()`；以后增加其他定时器回调逻辑时，
   在同一回调内按句柄分发，避免重复定义或替换电机回调。HAL 时基继续使用 SysTick。
5. 项目根目录不要创建名为 `tmp` 的文件夹，CubeMX 6.17 生成代码会使用该临时文件名。
   本项目临时资料放在 `build/` 下。
