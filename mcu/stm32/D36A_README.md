# STM32F407 + D36A 三轴串口控制

当前为正式串口控制程序，命令解析和项目逻辑位于 `Core/Src/main.c` 的 USER CODE 区域。
上电不自动运动，发出 `ready`，等待上位机命令；电机使能并保持当前位置。
对端可能错过这条开机消息，连接后可用 `wake` 重新握手；串口接收异常会自动恢复。
上电前必须断电手动归零三个机构。复位、重新烧录也会把软件位置清零，必须重新建立物理零点。

## 轴编号与方向

串口中的 n 是逻辑轴编号 1-3，不是四台物理电机的编号。

| 逻辑轴 n | 机构 | 物理驱动通道 | 正向时 DIR |
| --- | --- | --- | --- |
| 1 | 悬臂左右 | 第一块 D36A 通道 1，物理电机 1 | 低 |
| 2 | 整体龙门架前后 | 第一块通道 2，物理电机 2；第二块通道 1，物理电机 3 | 前者高，后者低 |
| 3 | 悬臂伸缩 | 第二块 D36A 通道 2，物理电机 4 | 高 |

轴 1 根据最新上电实测反转正方向：`measure 1 start` 和坐标增大时 PA4/DIR1 为低，返回零点时为高。
轴 1 的脉冲位置符号也同时转换，因此向新正方向运动时测量圈数和坐标均增加。
轴 2、3 保留原来的正方向。轴 2 反向时两台 DIR 同时互换，始终反向旋转。
两台电机应使用相同细分、步距角及对应的机械传动比。

## 串口与接线

使用 USART3，**115200 波特率、8 数据位、无校验、1 停止位、无流控（8N1）**。
使用 3.3 V TTL 的 USB 转串口模块，不是 RS-232 电平。

| STM32 | USB 转串口模块 |
| --- | --- |
| PD8 / USART3_TX | RXD |
| PD9 / USART3_RX | TXD |
| GND | GND |
| 5V、3V3 | 不连接模块电源脚，STM32 继续独立 USB 供电 |

PD8、PD9 在上传的 M144Z-M4 开发板照片中相邻。此串口不经过开发板 USB_OTG，
不能仅把 USB_OTG 连电脑就当作虚拟串口。断电接线，按芯片信号名找排针，PA0 继续不使用。

电机控制线保持原分配：

| 逻辑轴 | 物理电机 | D36A 通道 | ST / STEP | DIR | EN |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 第一块通道 1 | PA5 -> ST1 | PA4 -> DIR1 | PC2 -> EN1 |
| 2 | 2 | 第一块通道 2 | PA1 -> ST2 | PA2 -> DIR2 | PC3 -> EN2 |
| 2 | 3 | 第二块通道 1 | PA6 -> ST1 | PB5 -> DIR1 | PG8 -> EN1 |
| 3 | 4 | 第二块通道 2 | PB6 -> ST2 | PB11 -> DIR2 | PB10 -> EN2 |

两块 D36A 的 Vin+/Vin- 接外部 12 V 电源正负极；两块驱动、STM32 和串口模块信号地共地。
D36A 的 5V、3V3 输出不与 STM32 供电并接，ADC 不接。EN 是高有效，接芯片 nSLEEP。
PA11/PA12 的 USB 和 PA13/PA14 的 SWD 继续保留。

两块 D36A 均继续使用 **8 细分、0.93 A，开关 1-6：ON OFF OFF OFF ON OFF**。
电流由驱动板拨码设置，软件不设置电流；电源的最大 6 A 是供电能力。
四台电机共同运行的供电、温升和机械同步尚需上板验证，保持驱动风扇正常工作。

### 已修复的电机线序

用户已实测：原线束 1、3 属于一相，2、4 属于另一相；所用驱动接口要求相邻成对。
按用户当时的端子编号，修正为驱动板 1<-线束1、2<-线束3、3<-线束2、4<-线束4，
之后单电机及单向一圈验证已正常工作。此前嗡鸣、摆动和错误配对测得 OL，不能再解释为绕组损坏。

新增每条线束均需断电核对：从驱动端拔下线束，电机端保持连接，A+/A- 和 B+/B- 各有有限电阻，
跨相不导通。编号受观察方向影响，两个驱动插座也不能直接假定针序相同，以各自丝印为准。

## 通信规则

- 小写 ASCII 文本，每条命令以 LF、CR 或 CRLF 结束；回包以 CRLF 结束。
- 允许首尾空格、多个空格和制表符；不能省略参数或添加多余参数。
- **三个轴统一使用 0-100 的归一化坐标**：0 是手动归零点，100 是各轴设定的最远点，50 是半行程。
  `measure` 回报和 `set n m` 的 m 仍然使用电机圈数；`go x n k` 的 x、`state`、`done` 和已 set 轴的 `stopped` 使用归一化坐标。
- m、x 为非负十进制，支持最多 6 位小数，不接受负数、科学计数法、NaN 或 Inf。
- 以 1.8 度电机、8 细分计，一圈 1600 脉冲，分辨率为 0.000625 圈。
  先将 m 四舍五入为行程脉冲数 M，再将目标换算为 `round(x * M / 100)` 个脉冲。
  回报坐标为 `100 * 当前脉冲数 / M`，固定 6 位小数；实际坐标分辨率为 `100 / M`。
  `ok go` 显示实际采用的目标坐标，可能因微步取整而与输入略有不同；0 和 100 均准确对应端点。
- k 为整数 RPM，范围 1-60，只表示速度大小；正反转根据目标与当前位置自动选择。
- 最大可设置行程为 1000000 圈，仅为数值上限，不能充当机械限位。
- 每组同时接受一个运动任务，其他组可并行运动。主机应等待命令确认，再发送下一条；
  `go` 的确认表示已接受，`done` 才表示脉冲发送完成。等待运动期间仍可发送 `state` 或 `stop`。

### 冷启动与 wake 重连

正常连接时发送一行 `wake`，返回：

```text
ok wake
```

`wake` 不要求事先 set。程序会请求停止三组电机，丢弃尚未执行的接收数据，清除 UART 错误标志并重新启动接收。
软件当前脉冲位置、零点定义和已设置的行程保留，不重启 MCU，也不自动运动或清零。
`ok wake` 表示重连命令已执行；若此前正在运动，还会在脉冲周期结束后返回各轴的 `stopped`。
不要把 wake 当作运动期间周期发送的心跳，否则会取消运动。

对接另一块开发板时，推荐按以下顺序建立连接：

1. 双方完成上电和串口初始化，F4 使用 USART3、115200、8N1。电机 12 V 稍后上电不应阻止串口回应。
2. 发送实际字节串 `\r\nwake\r\n`，即十六进制 `0D 0A 77 61 6B 65 0D 0A`。
   前置换行用于结束上电杂波、残留半条命令或错误后的丢弃状态。
3. 等待 `ok wake\r\n`。若 1 秒未收到，可每隔 1 秒重试；不要依赖只发一次的 `ready`。
4. 收到确认后再逐条发送 set、state、go。不要把 wake 和运动命令一起发送，wake 会清空尚未执行的接收队列。

PC 串口助手可先发送一个空行，再发送 `wake` 并启用 CRLF 结尾。
若串口助手不支持转义，不要把字符 `\r\n` 原样输入后发送。
同一次上电期间重连无需重新 set；**整机断电或 MCU 复位后，RAM 中的位置和行程仍会丢失，必须先恢复物理零点再 set**。
wake 不能得知断电期间机构是否移动，也不能恢复真实机械坐标。

本次补强覆盖：RX 悬空时的电平保持、启动时残留的 UART 错误、接收启动暂时失败、错误中断反复触发、接收中断被关闭、错过 ready。
如果冷启动后仍然完全无回包，先只给 F4 和串口模块供电测试 wake，并检查开发板 **BOOT0 是否为 0 / Flash 启动**，然后按复位键再试。
ST-Link 能下载并启动程序，不代表断电后的启动选择正确。冷启动进入系统下载程序时没有运行 main，应用内的 wake 无法执行。
检查串口模块是否通过 DTR/RTS 控制了 BOOT0 或复位脚。应用通信接线只需 TX、RX、GND。

#### 2026-09-19 冷启动现场诊断

用户确认一直使用 ST-Link 下载。通过已连接的 ST-Link，以 HOTPLUG 模式只读查看故障现场，未发出复位、暂停、运行或烧录命令：

| 读取位置 | 现场值 | 含义 |
| --- | --- | --- |
| CPU 状态 | running | 内核并非暂停在调试器中 |
| SCB VTOR，0xE000ED08 | 0x1FFF0000 | 中断向量表指向系统 ROM |
| SYSCFG MEMRMP，0x40013800 | 0x00000001 | 系统 Flash 映射在零地址 |
| 零地址前两项 | 0x20002D98、0x1FFF4BCD | 与 0x1FFF0000 的系统 ROM 向量一致 |
| 应用 Flash，0x08000000 前两项 | 0x20020000、0x08005755 | 应用向量仍存在，并非零地址当前选中的启动向量 |
| USART3 CR1/CR2/CR3 | 全部为 0 | 当前没有执行本工程的串口初始化 |

结论：此次无回包时，芯片进入了系统下载程序，未运行本工程。下一步应修正硬件启动选择，不能靠增加应用串口命令解决。
断电后将 **BOOT0 设为 0（低电平，用户 Flash 启动）**，保持 BOOT 按键松开，再重新上电；使用 ST-Link 下载不需要将 BOOT0 置 1。
BOOT0 是专用启动信号，不是 PA0 或 PB0；按开发板启动选择丝印操作，不要猜测跳帽方向。
先保持电机 12 V 关闭，仅验证 F4 串口的 ready / wake 回包，成功后再接通驱动电源并恢复正常测试。
若 BOOT0 标识已经为 0，需核查该启动脚的实际电平、跳帽接触和外接电路，不能仅凭 ST-Link 指示灯判断冷启动成功。

后续用户反馈：按开发板 RST 键后已恢复正常，未再要求调整启动代码。以上寄存器是故障发生时的观察记录，
不代表已经确认 BOOT0 跳帽本身有误；仍需区分复位时序与启动选择，不将软件 wake 当作硬件复位的替代。

截图中 wake 显示为 5 字节，可能包含一个 CR 或 LF，不能据此认定缺少行尾。
协议保持每条命令以 CR/LF 结束；没有采用收到 wake 四字母就提前执行的方式，以免将 wake 后续非法内容误当作有效握手。

### 功能 1：测量行程

```text
measure 1 start
```

返回 `ok measure 1 start`，轴 1 从零点以 10 RPM 向正向持续运动。
只有该轴软件位置为 0 且空闲时才允许开始；如果以前 set 过该轴，重新测量会使该轴的 set 失效。
测量不会根据旧行程自动停止，用户需要在机械终点前留出反应距离并发送：

```text
measure 1 over
```

程序在当前脉冲周期结束时停止并保持，之后回报，例如：

```text
measure 1 12.345625
```

这是从零点累计的脉冲对应圈数；轴 2 只报告一台电机等效的圈数，不把两台的圈数相加。
位置保留在测得的终点，不会假装回到 0。该指令不自动 set，需要继续发送 `set 1 12.345625`。
用这次测得的圈数 set 后，该轴当前归一化坐标为 100；`go 0 1 10` 可返回原零点。
停止命令从解析生效到结束最多约一个脉冲周期，10 RPM 时约 3.75 ms；此外还有串口传输、
排队和人的反应时间。测量默认没有已知机械上限，不能依靠堵转判断终点。

### 功能 2：设置行程和定位

```text
set 1 12.345625
```

返回 `ok set 1 12.345625`，回包中的数字仍是实际采用的行程圈数。只设置行程上限，**不运动、不重置脉冲位置或零点**。
上电归零后 set，坐标为 0；测量结束后用测得圈数 set，坐标为 100。
要求 m 取整后至少一个微步、不小于当前已行走的圈数且该轴空闲。
空闲时更改 m 会按新行程重新计算归一化坐标，例如位置为 5 圈，行程从 10 圈改为 20 圈，坐标从 50 变为 25。

```text
go 0 1 10
```

含义是轴 1 以 10 RPM 到坐标 0。返回 `ok go 1 0.000000`，随后运动完成时返回：

```text
done 1 0.000000
```

命令顺序严格为 **`go x n k`**，x 的范围是 `[0,100]`，k 仍为 RPM。正向或反向由目标自动决定。
例如 `set 1 20` 后，`go 50 1 10` 表示以 10 RPM 走到离零点 10 圈处，`go 100 1 10` 表示去最远点。
未 set 该轴时报 `error not_set n`；非负目标大于 100 报 `error range n`；运动中重发定位报 `error busy n`。
范围检查在脉冲取整之前执行，`go 100.000001 1 10` 也会被拒绝。
目标已等于当前位置时立即回包 ok 和 done，不发脉冲。

### 功能 3：位置查询

```text
state
```

三个轴均 set 后返回，例如：

```text
state 0.000000 50.000000 25.000000
```

依次为左右、龙门架前后、伸缩三个归一化坐标；此例分别处于零点、半行程、四分之一行程，运动中可查询。
任一轴尚未 set 时返回 `error not_set n`，n 为第一个未配置轴。
这是已发出的步进脉冲位置估计，没有编码器反馈，不能识别失步、打滑或手动推移。

### 辅助停止与报错

`stop n` 可停止该组任意测量或定位，保留当前脉冲位置。
该轴已 set 时返回 `stopped n x`，x 为 0-100 坐标；尚未 set 或测量被中止时返回 `stopped n not_set`，此时没有有效归一化坐标。
需要获得测量圈数时应使用 `measure n over` 正常结束测量。
轴 2 会成对停止。取消的 go 不再返回 done；中止的测量不自动形成行程设置。

| 回包 | 含义 |
| --- | --- |
| `error syntax` | 命令、参数数量或 measure 子命令错误 |
| `error axis` | n 必须为 1、2 或 3 |
| `error number` | 坐标/圈数格式非法或超过数值上限 |
| `error speed` | k 必须为 1-60 的整数 |
| `error not_set n` | 该轴还未配置行程 |
| `error busy n` | 该轴正在运动或等待停止回报 |
| `error not_zero n` | 测量必须从零点开始 |
| `error not_measuring n` | 尚未 measure start，不能 measure over |
| `error range n` | 行程取整后为零、小于当前已行走圈数，或非负目标坐标大于 100 |
| `error travel_limit n` | 到达计数上限或未按预期完成定位 |
| `error driver` | 驱动未接受指令 |
| `error line` | 单行超过 95 字节或含非法控制字符；停止所有轴并丢弃该行 |
| `error serial_rx` | UART 接收错误、接收未运行或 512 字节缓冲区溢出；停止所有轴，清空数据并重启接收 |

收到 `error serial_rx` 后先单独发送换行重新对齐，再查询或发命令；已损坏的半行不会被当作新指令执行。
也可发送 `\r\nwake\r\n` 重新握手；重连操作不自动恢复之前被取消的运动。
UART 发送失败也请求停止所有轴。拔掉串口线本身不一定触发 UART 错误，尚未实现通信心跳超时。

## 操作示例

已有行程记录时，断电手动归零，上电后先发送 wake 并等待 ok wake，再逐条输入：

```text
set 1 12.345625
set 2 30
set 3 8
state
go 1 1 5
```

最后一条让左右轴去到全行程的 1% 处，速度 5 RPM。等 done 后，`go 0 1 5` 返回零点。
测试龙门架时可先从较小位移与较低速度开始，例如 `go 0.1 2 5` 表示全行程的 0.1%。
3 组的首次测量则分别使用 `measure n start`、`measure n over`，保存回报并逐轴 set。

所有位置与行程仅保存在 RAM。断电后不会保存，重启后需要手动归零并重新 set；
可由上位机保存测得的 m。未接限位开关、未实现自动回零或加减速曲线。
当前是开环定位，负载下失步会使软件坐标偏离实物，不能将 `done` 当作传感器确认到位。

## 实现与维护

唯一运动指令入口仍为 `D36A_Control(motor, rpm, pulses)`。
物理编号 1-4 保留，新增 `D36A_GANTRY=5` 代表物理 2/3 反向配对；不要把这里的 5 当作串口轴编号。
main 将串口 1/2/3 映射为驱动 1/5/4。首次 gantry 调用后，单独控制物理 2/3 会报错，直到复位。
`main.c` 的 `axis_direction = {-1, 1, 1}` 统一转换逻辑运动方向和驱动位置符号；底层物理电机接口的正负含义保持不变。
`axes[].limit`、`target` 和驱动位置始终保存为整数脉冲；仅在串口输入、输出时转换 0-100 坐标。
进入配对模式前两台必须停在软件零点，防止把已有的独立位移误当作同步位移。
新增只读 `D36A_GetStatus()` 获取脉冲位置及运行状态，不增加第二个运动入口。

TIM3（物理 3）为主定时器，TRGO=ENABLE 经 TIM5 ITR1 控制门控计数。
两个定时器使用同一 APB1 时钟、相同预分频和周期，先准备 TIM5 再启动 TIM3，保持固定相位关系。
TIM3 的更新回调统一计数并成对停止，TIM5 更新中断在配对运动时关闭。
这是控制脉冲的硬件同步，不能检测某一台机械失步；仍需上板核对双 STEP 波形和龙门架机械运行。

单轴使用 PWM2，前半周期低、后半周期高，在下降沿计数并停止。
查询同时考虑尚未进入回调的更新标志和当前高电平脉冲，停止回包在计数完成后发送。
原有四物理电机独立控制仅供未启用配对的测试使用，TIM5 会相应切换为独立计数。

USART3 中断仅收字节，主循环执行解析和回复，运动由硬件定时器与更新中断推进。
位置计算用整数脉冲和定点十进制，不使用浮点串口格式化。
不要长时间屏蔽定时器中断；60 RPM、1600 脉冲/圈时需在下一上升沿前约 312 us 内处理更新。

### 已同步的基础配置

以下基础配置均已同步到 `FPGA.ioc`，使用本机 CubeMX 6.17 加载并重新生成代码验证。

| 配置 | 用途 |
| --- | --- |
| USART3：PD8 TX、PD9 RX、115200、8N1、无流控 | 上位机通信；GPIO AF7，启用 GPIOD/USART3 时钟 |
| PD9 / USART3_RX 内部上拉 | 对端未上电或 RX 暂时悬空时保持空闲高电平 |
| USART3 全局中断，抢占优先级 2 | 持续接收，优先级低于电机定时器的 1 |
| TIM3 主触发改为 TIM_TRGO_ENABLE | 用主定时器使能信号控制龙门架另一台 |

系统时钟仍为 HSI 16 MHz，AHB/APB1/APB2 不分频，四路定时器 PSC=15，计数频率 1 MHz。

运行时 ARR/CCR、启停、方向、同步组中断控制属于运动状态，由驱动设置。
重新生成代码时保留 USER CODE；时钟若改变，需同步四路 PSC，使计数频率仍为 1 MHz。

复制或克隆后的 CMake 缓存含原电脑的绝对路径，必须重新配置。在本目录、已配置 STM32 工具链 PATH 的终端执行：

```powershell
cmake --fresh --preset Debug
cmake --build --preset Debug
cmake --fresh --preset Release
cmake --build --preset Release
```

构建需要 CMake 3.24 或更新版本（支持 --fresh）、Ninja 及 arm-none-eabi-gcc；本次使用 CMake 4.2.3、GCC 14.3.1。
build 中 before_*、Diagnostic、CubeMX 检查副本及其脚本保留作历史记录，可能含旧路径，不作为当前固件的构建入口。
