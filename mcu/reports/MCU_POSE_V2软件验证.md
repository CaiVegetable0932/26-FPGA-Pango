# MCU_POSE_V2 软件验证记录

日期：2026-10-11。范围：主机无硬件时的编解码、F1/F4 固件交叉编译和可控模拟测试。本文不替代传感器、舵机、电机、串口电平、FPGA 接收和停机延迟实测。

## 通过项

- `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1`：CRC 标准向量、半包/粘包/垃圾前缀/超时/坏 CRC、MPU 身份/配置回读/有符号突发读取/I²C 失败、标定期间运动重启稳定等待、倾斜下陀螺 yaw 运动学、舵机优先加权/分歧/过期回退、F1 重复命令和本地超时、F4 双会话/FPGA权限/任务接纳/租约故障/标定中断重试，以及旧舵机和 D36A 回归均通过。
- F1/F4 均通过 Release 和 Debug 构建，ELF/HEX/BIN 归 `build/f1`、`build/f4`。F1 静态 RAM 约15KB/20KB，F4约96KB/128KB；Debug Flash约54KB/62KB、59KB/768KB。最终值以本轮构建日志与 `.map` 为准；栈峰值还须实板量测。
- 独立 Python 解码器与 C 固件生成的 `tests/vectors.json` 互操作测试通过；每个构建目录的 `manifest.json` 保存编译器、配置与工程输入 SHA-256、ELF/HEX/BIN 长度及 SHA-256，不将此软件清单计作硬件验收。
- 迁移核对：原 `stm32/`、`yuntai/` 共1153个受控文件已迁移；重建会更新CMake自动生成索引，原F4受控构建记录额外归档为 `build/f4/history-before-v2.tar`。D36A驱动内容哈希保持一致。交接文档两份副本SHA-256一致。所有原厂和历史参考资料保留。

此前迁移逐文件核对为1147个新路径文件及6个仅保存在历史归档中的旧CMake索引文件，未保留数为0；归档包含786项。源码、测试、依赖和原始参考均在新目录，两个旧工程目录已移除。本轮固件目录分别改名为 `firmware/yuntai`、`firmware/longmenjia`，构建脚本接受新名称及 f1/f4 别名，构建与测试输出仍按板卡编号分区。

新增全系统紧急 STOP 接口及 F4→F1 停机转发已取消。模拟回归确认外部0x47/内部0x23返回UNSUPPORTED，不改变正在执行的动作或标定、不续期控制租约；GET_INFO固件版本为2.1且不再声明紧急停机能力。不再发送STOPPING/STOPPED，保留旧数值。原按轴 `stop n` 保持可用。内部序号65535不再保留给停机；耗尽检查仍在启动所选F4轴之前完成。

本地通信故障仍取消F4任务并暂停F1保活/待发送请求，由F1本地1000ms超时取消动作；回归确认该故障不会在每次轮询重复触发，不会继续发送内部保活或停机命令。未完成标定返回可重试的失败终态。此处理不作为两块板同时停机的证明。

## 未完成实板验收

- 尚未把固件烧录到 F1/F4，也没有实物 MPU6050、舵机、D36A、FPGA 或电平转换器可用；不能声称姿态角精度、200Hz 端到端帧率、串口误码率、F4↔F1 延迟、本地超时取消动作延迟或 FPGA 同帧绑定已经达标。
- F4 新增 USART1/USART6 以及 F1 I2C1 的引脚、电源、上拉、TX/RX 交叉、共地和 IO 电平必须依据目标板原理图确认。代码默认 F4 PA9/PA10 与 PC6/PC7，F1 PB6/PB7、AD0=0。
- MPU6050 安装四元数当前为单位阵；pitch/yaw 正方向、陀螺/加速度零偏、稳定阈值、融合分歧阈值和权重需通过独立角度参考调试后写入 `config/pose_config.h` 与实体配置哈希。`POSE_CONFIG_VERIFIED=0`，STATE 配置验证位保持清除，不能用于宣称正式精度验收。
- F4 `.ioc` 已同步新增 UART/时钟/定时器声明，但没有在本轮运行 CubeMX 再生成；生成前须备份并核对用户代码区，禁止覆盖已适配的链路模块。

## 联调顺序

先单独确认 F1 `WHO_AM_I`、寄存器回读、两个舵机反馈和 ready 到位；再只接 F4-F1 验证代理及本地超时恢复；然后确认 F4 PC 的 LEGACY 和结构化命令；最后接 FPGA 460800 链路，先 GET_INFO/OPEN/GET_CONFIG/STATE/SYNC，再开放 PC MOVE/HOME。每次复位都记录 device_id、boot_id、config_version、线缆和电平状态。
