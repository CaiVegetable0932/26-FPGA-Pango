# FPGA 分区优化交接总览

版本：V1.0。日期：2026-10-12。性质：设计与开发交接，不是实现或验证报告。

统一目标：**性能 > 时序 > 资源消耗**。本文及七份分区方案仅为规划，本次未修改实现、构建或操作硬件。

2026-10-19 布线专项执行口径见 [FPGA 布线效率与拥塞专项优化方案](../FPGA布线效率与拥塞专项优化方案.md)：功能、性能、真实时序和资源预算作为门槛，达标候选优先比较布线成功率、耗时与稳定性，再考虑资源节省。专项针对最新 P12 热点，允许必要的多智能体协作，但重型 PDS 构建串行调度，并遵守现有暂停状态。

## 1. 优先级的执行口径

1. 性能第一：提高完整有效帧吞吐、降低有界排队和处理时延，改善最坏工况下的服务能力；不能以降精度、降分辨率、压缩原始数据、重复帧或静默丢帧换取数字提升。
2. 时序第二：在满足同一功能和性能目标的候选中，优先选择布局布线后时序余量更好、CDC更清楚、对拥塞更稳健的实现。允许增加流水寄存器、FIFO、并行运算和RAM端口副本。
3. 资源第三：达到前两项后，再收窄经证明足够的位宽、复用低频运算或减少冗余缓冲；不能为节省LUT/APM/DRM使启动间隔或服务期限不达标。

功能正确、协议一致、物理接口合法及真实时序收敛是候选可交付的前提，不是可被性能目标豁免的条件。提高目标频率但实际WNS为负，不能记为性能提升；放宽约束、遗漏外部延时或扩大false path也不算优化。

若两个方案均达标，先比较实测/可信事务模型下的有效吞吐，再比较同口径最坏时延和时序余量，最后比较资源。性能尚无真实基线时，先补实现与可重复基准，不编造提升百分比。

统一测量有效吞吐R、II、stall比例/原因、队列峰值、平均/p95/最大延迟、丢帧/错误、WNS/TNS及资源。R可用`f_clk/II × 有效利用率`估计，但应以完整帧与事务计数确认。

资源先按整机报告分配，原设计约50,000 LUT、95,000 FF、180 APM、120块36 Kbit RAM是规划预算，不是各分区可独占的上限。资源逼近器件或导致拥塞时，必须重新比较候选，不能让“资源第三”变成无限复制。

## 5. 共同接口约定

| 接口边界 | 需冻结的语义 | 负责分区 |
| --- | --- | --- |
| 输入→ISP/RAW DMA | 格式/Bayer/尺寸、像素有效、行帧边界、错误帧及身份 | 02提供，03/04/06消费 |
| 流水模块之间 | 数据与tag同进退；可背压处的握手、稳定性、启动间隔与延迟 | 各发送/接收分区联合冻结 |
| 请求→DDR适配 | 地址单位、长度单位、掩码、完成/取消、在途上限和错误 | 04提供，03/05/06/07消费 |
| 帧池→消费者 | acquire/release、slot generation、在途事务排空、取消确认 | 03提供，04落实事务栅栏 |
| cache→插值 | 坐标tag、四邻域顺序、重复地址、miss/重放、有效掩码 | 06负责，04配合回填 |
| 参数→帧系统 | 影子提交、拒绝/生效状态、实体版本与源帧关联 | 07提供，02/03/06落实 |
| 显示/网络→主机 | 实际格式、完整性、来源身份、计数与失败状态 | 05/07提供，host测评 |

以上为需落实的内部语义，不是已存在统一端口，也不新分配外部协议编号。内部端口/宽度由接手者依据已有模式冻结；外部网络、UART和图像描述符遵循现有权威设计，修改时同步各端代码和测试。

单比特状态可按语义同步；脉冲、总线、计数快照和参数组需对应握手/FIFO/快照机制。不可暂停DVP不能靠后端ready暂停，HDMI有效区也不能通过背压停止扫描；缓冲、期限和整帧容错分别设计。

## 6. 协作与修改所有权

每个智能体在自己的模块、专用测试与报告范围工作。共享文件的最终写入由集成负责人统一合并；专项提供具体差异、端口定义、约束要求和测试证据。

共享文件包括：两个顶层、两套工程Tcl/PDS、`fpga/config/ip_catalog.json`、全局时钟/板级约束、跨端主方案及公共测试入口。01维护共同约束语义，集成负责人统一工程和IP配置。04负责DDR事务定义，03负责帧槽生命周期，避免双方各自定义“完成”。

`ip_integration_bank.v`仅为构建集成占位；业务逻辑放各自开发模块，不把所有正式实现塞入该模块。既有vendor副本按功能有范围地修改，新增正式模块可按主设计建立`fpga/rtl/input/isp/geometry/memory/video/network/control/`等目录，这些是建议落点，不声称已经存在。

代码、脚本、模型、工程、构建及实测证据直接放`fpga/`、`mcu/`、`host/`；本目录只放规划。新增/受影响代码块同步注释。不得回退既有改动、编辑原参考资料、擅增Git忽略规则或手改生成IP HDL。

## 7. 集成顺序与共同验收

1. 先统一基线、接口单位、帧身份和测量口径；已有代码与新增功能分别标记。
2. 01核验域/约束；02补输入与配置；03/04联合落实帧合法性和事务完成。各区可用契约模型推进，不把模型结果写成实板结果。
3. 05先用已知图案与DMA模型验证；06先用位精确模型和内存模型验证；07先用协议向量/源图案验证。
4. 集成RAW/ISP/矫正/显示/网络后，按混合负载和最坏服务期限测试；单区吞吐达标不能替代整机达标。
5. 对同一配置执行功能回归、目标器件PnR与约束审计；硬件操作另遵循现有放行条件。
6. 通过前两项后执行资源优化，重复受影响检查，保留候选对比及撤回条件。

共同验收项：有效尺寸/数据逐字节或位精确正确；帧身份和参数一致；过载明确整帧失败并计数；输入/处理/结果/RAW网络完整帧率分别通过；关键服务期限满足；所有声明覆盖的时序约束收敛且例外有效；资源按整机统计。

任何存在未签核外部接口、来源未确认或依赖未通过的分区，只能报告其已验证局部范围。快照是板端同帧S1与选定结果，普通HDMI到达次序不提供同帧证明。RAW60满流不承诺继续走千兆网。

## 8. 每个专项的交付格式

- 问题/新增能力、改动范围与依赖接口。
- 基线与候选的性能、时序、资源表，注明计算/仿真/PnR/实测层级。
- 使用的源码、配置、位流与工具版本、原始参考来源。
- 实际执行的测试、原始日志/数据路径和未覆盖项目。
- 共享文件需合并的差异、回归影响和下一阶段条件。

报告分别写`fpga/reports/`、`mcu/reports/`或`host/reports/`，不把实测报告放本目录。没有物理验证时，不用“最终达标”替代“局部仿真通过”。
