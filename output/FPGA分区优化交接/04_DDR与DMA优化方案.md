# 04 DDR 与 DMA 优化方案

V1.0，2026-10-12。专项优先级：**性能 > 时序 > 资源消耗**。以混合负载下完整有效帧和最坏服务期限评估，不能只报告顺序读写峰值。

## 1. 当前基线与资料

先读[总览](README.md)、[跨端方案](../OV5640_RAW8千兆网与HDMI双路回传方案.md) §4/§5、[主设计](../PG2L100H_1080p畸变矫正详细设计方案.md) §7、[帧池方案](03_帧池与帧身份优化方案.md)。

已有模块为[frame_read_write.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/frame_read_write.v)、[frame_fifo_write.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/frame_fifo_write.v)、[frame_fifo_read.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/frame_fifo_read.v)、[mem_write_arbi.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/mem_write_arbi.v)、[mem_read_arbi.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/mem_read_arbi.v)、[aq_axi_master_256.v](../../fpga/rtl/mini_camera_diag/vendor/frame_ddr3/aq_axi_master_256.v)及[Top适配](../../fpga/rtl/mini_camera_diag/vendor/Top.v)。

诊断采用32位物理DDR、256位用户数据口、16→256/256→16原生异步FIFO、固定16-beat帧突发。FIFO名称中的64是历史名称，不是实际数据宽度。主工程另准备32↔256 FIFO，但只是占位接线，没有地址请求。

原生DDR不是通用完整AXI接口。Top存在地址/LEN/ID宽度转换及常量`axi_bvalid`适配，需专项核对完成语义；generic master写计数中的`RD_LEN`引用、突发长度/尾段等也应逐项审计，不把厂商副本存在视作正确性证明。

必读安装版PDS/IP Compiler/Timing/UCE文档、目标DDR IP手册与原生生成的FDC/RCF、板级DDR颗粒资料。`I_ips_ddr_top`及内部层级与约束关联，改名/重生成时同步审计。原生示例引脚不得覆盖MINI板级引脚。

## 2. 性能预算与服务目标

| 项目 | 参考预算/要求 |
| --- | --- |
| 1080p30 RGB单向有效流量 | 186.624 MB/s |
| RAW写入+网络读出 | 合计124.416 MB/s有效载荷 |
| 源回填近似一帧工况 | 整机有效DDR参考870.912 MB/s |
| 四邻域无复用工况 | 整机有效DDR参考1,430.784 MB/s |
| 一组S1+结果快照复制并导出 | 至少37.3248 MB额外有效DDR流量，依阶段捕获方式重算 |

上述不是保证或最坏上界；需加入刷新、读写切换、短突发、首尾掩码、过量cache回填、stride/对齐访问及其他通道。stride占地址空间不等于每次必须搬完padding，应记录实际总线字节和有效像素字节两种统计。

吞吐目标是02不可暂停输入、05显示deadline、06主处理、07完整RAW流同时满足；快照低优先限流。仲裁保护输入/显示但不能无限饿死RAW而声称整机通过。

## 3. 性能优先优化路线

### D1 原生事务正确性先落实

核对地址是字节/字/beat、LEN是否beats-1、读写数据握手、掩码、ID/响应能力、允许突发长度/跨界范围、读写顺序及可见性。把byte-address统一转换集中在适配层，不在每个消费者重复猜测。

建立原生DDR事务模型，并为每个请求定义accepted、data_complete、drained、cancelled及error等语义。完成不得仅看地址被接受、最后像素产生或常量BVALID；03发布/释放所需的栅栏必须有控制器支持依据。若原生接口不支持某类背压/取消，不向上虚构该能力。

### D2 数据搬运与突发效率

1. 为RAW写、S1写、结果写、显示读、cache回填、RAW网络读及快照复制配置独立有界队列，消除无关客户端互阻。
2. 以原生支持范围比较合法突发长度，统计每突发有效字节、开销及最长占用。不能直接把generic 8位AWLEN能力套到原生4位LEN。
3. RGB888打包支持3字节/像素跨32 B beat残留、行首偏移与尾mask；RAW去stride/输出段跨行逻辑与07一致。
4. 16×16 RGB tile每行48 B，不保证首地址beat对齐；验证首尾写掩码。不支持掩码时聚合合法行段，不能无保护读改写覆盖相邻tile。
5. 探索双缓冲、描述符预取和请求/数据重叠，但在途数以控制器实际能力为上限。性能只在合法ordering下增加，不能仅增请求数量。
6. 缓冲容量按峰值输入与最大合法无服务时间设计；至少检查`可用缓冲字节 ≥ 峰值字节率 × 无服务时间 + 突发/CDC余量`，各域水位单位独立注明。

### D3 有界仲裁

采用符合现有风格的有界配额/紧急水位机制，不预设某算法必然最优。比较输入满风险、显示空风险、cache等待和RAW发送队列；允许紧急通道提升优先级，同时给其余实时通道可证明的最大等待。

报告每客户端的有效服务率、最大请求等待、最长无服务间隔、队列峰值、deadline miss及过载原因。优先排空接近欠载/溢出的实时请求，快照在剩余预算不足时明确拒绝。

## 4. 时序优化

- 请求选择、地址加法、长度/跨界切分与mask生成分级；必要时加入请求寄存器和局部弹性缓冲，保证握手停顿时地址/数据稳定。
- 将水位比较与读写使能分离并核对FIFO读延迟，避免水位到仲裁到FIFO控制形成长组合路径。
- 共享宽总线mux按客户端分组/寄存，tag和事务状态同步推进；避免流水化后响应与请求错配。
- FIFO两端复位独立在本端同步释放；错误恢复先阻止新事务并排空/作废，不能在合法传输中途只清一侧FIFO。
- 原生DDR时序/优先布线约束保留；根据01审计Gray指针和复位端点，重构后证明约束命中。

PnR与接口约束真实收敛后才比较资源。候选DDR速率/用户时钟不等于实物支持或有效带宽，提升频率应先核对颗粒与IP配置。

## 5. 资源优化

吞吐与deadline达标后才合并低速队列、减少过量缓冲或共享地址生成；不得合并导致显示/输入与快照相互阻塞的资源。报告每通道FIFO/DRM、仲裁LUT/FF、总线mux及拥塞，按整机预算判断收益。

不为省RAM把RGB888正式通路改RGB565，不缩减76 MiB正式布局。生成FIFO/IP参数改动从配置重生成，记录新旧水位单位、深度和依赖。

## 6. 依赖、测试与交付

04拥有DDR适配、请求/数据、完成和取消语义；03拥有槽状态，06拥有cache策略，05/07提供deadline与流量。接口共同冻结，顶层/工程/IP配置由集成负责人合并。

| 测试层级 | 必测项目 |
| --- | --- |
| 事务 | 随机AW/AR/数据等待，允许的读返回模式，长/短/尾突发、零/非法长度、ID、重启与错误 |
| 地址/数据 | RGB888跨beat、首尾掩码、RAW/RGB不同stride、slot末端、tile交界与实际容量边界 |
| 完成/取消 | 最后beat尚未接受、读响应未排空、帧切换、消费者取消、DDR重初始化 |
| 混合压力 | 输入+显示+算法cache miss+RAW发送+快照同时工作，刷新及最坏无服务间隔 |
| 实物 | 获准条件下已知pattern读写、混合负载、完整帧率及错误计数 |

必须用scoreboard逐事务核对内容和地址，并断言无越界、无重复/漏beat、无提前completion、无消费者永久饥饿。单纯FIFO或帧池TB不能证明DDR事务回归通过。

实现可在现有诊断副本及`fpga/rtl/memory/`适配层内推进；测试/模型落`fpga/sim/`、`fpga/model/`，构建/报告落`fpga/build/`、`fpga/reports/`。没有实物容量/混合带宽验证时明确未通过范围。

## 7. 专项智能体任务描述

请按本方案、总览和AGENTS，以性能>时序>资源优化DDR/DMA。先审计原生DDR与generic AXI适配的单位、LEN/ID、写完成和取消语义，再实现正确的RGB888/RAW打包、掩码、合法突发及有界多客户端仲裁。与帧池冻结事务栅栏，和显示/cache/RAW网络共同测最大无服务间隔与deadline。优先提升整机混合有效带宽，允许增加流水与队列，不以顺序峰值、常量BVALID或非法超频证明达标。交付scoreboard回归、性能/PnR/资源表、共享差异与实物未验证项，硬件操作遵循既有放行条件。
