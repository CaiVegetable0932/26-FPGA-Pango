# 07 网络与控制接口优化方案

V1.0，2026-10-12。专项优先级：**性能 > 时序 > 资源消耗**。本文件含可分别交接的网络与控制两条工作线，共享帧身份/参数协议由集成负责人合并。

## 1. 当前基线与入口

先读[总览](README.md)、[RAW8双路回传权威方案](../OV5640_RAW8千兆网与HDMI双路回传方案.md)、[主设计](../PG2L100H_1080p畸变矫正详细设计方案.md)、[MCU V1.3交接](../MCU五轴控制与FPGA通信开发交接文档.md)、[MCU V2补充](../MCU_POSE_V2接口实现补充.md)、[云端同步计划](../MCU_POSE_V2云端同步实施计划.md)。

已有[rgmii_phy_io.v](../../fpga/rtl/board/rgmii_phy_io.v)只完成4位双沿与8位字节转换，不含MAC/FCS、MDIO或ARP/IP/UDP。主工程PHY保持复位、TX空闲，`net_tx_fifo`只进入观察位。`parameter_ram`为候选资源，不代表已有下载/按帧生效协议。

FPGA独立MCU_POSE_V2接收尚未集成。MCU云端工程目标F407xx/F103xB，实物、引脚和时间映射仍待验收；不能把云端软件测试当本机/板端通过。

## 2. 网络工作线N：目标与预算

| 项目 | 目标/预算 |
| --- | --- |
| 主流 | 单路1920×1080 RAW8，完整30 fps，62.208 MB/s有效像素 |
| 包格式 | PRAW V1，64 B应用头，至多1400 B有效图像载荷 |
| 包率 | 1482包/frame、44,460包/s |
| 参考线占用 | 约543.9024 Mbps，未含VLAN/重传/额外控制 |
| PHY接口 | 千兆RGMII125 MHz、每周期1字节业务能力，两沿电气核验 |
| 快照 | 低优先且有界，容量/带宽不足时拒绝；不持续挤掉RAW帧 |

主流带宽预算不是实际吞吐。网络完整帧率与相机/处理/HDMI分别验收。RAW60加协议超出千兆链路能力，本专项不承诺60 fps完整RAW仍走千兆网。

## 3. 网络性能优先路线

1. 分层构建RAW读DMA、row compactor、packetizer、ARP/IPv4/UDP、MAC/FCS、RGMII管理与统计；以边界清楚的模块代替一个长状态机。
2. 从DDR RAW stride2048提取每行1920 B有效数据，支持跨beat与跨行包，线上stride1920。帧尾最后包200 B，不能发送padding或补旧帧像素。
3. 使用描述符预取、双/多包有界缓冲和准备/发送重叠，按完整包率与DDR最大无服务时间确定容量。MAC开始发送前确保不会发生无法容忍的帧中欠载。
4. 应用CRC32字段位于64 B头内，覆盖CRC字段置零后的头和实际载荷；发送该字段前必须知道CRC。设计buffer/precompute与发送重叠，不能在头已发送后才完成CRC或只算payload。
5. Ethernet FCS独立覆盖其标准帧内容，放以太网尾；它与PRAW CRC32、UART CRC16是不同层次，不能互相替代。头部应用字段小端，标准IP/UDP头按网络字节序。
6. IPv4/UDP长度、校验和/是否允许零UDP校验和及帧padding等按已冻结实现规范与接收端向量核对；不通过省去尚未协商的校验私改协议。
7. ARP、PHY管理、链路失效、重传和诊断快照均为有界控制工作，不应造成主流长期饿死。链路断开时停止新读/排空并按03释放引用。
8. FPGA生成源epoch/frame_id和描述符；PC重连只管理网络会话，不自动更改已有采集身份。丢包只能明确不完整或在允许槽/带宽/截止内重传。

## 4. 网络时序及资源优化

- 将字节选择、跨行偏移、头部mux、CRC更新/比较和发送调度分级；有效/包边界/tag同步推进。
- 125 MHz发送域维持1 byte/cycle可服务，复杂头部参数在包准备阶段锁存，不在RGMII逐字节端构造长组合逻辑。
- CDC用经核验异步FIFO/描述符握手，包中断/取消使用明确边界。与01验证PHY delay、两沿及MDIO电平，不用链路灯替代千兆数据证明。
- 性能/PnR达标后压缩低速统计、优化头部存储与缓存配置；不把包缓冲做成无界、不缩小有效载荷掩盖接收能力，也不增加压缩。

IP目前只有FIFO/RAM与物理原语。若引入成熟MAC/协议实现，先核验目标器件、接口、吞吐、许可和依赖，将实际使用源码复制到开发区并记录来源，不正式依赖被忽略的参考目录。

## 5. 控制工作线U：目标与权威语义

PC配置UART与MCU→FPGA独立UART分别接入，不能并接电气或把两套消息拼成同一解析器。PC不逐包转发MCU状态，FPGA只查询/同步/接收，不下发运动。

MCU外层为version=2、profile=0x4D32；独立链路460800、8N1，小端及CRC-16/CCITT-FALSE按V1.3/补充文档，boot/session/有效位/来源逐项校验。STATE为96 B载荷、106 B完整帧，200 Hz约占46.0%标称串口带宽，单帧纯线时间约2.30 ms；均为预算，实物HSI/波特率误差另验。

XYZ是满行程100000000的归一化坐标，yaw是机械相对角；未知roll、绝对航向、q_wc和外参保持未确认。旧V1、pitch/roll、XYZ微米和全系统STOP已撤销，不为兼容新造旧语义。

## 6. 控制性能优先路线

1. 字节接收、同步头/长度/版本校验、CRC、事务上下文和分发分层。接收队列有界，坏长度、超时、截断、未知命令和错误CRC明确拒绝并恢复同步。
2. MCU状态入有界姿态队列，查询/诊断回应不能无限阻塞状态。按权威会话规则接收SEQ/boot，迟到或旧boot数据不能覆盖新状态。
3. SYNC保留接收/发送时刻语义，建立时钟偏移、漂移与误差界；仅到达时间只能标近似同步。200 Hz发送频率不等于200 Hz舵机真实反馈。
4. 姿态按采集/曝光时间选择或插值，帧内锁定并与03/06关联。超时、不同来源或不同boot不能跨界插值，按已定义降级计数；插值误差与映射延迟独立测量。
5. 静态参数在影子区校验整体实体后提交，采集/ISP在合法采集边界、几何在处理该源帧时锁定。成功接收、成功校验和实际生效分别回应/可查询，不只返回ACK。
6. 低速大参数解析与高频状态解耦；系数转换、CRC和合法性校验在提交前执行，逐像素路径只读已冻结参数。坏参数保持最后有效版本并明确拒绝。
7. 调试/状态计数跨域采用快照，读数不是多个自由运行计数器拼成的原子实体；运行期摄像头服务与02约定事务所有权。

本工作线不改MCU运动驱动、行程/零位或已冻结权限；需要跨端新增字段时同步MCU/FPGA/host实现与测试，并维护主设计、`output/host/`和整机方案。

## 7. 控制时序和资源优化

- 宽CRC、地址/范围比较、参数分发和描述符mux逐级寄存；UART接收采样、波特率误差和电平由01/板级核验。
- 低速参数解析可以多周期，但必须有真实握手和可证明deadline，不能只加multicycle约束而不改变执行语义。
- 姿态查找、时间计算和坐标参数生成与实时像素运算隔离；必要时缓存预计算结果，保留来源和误差标签。
- 达标后复用低速CRC/参数运算、收窄有界计数；不共享到接收/状态被阻塞，不删除来源/时间/权限检查省资源。

## 8. 分区边界与验证

07网络负责去stride与包/链路；04负责DDR事务，03负责持槽与来源，01负责RGMII物理。07控制负责协议/参数/时间服务，02/03/06实际执行按帧生效。共享外部协议与顶层由集成负责人合并。

| 工作线 | 必测场景 | 验收证据 |
| --- | --- | --- |
| 网络内容 | 已知RAW逐字节、首尾包、跨行、长度/偏移、CRC/FCS | RTL/host共享向量与完整覆盖scoreboard |
| 网络异常 | 丢/乱/重复包、坏CRC、链路中断、ARP等待、重传截止、PC重连 | 有界队列、完整帧失败/释放与来源保持 |
| 网络压力 | RAW+显示/cache/快照DDR争用及PC慢接收 | 完整30 fps、包率/有效速率、峰值队列与丢帧原因 |
| 控制解析 | 逐字节分片、坏长度/版本/CRC、超时、重复/旧会话 | FPGA/MCU/host共享协议向量与错误统计 |
| 参数/姿态 | 帧中提交、坏实体、boot更换、时间漂移、过期/降级 | 生效版本/源帧关联与时间误差界 |
| 时序/实物 | 目标PnR、合法CDC、RGMII/UART电气及实际波特率 | 时序报告、接口测量和未签核项 |

MAC/UDP事务模型通过不能代替千兆实板测试；CRC仅做错误检测，不证明源身份。来源未确认的HDMI不由网络包到达顺序补配对。

性能报告分别列有效RAW帧/包/字节、线速占用、重传/丢帧、DDR读服务等待、控制接收峰值与最坏延迟、参数生效延迟、时间同步误差、PnR及资源。报告不能只给UART解析或网口链路灯。

新增FPGA模块建议落`fpga/rtl/network/`、`control/`，共享向量与TB落`fpga/sim/`；PC接收/测评落`host/src/`、`host/tests/`、`host/data/`、`host/reports/`；必要MCU接口适配落`mcu/`。正式协议变更不落在本规划目录的可执行代码中。

## 9. 可分别交接的任务描述

### 网络专项

请按本方案、总览和RAW8跨端权威方案，以性能>时序>资源实现并优化PG2L100H的RAW网络DMA、去stride、PRAW V1、MAC/ARP/IPv4/UDP与RGMII管理。目标完整1080p30 RAW8，1482包/帧和44,460包/s预算；先证明逐字节/CRC/FCS及事务正确，再提高准备/发送重叠和混合DDR服务。应用CRC在头内须发送前准备，有界重传/快照不得饿死主流。交付共享向量、异常/压力回归、吞吐/PnR/资源、来源及实板未验证项，协议/顶层差异交集成负责人合并。

### 控制专项

请按本方案、总览、MCU V1.3和V2补充，以性能>时序>资源实现FPGA独立MCU_POSE_V2接收/查询/SYNC与PC配置按帧提交。保留version=2/profile=0x4D32、归一化XYZ/机械pitch-yaw、会话/来源/时间近似语义，FPGA不下发运动，PC不逐包转发。建立有界解析/队列、影子参数、生效状态、姿态时间关联和可观测降级，和输入/帧池/算法冻结帧内一致性。交付跨端向量、错误/时序/压力测试、控制延迟/同步误差/PnR/资源及实物未验证范围；不恢复旧V1/微米/全系统STOP，不绕过硬件放行。
