# 02 摄像头输入优化方案

V1.0，2026-10-12。专项优先级：**性能 > 时序 > 资源消耗**。目标是完整有效源帧，不以PCLK活动、初始化ACK或HDMI刷新率代替。

## 1. 基线与入口

先读[总览](README.md)、[AGENTS](../../AGENTS.md)、[跨端架构](../OV5640_RAW8千兆网与HDMI双路回传方案.md)、[150 Hz PWM专项](../OV5640_150Hz_PWM照明防条纹专项优化交接.md)。

现有实现位于[摄像头封装](../../fpga/rtl/mini_camera_diag/vendor/camera/camera.v)、[配置表](../../fpga/rtl/mini_camera_diag/vendor/camera/data_init.v)、[SCCB](../../fpga/rtl/mini_camera_diag/vendor/camera/SCCB.v)、[DVP接收](../../fpga/rtl/mini_camera_diag/vendor/camera/camera_data.v)、[帧请求生成](../../fpga/rtl/mini_camera_diag/vendor/cmos_write_req_gen.v)。

当前是单路720p RGB565：8位DVP字节拼接16位像素、启动丢帧、配置/DDR就绪同步。配置表244项，SCCB约100 kHz，支持开漏写、ACK/NACK/拉伸超时；只写不可回读。主工程的`raw_async_fifo`是8位×2048候选资源，尚未接正式RAW摄像头和帧标记。

已有字节重对齐不是整帧合法性校验。RAW8/1080p30、芯片ID读取、运行期参数更新、PWM匹配曝光及异常帧作废需新增实现。150 Hz为用户给出的照明条件，光学频率尚未核验。

## 2. 目标与性能指标

| 指标 | 目标/口径 |
| --- | --- |
| 输入模式 | 单路真实1920×1080 RAW8，保留Bayer相位、裁剪/镜像和有效位 |
| 有效吞吐 | 62.208 MB/s@30 fps；另核对消隐与PCLK峰值 |
| 帧完整性 | 所有行/像素数量及边界符合实际模式，无混帧或补零伪完整 |
| 控制恢复 | NACK、超时、模式切换及失锁均有界并明确状态 |
| 照明适配 | 实际PWM周期匹配、源帧率保持；曝光效果按独立专项验收 |

源帧率测VSYNC/有效帧及帧间隔。不能把8位DVP RGB565升级为1080p30后仍假设带宽合法；其仅有效字节需求124.416 MHz已经超过本项目主设计引用的96 MHz DVP门槛，正式基线采用RAW8并核验实物模式。

## 3. 性能优先实施

1. 保持诊断RGB565模式可回归，新建明确的RAW8配置/接收模式，避免两种格式通过隐式开关混用。模式切换停止事务、清FIFO并作废过渡帧。
2. 在PCLK域直接采样数据/HREF/VSYNC，不把源同步数据逐位两级同步后拼像素。控制状态跨域按01约定处理。
3. 逐行/逐帧计数与状态机判定：短行、超长行、缺失/重复边界、超时、启动期间及FIFO溢出均整帧标错；错误帧不进入正式READY。
4. 与03/04冻结输入tag、行帧边界、错误及最后写确认；给RAW写DMA与ISP并行分流，同源身份保持一致，基线不增加“DDR读回RAW再做ISP”的额外读流量。
5. DVP不可暂停。队列满时执行已定义整帧作废、排空及下帧重同步；RAW导出过载与ISP主视频错误分别计数，不通过压低源帧率隐藏瓶颈。
6. FIFO尺寸按输入峰值、DDR/ISP最长合法停顿与CDC余量确定，验证容量包含标记/打包开销。单纯扩大FIFO不能覆盖无限服务停顿。
7. 运行期SCCB与初始化事务仲裁、寄存器读取/写入/回读均有界；芯片ID与配置实体实读，不把ACK当作身份确认。

## 4. 150 Hz曝光和色彩维护

固定测评模式优先手动曝光/增益，按实际行时间计算6.667 ms的整数周期档位；上限满足本模式VTS余量并关闭未经允许的扩帧。未知XCLK/PCLK/行时间不直接生成标为已验证的曝光常量。

自动亮度独立开发，约束曝光档位和增益，防止亮场退回任意短曝光及暗场降帧。内部banding自定义为实验性路线，需要完整亮暗/低占空比验证。白平衡是独立功能，几何测评锁定，日常自动模式另验；不能让自动调节补偿掉本来要测的照明变化。

## 5. 时序与资源措施

- PCLK采样、边界检测与计数/校验分级，避免HREF/VSYNC高扇出组合控制贯穿打包和地址路径；所有像素tag与数据延迟对齐。
- 深度/宽度计算和参数合法性在配置阶段检查，逐像素路径使用有界计数和增量推进。
- FIFO必须使用匹配目标的原生IP或已核验结构，01签核跨域约束；不把摄像头暂定100 MHz预算当作外部setup/hold签核。
- 在吞吐和时序通过后收窄计数器、删除非正式模式残留；不得为省资源移除完整性检查或降低RAW有效位。

官方参考为[OV5640数据手册](../../reference/OV5640双目摄像头资料/芯片数据/OV5640_DataSheet.pdf)、DVP应用指南和对应模组原理图；PDS约束/仿真涉及安装版只读官方资料。依赖源码复制到开发区并记录来源，不在参考目录运行生成结果。

## 6. 分区边界

本区拥有传感器配置、DVP帧合法性和输入测量；03拥有帧身份/所有权发布，04拥有DDR写完成，06拥有RAW到RGB算法。参数控制07提供合法提交语义，本区返回模式/配置生效状态。

共享顶层、全局约束、IP配置和项目清单由集成负责人合并。新增正式输入模块建议放`fpga/rtl/input/`；现有诊断副本有范围地适配。禁止把RAW8网络头、MCU V2或76 MiB帧池布局自行改成不兼容版本。

## 7. 验证与验收

| 阶段 | 必测场景 | 证据 |
| --- | --- | --- |
| I1 | 原244项配置、RGB565字节序和启动门控 | 现有[SCCB TB](../../fpga/sim/tb_mini_sccb.sv)、[DVP TB](../../fpga/sim/tb_mini_dvp.sv) |
| I2 | RAW8 Bayer相位、全尺寸计数、短/长行、缺帧、FIFO满 | 模式向量、有效/错误帧计数、逐字节对照 |
| I3 | SCCB读写错误、回读不一致、参数切换与复位 | 事务日志、配置版本及过渡帧状态 |
| I4 | 混合负载下不可暂停输入和失锁恢复 | 最大缓冲水位、服务停顿、帧作废原因 |
| I5 | 获准硬件条件下真实输入及PWM变化 | PCLK/HREF/VSYNC、光强波形、原始图像及元数据 |

验收：真实模式/帧率、完整数据、错误可定位且恢复有界、配置可回读、PnR与01定义的接口约束通过。仅局部TB通过时，报告局部范围；没有身份/硬件证据时保持未验证。

实现/测试/构建/报告放`fpga/`；PC采集测评与证据放`host/`；照明固件和测量放`mcu/`。本次规划不授权绕过既有硬件告警。

## 8. 专项智能体任务描述

请按本方案、总览、150 Hz专项和AGENTS优化OV5640输入。以完整RAW8/1080p30有效吞吐为首要目标，先审计720p诊断基线，再实现可回读配置、模式明确的RAW8采样及整帧合法性；与帧池/DMA/ISP冻结错误和完成语义。按性能>时序>资源排序，保留源同步采样和可信CDC，覆盖短长行、溢出、切模式及恢复。固定曝光按实测行时间/PWM计算，未知时钟不编造常量。交付代码/注释、局部回归、输入与PWM测量需求、真实性和未通过范围；共享文件交集成负责人合并，硬件操作遵循已有放行条件。
