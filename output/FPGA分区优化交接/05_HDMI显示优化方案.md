# 05 HDMI 显示优化方案

V1.0，2026-10-12。专项优先级：**性能 > 时序 > 资源消耗**。目标为真实完整1080p30输出与有界显示延迟，保持正式RGB888数据及来源证据。

## 1. 基线与入口

先读[总览](README.md)、[跨端方案](../OV5640_RAW8千兆网与HDMI双路回传方案.md) §7、[主设计](../PG2L100H_1080p畸变矫正详细设计方案.md) §3/§7。

已有[诊断Top](../../fpga/rtl/mini_camera_diag/vendor/Top.v)、[sync_vg](../../fpga/rtl/mini_camera_diag/vendor/sync_vg.v)、[video_rect_read_data](../../fpga/rtl/mini_camera_diag/vendor/video_rect_read_data.v)、[rgb2tmds](../../fpga/rtl/mini_camera_diag/vendor/hdmi/rgb2tmds.v)、[tmds_encoder](../../fpga/rtl/mini_camera_diag/vendor/hdmi/tmds_encoder.v)、[outputserdes](../../fpga/rtl/mini_camera_diag/vendor/hdmi/outputserdes.v)、[原生串行器封装](../../fpga/rtl/board/tmds_serializer.v)。

诊断输出720p RGB565展开为RGB888，包含raster、读请求、单周期FIFO延迟、TMDS编码与串行化。主工程只输出固定符号，不具备视频时序与内容。原生IP为`video_pll`和显示侧FIFO，OSERDES/差分缓冲是器件原语。板载唯一HDMI OUT为FPGA直出，MS7200是输入相关器件，不改成其他板卡的MS7210输出方案。

现有短时动态采集不证明源身份或正式1080p30，报告仍有过温告警和外部时序未验证项。

## 2. 性能目标

| 项目 | 基线目标 |
| --- | --- |
| 视频模式 | 真1920×1080@30，RGB888，真实有效尺寸 |
| 候选时钟 | 74.25 MHz像素、371.25 MHz串行，10:1双沿TMDS |
| 扫描能力 | 每像素时钟输出1个RGB像素，活动区不可暂停 |
| DDR有效显示读 | 186.624 MB/s，另计打包/突发效率 |
| 显示完整性 | 无读未完成帧、无帧内切槽、欠载明确计数和恢复 |
| 身份与计数 | 处理帧、显示新帧、重复显示、采集卡帧数分别统计 |

不把720p放大或60 Hz重复显示当真1080p30处理；1080p60发送另核验器件、电气和工具能力，不从148.5 MHz PLL配置推断已经支持。

## 3. 性能优先路线

1. 正式RGB888读DMA/解包从诊断RGB565逻辑分离，支持6144 B DDR stride、5760 B有效行及跨beat残留。正确性先用已知像素pattern验证。
2. 与03在场边界获取完整结果槽，当前显示帧全程持引用；释放时与04确认读响应/预取全部排空，禁止帧内切base地址。
3. 加入行预取、行段/双缓冲与明确低水位请求，按04最大无服务间隔确定FIFO容量及提前量。平均带宽达标仍须证明活动区不会断粮。
4. 将读请求提前到可满足首像素的时刻，计算解包、RAM/FIFO、编码与寄存总延迟，HS/VS/DE/像素/tag精确对齐。预取不越过合法持槽范围。
5. 输出时序保持运行，欠载不能暂停pixel clock。定义黑色/既有整帧保持等明确容错，避免旧FIFO像素错位；计数欠载和受影响帧，重新对齐从合法边界开始。
6. 减少结果READY到可显示场边界的无谓等待，同时保持完整帧处理顺序。仅选最新帧的诊断模式必须单列跳帧，不能用于完整处理帧率验收。
7. 网络/快照压力不能破坏显示deadline；与04联合证明水位紧急服务及最大等待。

## 4. 时序优化

- 将RGB解包/选择、边界mask和输出寄存与TMDS编码流水拆分；所有控制信号按实际延迟推进。
- 保持原生PLL、IO时钟缓冲、/5分频和OSERDES启动关系，调用方使用经验证的专用复位脉冲；普通pixel复位不随意替代串行器启动复位。
- TMDS运行差异、消隐控制符号和串行bit顺序逐通道回归；流水修改不能改变符号时序或通道对应。
- 不用普通逻辑构造371.25 MHz串行数据或时钟门控。01审核生成时钟、局部复位和输出约束，目标器件PnR检查实际packing/路由。
- 如果为改善时序增加流水/缓冲，记录对显示相位和延迟的影响；不能通过false path屏蔽真实pixel/serializer路径。

官方参考：安装版Timing/UCE/物理/路由约束手册、Logos2串行输出原语资料和目标MINI HDMI例程。原件只读，运行副本及产物放`fpga/`。

## 5. 帧身份与像素保真

普通HDMI采集卡仅有自身序号/时间戳，默认`source_frame_id=null`、`pairing_status=unverified`。UART当前帧号或软件到达顺序不形成可靠配对。

如开发逐帧标识，需验证掉帧、重复显示、重连和模式切换；像素内标记/OSD只能放明确的诊断模式或定义的排除ROI，并记录对像素测评的影响。正式几何精度以板端S1与选定结果同帧快照为准，不能通过覆盖有效图像建立身份后声称全部像素仍无改动。

采集卡实际RGB24/BGR24、量化范围、色彩转换及未经压缩保存独立验证，不能把RGB565/YUY2转换画面等同正式RGB888保真结果。

## 6. 资源与协作边界

性能/时序达标后才缩减FIFO和解包寄存、共享低速统计；最低容量不得小于deadline预算。统计RAM/FIFO/OSERDES与时钟资源，不只LUT。正式质量链不退回RGB565省带宽。

05拥有扫描/编码/显示解包与欠载策略，03拥有槽生命周期，04提供读DMA服务，01拥有物理时钟/复位约束。共享顶层/工程/PLL配置由集成负责人合并；新增正式视频模块建议落`fpga/rtl/video/`，现有诊断模式保留回归。

## 7. 验证与交付

复用[视频TB](../../fpga/sim/tb_mini_video.sv)、[串行器TB](../../fpga/sim/tb_tmds_serializer.sv)，覆盖整帧raster、首末像素、RGB888跨beat、随机DDR停顿、场边界切槽、空FIFO、复位/失锁、TMDS符号与bit顺序。模型中延迟可变时断言数据/DE/tag仍一致。

分别报告：图案逐像素正确性、FIFO低水位/欠载、最大DDR无服务时间、READY到显示时延、显示新帧/重复帧、post-PnR时序及资源。已知图案可验证输出链，不替代摄像头来源证明。

获准硬件条件下验证真实模式、色彩和源身份；没有连续同源证据时仅报告独立输出或板端快照范围。实现/测试/报告落`fpga/`，采集证据/测评落`host/`，既有硬件告警不因本文解除。

## 8. 专项智能体任务描述

请按本方案和总览，以性能>时序>资源优化HDMI显示。保留原生时钟/串行器拓扑，建立正式RGB888/1080p30扫描、读DMA预取和可证明的显示deadline，逐级对齐数据与HS/VS/DE/tag。与帧池/DMA冻结持槽和排空，覆盖欠载、首末像素、场切换及失锁恢复。分别计处理/显示/重复/采集帧，普通HDMI身份保持未验证直至证明。交付局部回归、显示服务与延迟、PnR/资源对比和采集格式/来源未验证项；共享文件交集成负责人合并，不绕过硬件放行。
