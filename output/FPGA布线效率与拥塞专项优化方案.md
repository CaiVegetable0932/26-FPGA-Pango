# FPGA 布线效率与拥塞专项优化方案

日期：2026-10-19。适用目标：PG2L100H、FBG676、-6，PDS 2022.2-SP6.4；具体 build、板卡版本和源码以每次构建清单为准。性质：实施与验收方案，尚未执行本轮 RTL 优化及对比构建。

本轮目标是在满足既定功能、精度、吞吐、延迟和真实时序要求的前提下，优先缩短布局布线耗时、减少拥塞及长尾失败。允许增加 LUT、FF、APM（DSP）和 DRM 消耗，优先采用局部互连、规则流水和适配器件结构的写法；资源总量和局部布局仍必须可承受。不能承诺任意完整设计都能在固定分钟内成功，但必须限制每次实验等待时间，超时后转入诊断和结构修改，而不是无限等待。

## 1 优化目标与选择规则

本专项细化既有“性能 > 时序 > 资源消耗”原则：

1. **准入条件**：功能、精度、协议、帧身份、工作范围、资源上限与真实约束全部有效。保持真实 1080p30、板端 ISP/几何、S0 网络回传及单 HDMI 架构。新增防抖和补全按已冻结功能组合验收，不以关闭承诺功能换取成绩。
2. **性能条件**：达到约定完整帧率、最坏服务期限及延迟预算；保持相同目标时钟比较，处理域初始目标为 150 MHz、关键流水 II=1。增加流水延迟须列入预算，不能假设用户允许任意增加整帧延迟。
3. **通过以上条件后，优先选择能在限定时间内稳定完成布线和 STA 的候选**；比较超时/失败次数、布局布线耗时、整轮迭代时间和不同 seed 的稳定性。满足既定性能后，不为追求用不到的更高频率牺牲构建效率。
4. 在布线耗时近似的候选间比较时序余量、最坏服务余量，再比较资源和功耗。资源更少不是自动胜出理由；资源更多也不是自动更易布线。

禁止降低精度、缩小输入、压缩原图、持续丢帧、删有效掩码、伪造同帧、放宽时钟或扩大 false path 来获得“优化”。功能范围不变时，不把软件替代板端运算计为成功。

## 3 整体实现方向

```text
功能与性能门槛
  └─ 面向布线的结构
      ├─ 控制局部化：参数副本、分级译码、本地使能
      ├─ 数据规则化：模块边界寄存、分级选择、弹性缓冲
      ├─ 存储就近化：小标签 LUT RAM、大数据 DRM、分 bank
      ├─ 算术流水化：匹配 APM 宽度、分级部分积、必要时复制
      └─ 互连分层化：客户端队列、分组仲裁、有限广播
          └─ 局部验证 → 子系统验证 → 完整工程验证
              └─ 限时构建、少量候选、失败留证、结构修正
```

### 3.1 控制与复位

- 将高扇出帧参数、模式译码和使能按实际消费者分组，在模块附近保留本地寄存器副本。优先复制输入简单、输出分散的驱动，不复制庞大的组合前驱网络。
- 分发树各分支保持相同生效语义；按帧提交先写完全部影子副本，再在一致边界生效。不能出现同一帧不同 bank 使用不同参数。
- 区分同步器和同步后本地分发：不随意复制异步复位同步链，不改变 CDC 安全性；同一接口两端的复位释放和启动协议保持一致。
- 仅在证明 valid 屏蔽、初始化和重启语义完整后，取消大数据阵列的不必要逐元素复位。有效位、所有权、代次、计数和状态仍按功能要求复位。RAM 内容清零改为初始化/有效位策略时单列验证。
- 观察综合后的驱动扇出和副本是否被合并。保持属性仅针对必要对象，先验证本版 ADS 语法，不全局添加保护属性冻结优化。

### 3.2 宽选择器与握手

- 将集中式 N 路宽数据选择拆成分组选择、寄存、最终选择；选择信号与数据一起流水。互斥选择可比较 one-hot 分组实现，原本有优先级的选择必须保留优先级和非法输入行为。
- 用经过回归的弹性缓冲或 skid buffer 切断长 ready 链。仅给 ready 加一拍而不给数据保留空间会丢数据，禁止这种修改。
- 仲裁决策、地址选择与数据搬运分级；将资源复制放在客户端本地，避免复制后仍接同一个全局 mux。
- 不盲目给所有连接加寄存器；每处增加须对应长路径、跨模块互连或服务隔离收益，并核对 hold、控制链和新增时延。

### 3.3 缓存与查表

- 延续当前小型多读口 tag 使用本地 LUT RAM、图像数据使用四 bank DRM 的方向。扩大缓存容量前先测 miss 与回填，不能靠增加大量 RAM 缓解所有停顿。
- ISP writer 的段缓存与几何 tag 是不同对象：前者已有集中 LUTRAM WE 热点，优先验证现有 BRAM 候选；后者有改回本地 LUT RAM 后改善的历史证据。不能制定“所有 RAM 都改成 BRAM”或“所有 RAM 都改成 LUTRAM”的统一规则。
- 保留四邻域并行采样能力，采用本地标签比较和分级命中选择；避免全表内容广播到中央组合逻辑。
- 保留 pre-resample Gamma 所需的 12 个查表读端口及本地副本。不能改为 post-resample 冒充等价，也不能因共享端口使 II 不达标。
- 双回填缓冲和预取作为性能候选单独实现；当前接口不支持乱序返回，增加在途事务必须同步修改 DMA 契约、返回标识和取消排空测试。
- RAM 模板必须匹配同步读、读写冲突和输出寄存行为；以网表和报告确认实际推断，不凭 RTL 数组声明判断已使用 DRM。

### 3.4 算术与 DSP

- 按 PG2L100H 的 APM 能力及官方模板组织乘法与乘加流水。明确 signed/unsigned、有效位、部分积、舍入和饱和，优先使用局部、可预测的算术结构。
- 允许用更多 APM/FF 将宽乘法拆为规则部分积流水；不为少量 DSP 节省在关键路径引入宽共享 mux 和跨区域反馈。
- 局部加法/比较不一律强制 APM；若硬块位置使数据绕行，比较本地 LUT 实现。DSP 使用率上升不是验收目标，整条路径更容易布线才是。
- 配置期计算常量、像素期递推可保留，但改变计算次序必须证明位精确一致或符合已经冻结的数值误差口径。不能悄悄扩大误差。

### 3.5 DDR 与未来功能

- 输入/ISP、几何、HDMI/网络、快照等客户端保留独立队列，分层汇聚；按照最坏无服务间隔配置 FIFO，而不是无限增加深度。
- 视觉运动估计使用独立小图缓存和局部计算阵列；通过有限并行单元满足期限，避免全搜索窗口像素广播。
- 历史补全优先给历史采样独立缓存和必要计算通道；当前帧与历史帧在局部融合，不建立所有像素、所有帧任意互连。
- 基础整机收敛后再逐项加入新增功能。为每个功能组合保留独立资源与耗时记录，不能用关闭功能的快速构建代替全功能验收。
- 容量在外部 DDR 的 76 MiB 帧池不等于片上资源开销；访问端口、缓存、标签和仲裁才需要片上预算。DDR 带宽与布线拥塞分开判断。

## 4 资源预算与增加资源的条件

当前规划中的约 50,000 LUT、95,000 FF、180 APM、120 块 36 Kbit RAM 作为启动总预算，来自[分区总览](FPGA分区优化交接/README.md)，不是当前整机利用率。主设计列出的器件总量为 66,600 LUT6、133,200 FF、240 APM、155 块 36 Kbit RAM；最终以目标器件映射报告核对，DRM18K 与 DRM36K 必须按物理占用折算。

总预算由集成负责人维护：已集成逻辑＋固定 IP＋本轮候选增量＋已承诺待集成功能预留＋必要调试预留。不能将独立测试夹具资源简单相加，不能让多个智能体分别消耗同一份余额。

每个资源增加提案提交：改变的互连结构、LUT/FF/APM/DRM 增量、预期缩短的路径、性能影响、验证范围。预算内允许试验，不要求逐项向用户申请。超预算先在模块间重新分配并复核整机；器件放不下或本地硬块资源冲突时必须更换结构，不能绕过容量条件。

不设置“低于某利用率就不会拥塞”的结论。全局未满也可能局部拥塞；增加副本后应观察拥塞位置、布线延迟和时序是否改善。面积很大但互连规则的方案与面积很小但高度交叉的方案必须实测比较。

## 5 构建耗时管理

### 5.1 先建立可比的基线

每次运行冻结源码、IP、约束、顶层和参数哈希；记录 PDS build、CPU、内存、线程设置、电源模式、磁盘位置及其他负载。区分 clean build 与复用结果，禁止混合计算加速比。

记录 compile、synthesize、dev_map、PnR、STA 的开始/结束时间、退出状态、峰值内存和可获得的进度。若日志暴露布线迭代、未布通网络或拥塞数，原样保留；若没有就标记不可获得。许可证等待、换页、磁盘瓶颈与布线计算分别记账。

每台机器默认同时只运行一个重型 PDS 实现任务。安装版 PDS 手册印刷页 117 明确 **PG2L100H 使用单线程布线器**，general/router 参数按 Logos 对应项，而不能机械套用其他 Logos2 器件设置。多智能体可并行阅读、编写不同模块和运行轻量测试，但共享一个构建队列；增加 router threads 不作为本器件加速方案。

### 5.2 建议的首轮限时规则

以下为本方案提出的实验等待上限，不是 PDS 保证耗时，也不是已有实测门槛。实施时写入可配置的构建清单，不能在超时后静默延长。

| 范围 | 无可用基线时的首轮 PnR 上限 |
| --- | --- |
| 单模块或隔离算法核 | 20 分钟 |
| 多模块子系统 | 40 分钟 |
| 完整正式工程 | 60 分钟 |

有相同规模的有效成功基线后，停止点取“上述范围上限”和“2 倍基线时间加 5 分钟”的较小者；预警点取“1.5 倍基线时间”和“本次实际停止上限的 80%”的较小者，确保预警早于停止。无成功基线时也在上限的 80% 预警。快速 smoke test 不能用作完整工程基线。若无候选能在预算内完成，记录“构建时间目标未达成”，先诊断/重构；只有形成具体原因和新的实验预算后才能另开较长任务，不自动反复续时。

监控每 30～60 秒检查状态。10 分钟没有日志只触发调查，不能单凭无日志判死锁；同时核对进程 CPU 增量、内存、阶段文件及工具状态。硬超时依然执行。另加收敛停滞规则：完成前 5 轮后，若最近 5 轮窗口内的最优未布通数较窗口起点下降不足 1% 且仍有超过 1,000 个未布通子网，判为停滞候选并停止；接近收敛时不套用该比例阈值，但仍受总时限约束。数值为首轮管理参数，需记录在清单中，不是厂商标准；五轮尚未完成也不能突破总时限。同步保存每轮 CPU/墙钟、剩余数、历史最优值及 CongestionNetInfo，避免将冲突在热点间转移误认为进展。

优先使用工具支持的停止方式；必要时仅终止本次运行拥有的 PID 及其子进程，绝不按进程名结束所有 PDS，也不影响用户已有任务。超时结果标为 TIMEOUT，停滞标为 STALLED，保存已有日志与快照，不算完成布线。

现有脚本中的 `-action_timeout 15` 不能直接解释为整个任务最多 15 分钟；必须按安装版帮助核对作用范围和单位。外部监督器负责整次任务上限。脚本新增计时、监控和停止逻辑应落在 `fpga/scripts/`，记录落在 `fpga/build/route_optimization/` 与 `fpga/reports/`。

完整工程优先扩展现有 `fpga/scripts/build_full_integration.py`、`run_video_route_attempt.py` 和 `observe_video_routes.py` 的职责边界，先审计已有超时/暂停机制再补齐，不能另建一个绕过现有停止状态的驱动。隔离核继续使用对应专项入口。

### 5.3 有限候选与复验

1. 每轮只比较基线和最多两个结构候选，先做功能、服务模型与综合映射检查。
2. 初筛固定相同 seed、时钟和工具策略；失败先定位，不立即遍历几十个 seed。
3. 只对最优候选和有效基线做相同的三个 seed 验证。完整 P12 组保留既有 11，再选固定 7、13；隔离几何组可沿用 7、1、13，二者不能混作同一组加速比较。三个样本仅报告中位数、最大值、成功/失败数，不用三个点声称统计学 P95。
4. 同一结构连续两次布线失败或超时后，停止该结构的自动 seed 扫描，输出下一项结构修改。不得无限提升 effort。
5. 长期积累足够日常构建后再评估耗时 P95；统计必须包括失败与超时，不能仅保留快速成功样本。

建议首轮改善目标：同功能、同机器、同约束下 PnR 中位耗时降低至少 30%，最大值不退步，三个测试 seed 全部完成且 STA 通过。30% 是待验证目标，不是承诺；基线从未成功时不计算加速比，以预算内成功收敛为首要结果。

## 6 官方模板与公开经验的采用方式

优先级为：安装版 PDS 官方资料及匹配 MINI 例程 → 本项目已验证 RTL 与报告 → 其他厂商官方方法 → 论坛问题线索。原目录保持只读；模板、文本提取与试验全部放在 `fpga/`，记录原路径、版本、修改和许可证要求。

### 6.1 安装版 PDS 的直接依据

以下页码均为印刷页。官方目录 `E:/PDS_Pangu/PDS_2022.2-SP6.4/doc` 已只读查阅；实施时继续以原文和目标工程 `pnr -help` 核对实际参数。

| 官方资料与页码 | 本项目采用方式 |
| --- | --- |
| [ADS Synthesis User Guide](E:/PDS_Pangu/PDS_2022.2-SP6.4/doc/ADS_Synthesis_User_Guide.pdf) p19、87～88 | Fanout Guide 不作用于 CLK、同步/异步复位置位、使能；局部 syn_maxfan 也有适用限制。不能期待全局 fanout_guide=64 解决 writer WE 或全局复位热点 |
| ADS p20 | Resource Sharing 省面积但可能降低时序；关闭共享作为单变量候选。Retiming 是移动已有寄存器，Pipelining 选项有特定 RAM mux 场景，不能当成自动替任意 RTL 加流水 |
| ADS p69～72、93～95 | syn_dspstyle 的 block_mult/logic 与 syn_ramstyle 的 block_ram/lut_ram/registers 可用于局部 A/B；no_rw_check 有行为不一致风险，不用它规避功能问题 |
| [PDS User Guide](E:/PDS_Pangu/PDS_2022.2-SP6.4/doc/Pango_Design_Suite_User_Guide.pdf) p111 | Placement Decongestion Mode 为 0～9；值增大通常更分散、布线更快但可能损失时序。任一主要资源利用率超过 70% 时，官方建议范围 0～4；这不是低于 70% 即不拥塞的保证 |
| PDS p111～114 | Action Timeout 单位为分钟，0 为不超时；布局 refine 增多会耗时；可检查 CE/RS 控制链、单元复制、LUT6D 打包及逐迭代拥塞输出 |
| PDS p117、251～253 | PG2L100H 单线程路由；已核对 plc_decongestion、dc_duplication、gplace_seed、place_only 等名称，实际使用仍以器件适用项与本版帮助验证 |
| [Route Constraint Editor](E:/PDS_Pangu/PDS_2022.2-SP6.4/doc/Route_Constraint_Editor_User_Guide.pdf) p35 | manual_route 针对具体网络分支且有端点约束等前提；只用于极小范围定位问题，不作为全设计常规优化 |

先跑布局前筛：审查 MAP 的实际 RAM/APM 推断，再比较布局线长、预估 WNS、硬块分布和热点。像已拒绝 writer 上下文候选那样线长大增且余量恶化时，优先退回结构修改；预估好也不能直接证明可布通。

工具策略与 RTL 改动分开实验：先保留现有 decongestion=1；结构候选有效后，仅对优胜者单变量比较 2，再按资源/时序决定是否尝试 3～4。适用范围与命令验证后才执行。默认不增加 refine 次数、不扩大 seed 搜索、不先做全芯片强制位置约束。不同资源负载的最佳值需重新验证，不能把某个值写成通用最优。

板卡匹配依据为 [MINI 硬件指导 V1.3](../reference/盘古100K200K%20MINI开发板/1_Demo_document/实验例程说明篇/教程1_盘古MINI系列开发板硬件指导手册_V1.3.pdf) p6、10，以及[官方器件手册 DS04001](../reference/盘古100K200K%20MINI开发板/4_IC_datasheet/FPGA/DS04001_Logos2系列FPGA器件数据手册.pdf) p10。前者 p11 的 APM 740 与器件表冲突，资源预算采用器件表的 240 并由 PDS MAP 交叉核对；仅 CLMS 支持分布式 RAM，全部空闲 LUT 不能直接当作可用 LUT RAM。

### 6.2 通用方法与论坛线索

每种成熟写法先做最小验证夹具：端口/复位语义测试 → 综合看真实映射 → 限时 PnR → 放回子系统。验证对象包括 RAM 推断、乘法部分积、分级 mux、局部寄存器副本、弹性缓冲。不能因论坛称其优秀就直接替换业务核。

公开资料核查日期为 2026-10-19：

- [AMD UG949 逻辑边界寄存](https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Register-Data-Paths-at-Logical-Boundaries)：支持把跨模块长路径分隔在逻辑边界的通用方法。本项目据此比较带完整握手语义的接口寄存。
- [AMD UG949 高扇出驱动复制](https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Replicate-High-Fanout-Net-Drivers)：支持按层次和负载分组复制；全局降低复制门槛可能产生无用副本。本项目采用局部分发，不照搬 Vivado 属性。
- [Intel Register Spread 分析](https://www.intel.com/content/www/us/en/docs/programmable/683641/25-1/understanding-report-register-spread-data.html)：讨论物理分散负载与复制候选选择。用于解释局部性，不宣称 PDS 提供同名报告。
- [AMD UG949 拥塞处理](https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Addressing-Congestion)：强调先检查约束与时钟，hold 修复绕线可能增加拥塞。因此本专项同时核对 setup/hold，不只追 WNS。
- [AMD 官方社区高扇出讨论](https://adaptivesupport.amd.com/s/question/0D52E00006uTh6ZSAS/high-fanout%E7%9A%84%E8%AE%AF%E5%8F%B7net-delay%E5%A4%AA%E5%A4%A7%E5%A6%82%E4%BD%95%E6%94%B9%E5%96%84?language=en_US)：搜索可见讨论引用 UG949 的寄存器复制经验，页面正文抓取受限；仅列为论坛线索，实际采纳结论由上述官方原文支持，不引用未完整核实的代码。

Vivado 的 Pblock、phys_opt、MAX_FANOUT、KEEP/DONT_TOUCH，Quartus 的 fitter 策略以及 DSP48 模板不能直接当作 PDS 指令或 APM 模板。增量实现、复用布局、线程数、区域约束也必须先确认本版工具和目标器件支持，未核实前不列入必需流程。

## 7 实施任务与多智能体协作

本方案允许实施负责人在必要时启动多个子智能体。推荐一名集成负责人加最多三名同时工作的专项智能体；按阶段复用名额。多智能体不等于同时运行多个 PnR。

| 任务 | 主要所有权 | 交付与放行条件 |
| --- | --- | --- |
| R0 基线与构建监督 | `fpga/scripts/` 的专项入口、整机资源表、公共工程与约束的最终写入 | 可复现快照、阶段耗时、超时规则、构建队列及机器基线 |
| R1 缓存与几何 | `fpga/rtl/geometry/` 及对应模型/测试 | tag/bank/mux/算术候选，位精确与吞吐结果，限定 PnR 对比 |
| R2 writer 与存储互连 | `fpga/rtl/memory/` 及对应测试；先按实际 writer 路径登记所有权 | 优先现有 writer BRAM/局部 WE，再做 DMA、所有权与取消排空，混合服务证明 |
| R3 控制与 ISP 接口 | `fpga/rtl/control/`、`fpga/rtl/isp/` 中指定文件 | 扇出分发、复位有效性、参数提交和跨模块流水对齐 |

共享顶层、工程、IP 清单、全局约束和跨端协议只由 R0 写入；其他任务提交端口差异和测试证据。R1 与 R2 先冻结 cache/DMA 事务合同。任何智能体不得覆盖另一任务修改，不得同时编辑同一文件，也不得自行扩展协议语义。

执行顺序：

1. R0 冻结源码与指标，检查当前未提交改动，划定文件所有权；以 writer BRAM 清单绑定的完整源码快照核对共享 RTL，先识别尚未推广的差异再开展修改，不能把 HEAD 或当前同名文件默认当作 P12 快照。综合未完成的模块先解决综合，不跳到布线优化结论。
2. R1/R2/R3 并行进行只读分析、局部修改及轻量回归，各提交一个优先候选；重型构建进入 R0 队列。
3. R0 按最新 P12 热点逐项集成，一次只引入一个主要结构变化；先 writer 候选及现有完整工程的布局前筛，再处理 DMA/refill/控制热点。隔离几何仅用于定向诊断，不能退回旧骨架替代完整业务基线。
4. 同功能候选通过后执行三 seed 小样本复验，冻结通过版本；再规划防抖与历史补全扩展。
5. 任何任务失败都保存日志、变更及退回原因；不能以未完成的局部模块宣称整机实现。

本次用户请求是制定方案；后续启动实施时按本节调度。硬件下载、板卡操作及既有告警放行仍遵循原约定，本方案不扩大硬件操作授权。

## 8 验收与交付

每个候选至少提交以下一行完整记录：源码/约束/IP 哈希、功能组合、机器与工具、seed、阶段耗时、是否超时、峰值内存、LUT/FF/APM/物理 DRM、拥塞信息可用性、setup/hold WNS/TNS、失败端点、未约束项、有效吞吐、最大服务间隔、延迟变化、功能回归结论。

验收分为四道门：

- **功能门**：像素/坐标、边界、同帧、参数原子切换、随机背压、复位/取消、迟到响应全部符合契约；关键新增写法有独立参考，代码块注释同步。
- **性能门**：冻结功能组合在真实 DDR 服务模型与混合压力下满足期限；模型与实板结论分开。主链路、网络完整帧率与结果输出分别验收。
- **物理门**：资源在整机预算内，目标器件完成布线，相关 corner 的 setup/hold 通过，外部/CDC 约束检查无遗漏。隔离夹具通过不等同板级签核。
- **效率门**：限时规则生效，有限 seed 内无长尾失败，耗时与基线可比；未达到改善目标明确报告，不使用选择性样本。

规划继续放 `output/`；RTL、模型、脚本、配置、日志和测量报告全部归 `fpga/` 对应目录，跨端影响才修改 `host/` 或 `mcu/`。不新增 Git 忽略项，不修改官方资料，不自动提交或推送无关工作区变化。
