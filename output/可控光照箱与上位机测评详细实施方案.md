## 1. 范围与设计基线

### 1.1 与现有项目衔接

- 硬件与视频主链以 [PG2L100H 详细设计方案](./PG2L100H_1080p畸变矫正详细设计方案.md) 为基础，旧 PGL50H 方案仅供追溯。
- 当前回传依据 [OV5640 RAW8 千兆网与 HDMI 双路回传方案](./OV5640_RAW8千兆网与HDMI双路回传方案.md)：单路 OV5640 RAW8 Bayer DVP 在 FPGA 接收后分路，S0 经板载千兆网发给 PC，同时经 FPGA 基础 ISP 转为 S1 RGB888 后执行几何处理，完整结果经板载唯一 HDMI OUT 和采集卡返回 PC。
- PC 对 S0 的去马赛克仅用于原图可视化，不能自动等同 FPGA S1；正式几何参考仍取 FPGA S1 与同帧 S2/S3 独立快照。PC 不转发主视频，也不执行替代 FPGA 的实时几何矫正。
- 真实 1920×1080@30fps 是交付目标；VGA/720p 仅用于联调。须先实板验证 RAW8 DVP 1080p30 的寄存器模式、有效行列、PCLK 与暗光帧率。1080p60 需要真实 60fps 输入源和完整链路，RAW8 1080p60 加协议开销不能沿用单千兆网全帧回传。
- 正式长稳不少于 2 小时，冻结版本争取 8 小时；30 分钟仅作快速回归。
- PC 负责标定、控制、软件参考和测评；比赛主视频的坐标计算与插值由 FPGA 完成。
- 本文的命令、数据结构、界面和测试脚本是待实现规格，不表示代码或接口已经存在。

### 1.2 本轮新增与调整

| 项目 | 本文决策 | 实施影响 |
| --- | --- | --- |
| IMU 接入 | 优先采用具有姿态融合输出的 UART 模块，直接接 FPGA | 用户本轮偏好优先；原 ICM-42688-P SPI 路径保留为备选，不能将其写成串口姿态模块 |
| 环境控制 | 外置 MCU 控制灯光、云台和实体按钮 | MCU 不计算逐像素映射，光照档位不直接决定自适应 Gamma |
| 连续回传 | S0 RAW8 千兆网＋完整结果 RGB888 HDMI，均为 1920×1080@30fps | PC 双缓冲显示；禁止编码压缩、缩小、裁剪或色度抽样替代规定数据 |
| 精度采集 | 保存 FPGA S1 与同帧 S2/S3 的完整裸像素及实际参数 | 经独立 DDR 快照从网口低优先级导出；S0 可视化不能冒充 S1 |
| 增强位置 | 为验证赛题“矫正前或过程中”的要求，定义源像素增强后再插值的 pre_resample 模式 | 原详细设计的双线性后 Gamma 记为 post_resample 对照；两者分别验证，软件参考不得混用 |
| 诊断缓存 | SRC/DST 共 48 MiB＋RAW 三槽 12 MiB＋双快照 16 MiB | 共 76 MiB；描述符、掩码与日志另算；新增访问需重新核算 DDR |
| 同源关联 | 网络报文携带源帧身份，HDMI 采集关联单独验证 | 未验证的 HDMI source_frame_id 使用 null/unverified，不以到达顺序猜配 |
| 能效与计算来源 | 独立板级直流测量、断开 PC 后板上按键与直连显示器演示 | 区分板级与整机能耗，保存板内运算及同帧验证证据 |
| 测评结果 | 区分通过、失败、无效、未测和未实现 | 缺数据、功能未做或图卡检测失败不能记为通过 |

实现对应模块时，应同步更新详细设计、协议和版本记录。以上是当前待实施规格；不得据此宣称网络、配对、无压缩采集或板级指标已经验证通过。

### 1.3 能力边界

| 能力 | 解决的问题 | 评价依据 |
| --- | --- | --- |
| 镜头去畸变 | 径向、切向畸变造成的直线弯曲 | 真实标定、独立网格直线度、映射坐标误差 |
| 姿态补偿 | 相机转动后参考方向或参考视角改变 | 固定图卡方向、角点位置、独立实际角度 |
| 平面透视恢复 | 倾斜平面图卡的正视恢复 | 明确平面信息、目标视图和角点几何 |
| 光照增强 | 暗部对比不足或灰度分布不利于观察 | 灰阶、对比与噪声、饱和比例、响应时间 |

纯旋转可由内参与相对旋转建立映射；一般三维场景中出现相机平移时，一个整帧单应变换不能消除全部视差。双线性插值不能恢复视野外、被遮挡或已经饱和丢失的内容。[OpenCV 单应性说明](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)

“任意角度”应分别申报：算法角度参数域、机械运动范围、保留视场和最大测试速度。软件支持 0～360° 不等于云台可以带线无限旋转，也不表示所有角度都有完整有效视场。

图中所有帧槽均属于同一组板载 DDR 的不同地址区；网络 MAC、协议与发送调度由 FPGA 工程实现，板载 RTL8211F PHY 不能替代这些逻辑。PC 的两份图像均为完整 1920×1080 数据，FPGA 不输出缩小拼接画面，不新增第二路 HDMI 发送器。

### 2.1 箱体、光源与运动机构

| 部件 | 实施要求 | 验证方法 |
| --- | --- | --- |
| 箱体 | 消光内壁、可开合侧门、可遮光观察窗、合理散热 | 关门后测外部光变化对目标区的影响 |
| 图卡位 | 刚性平整底板、抽拉卡槽、距离可调 | 换卡不碰动相机；记录尺寸、距离、图卡编号 |
| 相机/IMU | 共用刚性安装板，线缆应力释放 | 转动时无相对晃动；拆装后复核安装外参 |
| 云台 | 必须包含绕镜头光轴的滚转轴，另有俯仰、偏航 | 记录各轴实际方向、行程、速度、回差 |
| 角度真值 | 编码器或独立量具，记录分辨率和误差 | 不以云台指令角或待测 IMU 自报值代替真值 |
| 光源 | 均匀漫射光＋独立侧光，可调光 | 在实际曝光配置下检查条纹与闪烁 |
| 照度测量 | 图卡中心与四角测量，固定点连续监测 | 记录传感器位置；PWM 占空比不能代替 lx |

先搭支架，验证镜头对焦距离及最差姿态的视场包络，再确定箱体尺寸。旋转中心尽量靠近相机投影中心，降低近距离偏心平移。图卡位置、相机距离或机械零位变化后，重新建立基准几何。

云台负责主动施加运动，关闭云台自身稳像。人工转动前使用适当释放/手动模式，不强行掰动锁定电机。MCU 提供停止运动、正常光照和回零功能；机械回零与 IMU 参考姿态重置为不同操作。

### 2.2 光照配置

下列值为布置起点，不是赛题标准或实测值。灯光能力不足时记录实际可用范围，不用软件标签冒充实测照度。

| 编号 | 工况 | 初始设置 | 必录信息 |
| --- | --- | --- | --- |
| L0 | 正常 | 漫射光，中心约 500～1000 lx | 五点均匀性、曝光、增益、灰阶饱和情况 |
| L1 | 夜间 | 整体约 5～20 lx | 暗部对比、噪声、曝光是否导致降帧 |
| L2 | 强光 | 逐步加光，例如中心约 3000～10000 lx | 高亮比例、眩光位置、实际峰值 |
| L3 | 明暗不均 | 一侧照明、另一侧遮挡 | 亮暗区域分别测量，不能用单点代表全图 |

几何测试锁定曝光、增益、对焦、白平衡及 ISP 配置。增强测试先固定曝光，再单列自动曝光开启的系统测试；监控暗光是否触发自动降帧。灯光改变起点使用光传感器或实际驱动事件，PC 发指令的时间仅供辅助。

## 3. 上位机功能与界面

当前S0工作台采用Python标准库本机Web服务与浏览器界面，已接入PRAW核心；详见[Web接入说明](../host/docs/Web界面与核心接入说明.md)。后续建议OpenCV处理测评图像、pySerial连接设备，均需单独实现与验证。MTF 使用经过验证的斜边分析实现，不能把拉普拉斯方差当作 MTF50。[pySerial](https://pyserial.readthedocs.io/en/latest/shortintro.html)

| 模块 | 输入 | 职责与输出 |
| --- | --- | --- |
| 设备管理 | 串口、采集卡、数据口 | 能力查询、版本、连接状态和恢复 |
| RAW 接收 | 千兆网 S0 数据包 | 按帧组装、偏移/长度/CRC 校验、丢包恢复、Bayer 可视化及网络统计 |
| 结果采集 | HDMI 完整 RGB24/BGR24 | 保留 1080P 像素缓冲、采集时间戳、关联状态与采集端丢帧计数 |
| 快照接收 | 图像块、帧描述符 | 完整性校验、同帧配对、像素格式恢复 |
| 标定管理 | 参数和真实图像 | 模型检查、版本、定点编码和回读 |
| 参考计算 | 输入帧、本帧参数 | 浮点/定点结果、参考有效掩码 |
| 指标分析 | 图像、ROI、时间、计数 | 几何、清晰度、光照、延迟和异常 |
| 测试调度 | 工况配置、按钮事件 | 执行、稳定等待、超时和失败处理 |
| 证据归档 | 配置、图像、指标 | 文件校验、CSV、曲线和报告 |

采集、串口、写盘、分析和界面分离。连续 S0 和结果接收目标各为 30FPS，界面缩放不改变底层完整 1080P 缓冲。预览队列可丢弃旧预览并计数；证据队列不能静默覆盖。分析线程的处理能力可先以每秒 1 组为调试目标，但它不代表快照允许的常规采样频率；完整精度快照的常规长稳频率为每 60 秒 1 组，1Hz 只作带宽与 DDR 验证后的短时条件上限。界面分别显示输入、FPGA 处理、S0 网络接收、HDMI 接收、已配对帧率及分析更新率。

实时结果窗口只接受 FPGA 返回数据；采集断开或配对不可信时显示故障/未关联，不得静默切换为 PC 软件矫正。参考模型单列标注为软件参考。原图窗口标注“S0 经 PC 基础可视化”，不得标为已经验证一致的 FPGA S1。两幅图同时按 1:1 像素显示需要至少 3840×1080 的可用显示区域，否则提供同步缩放、滚动和全屏切换。

| 界面区域 | 内容 |
| --- | --- |
| 顶栏 | 板卡/位流版本、相机模式、通信状态、参数版本 |
| 图像区 | S0 可视化、FPGA HDMI 结果；精度模式另开真实 S1/S2/S3 快照、软件参考和差异图；原比例 ROI 放大 |
| 控制区 | 光照、云台、自动扫角、三项算法独立开关 |

每项数值注明“实时遥测”“当前快照”“最近一次测量”或“报告导入”。没有测量结果时显示未测，不填零或预置成绩。

## 4. 传输通道与带宽

### 4.1 通道安排

| 通道 | 当前用途 | 限制 |
| --- | --- | --- |
| 板载千兆网 | 连续未压缩 S0 RAW8 1080P30；余量内低频 S1＋结果快照及元数据 | 需实现 MAC、协议、DMA、重组和恢复；实时 S0 优先，快照最低优先级 |
| 唯一 HDMI OUT＋采集卡 | 完整结果 RGB888 1080P30，经验证后接收 RGB24/BGR24 | 不缩放、裁剪、MJPEG/H.264/H.265 编码或转为 YUY2/NV12；实际采集格式需核验 |
| USB-UART | 控制、标定参数、遥测、少量诊断 | 沿用 115200 bit/s、8N1；不传实时全图；IMU 专用口独立预算 |

RGB888 一张 1080p 图像为 6,220,800 byte，约 6.22 MB / 5.93 MiB；一组 S1＋结果为 12,441,600 byte，约 12.44 MB / 11.87 MiB，不含掩码及描述符。

| 载荷 | 数据量，不含协议开销 | 结论 |
| --- | --- | --- |
| S0 RAW8 单帧 | 2,073,600 byte | 每个采样位置 1 byte，传输不改变 Bayer 数据 |
| S0 RAW8 1080P30 | 62.208 MB/s＝497.664 Mbit/s | 千兆网有吞吐空间，仍需实测持续接收和 DDR 调度 |
| RGB888 1080P30 | 186.624 MB/s＝1,492.992 Mbit/s | 千兆网不能连续回传这种彩色全图 |
| S0＋RGB 结果各 30FPS | PC 有效载荷合计 248.832 MB/s | 两条接口分别验收，不把它们当作同一个千兆网负载 |
| S1＋结果快照每秒 1 组 | 12.4416 MB/s 额外网口有效载荷 | 与 S0 共用网口且产生额外 DDR 复制，1Hz 仅为短时条件上限 |
| S0 RAW8 1080P60 | 124.416 MB/s＝995.328 Mbit/s | 按当前报文线上约 1087.8048 Mbit/s，超过单千兆网能力，进阶接口须另设计 |

115200、8N1 的理论字节载荷上限为 11,520 byte/s；一组 S1＋结果理论导出约 18 分钟。UART 冻结导出只作早期静态调试，ROI 不能代替全域精度测量。

### 4.2 S0 网络帧协议与恢复

首版采用 IPv4 UDP、MTU 1500；每包自定义头 64 byte，图像有效载荷最多 1400 byte，避免 IP 分片。每张紧凑 RAW8 图为 1482 包，最后一包为 200 byte；网络 stride 为 1920 byte。自定义头承载协议版本、stream_epoch、frame_id、图像类型、尺寸、Bayer 排列、参数版本、字节偏移、帧总长度、有效长度及 CRC32；字段位宽、CRC 覆盖和算法参数按统一接口冻结，不由各端独立猜测。

网络发送前从 DDR 的 2048 byte 行跨度中取每行 1920 byte 有效数据，不能把行填充误当像素。按当前 64 byte 头＋1400 byte 最大载荷计入帧间隔等线上开销，RAW30 约 543.9024 Mbit/s；1Hz 双快照额外约 108.7763 Mbit/s，总计约 652.6787 Mbit/s（均不含重传等额外流量）。这些只是预算，必须通过 MAC/DDR/PC 混合负载实测；不能以算术余量直接承诺持续能力。PC 按唯一帧身份和偏移组装，允许乱序包与可识别的重复包；检测越界、长度不一致、CRC 错误、模式突变和超时，不把缺失数据填黑后当作有效帧。未完整帧标 INVALID，并统计丢包及缺帧。丢包恢复使用有界重传窗口和独立保留策略，超窗明确失败，不能无限固定实时 RAW 帧槽或阻塞 DVP/矫正。

实时 S0、重传、快照和遥测共同计入线上吞吐。快照只使用经过验证的剩余网络与 DDR 预算；出现积压时暂停快照或返回 BUSY，先保护实时采集、处理和 HDMI。PC 断连后停止/丢弃网络导出并计数，FPGA 继续独立处理与显示。

### 4.3 HDMI 采集链校验

用 FPGA 已知彩条、灰阶、单像素图案验证采集卡是否缩放、裁剪、压缩、改变色度或量程；逐字节核对实际收到的 RGB24/BGR24，显式处理通道顺序与行填充。帧号测试图只用于诊断链路，正式图像不覆盖身份标记。HDMI 30Hz/60Hz、独立处理帧率及采集接收帧率分别记录；30 个结果在 60Hz 输出中重复不等于处理 60FPS，USB/PCIe 带宽按实际采集模式计算。

正式像素误差优先由 DDR 裸像素快照计算。必须经采集卡测 MTF 时，先验证链路并固定配置，结论标为“包含采集链路的系统 MTF”。禁止以卡上标注“1080P”或“未压缩”替代实际格式验收；未压缩 YUY2/NV12 仍有色度抽样，不符合 RGB888 像素保持要求。

### 4.4 两路关联与显示

网络 S0 自带 stream_epoch/frame_id；HDMI 通常不会把该源帧身份直接交给采集 API。必须另行验证板端 HDMI 输出事件、采集硬件时间戳与元数据之间的关联，并覆盖时钟漂移、重复输出、采集丢帧、断连和恢复。不能按两路到达顺序、固定延迟或串口报文先后盲目配对。

关联能力未通过时，HDMI source_frame_id 为 null、pairing_status 为 unverified。两路可以各自实时显示并明确标注未关联，但不能据此形成同帧误差、动态峰值或正式配对成绩。精度用例使用 FPGA 独立 S1＋结果快照，其源帧身份由 FPGA 内部保证。实时配对是独立验收项，快照通过不能替代它。

### 4.5 完全未压缩保存

S0 原始证据保存为裸 RAW8 字节＋元数据，S1 与结果保存为裸 RGB/BGR 字节＋尺寸/stride/格式描述。PNG 本身属于无损压缩，只能作为派生预览或报告插图，不能作为“完全未压缩文件”的交付证据。实时输入和回传不使用 MJPEG、H.264、H.265；禁止把压缩视频解码后的 RGB 冒充未压缩采集源。连续数据是否写盘由测试配置决定，不要求长稳期间全部录制。

## 5. 同帧快照与缓存

### 5.1 观测位置

| 位置 | 数据 | 用途 |
| --- | --- | --- |
| S0 | 连续网络 RAW8、Bayer 排列、位宽与源帧身份 | PC 原图可视化与 ISP 专项调试，不直接作为 FPGA S1 几何参考 |
| S1 | 基础 ISP 后、几何前 RGB888 | 正式几何评估的真实输入 |
| S2 | 重采样后、最终 OSD/分屏前 | 几何结果，是否已含前置增强由元数据说明 |
| S3 | 完整算法结果、显示缩放前 | 含增强的系统质量评估 |

几何精度关闭自适应增强。增强测试保存实际 LUT 和增强位置；pre_resample 表示源邻域查表后插值，post_resample 表示插值后查表，两者通常不相等。

前置增强是需要重新实现和测量的扩展：RGB四邻域在每周期接收1个输出像素请求时，需要最多12次通道查表，原后置方式只需3次。应采用足够的LUT副本/端口或明确的复用调度，并重新核算资源与最坏吞吐。LUT按源帧版本锁定，不能在同一像素的四邻域或一帧处理中混用两张表。

每次标准成对快照仅包含 S1 输入和 S2/S3 中一个选定输出位置；两个快照槽不保证同时保留 S1、S2、S3。若要同时比较增强前后两个输出，需另外提供缓冲或在可重复静态诊断模式分别取样，并明确数据来源。

### 5.2 内存扩展

统一内存布局与当前回传方案一致；地址是待实现分配，实物 DDR 容量和控制器可访问范围必须核验。

| 区域 | 槽数与容量 | 地址/布局 |
| --- | --- | --- |
| SRC S1＋DST 结果 | 各 3×8 MiB，共 48 MiB | 保留主设计现有前 48 MiB 帧池 |
| RAW0 | 4 MiB | 0x03000000 |
| RAW1 | 4 MiB | 0x03400000 |
| RAW2 | 4 MiB | 0x03800000 |
| snapshot_S1 | 8 MiB | 0x03C00000 |
| snapshot_result | 8 MiB | 0x04400000 |

上述区域合计 76 MiB，结束地址为 0x04C00000（不包含该地址）；描述符、掩码、日志及其他用途另行分配。RAW DDR stride＝2048 byte，一帧实际占用 2,211,840 byte；网口只发紧凑的 2,073,600 byte，有效 stride＝1920 byte。

RAW 三槽与快照槽具有独立所有权和未决访问计数。满帧发布需等待写完成，释放需等待读取/发送引用及未决事务结束。没有可用导出槽时拒绝快照或按网络导出策略丢弃待发送帧，不能阻塞不可背压的 DVP、覆盖仍在使用的数据或耗尽结果显示缓冲。重传保留窗口与三个 RAW 槽的周转共同验证。

新增 RAW 写入、RAW 网络读取、快照复制和网络读取均纳入 DDR 仲裁和最坏角度压力测试，不能沿用只计算 SRC/DST 的旧带宽数字。视频及网络帧池容量规划不代表控制器、吞吐和实物容量已经验证。

### 5.3 实时快照流程

1. PC 请求下一组可采集完整帧，或指定仍可获取的帧号。
2. FPGA 检查独立快照缓冲、复制时限、队列、连续 S0 网络负载及 DDR/网口剩余带宽；不可满足时返回 BUSY。快照不会抢占实时 S0 发送预算。
3. 在 S1 可用时复制/镜像目标帧到独立快照槽，确保复制期间源槽不被覆盖。
4. 同一 frame_id 的处理结果完成后获取对应输出，锁定参数、姿态和时间戳。
5. 全部写事务完成才标记 SNAPSHOT_READY；PC 分块读取并校验。
6. 输入、输出、描述符及必要掩码完整后，PC 确认释放快照槽。

不能长期占用实时源槽迫使视频等待。若复制无法在预算内完成，应拒绝/安全取消快照；待未决事务安全结束后释放引用，继续正常视频。禁止边覆盖边导出。

下一请求遇到未释放快照应返回忙，不能替换旧证据。正式性能报告分列 S0 导出关闭、S0 连续导出、S0 导出＋低频快照等功能组合；默认长稳每 60 秒 1 组精度快照。

### 5.4 图像块完整性

每块包含会话号、快照号、帧号、图像类型、字节偏移、有效长度及分块校验；重传不能混入新帧。文件落盘后计算 SHA-256。板端没有全帧哈希能力时，使用分块校验与完整字节计数，不声称完成板端全帧哈希对照。


### 5.5 坐标诊断数据

RGB输出不能唯一反推出硬件源采样坐标。全域坐标精度必须有以下明确证据之一：

- 板端坐标诊断：冻结一组真实参数，由实际坐标RTL遍历完整输出域，按行序分块导出有符号源坐标、有效位、参数版本和numeric_format_id。坐标可按int32容器保存，实际位宽/小数位由格式声明给出。
- 全域RTL仿真＋板端抽点：仿真导出全图坐标，板端抽检中心、边缘、块边界及异常域。报告分别写“仿真全域结果”和“板端抽样结果”，不能写成板端全域实测。

两路int32源坐标在1080p下约16.59MB，不含有效位。采用分块遍历和传输可避免整图坐标常驻DDR；若沿用已有视频存储区，必须在独立诊断模式安全停用相关客户，不得与实时帧池重叠读写。

新增 GET_COORD_CAPS、START_COORD_DIAG、READ_COORD_BLOCK、STOP_COORD_DIAG 等语义，编号随统一协议冻结。诊断需支持分块校验、参数锁定、停止和超时释放。允许背压的离线坐标导出不用于证明实时吞吐；正式实时性能另测。

## 6. 控制协议、元数据与时间同步

### 6.1 沿用现有 UART 包格式

~~~text
55 AA | version:u8 | cmd:u8 | seq:u16 | length:u16 |
payload | CRC16:u16
~~~

- 多字节小端，payload 最长 1024 byte。
- CRC-16/CCITT-FALSE：多项式 0x1021，初始 0xFFFF，不反射，xorout 为 0；覆盖 version 至 payload，CRC 本身也小端发送。
- 以下命令名为新增/细化语义，具体 cmd 编号由协议表统一分配，PC、MCU、FPGA 不各自定义。
- 会话握手建立 session_id。请求序号回绕与重连后不能误匹配旧回应。
- CRC 失败只统计并丢弃不可信包，不能按其中的命令或序号执行操作。
- 解析超时按波特率和最大包长核算；初版可用整包 300 ms、普通请求 1 s 超时和最多 2 次重试作为调试起点。
- 长操作先确认接收，再异步报告完成；快照、运动不能都塞入普通请求超时语义。

### 6.2 命令语义

| 目标 | 命令名 | 关键请求 | 必须回应 |
| --- | --- | --- | --- |
| FPGA | HELLO / GET_CAPS | 协议版本、会话标识 | 位流标识、像素格式、可用快照点、缓存和计时能力 |
| FPGA | GET_CONFIG | 当前或指定版本 | 实际参数值、版本、有效源帧号 |
| FPGA | WRITE_SHADOW | 参数块、偏移、编码格式 | 已接收范围及校验状态，不表示生效 |
| FPGA | COMMIT_CONFIG | 参数版本、整组校验、切换策略 | 实际生效的 stream_epoch、frame_id、param_version |
| FPGA | GET_STATUS | 查询范围 | 时钟、输入锁定、IMU状态、网络链路、错误与资源忙状态 |
| FPGA | START_RAW_STREAM / STOP_RAW_STREAM | 网络目标、流模式与恢复配置 | 接受状态、流代次和实际源帧范围；停止网络不停止处理 |
| FPGA | GET_STREAM_STATUS | 流与关联能力 | RAW 完整帧/包统计、重传、HDMI 输出事件及关联能力 |
| FPGA | GET_COUNTERS | 计数快照请求 | 原子计数快照、时间计数及计数频率 |
| FPGA | REQUEST_SNAPSHOT | 下一可用帧/明确帧号、观测点 | 接受或忙，随后给出实际捕获帧号和快照号 |
| FPGA | GET_SNAPSHOT_INFO | 快照号 | 输入输出描述符、块数、参数关联、错误位 |
| FPGA | READ_SNAPSHOT_BLOCK | 快照号、类型、偏移、长度 | 对应数据块及完整性信息 |
| FPGA | RELEASE_SNAPSHOT | 快照号 | 已释放或明确失败原因 |
| FPGA | SET_VIEW / SET_REFERENCE | 显示模式或参考姿态 | 实际生效帧号；参考重置必须有事件记录 |
| MCU | SET_LIGHT | 各路目标值、事件号 | 接受状态；执行事件、实测照度另报 |
| MCU | MOVE / START_SWEEP | 轴、目标、速度、加速度、次数 | 接受状态、实际执行状态、停止/限位原因 |
| MCU | STOP / HOME | 操作号 | 已停止/已回零；不隐含 IMU 重新归零 |
| MCU | GET_ENV / EVENT_LOG | 时间区间或事件号 | 照度、实际角度（若有）、按钮和执行事件 |

为重传安全，优先使用“设置为某状态”，不用“再切换一次”这类非幂等操作。按 session_id、seq、cmd 和载荷摘要识别重复请求；同序号不同载荷拒绝。已执行请求重传返回原结果，不重复启动运动。回应缓存失效后先查询实际状态，不盲目重放旧命令。

### 6.3 接收不等于生效

| 状态 | 含义 | 上位机行为 |
| --- | --- | --- |
| REJECTED | 格式、范围、资源或版本不允许 | 报告原因，当前工况不能继续假装成功 |
| ACCEPTED | 已校验并排队 | 等待执行结果，不更新“当前生效参数” |
| APPLIED | 已实际执行 | 核对版本和实际生效帧号，开始采样 |
| FAILED | 接受后未执行成功 | 保存错误与当前真实状态，按用例决定停止或恢复 |

静态配置写入影子区，整组校验后原子提交。采集/ISP 参数在合法采集边界切换；几何参数在开始处理该源帧时锁定；所有环节最终关联源 frame_id。动态姿态逐帧匹配后锁定，禁止处理中途换版本。

增强同时记录“统计来自哪一帧”和“LUT在哪一帧生效”。回放自适应过程需要初始状态与连续统计，单张图片无法独立复现带历史状态的选择过程。

### 6.4 数据契约

唯一键使用 run_id＋stream_epoch＋frame_id；snapshot_id 表示一次快照请求。设备复位、视频模式重启或帧号重新开始时改变 stream_epoch。

| 类别 | 最小字段 | 约定 |
| --- | --- | --- |
| 标识 | run_id、stream_epoch、frame_id、snapshot_id | 两图同源；请求帧号与实际帧号都可追溯 |
| 图像 | tap、width、height、pixel_format、bayer_pattern、stride_bytes、payload_bytes | S0 为 RAW8；首版正式几何参考为 FPGA S1 RGB888；网络/DDR stride 分开记录 |
| 连续传输关联 | CaptureFrame.source_frame_id、pairing_status、capture_timestamp、display_event_id | 未验证时 source_frame_id 为 null、pairing_status 为 unverified；时间戳注明来源/时基 |
| 模型 | calibration_hash、K、D、K_out、model_id | 保存真实参数文件，不只保留名称 |
| 变换 | param_version、transform_mode、pose_used、reference_pose | 固定坐标系、四元数顺序、角度单位 |
| 插值 | interpolation_id、numeric_format_id、border_policy | 记录权重位宽、舍入、饱和、边界规则 |
| 增强 | enhancement_stage、lut_version、lut_hash、stats_frame_id | 保存 LUT 实体；disabled 也是明确状态 |
| 姿态同步 | sensor_timestamp、fpga_receive_tick、pose_age、sync_quality | 多时基先转换；缺失不得填成有效零值 |
| 时间 | capture_first_tick、capture_last_tick、process_start_tick、result_ready_tick、first_display_tick、tick_hz | 明确每个端点，采用同一或已同步时基 |
| 环境 | light_event_id、lux、exposure、gain、AE_state | 无法读回时用 null，并说明来源/可靠性 |
| 完整性 | input_ok、output_ok、crc_ok、valid_mask、invalid_reason | 图像缺失或参数缺失时不得计算合格结论 |

first_display_tick 在结果快照就绪时可能尚未产生，应暂记 null，并由首次显示事件按唯一帧键补齐。未取得该端点时不得计算输入到显示输出的延迟；不能用预计显示时刻填充。

完整元数据为 PC 端归档结构，不要求全部塞入一帧 UART 包。遥测可使用短二进制结构、参数版本引用和分块查询。版本引用的实体必须随测试资料保存。

### 6.5 IMU 接入与同步

1. 选择能输出融合姿态的 UART 模块；先核对逻辑电平。RS-232/RS-485 要配置相应收发器。
2. 固定相机与 IMU 安装旋转，标定轴向和零偏。建议内部统一为 Hamilton 四元数 [w,x,y,z]，注明是主动旋转及其源/目标坐标系。
3. 建议统一保存 q_wc，即从相机坐标到世界/参考世界坐标的旋转；相机轴取 x 向右、y 向下、z 向前。模块输出不是此定义时，在适配层显式转换并用单轴运动验证。
4. 传感器时间与 FPGA 时间不同，需建立偏移/漂移关系；只有 UART 接收时刻时，校准传输和融合延迟，并标记为近似同步。
5. VSYNC 或首个有效像素不自动等于曝光中心。按相机模式估计/测量曝光时间关系，姿态按该时间插值并绑定源帧。
6. OV5640 的卷帘与长曝光影响单列记录；整帧姿态补偿不承诺消除所有行间形变与运动模糊。
7. 姿态丢包、过期或晚到时采用已定义的保持/预测/暂停补偿策略，并标记降级。报告正常帧和降级帧的数量，不能只删除失败帧后宣称全部合格。

32 byte、200 Hz、8N1 的姿态链路需求为 64,000 bit/s；115200 波特率下单包约 2.78 ms。这只是带宽示例，不是指定模块的实测能力。PC 控制、MCU控制、IMU 输入不得无仲裁共用同一 UART。

### 6.6 跨域与计数

FPGA 各时钟域的事件用可靠握手/FIFO或经过验证的时间戳方案传递，不能直接采样多位计数总线。建议 64 位计数；必须记录 tick_hz、复位代次及回绕规则。

分别统计：

- 视频：检测到的输入帧、合法完整帧、处理完成帧、首次显示的唯一结果帧、重复显示、未显示结果、溢出/欠载。
- 快照：请求、接受、成功、忙拒绝、复制失败、传输校验失败。
- 网络：RAW 帧发布/发出/完整接收、包/字节、CRC 失败、重传、窗口超时、导出丢帧、队列水位与快照暂停。
- PC：RAW 完整帧、HDMI 接收帧、帧号缺口、重复帧、配对成功/未关联/重同步、分析队列拒绝、图卡检测无效；未压缩链路不以视频解码帧率替代接收帧率。
- 控制与姿态：CRC失败、命令超时、IMU丢包/过期、MCU事件遗漏。

板端只能观测其输入边界之后的帧；相机不提供自身序号时，不能声称检测到了所有相机内部丢帧。

## 7. 标定与软件参考

### 7.1 标定流程

1. 固定镜头、焦点、分辨率、有效裁剪、镜像、RAW 位宽、Bayer 排列和基础 ISP。
2. 优先从 FPGA S1 快照采集约 25～40 张清晰棋盘/圆点图，覆盖中心、四角、距离和倾斜方向；另留独立验证集。若使用网络 S0 的 PC 重建图标定，先验证其尺寸、镜像、裁剪和基础 ISP 与目标 S1 的关系，并保存可追溯配置，不能默认两者相同。
3. 测量格长和平整度，记录图卡编号和单位；不从显示缩放后的图片估算格长。
4. 用 k1、k2、p1、p2 模型标定，固定 k3，不启用额外高阶模型；不能先依赖高阶系数拟合，再删掉它们沿用原误差。
5. 保存逐图重投影误差，并检查独立网格和有效域。拟合失败的图与剔除原因保留，不只保留好看的结果。
6. 生成参数文件、哈希和模式说明，下发后回读定点值、版本及实际生效帧号。
7. 更换相机、焦点、裁剪或模式后重新验证；只有确认属于纯尺度变化时才换算内参。

标定求解由 PC 完成，FPGA 需真正解析下发报文：K 中 fx、fy、cx、cy（像素单位），D 中 k1、k2、p1、p2，以及尺寸、模型、数值格式、版本与校验。PC 解析标定文件并编码定点报文；板端校验、写影子寄存器、整组提交，再回读当前生效寄存器，而不是仅回显接收包。需验证字段顺序、符号、字节序、小数位和约定量化误差。动态姿态与镜头内参分开管理。

相机姿态改变更新的是视图旋转关系，不能随意修改真实镜头畸变系数。[OpenCV 标定模型](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

### 7.2 两类参考不能互相代替

| 参考层次 | 输入 | 证明什么 |
| --- | --- | --- |
| 算法实现参考 | S1 原图＋硬件实际使用的参数、姿态、LUT | FPGA 运算是否符合规定模型 |
| 实际几何真值 | 固定图卡、已建立的参考视图、独立实际角度 | IMU、安装关系、同步和系统补偿是否准确 |

与使用同一份错误 IMU 数据的软件高度一致，不能证明姿态正确。也不能逐帧对输出再拟合任意单应变换、平移或旋转后才计算误差；这种对齐会消除待测错误。允许一次性建立并冻结的坐标约定转换，必须留档。

### 7.3 联合逆映射定义

统一像素中心为整数坐标：左上像素中心(0,0)，右下(W−1,H−1)，与本参考所用OpenCV约定一致；软件和硬件均不额外增加0.5。K、K_out、裁剪偏移、ROI及图卡坐标均沿用该约定。源图归一化后采用：

~~~text
r2 = x*x + y*y
radial = 1 + k1*r2 + k2*r2*r2
xd = x*radial + 2*p1*x*y + p2*(r2 + 2*x*x)
yd = y*radial + p1*(r2 + 2*y*y) + 2*p2*x*y
us = fx*xd + cx
vs = fy*yd + cy
~~~

纯旋转模式下，设 R_ref_cur 将当前相机方向向量变换到参考相机坐标系。对输出点 p：

~~~text
ray_ref = inverse(K_out) * p
ray_cur = inverse(R_ref_cur) * ray_ref
x = ray_cur.x / ray_cur.z
y = ray_cur.y / ray_cur.z
然后应用上述镜头畸变模型，得到源坐标 us、vs。
~~~

K_out 必须包括真实输出尺度/裁剪约定；额外二维变换也要按固定次序计入。透视分母异常或越域按冻结规则产生无效标记。

用统一映射一次重采样；不能软件先去畸变再旋转插值两次，而硬件只插值一次却直接比较。OpenCV remap 可作为工程参考，但插值表精度可能与硬件不同，逐位一致以自定义定点模型为准；当前 remap 不支持 INTER_LINEAR_EXACT。[OpenCV 重采样文档](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)

### 7.4 四层验证

1. RAW 参考 ISP 对 S0/S1：检查 Bayer、黑电平、增益和基础颜色处理。
2. 浮点几何对定点坐标：定位归一化、径向项、透视除法和递推误差。
3. 定点采样模型对 FPGA：逐级复现位宽、权重、舍入和饱和。
4. 完整系统对真实图卡：测直线、姿态、清晰度和增强效果。

保留参考有效掩码与 FPGA 无效标记差异。不能只取两者有效交集后把硬件漏算像素隐藏掉。先统计参考有效区域中硬件错误失效的比例，再对配对有效像素算数值误差。


## 8. 指标计算与判定口径

### 8.1 坐标与像素误差

对参考有效输出点，设 FPGA 源坐标为 (u_f,v_f)，浮点参考为 (u_r,v_r)：

~~~text
e_i = sqrt((u_f-u_r)^2 + (v_f-v_r)^2)
coordinate_RMS = sqrt(mean(e_i^2))
coordinate_max = max(e_i)
~~~

单位为源图像素；坐标误差与输出网格直线度的像素单位不能混用。正式数值验收覆盖全部参考有效输出域，不能只抽中心。调试时允许抽点，但报告标为抽样结果。

像素 MAE、MSE、PSNR在同尺度、同格式、同源帧及同算法状态下计算。8 bit 全量程的 PSNR 为 10×log10(255²/MSE)，MSE＝0 时记录正无穷；无有效样本时记为无效，不记为无穷。也可输出 SSIM，但不能代替几何指标。

逐通道报告 MAE、最大差值及差异热力图，图上注明误差显示倍率。禁止直接比较原图与矫正图的 PSNR，因为正确几何变换本身会移动像素。

### 8.2 直线度

1. 使用独立网格图卡，正常光照，固定曝光、焦点，关闭自适应增强。
2. 在未缩小的输出中检测同一物理网格线，优先采用亚像素边缘定位。
3. 为每条线拟合 a*x＋b*y＋c＝0，计算垂直距离：
   d_i＝abs(a*x_i＋b*y_i＋c)/sqrt(a²＋b²)。
4. 每条线输出 RMS、P95、最大误差、长度、有效点数；分中心/四边/四角汇总。
5. 保留被剔除点和剔除规则，不能通过大量剔除弯曲点或切成极短线段掩盖误差。
6. 所有工况使用预先冻结的 ROI 和最低覆盖要求，同时报告有效视场比例。

拟合直线可以评价弯曲，但不能证明方向、位置或比例正确；应同时查看姿态误差和网格角点。图卡不平、打印弯曲和检测噪声要单独记录。

### 8.3 姿态与角点

- 固定图卡，用独立角度量具检查相机实际姿态，建立参考方向/视图后冻结。
- 滚转残余角为输出图卡方向相对参考方向的差值，归一到约定角度范围；不在每个采样时刻重新归零。
- 使用不对称箭头或带编号角点区分 180°翻转；仅靠无方向直线可能存在歧义。
- 对平面参考视图，计算相同物理角点到预定输出位置的距离，报告 RMS、P95、最大值。
- 不能逐帧再拟合一个任意单应矩阵消除位移后，只报告剩余残差。
- 动态同时保存实际角度、速度、加速度、曝光、姿态时间差和残余误差。

建议出图：实际输入角度/输出残余角度随时间、角点轨迹、误差分布、停止后的收敛过程。区分 RMS、峰值和峰峰抖动；只给平均值会掩盖短时失败。

时间失配造成的角误差可用角速度×时间偏差作量级检查：30°/s 下 33 ms 已约为 1°。这只是诊断估算，不能代替实测。

### 8.4 MTF50 / SFR

MTF 在指定斜边 ROI 上评价，记录中心、四角及必要的水平/垂直方向。优先使用经验证的斜边分析工具和固定版本，保留设置文件与完整曲线。

执行步骤：

1. 保持同一输出尺度、对应图卡区域、曝光、增益和基础 ISP；几何专项测试关闭自适应增强与额外锐化。
2. 选择符合工具要求的斜边，避免完全水平/垂直边缘；通常约 5°倾斜用于降低采样相位影响。
3. 检查边缘两侧是否饱和、信噪比是否足够、ROI长度是否足够。记录有效性判定，不强行输出数值。
4. 按工具要求处理已知光度响应/线性化，再由边缘扩展函数 ESF、线扩展函数 LSF 和频域响应得到 SFR。
5. 记录 MTF50，单位 cycles/pixel；需要时附 cycles/picture-height，并注明所指图像高度。
6. 比较 FPGA 与相同映射、相同采样尺度的软件参考；原图和矫正图局部放大率不同时，不直接比较 cycles/pixel 断言清晰度提高。
7. 保留光晕、过冲、噪声及曲线形状，不能只看 MTF50 数字。

可定义 MTF保持率＝MTF50_FPGA / MTF50_reference，但参考无效或过低时比例本身无意义，应标为无效。锐化可能抬高 MTF50 而引入光晕，增强测试结果须单列。[Imatest 测量一致性](https://www.imatest.com/docs/mtf-measurement-consistency/)、[斜边方向与区域说明](https://www.imatest.com/docs/rescharts_edge_results-3/)

### 8.5 光照与增强

固定相机进行灯光阶跃，先测 AE 关闭，再测 AE 开启。两组不能混成一个成绩。

| 指标 | 计算方法 | 注意 |
| --- | --- | --- |
| 平均亮度、分位数 | 固定灰阶 ROI 的均值、P5/P50/P95 | 亮度提高不等于细节恢复 |
| 高亮/暗端比例 | 统计达到冻结阈值的像素占比 | 8 bit全量程可先用≥250和≤5作工程阈值，实际按量程冻结 |
| 暗部对比 | 固定暗灰块或文字/背景的亮度差 | 对应同一场景区域 |
| CNR | abs(mu_A-mu_B)/sqrt(sigma_A²+sigma_B²) | A/B为均匀对照灰块；噪声估计方法和空间/时间口径需固定 |
| 时间噪声 | 静止场景、固定曝光下同像素跨帧波动 | 不把运动或图卡纹理方差当作传感器噪声 |
| 响应帧数 | 实际光变到进入稳态判据的源帧间隔 | PC收包时间不作硬件响应起点 |
| 振荡/过冲 | 稳定目标附近的波动和最大偏移 | 保存Gamma/LUT和统计来源帧号 |

建议响应判据：以阶跃后预定末段连续30帧的灰块平均亮度作为观测稳态值；首次进入该值±max(5%×稳态值,2个8bit灰度级)，且连续5帧保持在范围内，记为收敛。若末段仍明显波动，则本次“不稳定”，不强行定义稳态。时间窗口和阈值在正式测试前冻结。

CNR 增大不能单独证明新信息被恢复，需同时给灰阶、纹理、噪声和饱和情况。使用自适应 LUT 时，软件重放保存实际 LUT；若要验证自适应策略本身，则还需重放完整统计序列与初始状态。

逐帧响应时间需要每个源帧的输出灰块统计或经过验证的连续帧观测。原图全局平均亮度不能自动替代增强后指定灰块亮度；如FPGA新增ROI统计，应记录统计位置、区域、帧号和采样规则。只有1Hz快照时只能报告采样分辨率下的响应，不宣称5帧内收敛。

### 8.6 吞吐、延迟与稳定性

分开记录以下时间，均关联源 frame_id：

| 符号 | 端点 |
| --- | --- |
| t0 | FPGA收到该帧第一个有效输入像素 |
| t1 | FPGA收到该帧最后一个有效输入像素 |
| t2 | 开始处理该完整源帧 |
| t3 | 对应结果全部写事务完成，可安全使用 |
| t4 | 该结果首次在FPGA输出接口输出首个有效像素 |
| t5 | 显示器对应区域发生可测光学变化，需外部仪器 |

计算输入跨度 t1−t0、排队 t2−t1、处理完成时间 t3−t2、显示等待 t4−t3、FPGA输入到输出 t4−t0。以计数差/tick_hz换算。t5不能由软件推测，完整光到屏延迟还需要场景实际光变化时刻。

输入帧周期、处理耗时、硬件端到端延迟是不同指标。处理平均快于帧周期不等于无队列积压，需看逐帧最大值和长期队列深度。

- 30fps结果可以用60Hz显示，每帧正常显示两次；这种重复不是新处理帧。
- 单独统计时钟漂移、无新结果重复、以及来不及显示的结果。
- 用硬件帧号判断新帧，不能用画面是否变化判断，静态图像仍然可以是新帧。
- PC收到图像时刻包含采集卡、USB与系统缓冲，不能当作FPGA延迟。
- 延迟报告中位数、P95、最大值、样本数、时间端点与仪器误差。

外部测量：用LED驱动图卡中的测试亮块，探头测真实发光变化，另一个探头测显示器对应位置；或使用高速摄影。记录曝光、屏幕刷新、探头位置、响应阈值和采样率。

### 8.7 资源与时序

导入对应位流版本的 PDS 布局布线报告，列出 LUT、FF、APM/DSP、块RAM、时钟、WNS/TNS、保持时序和未约束路径。检查CDC与复位处理；不能用综合估计频率替代实现结果。

DDR统计 RAW 写入/网络读取、S1 采集/结果显示/处理/快照复制及导出字节数、缓存回填效率、命中率、最大等待和FIFO高低水位。既有资源预算沿用详细设计，以实物及实现报告为准，不在本文生成虚构占用率。

### 8.8 能效测量与报告边界

主指标为开发板直流输入功耗：适配器→直流功率测量设备→MINI，记录电压、电流和所有实际供电入口，避免通过其他端口供电而漏计。板级范围包含 FPGA、DDR、PHY/视频接口及板上电源转换；不得将其直接命名为 PG2L100H 芯片功耗。芯片各供电轨测量与整机交流输入测量分列，传感器型号、精度和采样率需在采购/实物确认后填写。

相同时间窗口 T 内测得能量 E、完成 N 个有效独立源帧，则 P_avg＝E/T、FPS＝N/T、E_frame＝E/N、能效＝N/E＝FPS/P_avg。重复显示不计新帧；处理完成、首次输出与 PC 完整接收数量分别报告。功耗数值来自测量设备，处理数来自 FPGA 完整帧完成事件，时间窗口对齐并保存原始记录。

| 工况 | 要求 | 报告用途 |
| --- | --- | --- |
| 视频旁路 | 同一位流/输入/时钟/网络/显示配置，矫正计算真正停止 | 视频与回传基础负载 |
| 完整处理 1080P30 | 全部规定算法开启，分别记录 S0 导出开/关及快照状态 | 主能效指标及回传增量 |
| 完整处理 1080P60 | 真 60fps 源及已验证接口，功能和精度一致 | 独立进阶指标 |

只把显示切到原图而后台继续矫正，不算关闭计算。完整处理与旁路的功率差称为板级增量功耗，包含相关 DDR 流量等变化，不声称是算法逻辑的精确功耗。待温度和功率稳定后，建议各工况测量 5 分钟、重复 3 次，覆盖最差访存角度及不同图像内容；这是项目测试安排，不是已取得成绩。

若比较 PC 软件与 FPGA 的节能效果，应固定相同输入、画质、帧率和系统边界，单列整机（PC、板卡、摄像头、采集设备等）功耗。不能用开发板功耗和整台 PC 功耗直接计算整机节能倍数；USB 供电设备已计入 PC 输入时避免重复相加。调试逻辑、网络导出与采集配置均随位流和结果记录。

| 直线度 | 指定完整线段各自RMS≤0.5输出像素；附P95、max与边缘覆盖 | 沿用详细设计；P95≤1像素可作附加内部目标 |

| MTF保持率 | 指定有效ROI中不低于相同映射软件参考的90% | 本轮建议；同时报告绝对值及曲线 |
| 单帧处理时间 | 30fps内部留量目标≤30ms，截止按实测输入周期约33.33ms | 沿用详细设计；不等同端到端延迟 |
| 延迟 | 实测中位数/P95/max，注明端点 | 尚无已验证硬阈值，不预填合格数值 |
| 稳定性 | 正式≥2h，冻结版争取8h；正常输入无视频溢出/欠载、无处理丢帧和撕裂 | 沿用详细设计 |

### 10.1 组合姿态建议

9个姿态：零位；滚转±30°；俯仰±15°；偏航±15°；两个小角度复合姿态（例如滚转15°＋俯仰10°、滚转−15°＋偏航10°）。

这些是名义指令，实际角度由测量给出。按已验证的机械范围和共同可见ROI调整；调整前冻结测试配置，不能在看到坏结果后只删坏姿态。俯仰/偏航功能未实现时保留对应用例并标记未实现，不能将矩阵全项写成通过。

### 10.2 动态曲线需要连续证据

低频快照仅证明抽样时刻的精度，不能据此宣称动态峰值误差在所有帧都合格。

T07应获得覆盖目标源帧率的连续原分辨率数据或经验证的逐帧特征观测，并通过帧号去除60Hz显示中的正常重复帧。采集链须先证明几何保真度足以支撑角度/角点门槛。PC算力不足时保存可验证数据，离线逐帧分析；若只能低频抽样，报告名称必须为“采样观测最大值”。

当前正式链路禁止有损编码。经验证的完整 HDMI 结果可用于相应输出轨迹分析，但需要明确关联能力；未验证的 S0/HDMI 配对不用于输入输出同帧分析。历史或辅助有损录像不得作为逐像素/正式 MTF 证据。检测失败帧、遗漏帧均纳入覆盖率，不得从峰值统计中无声消失。

### 10.3 稳定性测试采样负载

- 硬件按每帧记录关键时间与错误，PC批量获取；遥测量超过UART预算时使用聚合/分块和完整性检查。
- 长稳保持 S0/结果各 30FPS 接收与统计，但不要求全部写盘。正式 S1＋结果快照每60s一组，并在异常前后尽可能保留证据；1Hz 快照仅作通过带宽验证的短时工况。
- 连续保存 S0 RAW8＋RGB888 结果各30FPS约14.93GB/分钟，2h约1.79TB，不含元数据；接收性能与持续写盘能力分开测试。
- 1080p RGB888每秒1组双快照，2h约89.6GB，仅含两张原始图；8h约358GB，不含参考图、掩码和录像。
- 每60s一组，2h约1.49GB双图载荷；报告中记录实际抽样频率和遗漏次数。
- 长稳前检查磁盘预算、写盘速度和队列容量，不能让存储满后仍显示测试正常。
- 精度快照开启时重新检查实时帧率；单独保存诊断关闭和开启的性能数据。

### 10.4 故障用例的执行约束

不通过超额供电、碰撞机械限位或破坏性操作制造故障。通信故障可用测试开关暂停报文、注入错误或模拟失锁实现。每项测试定义开始、故障保持、恢复动作和最长等待；恢复失败停止该用例并保留现场状态。

### 11.1 执行步骤

1. 建立run_id，读取位流、相机、协议与能力；设备重启则建立新的stream_epoch。
2. 加载真实标定及ROI，核对像素格式、图像尺寸、插值、增强阶段和参考坐标系。
3. 先记录基准姿态，再设置工况。灯光/运动请求使用事件号，避免把前一工况回应误配。
4. 等待参数APPLIED；静态姿态用实际角度误差、速度和持续时间判断稳定，光照用实测值判断；不只固定等待若干秒。
5. 超时保留实际状态并记录失败；不把未到位工况当作目标工况采样。
6. 获取规定数量的样本，检查同帧、参数、长度、校验、有效域及姿态年龄。
7. 计算参考和指标；检测失败记录原因，不生成合格数值。
8. 写入不可混淆的证据目录，计算文件哈希，确认写盘成功后释放快照。
9. 汇总该工况全部重复结果，包含最差结果和无效次数。
10. 下一工况继续；用户按停止时停止新运动与新采样，完成安全释放，保存部分报告。

## 13. 现场演示与上位机操作

### 13.1 演示画面与来源

| 模式 | PC 左侧 | PC 右侧 | 证明范围 |
| --- | --- | --- | --- |
| 连续视频 | S0 RAW8 经 PC 基础可视化 | HDMI 返回的完整 FPGA 结果 | 两路均保持1080P；仅关联验证通过后称为同帧实时对比 |
| 几何精度快照 | FPGA S1 原图 | 同源 FPGA S2/S3 及独立软件参考 | 原分辨率像素、几何与 MTF 证据 |
| 姿态/增强专项 | 冻结工况下选定的基线快照或连续观测 | 对应条件下的补偿/增强结果 | 不声称两快照槽同时提供S1、S2、S3；不同帧/重复工况明确标注 |

PC 只提供可视化与测评，FPGA 输出保持一幅完整结果，不以板上缩小拼接图作为正式数据。界面明确 S0 与 S1 的区别；HDMI 帧身份未验证时标“未关联”，不能用固定延迟补齐后宣称同帧。输入/处理fps、HDMI Hz、网络/采集接收fps、照度、IMU状态和有效区域分开标注。MTF 与像素误差使用原分辨率快照，界面缩放只用于观察。

### 13.2 五分钟流程

| 时间 | 操作 | 上位机与证据 |
| --- | --- | --- |
| 0:00～0:30 | 展示 OV5640→DVP→FPGA，以及网口原图和 HDMI 结果两条线 | 显示实际输入模式、无压缩格式、标定来源和当前生效参数版本 |
| 0:30～1:15 | 正常光照切换去畸变，放大边缘 | 显示同帧快照和明确标注的测量结果，不冒充实时全帧分析 |
| 1:15～2:15 | 滚转及已验证的俯仰/偏航，改变灯光 | 记录实际姿态、照度、参数生效与降级情况 |
| 2:15～3:15 | 评委随机换卡、按板载键切换旁路/矫正/旋转 | 真实标定保持不变，显示真实运算响应和有效范围 |
| 3:15～4:15 | 断开 PC 网口、控制串口和采集支路 | 相机/FPGA/显示器独立供电、参数已加载；直连显示器继续实时响应板载键和图卡 |
| 4:15～5:00 | 展示功率仪、板内诊断与本版本报告 | 报告有效帧数、能效边界、已测指标及未测范围；重新连接后明确新关联状态 |

断开 PC 前保证独立显示链路不依赖 PC 供电、软件或 EDID。网络断连只能停止导出，不能停止 FPGA 主处理。灯光/云台设备独立供电与控制方式也应核验；MCU 型号仍由后续选型确定，不为演示临时假定型号。

断电后画面消失只说明 FPGA 位于链路中，不能单独证明进行了运算。进一步展示实际 RTL 对应的源坐标、邻域像素、插值权重/结果、参数版本和完整帧完成事件，并与同帧软件参考比较；记录调试逻辑是否在能效测试位流中启用。正式结果图不嵌入覆盖像素的文字，状态在 PC 窗口或板载指示显示。

演示前确认图卡、参数、位流和报告对应同一硬件版本；准备一键恢复已验证模式。现场录像与历史报告标清时间，PC 断流后不得自动用软件矫正顶替板端结果。

交付检查：

- [ ] S0 RAW8 与完整 RGB888 结果各30FPS未压缩接收，像素保持与包/帧统计真实。
- [ ] S0 可视化与 FPGA S1 分开标注；正式同帧 S1/结果、参数实体与有效域齐全。
- [ ] HDMI source_frame_id 关联经丢帧/断连恢复验证；未验证时维持 null/unverified，不输出同帧成绩。
- [ ] 增强位置和参考流程一致，实际LUT可追溯。
- [ ] 标定基于真实相机，验证图卡与标定图分开。
- [ ] 角度、曝光、光照和时间同步条件已冻结。
- [ ] 图像精度、姿态真值、实时性能分别有证据。
- [ ] 快照/重传过载、PC断连不阻塞实时链路，网络、采集和FPGA丢帧分开。
- [ ] 裸RAW/RGB证据、Bayer/stride/格式和校验齐全；PNG仅作派生预览。
- [ ] 功耗测量与有效帧计数窗口一致，板级与整机边界分开。
- [ ] PC断开后可独立实时处理、板载操作与显示，板内计算证据可核验。
- [ ] 全部必需用例有明确结果；无效、未测和失败完整保留。
- [ ] 位流、配置、软件、报告哈希一致，PDS报告来自该版本。
- [ ] 至少2h正式长稳完成；8h若未完成应如实标注。
