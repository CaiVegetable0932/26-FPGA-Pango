# MCU 对接现有 FPGA 串口的修改方案

日期：2026-10-07。性质：待实施的接口与固件修改方案，不是已完成的 MCU/FPGA 联调记录。

历史方案存档：2026-10-11 的实际 MCU 接口以 [五轴交接文档](MCU五轴控制与FPGA通信开发交接文档.md) 和 [MCU_POSE_V2接口补充](MCU_POSE_V2接口实现补充.md) 为准。本文保留原方案及迁移前路径供追溯。

## 1. 保留什么，不改什么

以 `fpga/rtl/control/mcu_protocol.v` 的实际实现、[FPGA–MCU V1](FPGA_MCU通信协议V1.md)、[几何参数接口](FPGA灰度鱼眼矫正参数接口.md)为兼容性基线。**保留 FPGA 现有帧格式、命令、长度、能力位、CRC、会话隔离、帧边界生效规则；本方案不修改 FPGA RTL、引脚或位流。**

现有 MCU 两个工程已合入主线：

| 工程 | 当前职责 | 必须保留的行为 |
| --- | --- | --- |
| `mcu/stm32/`，STM32F407ZGT6 | D36A 三轴机构，USART3 文本控制 | `wake/state/measure/set/go/out/stop`，脉冲/配对同步、软件行程、停止与异常恢复；上电不自动运动 |
| `mcu/yuntai/`，STM32F103C8T6 | 二维总线舵机，USART1 接 PC、USART3 接舵机 | `ready/go/get`，实际位置反馈，270°刻度与已测中心 raw，±60°范围；不擅自写舵机 EEPROM |

合并来源为 `origin/codex/mcu-test-system` 的 `9b82940c`。MCU 工程当前的 ASCII 命令不是 FPGA 二进制协议，不得将其直接发往 FPGA。两侧存在不同的命令 `go`，后续 host 必须按设备身份区分。

## 2. 必须按现状处理的差异

1. FPGA 当前 `0x10` 只包含**一条角度和一条实测照度**，没有 Roll/Pitch 两轴、颜色 ID、XYZ 字段。只改 MCU，不能让当前 FPGA 接收尚不存在的字段。
2. 云台实际代码的轴名为 **pitch、yaw**，旧测试状态草案写的是 Roll/Pitch。必须核验实际装配轴向后冻结对应关系；不能仅改变量名就宣称 yaw 是 roll。
3. 龙门架 `state` 返回 **0～100 归一化位置**，不是 mm/μm。位置来自累计 STEP，不能冒充独立位置传感器反馈。第三轴行程尚未实测，其临时 2 圈分母仅用于查询，不是已标定行程。
4. 当前 MCU 工程没有三色灯光驱动/应用确认模块。颜色 ID 不等于实测照度，不能把 1/2/3 填进 `lux_milli`，也不能把设定值标成测量值。
5. 当前 FPGA 顶层只有一组 `uart_rx/uart_tx`，同时承担启动、诊断和矫正控制。板载 CP2102 与 MCU TX **不能直接并接**。新增独立 UART 或硬件仲裁属于下一轮 FPGA/接线工作，需单独实现验证。
6. 现有能力 `0x80` 已用于几何参数，`0x100` 用于显示/标记。旧 72 字节草案将 bit7 用于 TEST_STATE，与当前实现冲突，**不能照旧启用**。

## 3. 第一阶段：完全兼容当前 FPGA V1

### 3.1 线路格式

115200 bit/s、8N1、无流控；仅使用经过板卡和 MCU 手册核对的 TTL 电平、交叉 TX/RX 和共地，不接 RS-232 电平。独立供电，不将电源脚并接。具体 UART、引脚和扩展接口在实施前通过现有 `.ioc`、板卡引脚和占用表确认，不在此猜定。

```text
55 AA | version=01:u8 | cmd:u8 | seq:u16 | length:u16 |
payload[length] | CRC16:u16
```

所有多字节整数小端。CRC-16/CCITT-FALSE：poly=0x1021，init=0xFFFF，不反射，xorout=0；覆盖 version 至 payload，不含帧头和 CRC 自身。`123456789` 校验值为 `0x29B1`。本端请求最多 32 字节、响应固定 32 字节；协议总上限 1024 不能误当成本端实际接收能力。

### 3.2 保留的命令

| 命令 | 请求 payload 长度 | MCU 行为 |
| --- | ---: | --- |
| `0x01` 能力查询 | 0 | 读当前 epoch、会话、能力和本端上限；epoch 未就绪也允许查询 |
| `0x02` 建立会话 | 12 | 非零 epoch:u64 + session:u32；同 epoch 内 session 单调增加、不回绕 |
| `0x03/04` 状态/计数 | 12 | 使用当前 epoch/session；心跳不使用会停止机构的 `wake` |
| `0x05～09` 可选诊断 | 按现有定义 | 能力允许后只读，不改变视频或机构 |
| `0x10` 环境事件 | 32 | 按下表提交，原样幂等重试 |
| `0x30～34` 几何参数/回读 | 按几何接口 | 保留给当前 host 参数控制，不由遥测任务擅自写入 |
| `0x35` 显示/标记 | 24 | 保留模式、开关和直径语义；不得重启视频 |

`0x10` 的固定载荷：

| 字节偏移 | 字段 | 编码及使用要求 |
| ---: | --- | --- |
| 0 | epoch | u64，从 FPGA 查询，不使用 MCU 自制常量 |
| 8 | session_id | u32，当前已建立的非零会话 |
| 12 | event_seq | u32，非零递增，不回绕 |
| 16 | mcu_time_us | u32，设备微秒时间；约 71.58 分钟回绕，不能冒充曝光时间 |
| 20 | lux_milli | u32，毫勒克斯；没有真实传感器时有效位清零 |
| 24 | angle_mdeg | i32，有符号毫度；选定轴、正方向与零位配置冻结后使用实际反馈 |
| 28 | measurement_valid | bit0=实测照度有效，bit1=实际角度有效，其余 0 |
| 29～31 | reserved | 必须全 0 |

角度兼容配置应包含 `axis_id`、`zero_raw`、符号、编码器刻度、配置版本。两只舵机不同时塞进一个角度字段；未决定物理轴对应关系时，角度 valid=0。其他未被 FPGA V1 容纳的字段先保留 MCU/host 状态记录，不能标成 FPGA 已接收。

### 3.3 会话与链路仲裁

状态机：`WAIT_LINK → GET_CAPS → OPEN_SESSION → RUN → RECOVER`。FPGA 必须先由现有启动流程取得有效 boot epoch；MCU 不抢先发送启动配置 `0x71`，不重置板卡、不关闭视频。

同 epoch 中使用查询到的 session+1 建立新会话，达到上限明确报错，不回绕。**只有一个会话管理者和串口事务队列**：若 host 与 MCU 独立提升 session，会互相使对方配置请求失效。实施独立 MCU UART 前，按接线选择单一占用者进行受控兼容联调；可由 host 代理测一次协议，但不得把代理结果称为“MCU 直连 FPGA 已验收”。

每路只保留一个未确认请求；建议初始 20 Hz、响应等待 100 ms、有限重试并记录计数。外层 seq:u16 只关联回复；业务去重靠 `(epoch, session, event_seq)`。重试保持原始内容和时间戳，同号不同内容报冲突。ACK `0x80`/NACK `0x81` 的 32 字节公共前缀与错误码完全沿用 V1；ACK 不是到位、曝光同步或矫正已应用的证明。

FPGA 字节间恢复超时为 20 ms。超长/停止位错误后等足空闲时间再握手；UART 过载不得无限发送。FPGA 回复 FIFO 有限（8 项），不能依赖队列容量代替限流。CRC、错误、掉线不触发运动；遥测故障不阻塞脉冲调度和急停。

## 4. 第二阶段：六项完整回传，仍保留全部旧协议

六项要求即：角度、三色状态、XYZ 同时分别到 FPGA 和 PC。沿用[双 UART 测试状态草案](FPGA_MCU_PC双UART测试状态协议草案.md)的同一采样、72 字节 TestState 和独立 ACK/队列设计，**这是待协同实现的增量，不是当前位流支持的功能**。

- `0x11` 作为新增命令，保持 `0x10` 的 32 字节定义不变，不借用其 reserved，也不把 XYZ/颜色塞入照度/角度。
- 提议能力 bit9=`0x200` 表示 TEST_STATE_72（正式实现前冻结）；保留 `0x80` 几何、`0x100` 显示。FPGA 报本端上限至少 72 且具备该新能力后，MCU 才发送 `0x11`；旧位流只使用第一阶段。
- 两端发送同一份冻结快照，`mcu_boot_id + sample_seq` 一致，链路 seq、ACK、重试独立；PC-only 未就绪状态不能发给 FPGA，也不能与视频强行配对。
- MCU 先明确两物理轴和草案 Roll/Pitch 的映射。若确为 pitch/yaw，应在新协议冻结前修订字段定义并版本化；不能默默将 yaw 当 roll。
- XYZ 先保存脉冲、归一化位置及来源；测出丝杆/皮带传动比、三轴真实行程和物理原点后，才发布 μm 坐标和非零 coordinate_version。复位、失步、急停或未知零点立即撤销有效性。
- 三色 ID 对应版本化灯路/配方；只在驱动确认实际应用且稳定后有效，切换期间无效。预设名、灯路、GPIO/PWM、电气联锁及稳定时间待实物确认，不假定已安装传感器。
- FPGA 增加独立 MCU 接收、72 字节解析、一致快照 CDC 和源帧上下文；host 增加独立 MCU 接收与过期显示。现有启动/矫正 UART 继续由 host 管理，不共享无仲裁物理 TX。
- 若双 MCU 分别控制云台和龙门架，应明确谁是状态汇聚者、两 MCU 间链路与采样年龄。不是把两个 MCU TX 接到同一个 FPGA RX。无汇聚链路时不能称为同一原子快照。

单凭 XYZ 不能唯一决定图像变换；位置补偿还需世界坐标系、测试平面/深度与外参。当前角度记录也不是曝光同步姿态。上述字段先做真实状态和来源记录，后续按帧选择/插值与几何模型另行验证。

## 5. MCU 分块修改落点

新增代码均在 `mcu/`，并按功能块添加用途/意图注释；CubeMX 生成区不写业务逻辑，保留 USER CODE 边界。不要重复编辑厂商参考源码。

| 建议块 | 建议位置 | 职责 |
| --- | --- | --- |
| V1 编解码 | `mcu/firmware/common/fpga_v1_codec.c/.h` | 显式 LE 装包/解包、CRC、准确长度/保留位；不用带 padding 的 struct 内存当线路格式 |
| UART 链路任务 | `mcu/firmware/common/fpga_link.c/.h` | 能力、会话、有限重试、响应关联和错误恢复，非阻塞队列 |
| 同一状态采样 | `mcu/firmware/common/test_state.c/.h` | 实际反馈、有效性、字段年龄和身份；与两路发送解耦 |
| 云台反馈适配 | `mcu/yuntai/Core/Src/` | 复用实际舵机位置读取；不改变 raw 中心/刻度/软限位，缓存两轴新鲜度 |
| 龙门架适配 | `mcu/stm32/Core/Src/` | 原子读取各轴当前脉冲和标定配置，区分目标/估计/实测 |
| 光照驱动 | `mcu/firmware/lighting/` | 预设应用确认、稳定/故障、版本；接线冻结后才启用输出 |
| UART/设备配置 | 各工程 `.ioc`、CMake 和 `mcu/config/` | 核对不占用舵机总线、STEP 定时器、SWD/USB；参数单独保存 |
| 离线测试 | `mcu/tests/` 和各工程 `tests/` | V1 对照向量、错误恢复、状态来源、双路一致性及旧运动回归 |

这些路径是实施建议，本次没有创建上述固件块。构建公共模块时显式加入工程 CMake/包含路径，不能只复制文件后宣称参与编译。

## 6. 验收顺序

1. **协议兼容**：CRC `0x29B1`；0x01/02/03/04/10 的精确字节；负角二补码；有效位/保留位；错误长度/CRC/版本；重复、冲突、旧 epoch/session、断帧、限流、重启恢复。
2. **不回退机构**：重跑现有 D36A、go/out/wake、舵机 ready/go/get、UART console 五组回归；编译 Debug/Release；没有接设备前不发送运动/灯光命令。
3. **单链路板测**：电平/引脚核对，独占 UART；实测握手、ACK 往返、20 Hz 遥测、错误计数和掉线恢复。不用软件回环替代物理验收。
4. **完整六项**：仅在新 capability 和三个端的 0x11 实现通过后启用；两 UART 同采样身份、单路断开不阻塞另一侧，未知字段 UI 显示无效。
5. **精度及视频关联**：独立角度/位置量具与灯光测量，标定坐标轴与单位；曝光时间与源帧 ID 关联后才能做同帧姿态测评。HDMI 身份仍为 null/unverified 时不得按到达顺序配对。

实施优先级：先冻结轴向/坐标与接线 → MCU V1 兼容模块 → 独立链路/会话仲裁 → 72 字节协同扩展 → 三色驱动与位置标定 → 视频帧关联。当前保留 FPGA 位流可用性，不为完整状态扩展牺牲现有视频链路。
