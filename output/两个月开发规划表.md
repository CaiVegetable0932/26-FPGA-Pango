# PG2L100H 1080p 畸变矫正项目：两个月开发规划表

版本：V2.0 · 日期：2026-09-05  
关联方案：[详细设计方案](./PG2L100H_1080p畸变矫正详细设计方案.md)

## 1. 时间与人员假设

按2026-09-05启动，至2026-11-04完成两个日历月：8个项目周（每周7个自然日）＋5天交付缓冲。实际启动日期不同可整体平移，具体休息日由团队安排。日期不是自动提醒或计划任务。

规划按3类工作角色安排，可由2～3人分工或一人兼任；单人执行时优先保证30fps主线，60fps和透视扩展不应挤占测试时间。

| 角色 | 主要职责 | 每周固定产出 |
|---|---|---|
| A：硬件与视频链路 | 板卡、DVP/HDMI、RAW ISP、DDR、CDC/时序 | 可运行工程、接口/带宽测量、时序报告 |
| B：算法与RTL | 逆映射、定点、缓存、插值、吞吐优化 | 模块仿真、综合结果、逐帧处理记录 |
| C：上位机与测试 | 标定、浮点/定点参考、UART、IMU分析、验收 | 真实数据集、误差图、回归和文档 |

共同优先级：**指定相机真实1080p30 → 完整矫正1080p30 → 动态与画质 → 稳定交付 → 1080p60扩展**。VGA/720p只用于快速联调，不算通过主指标。

## 3. 第一周每日执行安排

| 时间 | 任务 | 必须留存的证据 |
|---|---|---|
| D1～D2 | 板卡版本/丝印、DDR与HDMI冲突核对；安装匹配PDS；下载官方例程；逐脚检查模组 | 实物配置记录、手册版本、成功下载记录、原始约束归档 |
| D2～D3 | DDR基本读写、HDMI输出彩条；摄像头ID/SCCB读回；低分辨率快速检查连接 | DDR错误计数、显示照片、寄存器读回；低分辨率仅为中间结果 |
| D3～D5 | 配置RAW8/可用RAW10；检查PCLK、有效尺寸、帧间隔、Bayer相位 | 完整原始帧、每行/帧计数、连续帧日志、RAW配置来源 |
| D5～D6 | 固定曝光与自动曝光分别测30fps；运行至少10分钟；评估未来HDMI输入 | 帧周期分布、AEC是否降帧、接口锁定情况 |
| D7 | G1评审：输入是否成立、未决问题、责任人与截止时间 | 一页输入结论，不能写“基本能亮屏所以通过” |

如果第7天仍没有RAW1080p30证据，算法/DDR工作可以继续，但输入风险必须明确升级处理；第14天仍不成立，不再按“最终指定输入已解决”排期。用户允许后期更换相机不等于组委会已豁免指定模组，替代输入的合规性单独核对。

## 4. 关键依赖与失败时的处理

| 依赖 | 阻塞什么 | 失败时继续做什么 | 不允许的替代说法 |
|---|---|---|---|
| RAW1080p30实际输入 | 指定相机最终验收 | 用人工帧验证核，取得板厂支持；必要时准备允许的HDMI相机 | “显示器是1080p所以输入达标” |
| RAW ISP及Bayer排列正确 | 彩色标定/图像质量 | 用RAW转储定位、冻结色彩参数 | “有画面就说明RAW正确” |
| DDR读写完整性/所有权 | 全部视频结果可信度 | 先关算法，用坐标图验证地址/帧号 | “偶尔撕裂可以现场重启” |
| cache混合读写吞吐 | 任意角度30/60fps | 真实轨迹调块形状、组索引、并发事务 | “峰值DDR带宽大于像素率就足够” |
| 30fps冻结版 | 60fps扩展的前提 | 保持30fps主分支、限制新增工作 | 为尝试60fps破坏唯一可演示版本 |
| 真正60fps相机/源 | 端到端60fps验收 | 先发布处理核回放性能，明确边界 | 把30fps重复帧计为60fps |

## 5. 功能分级与工期保护

| 优先级 | 功能 | 工期紧张时的决定 |
|---|---|---|
| P0 必达 | 真1080p30输入、彩色链、真实标定、径向/切向、双线性、完整帧管理、时序/CDC | 不删除，不降低成720p交付 |
| P1 主线 | 连续面内角度、按帧参数、Gamma、IMU面内演示、性能/质量报告 | 先保留上位机角度控制，复杂姿态融合可后移，但必须明确完成范围 |
| P2 扩展 | 有限透视补偿、1080p60、低延迟优化、更高质量ISP | 未通过单独列为研究项，不能占用最后一周基础回归 |
| P3 后续 | 双目同步/深度、复杂CLAHE、多路显示、主板自研 | 不进入本次两个月关键路径 |

“P1可先用上位机”不意味着图像转交PC处理：逐像素几何计算、采样和视频流仍在FPGA。IMU与透视功能若未完成，应在最终报告中明确说明。

## 6. 每周固定检查表

每周保留一次可运行里程碑；每次改变位宽、cache、DDR或时钟后运行与该变化有关的回归，避免仅重看显示器画面。

- [ ] 完整尺寸、输入fps、处理fps、显示Hz分别记录。
- [ ] frame_id一一对应；无溢出、欠载、越界写或静默丢帧。
- [ ] 参数版本在一帧内唯一；读写槽位所有权正确。
- [ ] 恒等、边界、跨图块、正负角度测试通过。
- [ ] PDS实际资源、WNS/TNS及未约束路径可追溯。
- [ ] cache填充字节/输出像素、最坏帧时间有记录。
- [ ] 标定图、相机模式、ISP版本和系数保持一致。
- [ ] 稳定版本可恢复，未验证功能有明确标签。

## 8. 演示脚本建议

1. 启动后显示实际输入分辨率和fps，确认完整新帧连续变化。
2. 展示原图网格，再开启真实参数矫正。
3. 对同一帧做前后对比，说明有效视野和裁剪。
4. 连续改变面内角度，停在45°/90°观察直线与帧率。
5. IMU零位复位，缓慢转动相机，显示补偿与误差。
6. 改变照明，切换Gamma前后，显示曝光与统计。
7. 读取资源、处理帧率和延迟证据；如60fps已通过，再切换真实60fps输入及匹配标定。
8. 演示回到稳定模式与重启恢复。

本表是研发规划，不代表硬件与指标已实测通过。实际进度以各G检查点的证据为准。
