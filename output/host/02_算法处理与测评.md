## 1. 职责和验证层次

上位机负责S0 RAW8千兆网接收与基础可视化、FPGA结果HDMI采集、真实标定、参考调用、测评和报告。链路以[跨端回传方案](../OV5640_RAW8千兆网与HDMI双路回传方案.md)为准。PC不转发相机主视频，不提供实时软件几何fallback。比赛主视频的坐标映射与插值由 FPGA 完成；MCU 负责施加光照和运动条件。上位机生成参考画面时，界面必须标明“软件参考”，不能替代 FPGA 输出。

FPGA 的 RAW/ISP、浮点坐标、定点运算与位精确采样参考模型统一维护在 `fpga/model/`，相关 RTL 仿真证据归 `fpga/sim/`。上位机只建立版本固定的适配调用与重放编排，不在 `host/src/` 复制一套可独立漂移的硬件模型。

| 层次 | 输入与比较对象 | 上位机输出 | 能证明什么 |
| --- | --- | --- | --- |
| A：RAW/ISP | 同源 S0 RAW、ISP 配置，与 S1 RGB | 格式/颜色诊断、参考 ISP 差异 | Bayer 排列、位宽、黑电平和 ISP 实现是否一致 |
| B：数值模型 | 同一真实参数下的浮点坐标与定点坐标 | 全域坐标误差及最大误差位置 | 定点位宽、归一化、除法和累积误差是否满足目标 |
| C：RTL/板端 | 位精确参考输出与 RTL 仿真或 FPGA 快照 | 坐标/像素差异、边界和有效位差异 | 硬件是否按已冻结的数值规则工作 |
| D：物理系统 | 独立图卡、参考姿态、实际角度和光照 | 直线度、姿态、MTF、增强与性能结论 | 真实镜头、IMU、同步及整机的实际效果 |

A～C 层通过不能代替 D 层：同一份错误 IMU 数据可以使软件和硬件完全一致。反过来，图像“看起来变直”也不能证明定点溢出、极端坐标和全部边界均正确。

输入对象应只读，分析结果创建新对象。分析模块不得自行改变设备配置、重置参考姿态或回写原图；需要重新采集时向测试调度模块返回明确请求。

## 3. 单个样本的处理顺序

1. **识别来源。**区分S0原始字节、PC基础ISP预览、板端S1、HDMI结果、严格快照、仿真和mock，先确定允许计算的指标。
2. **校验传输。**验证分块校验、字节数、图像布局和缺失块，拒绝重复偏移携带冲突数据。
3. **核对同帧。**正式成对评价需相同运行、流代次及源帧号；重启前后不能配对。普通HDMI帧source_frame_id=null、pairing_status=unverified，S0帧号或UART事件不能自动赋予其同帧身份。
4. **恢复实际状态。**取得该帧已经生效的参数、姿态、LUT 及版本实体，不能用当前界面设置替代历史帧状态。
5. **检查测量前提。**核对相机模式、输入输出观测点、图像尺度、ROI、曝光状态、同步质量和功能组合。
6. **生成参考。**调用匹配版本的模型；若不能复现某个功能组合，该组合的参考一致性检测保持未实现。
7. **检查覆盖。**先检查参考有效域、硬件失效差异、ROI 完整性，再计算配对有效点上的数值指标。
8. **计算专项指标。**静态图像、动态序列、图卡和时间数据按各自条件测量，不给所有图片强行套同一组指标。
9. **保存证据。**写入原始输入关联、参考结果、指标、无效原因及哈希；界面仅从已确定的结果对象读取数值。
10. **执行判定。**使用本次运行开始前冻结的阈值配置，汇总全部计划样本，保留失败与未覆盖范围。

模型运行失败、缺元数据、ROI 检测失败时，相关数值为 `null`。无法测量并不等于误差为零；有完整证据证明硬件输出错误时应判失败，不能借“无效”规避失败。

## 4. 真实标定与参数管理

### 4.1 输入准备

固定相机、镜头焦点、有效分辨率、裁剪、镜像、RAW 位宽、Bayer 排列及基础 ISP。图卡编号、实际格长、单位和平整度随数据记录。采集约 25～40 张清晰且覆盖中心、四角、不同距离和倾角的图像，另留独立验证集。

正式几何标定默认使用板端S1：基础ISP后、几何前RGB图像，通过独立快照导出。S0实时回传用于原始数据预览及ISP诊断；PC重建图要用于同等标定或参考，需先验证与S1的几何布局及所需数值规则等价，记录范围。共享参数不代表去马赛克、边界和舍入一致。OSD、分屏、缩放或未知色彩处理预览不作为默认标定输入。

### 4.2 处理与输出

- 检测角点/圆心并显示叠加结果，检查排列方向、数量和覆盖；保留检测失败图及原因。
- 按硬件支持的二阶径向与切向模型拟合 `k1、k2、p1、p2`，固定 `k3=0`，不启用未实现的高阶项。
- 可使用 OpenCV 的标定接口；输出相机内参、畸变系数、逐图重投影误差和空间覆盖图。不得先依赖高阶项拟合，再删系数沿用旧误差。[OpenCV 标定模型与标志](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)
- 用独立图像和网格测量验证，不能只提交拟合集的总平均重投影误差。
- 标定参数转成板端编码时调用 FPGA 维护的参数编码/数值定义，不在 PC 通信层硬编码另一份位宽规则。
- PC解析YAML/JSON并封装真实K/D；FPGA独立解包、CRC/范围/模式校验，写影子参数并按帧commit后用于逆映射。此流程与SCCB传感器配置分别验收。
- 回读实际寄存器编码值、版本及生效帧号，不仅回显收到的数据；保留原始浮点与定点值。PC文件解析和FPGA协议解析分别表述，不声称FPGA已实现直接读取YAML。

更换镜头、焦点、分辨率、裁剪或镜像方式后，重新检查模式适配性。只有验证属于纯尺度变换时才换算内参；相机转动本身不允许随意改写真实畸变系数。

## 5. 软件参考的处理方案

### 5.0 S0基础预览与S1边界

S0网络数据保持1920×1080 RAW8，PC按Bayer相位、黑电平、增益及记录的基础ISP做彩色显示，不执行畸变矫正、旋转重采样或几何fallback。需要位精确ISP对照时调用fpga/model冻结版本。原始数据存未压缩.raw，板端彩色证据存.rgb并配metadata；PNG只用于派生预览。

ISP专项比较同源S0与板端S1及实际配置，检查Bayer、位宽、裁剪相位和边界。网络S0不能与身份未经验证的HDMI结果直接组成正式样本。严格几何参考仍用板端S1＋选定S2/S3及实际LUT/姿态/参数，不能直接以原图与矫正图PSNR评价矫正质量。

### 5.1 模型调用契约

`reference_adapter` 负责发现项目内模型、检查接口和版本、构造输入、读取输出；模型发布应提供明确版本、数值格式及支持能力。上位机发布包使用从 `fpga/model/` 构建的固定模型包或明确的项目内依赖，记录来源和哈希，不依赖被忽略的 `reference/`。

每次重放至少绑定输入哈希、模型版本、标定/输出视图、姿态、插值与边界规则、增强阶段和 LUT。缓存命中必须包含这些因素；仅按帧号或标定文件名缓存会把旧结果错误复用。

模型调用失败应保留日志。禁止自动换成另一种插值、忽略畸变项或关闭增强后仍把结果标为原用例的参考。

### 5.2 联合逆映射与坐标约定

像素中心采用整数坐标：左上像素中心为 `(0,0)`，右下为 `(W-1,H-1)`，软件和硬件均不额外添加 0.5。ROI 使用原尺度坐标并按公共数据约定解释右下边界。

对输出像素，从 `K_out` 恢复参考相机射线，经已冻结方向的参考/当前相机旋转关系变换到当前相机，再进行透视归一化、二阶径向及切向畸变、源相机内参投影，得到源坐标。姿态坐标系、四元数顺序和有效条件由公共契约唯一规定。

按一张联合映射表完成一次重采样。不能软件先去畸变插值一次、再旋转插值一次，而硬件只插值一次，却直接把差异归因于硬件。逆映射与边界处理见 [OpenCV 几何变换文档](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html)。

`cv.remap` 可用于工程参考与可视化，其插值表与定点规则不必然与 FPGA 相同；该版本文档明确不支持 `INTER_LINEAR_EXACT`。逐位一致以 `fpga/model/` 的位精确实现为准，不能把 `INTER_LINEAR` 名称相同当作完全相同的计算规则。

### 5.3 Gamma 与自适应重放

| 模式 | 处理顺序 | 上位机必须取得的内容 |
| --- | --- | --- |
| `disabled` | 原始源邻域 → 双线性插值 | 明确增强关闭；用于几何专项比较 |
| `pre_resample` | 源邻域按实际 LUT 增强 → 双线性插值 | 同一源帧锁定的 LUT 实体、阶段与版本 |
| `post_resample` | 双线性插值 → 实际 LUT 增强 | 对应输出处理使用的 LUT 实体、阶段与版本 |

一般情况下，先查表再插值与先插值再查表的结果不同，不能互换。只保存“Gamma=某值”不足以重现 LUT 的量化、舍入及逐通道实现，正式重放保存实际 LUT。

单帧重放实际 LUT 只能检查应用过程；验证自适应策略本身，还需连续统计、统计来源帧号、LUT 生效帧号、初始状态和时间平滑规则。缺少历史时将策略重放标为未覆盖，不擅自从该张图片重新估计一张 LUT。

## 6. ROI、有效域与覆盖

正式测试前冻结 ROI 版本、图卡物理区域、最低线长/点数、中心和边缘覆盖要求，以及每种姿态允许的有效视场。裁剪后的指标同时附裁剪比例，避免以越来越小的中间区域证明全画面合格。

设参考有效域为 `Vref`，硬件有效域为 `Vhw`，配对域为 `Vpair = Vref ∩ Vhw`。上位机至少分别输出：

| 数量 | 定义 | 含义 |
| --- | --- | --- |
| 参考视场比例 | `count(Vref) / (W×H)` | 当前映射理论保留的输出面积 |
| 错误失效比例 | `count(Vref - Vhw) / count(Vref)` | 理论可计算但硬件漏算/错误作废的范围 |
| 错误有效数量 | `count(Vhw - Vref)` | 硬件声称有效而参考判断越域的点 |
| 配对覆盖率 | `count(Vpair) / count(Vref)` | 实际可做配对数值比较的比例 |
| 任务 ROI 覆盖 | 各冻结 ROI 的有效点、线段与角点覆盖 | 是否满足该指标的最低测量条件 |

先报告有效位差异，再在 `Vpair` 上算数值误差。硬件在参考有效域存在漏算时，不能只报告交集内很小的误差并宣称全域通过；应定位边界容差是否符合已冻结规则，否则判实现失败。

越出真实源视场的区域、透视分母无效和合法边界规则产生的无效区域，不按内部空洞混算。反之，不能在测试后随意扩大无效掩码隐藏断线或错误像素。硬件未提供有效位时，不从黑色像素猜测掩码，相关硬件覆盖结论保持未测。

## 7. 坐标误差与像素一致性

### 7.1 全域坐标评估

输入必须是实际坐标 RTL 导出的源坐标和有效位，或与版本对应的全域 RTL 仿真证据。普通 RGB 输出不能唯一反推出采样坐标。

优先通过板端独立诊断模式，冻结真实参数并按行导出整个输出域的有符号源坐标。替代路径为全域 RTL 仿真＋板端抽点一致性检查，报告明确全域证据来自仿真。离线导出允许背压，不能据此证明实时吞吐。

设浮点参考坐标为 `(ur,vr)`、被测坐标为 `(ut,vt)`，对每个参考有效点：

~~~text
e[i] = sqrt((ut[i]-ur[i])^2 + (vt[i]-vr[i])^2)
coordinate_RMS = sqrt(mean(e[i]^2))
coordinate_max = max(e[i])
~~~

单位为**源像素**。分别报告浮点对定点、定点对 RTL/板端、浮点对 RTL/板端；存储最大误差的输出位置、两组坐标、参数和数值格式。正式阈值覆盖完整参考有效域，抽点结果必须标为抽样结果。

调试图输出 `du`、`dv`、误差模长及无效位差异；绘图颜色范围固定并标明倍率，不能每张图自动拉伸后直接比较颜色深浅。

### 7.2 像素评估

使用同源帧、同尺度、同格式、同输出视图和同算法状态的 FPGA/参考结果。分别计算 RGB 各通道及明确规定的总指标，先提升到足够精度的有符号或浮点类型再作差，避免无符号溢出。

~~~text
MAE = mean(abs(I_fpga - I_ref))
MSE = mean((I_fpga - I_ref)^2)
PSNR = 10 * log10(P^2 / MSE)
~~~

`P` 是所声明量程的峰值，8 bit 全量程取 255。MSE 为零时数学结果为正无穷；严格 JSON 不写非法 Infinity 字面量，使用公共约定的数值状态表示。零有效样本是无效，不能记作无穷高 PSNR。

输出 MAE、最大像素差、PSNR、逐通道统计与差异图；SSIM 可作补充。几何变换会移动像素，原始图与校正图之间的 PSNR 不作为校正质量成绩。项目尚无统一像素 PSNR 合格线，不能临时发明一条官方门槛。

## 8. 直线度与姿态测量

### 8.1 直线度

输入为独立网格图卡的原尺度校正图，正常光照、固定曝光/焦点，关闭自适应增强。按冻结图卡编号和 ROI 提取同一条物理线的亚像素点，采用最小正交距离拟合直线。

~~~text
line: a*x + b*y + c = 0
d[i] = abs(a*x[i] + b*y[i] + c) / sqrt(a*a + b*b)
line_RMS = sqrt(mean(d[i]^2))
~~~

逐线输出 RMS、P95、最大距离、有效长度、点数、覆盖区域及剔除点。鲁棒拟合可用于定位，但剔除规则、剔除数量和原始点都要保存；不能将弯曲线切成短段或大量丢弃端点后宣称变直。

误差单位为**输出像素**，与坐标映射误差的源像素区分。直线拟合允许消除该线整体方向和位置，因而只能证明弯曲程度，不能代替姿态、角点位置和比例检测。

### 8.2 实际姿态与角点

在正式运行前一次性建立图卡参考方向/位置并冻结。使用不对称箭头或编号角点消除 90°/180°识别歧义。相机实际角度来自独立编码器或量具，记录其误差；云台指令角与被测 IMU 自报值仅作辅助。

- 滚转：计算输出图卡方向与冻结参考方向的角度差，按约定区间归一化，连续轨迹另做解缠用于绘图。
- 俯仰/偏航与平面视图：比较同一物理角点和预定输出位置，给出位置误差 RMS、P95、最大值及漏检率。
- 三维场景：存在平移和多景深时单独说明视差，不能把平面图卡的通过范围外推为任意场景的完整视图恢复。
- 动态：保存实际角度、速度/加速度、曝光、姿态年龄、输出残余角及角点轨迹，区分 RMS、绝对峰值和峰峰抖动。

禁止逐帧先对校正结果拟合旋转、平移或单应变换，再报告配准后的姿态误差；这会消掉待测错误。允许一次性坐标约定转换，但必须在测试前冻结并留档。

动态峰值必须有覆盖目标源帧率的连续证据。可使用经几何保真验证的连续采集图像或逐帧特征；离线分析可以，低频快照不能宣称全程峰值合格。只有抽样数据时写“采样观测最大值”，显示样本覆盖率和最大连续缺口。

## 9. SFR 与 MTF50

输入为中心、四角的原尺度斜边 ROI，需记录边缘方向、长度、输出局部尺度、曝光、ISP、增强和光度响应配置。几何专项关闭额外增强和锐化；开启增强后的系统结果另列。

处理应使用固定版本、经过验证的斜边分析实现：定位边缘 → 按亚像素距离形成 ESF → 按工具定义求 LSF → 加窗与频域分析 → 归一化得到 SFR → 提取 MTF50。OpenCV 可用于 ROI 和边缘预处理，不能把拉普拉斯方差或一个通用锐度函数当作 MTF50。

工具必须先用已知测试数据与独立可信工具交叉验证，记录相同 ROI、采样/窗函数、导数校正、光度线性化方式和允许差异；未验证的自编实现只能输出实验结果。

| 检查 | 要求 |
| --- | --- |
| 斜边有效性 | 满足工具角度、边长和对比要求；不得完全水平/垂直且忽略采样影响 |
| 饱和与噪声 | 记录两侧饱和、信噪和纹理；条件不足时无效 |
| 单位 | 主指标 cycles/pixel；附 cycles/picture-height 时注明图像高度 |
| 对照 | FPGA 与相同映射、相同采样尺度的软件参考比较，不能跨局部放大率直接比 |
| 输出 | ESF、LSF、SFR 原始曲线、MTF50、ROI 图、光晕/过冲和有效性 |

MTF 保持率定义为 `MTF50_FPGA / MTF50_reference`。参考无效、过低或曲线未能有效确定 50% 交点时，不输出有意义的通过比例。锐化可能抬高 MTF50 并引入光晕，所以保留完整曲线及过冲信息。[Imatest 测量一致性](https://www.imatest.com/docs/mtf-measurement-consistency/)

## 10. 光照增强和阶跃响应

先固定相机与曝光测试算法，再将自动曝光开启作为独立系统工况。记录实际照度、曝光、增益、AE 状态；不以灯光档位或 PWM 数值代替 lx，不把相机 AE 的作用全部计入 FPGA 增强。

| 指标 | 输入与方法 | 限制 |
| --- | --- | --- |
| 亮度分布 | 固定灰块 ROI 的均值、P5/P50/P95 | 固定亮度计算方式和量程，不称编码值为物理亮度 |
| 饱和/暗端比例 | 按预先冻结的上下阈值计数 | 8 bit 全量程可从 ≥250/≤5 起步，正式值须固定 |
| 暗部对比 | 对应灰块或文字/背景的均值差 | 区域必须对应同一场景，不随机挑更亮区域 |
| CNR | `abs(muA-muB)/sqrt(sigmaA²+sigmaB²)` | A/B 为固定均匀区域，明确空间/时间噪声口径 |
| 时间噪声 | 静止、固定曝光下同像素的跨帧波动 | 不用纹理的空间方差代替时间噪声 |
| 响应与振荡 | 实际光变事件＋逐帧 ROI 统计＋LUT 记录 | 必须明确起点、时间映射与观测覆盖 |

噪声分母为零或样本数不足时，CNR 标明未定义；饱和导致的“零噪声”不能解释为无限质量。灰阶、纹理、对比和噪声一起报告，单纯提亮不等于恢复新信息。

采用整机方案的初始收敛定义：以阶跃后预定末段连续 30 个源帧的灰块均值作为观测稳态值；首次进入稳态值 ±max(5%×稳态值, 2 个 8 bit 灰度级)，且连续 5 帧保持，记为收敛。正式测试前同时冻结末段时间窗口与波动判据；若末段持续波动，记录“不稳定”，不强行定义稳态。

响应起点使用光传感器或实际驱动事件，经已验证的时基关系关联到源帧；PC 发令和收包时间仅作辅助。源图全局均值不能替代增强后指定 ROI 的逐帧亮度。仅有 1Hz 快照时，只能报告该采样分辨率下的响应。

## 11. 帧率、延迟和长稳

### 11.1 分层计数

上位机分别展示真实输入、处理完成、首次显示不同结果、RAW发送、PC完整RAW接收、HDMI采集、显示刷新及PC预览/分析更新率。60Hz 显示同一结果两次，不能计作真实 60fps 处理。

板端输入、处理、显示、溢出/欠载等使用原子计数快照；PC 另记接收、解码、证据队列和检测遗漏。相机没有自身帧号时，只能证明 FPGA 输入边界之后的行为，不能断言没有相机内部丢帧。

### 11.2 时间端点

| 指标 | 端点 | 解释 |
| --- | --- | --- |
| 单帧处理时间 | `process_start_tick → result_ready_tick` | 不包含此前等待，不等于端到端延迟 |
| 输入至结果就绪 | `capture_first_tick → result_ready_tick` | 包含本方案采集、排队和处理等待 |
| 输入至首次输出 | `capture_first_tick → first_display_tick` | 必须关联同一源帧，且取得实际首次输出事件 |
| PC 接收/分析耗时 | PC 单调时钟的本地事件 | 包含采集卡、驱动、传输或计算，单列报告 |
| 光到屏延迟 | 真实光变至屏幕光变 | 使用外部测量；报告仪器、位置和触发条件 |

只有同一或已校准时基的端点才能相减。按 `(end_tick-start_tick)/tick_hz` 计算时检查流代次、回绕和计数器宽度；板端事件没到达时记缺测，不能填预计时刻。PC 时间不能直接减 FPGA tick。

按有效样本统计中位数、P95、最大值，同时附总数、缺失数、时间覆盖率和端点定义。存在超过预算的帧时保存对应上下文，不能只用平均值说明实时性能。

### 11.3 长稳证据

正式不少于 2 小时，冻结版本争取 8 小时；30 分钟只作快速回归。每帧关键计数/错误应连续覆盖，长稳完整图像对可降为每 60 秒一组并在异常附近加采，记录真实频率、漏采和队列容量。

分别测基础主路、RAW实时回传开启、RAW＋限流快照等负载；正式系统结论需覆盖两通道同时开启的主方案。记录最差访存角度、光照/运动、温度（若可读）及传输/写盘负载。预览队列可丢弃旧帧并计数；证据队列溢出、磁盘满或原始数据损坏时报告采集失败，不能继续显示全程正常。

### 11.4 能效测量与处理来源证明

测量以实际供电边界及同一窗口的能量E、时长T和完整有效处理帧N为准：平均功率E/T、处理fps=N/T、单帧能量E/N、能效N/E。N来自完成1920×1080有效输出的硬件计数，HDMI重复帧和PC刷新不计入；同时报告输入、遗漏、画质及不确定度，不靠少做工作改善成绩。

开发板直流入口测量称板级功耗，包含边界内FPGA、DDR、PHY及转换损耗；芯片电源轨功耗须另测，不从整板电流推算。PC、采集卡、显示器及其他供电入口明确纳入/排除，避免重复计数。旁路、完整30fps、实际通过的60fps分别测，旁路需停用矫正计算而不只是切显示；增量还含DDR访问变化，只称板级增量。

正式能效条件覆盖RAW实时发送和HDMI输出，注明快照与PC写盘状态。温度稳定后每工况可测5分钟重复3次，保存仪器原始曲线、共同窗口、板端计数、角度及版本；这是待执行计划。不同设备时基未经校准不能直接相减。

处理来源由组合证据支持：相机DVP直连FPGA；FPGA输出直连独立显示器；评委操作板上旁路/矫正/角度按键；参数装载后退出PC、断开控制与网络，独立供电下仍运行；ILA展示源坐标、邻域像素、权重及帧完成；板端同帧S1/结果对照冻结模型。断网期间RAW回传自然中断，不能计入连续传输通过。PC日志、位流哈希、低CPU或断电黑屏单独不足以证明算法执行，演示不宣称密码学防伪。调试与正式位流差别留档。

## 12. 验收用例和判定

以下为既有方案的**项目内部目标**，不是新增赛题官方评分线。具体范围、测量有效性和阈值配置须在正式运行前冻结。

| 用例 | 上位机必须给出的证据 | 判定要求 |
| --- | --- | --- |
| T00～T02 格式/参数/边界 | RAW包覆盖/布局、两通道身份、板端同帧快照、K/D寄存器回读及边缘诊断 | 拒绝坏数据，参数按指定帧生效；恒等图仅作工程检查 |
| T03～T05 几何/位宽/角度域 | 全域坐标证据、定点/RTL对照、掩码与分区直线 | 坐标 RMS≤0.05 源像素、max≤0.25；各规定完整线段 RMS≤0.5 输出像素 |
| T06 静态姿态 | 独立实际角度、不对称图卡、残余角/角点 | 静态滚转残余≤0.5°，仪器能力足以支撑目标 |
| T07 动态姿态 | 连续源帧覆盖、速度/加速度、残余曲线与缺口 | 实际速度≤30°/s及冻结条件下残余绝对峰值≤1°；缺口不能当零误差 |
| T08 清晰度 | 有效 SFR、各 ROI MTF50、同映射参考 | 指定有效 ROI 的 MTF50 保持率≥90%，附绝对值与光晕 |
| T09～T10 光照/组合 | 连续 ROI 曲线、光变事件、实际 LUT、完整工况矩阵 | 按冻结响应规则判定；尚未确认的响应硬阈值保持待定 |
| T11 长稳 | 主方案两通道持续开启，RAW完整帧/处理/HDMI分层计数、快照和异常 | 真实1080p30、正式≥2h；冻结版8h未完成须标明；GUI不能掩盖回传缺口 |
| T12～T13 故障/随机操作 | 所有失败、降级、恢复事件与对应帧 | 故障不可隐去，恢复后按新状态重新建立有效采样 |
| T14 60fps | 真实新输入、重新评估的数据口及独立几何/性能证据 | OV5640和千兆RAW8不沿用为完整60fps依据，重复30fps不算通过 |

坐标和直线度任一必要区域失败，不能靠全图平均或其他 ROI 的好成绩抵消。MTF、像素差异、姿态和光照分别判定，不压成一个没有解释的“综合分”。

每项测量区分 PASS、FAIL、INVALID、NOT_RUN、NOT_IMPLEMENTED；定义由公共文档维护。工况汇总包含计划、有效、失败、无效和未执行数量。只有规定范围内所有必需证据有效且满足门槛，才可声明该范围通过。

## 13. 分析模块自身的开发验证

上位机指标实现也需要验证，不能只验证 FPGA。以下属于 `host/tests/`；FPGA 参考模型的数值和 RTL 测试仍归 FPGA 开发区。

- 网络与同帧校验：RAW乱序/重复/尾包/缺包/CRC/超时、DDR/线上stride差别、Bayer错误、换图/复位/参数不符均应识别；未验证HDMI帧不得凭RAW帧号进入正式成对测评。
- 像素统计：全相等、固定差值、无有效点、极值输入、不同位宽及无符号相减风险；验证无穷与缺测能正确序列化。
- 几何测量：已知直线、已知弯曲、不对称旋转图、缺角点，检查单位、方向、漏检和剔除规则。
- 覆盖判定：人为屏蔽参考有效域中的一块区域，即使剩余像素差为零，也不能得到全域通过。
- 动态测量：帧号缺口、重复显示、时间戳回绕、近似同步、乱序事件，以及 1Hz 数据不能进入全帧峰值验收。
- 光照测量：已知阶跃、过冲、持续振荡、零噪声及缺帧，验证稳态窗口、收敛帧数和异常分类。
- SFR：可信基准数据和独立工具对照，不只写与内部计算过程一模一样的断言。
- 报告回放：从同一完整证据包离线重算，固定版本下结果应可复现；阈值修改需生成新的分析版本并保留旧报告。

合成与模拟数据统一标明 `mock`，用于软件开发和异常注入。它们不能计入真实标定、现场成像质量或板端实时性能验收。最终报告只填实际获得的结果，并保留未测、失败与未覆盖范围。
