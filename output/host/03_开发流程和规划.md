## 1. 首版交付范围

首版应形成一个能在Windows现场电脑运行的上位机软件，支持以下完整流程：

连接设备 → 核对实际配置 → 设置光照/姿态 → 等待实际生效 → 获取证据 → 调用冻结模型 → 计算指标 → 保存报告 → 可按同一证据重算。

| 优先级 | 功能 | 首版取舍 |
| --- | --- | --- |
| P0 | 设备能力、UART、K/D解析下发/寄存器回读、按帧commit、会话和错误 | 必须完成，不能仅有操作按钮 |
| P0 | S0 RAW8千兆网完整1080p30、基础可视化和单HDMI结果采集 | 两通道持续工作，不转发相机主视频，不使用PC软件几何fallback |
| P0 | 无损同帧证据、版本和元数据、完整性检查 | 必须完成；高速通道未通时明确静态诊断限制 |
| P0 | 真实标定管理、模型适配、坐标/像素/直线度测评 | 必须完成；权威模型由fpga/model提供 |
| P0 | 实际输入/处理fps、分层计数、硬件时间端点 | 必须完成，不能用显示Hz或PC时间冒充 |
| P0 | 有效性判定、归档、报告、历史回放 | 必须完成，失败和未测不能静默隐藏 |
| P1 | MCU灯光/云台控制、人工事件、姿态与光照曲线 | 在设备接口可用后集成；未到位可并行做mock |
| P1 | SFR/MTF适配、HDMI连续源帧关联、动态连续证据、自动用例与长稳 | 连续同源对比单独验收；独立双流和快照通过不能替代关联验证 |
| P2 | 真实60fps、已验证透视扩展、额外仪器自动接入 | 不阻塞30fps稳定版；未通过单列 |
| 暂不纳入 | 上位机替代FPGA视频算法、MCU固件实现、多端云服务 | 不属于本区当前交付 |

## 2. 建议技术路线

以下为建议选型，正式版本在兼容性验证后锁定，不把文档中的推荐当作已经安装的环境。

| 部分 | 建议方案 | 选型验证 |
| --- | --- | --- |
| 语言与运行平台 | Python，Windows x64为首个平台 | 验证Qt、OpenCV、采集后端及模型依赖的兼容组合 |
| 界面 | PySide6 / Qt Widgets | 优先可靠的设备控制、图像窗口和图表，避免先做复杂动画 |
| 串口 | pySerial | 验证设备枚举、超时、断线、粘包/拆包和两设备独立接收 |
| 网络接收 | UDP socket、批量接收和有界缓冲，后端经性能验证冻结 | 先测44,460包/s、RAW62.208MB/s、重组异常和Python开销，必要时接收路径下沉原生模块 |
| 图像与数组 | OpenCV＋NumPy | 基础Bayer显示与板端S1区分；固定类型、通道、插值/采集行为及版本 |
| 参考模型 | fpga/model冻结依赖＋host适配器 | 优先进程和文件接口隔离版本/失败；不复制一套模型源码 |
| SFR与图表 | 已验证的SFR实现；固定绘图依赖 | 用校验样本验证算法后接入，不能仅显示一个“清晰度分数” |
| 配置和证据 | YAML配置、JSON/JSONL元数据、CSV指标、未压缩.raw/.rgb证据；PNG仅派生预览 | schema与单位统一；科学数据格式必须明确位宽和轴顺序 |
| 发布 | 先测试目录式发布包，再评估单文件包 | Qt插件、采集依赖、模型和配置能在目标电脑找到 |

PySide6是Qt的Python接口；GUI对象应在主线程操作，后台工作通过事件/信号传递结果。[Qt for Python](https://doc.qt.io/qtforpython-6/)、[Qt线程与QObject](https://doc.qt.io/qt-6/threads-qobject.html)

打包可用PyInstaller验证，先采用目录式包便于检查依赖，再决定是否需要单文件形式。打包完成不代表驱动、视频采集或硬件运行已经验证。[PyInstaller运行方式](https://pyinstaller.org/en/stable/operating-mode.html)

## 4. 并发、队列与停止机制

### 4.1 线程和任务

- GUI主线程仅更新界面、处理交互，不阻塞等待串口、完整模型计算或磁盘写入。
- FPGA和MCU独立I/O任务；一条设备连接由一个明确的收发所有者管理。
- RAW网络、HDMI采集、基础ISP和快照分离，不能共用丢旧帧策略；RAW完整性和计数先于GUI取最新帧。
- 图像分析在后台执行；先限制并发以控制内存，需要时用独立模型进程/计算进程。
- 结果通过只读数据或明确所有权传递；后台不能修改GUI正在显示或测评正在读取的图像。
- 图表和预览可限刷新频率，完整硬件计数和证据保留独立通路。

### 4.2 有界队列

| 队列 | 起始策略 | 溢出处理 |
| --- | --- | --- |
| RAW重组 | 起始最多4帧在途、100ms期限，实测后冻结实际字节上限 | 超时/超限整帧失败，不补零或混帧 |
| 实时预览 | 最多少量完整帧，例如2帧 | 丢旧显示任务并计数，不影响RAW连续接收统计，不叫FPGA丢帧 |
| 控制请求 | 有限未决事务，按设备分队列 | 拒绝新任务/显示忙；停止请求不被图像导出长期阻塞 |
| 无损快照 | 首版最多1组未完成请求 | 暂停新请求或返回忙，禁止覆盖待保存证据 |
| 模型任务 | 首版单任务，内存预算按图像和坐标规模设定 | 延后新诊断；不改变实时视频主路 |
| 记录和报告 | 按磁盘速度和字节预算限流 | 写盘失败停止新采样、保存错误，不继续显示“记录正常” |

不要仅按帧数量估算内存：一组输入、输出、参考、坐标和中间数组远大于单张预览图。重型绘图和报告生成应避免挤占连续帧采集。

### 4.3 停止和异常退出

用户停止测试后：不再发新运动/快照→向MCU发停止请求→核对反馈→取消未开始的模型任务→结束在途接收与安全释放→保存部分结果。

停止请求已发送但设备未确认时，界面显示“停止状态未确认”，不能直接显示“电机已停止”。设备端限位与本地停止机制归mcu，PC连接失败不能代替设备端保护。

磁盘失败或分析崩溃不能无限占用FPGA快照槽。取消流程保留被丢弃证据的原因，安全释放资源，下一次运行使用新任务标识。

## 6. 开发流程与合入要求

### 6.1 每个功能的最小闭环

1. 写清输入、输出、失败情况和完成条件，引用公共数据契约。
2. 先准备正常和异常样本，包括来源与预期，不伪造真实标定成绩。
3. 完成无GUI核心服务，再接界面，确保自动测试与人工操作复用同一逻辑。
4. 运行与该变化有关的单元/集成测试，保留失败原因可观察性。
5. 使用真实设备或冻结历史数据完成相应验证，记录没有覆盖的部分。
6. 更新依赖、协议/模型兼容范围、操作说明和受影响报告。
7. 按现有仓库流程暂存、提交和推送；文档计划本身不执行这些操作。

### 6.2 模型协作

涉及公式、定点格式、舍入、插值、增强顺序或硬件参数编码变化时，先在fpga/model更新和验证权威版本，再更新host适配与兼容矩阵。

host的ROI、直线度、SFR适配、性能统计和报告算法由host维护；测评方法变动增加method_version，并对冻结数据重算。旧报告保留，不能原地覆盖后假装历史成绩未变。

### 6.3 配置与兼容

设备配置、相机标定、ROI、测试门槛和依赖版本分开管理。正式运行锁定配置并生成快照，运行中修改只能影响下一组明确版本的样本。

协议、模型、numeric_format_id或像素格式不兼容时拒绝相关操作；不能猜旧字段含义继续。未知能力显示未知，不自动默认可用。

| H4 动态环境 | 实际动作/光照事件与逐帧观测可关联 | 低频快照只报告抽样，不声称动态峰值全覆盖 |
| H5 正式验收 | 必需用例有有效证据、2h长稳、报告可回放 | 保留未测/失败，优先修主线 |
| H6 发布 | 目标机运行、依赖/模型可追溯、现场恢复与数据路径正确 | 目录式发布先验证，不追求单文件形式掩盖问题 |

## 8. 测试开发要求

以下是未来软件测试内容，本轮只验证文档，不运行不存在的应用测试。

| 层次 | 必须覆盖 | 失败应暴露什么 |
| --- | --- | --- |
| 协议单元 | UART拆粘包/CRC16；UDP64字节头/CRC32、1482包尾块、乱序/冲突/超时 | 不执行坏命令、不提交坏RAW，分层计数 |
| 事务单元 | ACCEPTED无APPLIED、重复回应、重传、断线/seq回绕 | 不误显示生效、不重复启动运动 |
| 同帧集成 | 缺块/epoch、S1错误配对、RAW编号误赋HDMI、未知时戳 | 拒绝错误样本；未验证配对不进入正式指标 |
| 数据门禁 | RGB/BGR、stride、位宽、tap、模型/LUT不匹配 | 相关指标INVALID并说明原因 |
| 模型适配 | 缺少入口、超时、异常退出、输出维度/哈希错误 | 不把失败模型的旧输出当本次参考 |
| 测评回归 | 冻结图卡数据、掩码失效、空ROI、缺真值、角点漏检 | 不以零误差或无限PSNR表示缺数据 |
| 时间与帧率 | 30fps输入/60Hz显示、重复帧、PC采集丢帧、晚到显示tick | 分层计数正确，不混用时基 |
| 状态机 | 环境未到位、稳定超时、停止、设备失联 | 及时结束相关步骤、保留部分结果 |
| 存储 | 磁盘满、文件不完整、哈希不匹配、重算 | 不覆盖原证据，不静默丢数据 |
| 长稳/发布 | RAW＋HDMI＋快照有界负载、断网/坏包/USB重连、写盘和目标机启动 | 漏采/降级可见，不启用软件几何fallback |
| 演示/能效 | DVP直连、板上按键/断开PC、独立显示、能量与帧数共同窗口 | 不用日志、HDMI重复帧冒充处理或能效证据 |

测评算法测试使用已知性质或经过独立验证的样本；不能仅让同一段代码计算预期值再验证自身。硬件模型的位精确测试归fpga；host只验证调用边界和测评逻辑。

软件回放长稳只证明PC稳定性。真实系统正式长稳至少2h，冻结版本争取8h；其条件、硬件计数与视频证据必须实际取得。

## 9. 自动测试工作流

每个用例明确：所需能力、冻结配置、实际到位判据、采样数量/频率、超时、计算方法、阈值来源、结束动作、必需/可选。

~~~text
连接和能力检查
  → 冻结配置/标定/模型/ROI
  → 下发FPGA参数，等待APPLIED
  → MCU设置环境，等待实际反馈与稳定
  → 收集满足覆盖要求的证据
  → 逐指标门禁与参考调用
  → 计算、存档、汇总全部重复结果
  → 下一工况或保存完整/部分报告
~~~

现场人工按键事件也进入同一日志流；不能只有PC指令才被记录。自动与人工控制冲突时，暂停工况、记录操作者改变的实际条件，再明确恢复策略，不继续沿用旧工况标签。

具体用例沿用总方案T00～T14；30fps主线与60fps进阶分别汇总。指标门槛见02，不能因工期或测量失败而在运行后自动降低。

## 10. 发布、数据与报告

开发脚本只放host/scripts，构建到host/build，发布到host/release。业务代码不先写output再复制；根scripts仅用于仓库管理。

发布包至少包含：应用、冻结依赖、配置模板、模型依赖标识/哈希、协议兼容信息、启动说明、数据目录规则、设备连接步骤、已验证功能/缺项和软件校验清单。模型依赖副本来自fpga/model的冻结发布，权威源码不迁移到host。

目标电脑检查：

- 无需开发者终端当前目录，应用能找到资源、模型、配置与可写数据路径。
- 能区分FPGA与MCU设备，重连后重新核对身份和实际状态。
- Qt、采集后端及外部模型依赖齐全，报告图片和本地链接可打开。
- mock、replay、live及S0基础预览/FPGA结果/板端S1/软件参考清楚区分；未连接不显示实时成绩，禁止几何fallback。
- 在目标网卡、USB控制器和采集卡上验证RAW62.208MB/s完整接收与实际HDMI格式负载；GUI降刷新不掩盖接收缺口。
- 磁盘预算足够，写盘失败有明确提示和结束行为。
- 同一冻结证据再次分析产生可解释、可追溯的结果。

host/data保存证据，host/reports保存结果；原始FPGA资源/时序报告仍属于fpga/reports，通过来源和哈希引用。按当前仓库规则不新增忽略目录，不默认移走数据或产物。

## 11. 本轮与后续工作的界线

本组文档仅定义输入输出、硬件连接、算法测评和开发规划，统一归档于 output/host/，由 host/README.md 提供开发入口。文档不代表依赖已安装、应用代码已实现、设备已联调或已生成真实测量数据。文档变更按仓库约定提交和推送。
