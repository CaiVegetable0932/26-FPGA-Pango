版本：V1.0 · 日期：2026-09-06  
适用范围：host 开发区的软件需求与数据边界

本文件属于上位机需求与接口规划，归档于 output/host/；对应实现及运行产物仍直接写入 host/。跨端总体依据仍为 [系统测评方案](../可控光照箱与上位机测评详细实施方案.md) 和 [FPGA详细设计](../PG2L100H_1080p畸变矫正详细设计方案.md)。本文件集中定义PC端数据对象，线缆和报文见 [硬件连接](./01_硬件连接与通信.md)，计算方法见 [算法处理](./02_算法处理与测评.md)，实施步骤见 [开发规划](./03_开发流程和规划.md)。

## 1. 上位机职责与工作区边界

上位机应完成：连接FPGA和MCU、控制试验环境、读取实际状态、采集视频与同帧证据、管理真实标定、调用参考模型、计算测评指标、自动执行用例、保存报告和发布软件。

| 工作内容 | 归属 | 上位机关系 |
| --- | --- | --- |
| RTL、DDR、ISP、硬件映射与插值 | fpga/ | 发送控制与读取观测，不在PC替代比赛主视频 |
| 浮点/位精确算法参考模型、模型单元验证 | fpga/model/，相关仿真归fpga/sim/ | 通过固定版本适配器调用，不能在host维护第二套权威实现 |
| 云台、电机、灯光驱动、限位与设备固件 | mcu/ | 上位机发送目标与动作请求，读取实际状态 |
| PC标定流程、质量与性能指标、界面、采集、自动测试 | host/src/ | 本区直接实现 |
| 设备/测试/标定配置 | host/config/ | 活跃配置与模板；每次运行另存配置快照 |
| 图像、元数据、日志、参考运行中间证据 | host/data/ | 原始证据和回放输入 |
| 本次测评的统计、图表、结论与报告 | host/reports/ | 通过run_id关联证据 |
| FPGA资源/时序原始报告 | fpga/reports/ | host引用或带来源复制；不能在PC重新“推算”硬件成绩 |

推荐软件栈是实现建议，尚未安装、锁定或验证。MCU型号、IMU型号、COM口、IP、引脚及DDR实际可用范围仍需核对，不在文档中预填成事实。

## 2. 对外输入

| 编号 | 输入 | 来源/频率 | 格式与校验 | 用途 |
| --- | --- | --- | --- | --- |
| IN01 | 设备能力与身份 | FPGA/MCU握手和重连 | 协议/固件/位流标识、接口能力、计时信息 | 决定哪些功能可启用 |
| IN02 | 控制回应与执行事件 | 设备按请求返回 | session_id、seq、状态、错误码、实际生效帧 | 确认动作实际完成 |
| IN03 | 预览视频 | HDMI采集卡，按实际模式 | 尺寸、格式、色彩量程、帧号覆盖、采集链校验 | 观察、录像和验证过的动态特征提取 |
| IN04 | 成对图像快照 | FPGA按需/低频导出 | S1输入＋一个选定输出tap；长度、分块校验、帧身份 | 像素和图像质量正式评价 |
| IN05 | 实际帧参数 | FPGA随帧/版本查询 | K/D、变换、LUT、插值、边界和格式版本 | 重现该帧实际处理 |
| IN06 | 帧时间与性能计数 | FPGA逐帧记录、批量读取 | 硬件计时基准、计数原子性、复位代次 | 处理fps、延迟、队列与丢帧统计 |
| IN07 | 姿态与同步状态 | IMU→FPGA，再由FPGA遥测给PC | 使用的姿态、采样/接收时刻、数据年龄、同步质量 | 动态参考与误差解释 |
| IN08 | 实际环境及按钮事件 | MCU/照度传感器/量具 | 事件号、时间来源、实际照度/角度、执行状态 | 按实际条件分组与响应测量 |
| IN09 | 真实标定资料 | 相机图像、图卡、配置文件 | 设备/模式、K/D、图卡尺寸、版本、哈希 | 生成与检验参考参数 |
| IN10 | 参考模型 | fpga/model发布的冻结版本 | 模型版本、算法/格式兼容性、代码哈希、调用约定 | 浮点与位精确对照 |
| IN11 | ROI、工况、阈值 | host/config/及操作界面 | schema、单位、范围、必填项、版本 | 自动测试与可重复计算 |
| IN12 | 外部仪器数据 | 示波器、光电探头、高速摄影、独立角度量具 | 原始文件、时基、仪器配置及测量说明 | 光到屏延迟和独立物理真值 |
| IN13 | 工程报告 | fpga/reports/及对应发布记录 | 位流/源码/PDS版本对应关系 | 资源、时序和工程规范评价 |

采集卡预览不默认等同于板端无损原图。不能从RGB输出反推完整硬件坐标表；坐标误差需专门诊断数据或明确的RTL仿真证据。

## 4. 运行模式

| 模式 | 可用输入 | 允许结论 |
| --- | --- | --- |
| mock | 合成图案、模拟设备与故障序列 | 软件行为验证；不产生真实硬件验收成绩 |
| replay | 已归档证据和冻结模型/配置 | 对历史证据重算，标注采集时间与分析时间 |
| live_preview | 实际设备视频和状态 | 连接、显示和部分遥测；不自动获得像素精度证明 |
| live_static | 实际成对快照和参数 | 对指定静态/抽样条件做精度评价 |
| live_dynamic | 连续逐源帧证据或已验证的逐帧特征 | 按实际覆盖率评价动态峰值与帧级响应 |
| hardware_diag | FPGA坐标/边界等专项诊断 | 指定诊断结果；允许背压的离线过程不证明实时吞吐 |

mock、replay、live始终在界面和报告显著区分。能力不足时记录未实现或未测，不能无提示从live切换mock并保留“实时通过”。

## 5. 标识、类型与单位

### 5.1 标识规则

- run_id：PC建立的一次试验或回放任务，唯一且不复用。
- device_id：设备身份；会话关联记录设备是哪一块板。
- session_id：一次协议连接会话，重连后的旧回应不得混用。
- stream_epoch：视频流代次；设备复位、计数重新开始或模式重启时改变。
- frame_id：**源采集帧编号**，处理结果、姿态和首次显示事件均关联此编号。
- snapshot_id：一次快照请求/结果标识，不等于frame_id。
- event_id：一次MCU动作、人工按钮或传感事件，跨端关联时保留来源设备。

单FPGA一次运行的样本键为run_id＋stream_epoch＋frame_id；多设备时再加device_id。若设备自身无法产生跨重启唯一的epoch，适配层必须结合boot_id或明确复位事件建立不碰撞命名空间，并保存原始字段与转换依据。不能只按文件名或PC收包先后猜测同帧。

### 5.2 数据表示

| 内容 | 约定 |
| --- | --- |
| JSON/文本 | UTF-8；schema_version显式保存 |
| 64位帧号/计数/tick | 内部整数；JSON建议十进制字符串，避免其他客户端浮点解析损失 |
| 缺失数据 | null＋缺失原因，不能以0替代 |
| 特殊数值 | 不输出非标准JSON NaN/Infinity；用value=null及special_value说明 |
| 像素中心 | 左上(0,0)，右下(W−1,H−1)，不额外加0.5 |
| ROI矩形 | 原分辨率整数像素索引的半开区间[x0,y0,x1,y1)，宽=x1−x0、高=y1−y0；0≤x0<x1≤W、0≤y0<y1≤H。注明输入/输出tap和坐标系，不能用预览缩放坐标直接计算 |
| 坐标误差 | 源图pixel；直线/角点误差为输出pixel，单位分别命名 |
| 角度 | 界面用deg；模型内部单位显式传入，不隐式猜测rad |
| 四元数 | 统一Hamilton [w,x,y,z]及相机→世界q_wc；保留模块原约定和转换 |
| 相机坐标 | x向右、y向下、z向前 |
| 时间 | 硬件tick＋tick_hz；PC墙钟用于人读日期，不能混算硬件延迟 |
| 照度 | lx；PWM为驱动量，二者分别存储 |
| 曝光/增益 | 曝光单位us，增益注明倍率或寄存器编码；读取不到时留空 |

## 6. PC内部标准对象

以下定义是接口语义，不宣称已有类、API或二进制布局。host只保留一份schema和校验实现，其他模块引用它；硬件报文不必与JSON对象逐字节同构。

### 6.1 DeviceCapabilities / CommandEvent

DeviceCapabilities至少包含协议版本、设备/固件身份、可用视频格式、快照tap、最大图像块、支持的算法/增强阶段、计时能力与计数列表。MCU另含可用轴、已配置行程与控制能力；未知能力不能当作支持。

CommandEvent至少包含目标设备、session_id、seq、cmd、请求摘要、请求/回应时间、REJECTED/ACCEPTED/APPLIED/FAILED状态、错误码、实际参数版本和生效帧身份。

ACCEPTED只是接收排队；不能更新“当前生效配置”。静态几何参数按源帧锁定，采集参数按合法采集边界切换，记录实际frame_id。

### 6.2 ImageDescriptor / FrameBundle

| 对象字段组 | 必需内容 | 条件 |
| --- | --- | --- |
| 帧身份 | run_id、device_id、stream_epoch、frame_id、snapshot_id | 所有实测样本必需 |
| 图像描述 | tap、width、height、pixel_format、bit_depth、channel_order、stride_bytes、payload_bytes、完整性信息 | 输入输出分别描述 |
| 数据路径 | 无损文件或受控内存对象、SHA-256 | 指明哈希由PC计算还是板端对照 |
| 配对关系 | input_descriptor、output_descriptor、requested_frame_id、actual_frame_id | 一组为S1＋一个输出tap |
| 固定参数 | calibration_hash、model_id、numeric_format_id、param_version、K_out、变换、边界、插值 | 几何实测必需 |
| 姿态 | pose_used、reference_pose、pose_source_tick、fpga_receive_tick、pose_age、sync_quality | 动态补偿指标必需；静态无姿态模式可标不适用 |
| 增强 | stage、lut_version、lut_hash、stats_frame_id、initial_state_ref | disabled/pre_resample/post_resample明确区分 |
| 时间 | capture_first/last、process_start、result_ready、first_display、tick_hz、clock_domain | 每项延迟只在对应端点齐全时可算 |
| 环境 | light_event_id、lux、exposure、gain、AE_state、实际角度及来源 | 相关环境/物理指标必需 |
| 有效性 | input_ok、output_ok、crc_ok、invalid_reason、reference/hardware_mask | 不默认两张RGB完整就等于全部指标可用 |

输入几何参考默认S1：基础ISP后的RGB888。S0 RAW仅用于ISP专项。输出位于OSD/分屏/显示缩放之前，包含哪个增强阶段由stage和tap共同决定。

RGB/BGR、紧凑行与带padding行不得混淆。保存去padding后的无损文件时保留传输stride和存档格式说明。10/12/16bit数据不能先降为8bit再称无损。

first_display_tick可能晚于结果快照，应允许暂缺并按帧身份后补。后补事件留日志；未得到真实端点时不预测延迟。

### 6.3 ParameterSnapshot / CalibrationProfile

保存真实K、D、相机/镜头、焦点、尺寸、裁剪、Bayer/ISP版本、标定板尺寸、标定日期、验证误差、源图清单和哈希。

ParameterSnapshot还保存下发的定点载荷、格式版本、硬件回读值、目标与实际生效帧。浮点值和编码值都留档，避免“档案参数正确但设备实际不同”。

只保存param_version或LUT版本号不够，必须能找到该版本的实体。重放时禁止自动使用磁盘上“最新标定”替代历史参数。

### 6.4 Telemetry / EnvironmentEvent

硬件遥测至少区分输入完整帧、处理完成帧、唯一显示帧、重复显示、未显示结果、溢出/欠载、诊断失败、CRC错误、IMU过期。读取计数应为同一原子快照并注明采样tick。

EnvironmentEvent分别保存请求目标与实际反馈。PC发命令、MCU执行和光源实际变化是不同事件；跨时钟域没有同步关系时，不用时间戳直接相减求物理响应。

只收到IMU原始姿态而不知道FPGA实际使用哪一个姿态，不能建立可靠的硬件数值参考。

### 6.5 EvaluationResult / RunManifest

每项指标至少含：

- metric_id、method_version、frame_key或帧区间、ROI版本。
- value、unit、special_value、valid、invalid_reason。
- 样本数、有效像素/线段/角点数、帧覆盖率、剔除数量及原因。
- 阈值、阈值来源、结果状态、参考模型版本、输入证据哈希。
- evidence_kind：board_full / board_sampled / rtl_simulation / validated_capture / external_instrument / mock / replay。
- source_run_id、采集时间与本次分析时间，用于历史数据回放。

RunManifest记录运行配置、设备/位流/源码/上位机/模型版本、工作区是否有未提交差异、数据与报告相对路径、测试计划、仪器和完成状态。

指标结果可为PASS、FAIL、INVALID、NOT_RUN、NOT_IMPLEMENTED。运行生命周期的RUNNING/STOPPED/COMPLETE/INCOMPLETE另存，不能把程序正常退出当成指标PASS。必需指标缺失时不能宣称整个方案通过。

## 7. 权威参考模型调用契约

### 7.1 输入与输出

| 方向 | 内容 |
| --- | --- |
| host→模型 | 任务编号、模式（浮点/位精确/ISP）、无损输入路径、帧身份、实际参数实体、输出尺度、边界/插值、增强阶段与LUT、必要的历史统计 |
| 模型→host | 明确完成/失败、模型和格式版本、输出图像、参考valid mask、可选源坐标、溢出/量化诊断、结果校验清单 |
| host自行计算 | 文件与帧校验、图卡检测、ROI、直线度、SFR适配、真实姿态误差、时序统计、工况判定及报告 |

可先用“请求JSON＋受控输入文件→独立模型进程→回应JSON＋结果文件”，之后再评估包内API。具体入口名与schema由双方冻结，本轮不声称已经有可执行入口。控制进程使用参数列表启动，禁止把配置内容拼成shell代码。

模型源码与测试始终以fpga/model为权威。发布时可以将其冻结发布产物连同哈希打包到host/release作为依赖副本，但不在那里修改源代码；重新构建应能追溯到同一模型版本。

### 7.2 兼容与失败

模型版本、numeric_format_id、畸变模型或增强阶段不匹配时拒绝该项数值评价。模型超时、输出不完整、路径越界或校验失败记录INVALID并保留诊断，不用上一帧结果补位。

自适应策略具有历史状态：只比较该帧增强输出可使用实际LUT；评价LUT选择逻辑时还必须提供连续统计与初始状态。逐位一致以冻结的位精确模型为准，OpenCV校准或探索性参考不另立硬件正确性标准。

## 8. 数据处理门禁

按以下顺序决定一个样本是否可用：

1. 检查能力、数据来源模式及协议版本。
2. 检查帧身份、图像长度、块覆盖和完整性。
3. 检查格式、tap、参数实体、模型版本和输入输出尺度。
4. 检查该指标依赖的姿态、时间、曝光、ROI或物理真值。
5. 比较参考valid mask和硬件失效分布；不能只取交集隐藏漏算。
6. 执行指标，检查最少样本与动态覆盖。
7. 保存证据后判定，不用预览缩略图产生正式指标。

门禁按指标执行：缺少显示时间戳不必阻断静态直线度，但会使输入到显示延迟无效；缺少独立角度真值不必阻断定点模型对照，却不能产生实际姿态通过结论。

图像检不出角点、光照未稳定、失去同帧关系、数据过期等均给出机器可读原因。只保存有效帧却删除无效帧，会导致总体结论失真。

## 9. 数据生命周期与路径

~~~text
host/config/                      活跃设备、标定、ROI和用例配置
host/data/<run_id>/config/         本次冻结配置及实体
host/data/<run_id>/frames/         输入/输出、参考、掩码、坐标诊断
host/data/<run_id>/logs/           命令、设备事件、遥测、错误、哈希
host/data/<run_id>/manifest.json   证据索引与来源
host/reports/<run_id>/             指标CSV、图表、Markdown/HTML报告
host/build/                       软件构建与中间结果
host/release/<version>/            发布包、依赖与校验清单
~~~

此树是后续运行布局，不表示现有文件已经生成。算法模型的自测输入与预期结果归fpga/model或fpga/sim；host调用模型产生的本次测评证据归host/data。

正常流程：接收临时文件→校验完整性→完成证据写入→更新清单→确认释放快照。磁盘写入失败应停止新采样、记录证据丢失并安全释放设备资源，不能无限占住FPGA帧槽；实时视频应继续按设备策略运行。

运行结束时将最终结果写到host/reports，并通过run_id和相对路径关联数据。原始证据不由重算覆盖；回放分析建立新analysis_id/报告，记录所用原始run_id。

当前仓库仅排除根reference/和PDS/。不新增忽略规则，不默认迁移数据或模型；保存前估算容量，明确采样策略，避免在长稳中无节制存全帧。报告内容与原始证据的保留范围由本区配置显式记录。
