# 赛题对照与功能裁剪建议

日期：2026-10-20。性质：候选范围分析，不执行RTL删除、参数关闭、重新构建或当前布线任务变更。

用户后续明确：原图和处理图像回传均用于呈现方案，**不可删除**。因此保留S0千兆网与处理结果HDMI双路回传，撤销本文初稿中的HDMI-only/删除原图网络支路候选。算法演示开关先按第7节盘点，不能仅因模式额外而直接裁掉。

## 1 原题依据与判断边界

用户于2026-10-20在本聊天提供了选题二“基于紫光同创FPGA的任意角度的畸变矫正”的完整任务、测评及注意事项。本文以该原文为依据；内容与先前读取的[2026选题指南PDF镜像](https://raw.githubusercontent.com/nbstarhkc/Qian-Sai/main/sources/pango.pdf)物理页11～14、正文页9～12相符。镜像仅便于追溯，第三方备赛摘要不作为要求依据；后续新增补充规则另行核对。

指南区分基础任务与高阶任务：基础涵盖采集缓存显示、二阶径向及切向映射、插值及黑边/空洞处理；高阶包含传感器或上位机驱动的动态变换、硬件实时优化及矫正前/过程中的自适应增强。评价还包含真实内参畸变参数、图卡清晰度/直线度、端到端性能和资源效率，现场可能改变相机角度。

因此需要区分三个问题：

1. 原题有没有指定某功能或实现手段？
2. 当前项目是否另行承诺了它？
3. 这个功能当前是否确实进入综合网表？

“原题未指定”不等于可以未经范围调整删除项目已承诺功能；“源码里有模块”也不等于删除文件能减少LUT。本文不修改现有RAW8千兆网＋单HDMI、同帧证据等权威基线，只列可审议的范围收缩。

### 原文确认后的范围结论

| 原题条款 | 最小实现方向 | 可不叠加的实现 |
| --- | --- | --- |
| 采集、缓存、显示 | 一路真实视频输入及结果显示；本项目另明确保留原图/结果双路回传 | 多输入源、双目并非必需；双路回传是用户确定的展示要求 |
| 径向、切向映射及重采样 | FPGA实时映射、插值和合理有效视窗 | 历史补全、生成式补全不是必需手段；仍需解释视场外区域 |
| 传感器或上位机控制动态矫正 | 选择上位机指令驱动，按帧更新真实变换 | 不要求同时集成IMU、五轴、视觉运动估计和轨迹平滑 |
| 倾斜/旋转及现场改变物理角度 | 冻结实际运动轴、角度范围、目标视图并实测 | 不能将仅面内旋转直接等同任意物理倾斜；完整透视仍是条件裁剪 |
| 自适应Gamma或直方图均衡 | 保留一种矫正前/过程中的真实自适应方案 | 不要求两种并存；固定Gamma或仅后置Gamma不能替代此项 |
| 标定、MTF50或SFR、直线度 | 真实标定与可信结果取样，PC分析 | 不强制连续独立双快照电路，但必须有可复核证据 |
| 实时性与端到端延迟 | 继续保持项目真实1080p30基线 | 原文举30或60fps示例，未要求两档同时实现；不据此降低现有30fps目标 |
| 性能达标后资源越少越好 | 在可布线、真实时序和性能合格后比较资源 | 不为无用的更高并行度消耗资源；也不以省LUT破坏可实现性 |

完整覆盖高阶任务的建议是“保留动态几何与一种自适应增强，裁掉重复模式和额外系统功能”。基础任务版可以用于联调，但不能当作完整覆盖高阶的最终版本。动态几何补偿不等于视觉电子防抖，题目也没有要求通过五轴机械系统实现该补偿。

## 2 建议功能实现树

```text

│
├─ A 核心视频与算法                         保留
│  ├─ 单路相机输入及完整帧检查
│  ├─ RAW基础ISP：去马赛克及必要色彩处理
│  ├─ DDR帧缓存、DMA、完整帧发布与显示隔离
│  ├─ 真实内参和畸变系数解析、校验、按帧生效
│  ├─ 二阶径向＋切向镜头映射
│  ├─ 双线性采样、有效掩码和合法边界处理
│  └─ 完整矫正结果 → 单路HDMI
│
├─ B 高阶参赛能力                          建议保留目标，选择较简实现
│  ├─ 动态角度控制
│  │  ├─ 上位机指令 → 帧级变换             优先实现路径
│  │  └─ IMU输入                           可替代/扩展路径，并非必须两套齐备
│  ├─ 仿射旋转、平移、缩放                 保留
│  ├─ 完整透视/齐次除法                    条件候选，不等于普通面内旋转

├─ D 证明与测评                            保留能力，可调整硬件实现
│  ├─ 真实标定、图卡、MTF/SFR与直线度      上位机离线分析
│  ├─ 帧率、错误、端到端延迟及资源报告    保留必要观测点
│  ├─ 板端同源图像获取                     保留可信证据路径
│  │  ├─ 当前实时双快照复制与导出          可改为低频维护模式的候选
│  │  └─ 停帧/锁帧后复用读取路径           需新设计及一致性证明

├─ E 项目展示与扩展

│  ├─ 五轴自动测评、光照箱自动编排         可由外部测试装置承担
```

“裁剪”不能恢复真实视场外信息，双线性也不能凭空补出未观测内容。黑边/空洞目标应以有效ROI、视场损失和结果图卡证明，不能删除历史补全后就宣称所有缺失已解决。倾斜平面矫正与面内旋转也不是同一种几何能力。

## 3 当前确实可影响资源的裁剪候选

收益均为结构判断，尚无本轮候选MAP差值，不给LUT节省百分比。

| 顺序 | 候选 | 当前实现证据 | 预期影响与代价 |
| --- | --- | --- | --- |
| 1 | 去掉插值后Gamma对照，只留disabled/pre | `rgb_enhance.sv`运行期支持0/1/2，post借用前3个bank | 可省地址、使能及输出选择，收益偏小；不会省“额外3套表”。需新增编译裁剪点并拒绝不支持命令，保留背压寄存 |
| 2 | 精简亮度遥测与分页状态 | `rgb_frame_statistics`及UART状态实际可观测，`pc_video_boot`有1536位状态快照与分页选择 | 可能减少累加器、宽寄存器和mux。保留自适应增强需要的统计、丢帧/故障计数和实际参数身份；字段标不支持，不填零伪装测量 |
| 3 | 完整透视改为仿射＋镜头矫正 | core默认`PROJECTIVE=1`，顶层未覆盖；generate有affine分支 | 可移除透视深度递推和齐次除法，潜在收益较大。仅适合明确收缩到面内旋转/仿射的版本；不能宣称仍能精确处理所有物理倾斜 |
| 4 | 同帧快照改为低频维护模式 | 顶层`SUPPORT_SNAPSHOT=1`，当前有独立复制、读取及网络选择 | 可能减少一套读/复制路径、状态和客户端互连，但需要暂停/固定源帧并复用读取服务的新方案。严格同帧证据不能直接丢弃 |
| 保留项 | S0实时网络＋HDMI结果回传 | 当前RAW writer、RAW reader、网络服务和HDMI均承担展示功能 | 用户明确不可删除；只能在维持完整双流能力的前提下优化结构 |

关于透视裁剪：赛题高阶任务使用“倾斜或旋转”描述，未在已读正文强制指定某个3×3投影模型，但现场物理转动会检验实际能力。**不能把PROJECTIVE=0列为无条件合规优化**。可做“仿射精简版”资源对比，明确有效角度/场景和失去的透视功能，再决定是否接受该范围变化。非仿射参数须拒绝，不能静默忽略。

关于增强：指南的高阶目标是自适应预处理。当前tone加载的是固定参考曲线，不能因为有12个Gamma端口就声称自适应目标已实现。若只保留固定Gamma，必须说明高阶能力不足；若保留自适应Gamma，至少保留其真实选择机制需要的统计/控制，不为省LUT删掉后仍报告自适应。

## 4 不应把删除文件当作资源优化

以下不进入当前生产顶层或可能已被综合裁掉，删除源码通常没有当前LUT/PnR收益：

- 未集成的视觉防抖、历史补全、滚动快门扩展：取消规划能防止未来膨胀，但不能节省当前尚不存在的电路。
- MCU姿态队列/XYZ逻辑：当前board没有接入姿态选择器，capture_meta还标识本接线无MCU样本。删MCU固件不减少FPGA资源。
- 旧低层CDC参考adapter、独立实验顶层及仿真模型：未实例化部分不形成当前电路，保留追溯价值。
- DMA bus_bytes/max_wait_cycles/useful_write_bytes及几何cache统计：生产上层输出未连接的部分可能已被优化掉；须看网表，不能按源码计数器宽度算节省。
- host界面、报告、自动测试以及output文档：不参与FPGA综合。它们复杂不等于占FPGA LUT。

生成条件、参数常量和不可达逻辑必须在综合报告中确认。运行时关闭开关不等于编译时删除硬件；删除文件也可能只导致工程无法编译。

## 5 不可直接关闭写后读回

`ddr_native_dma`的模块默认`VERIFY_WRITES=0`，但生产`frame_memory_fabric`显式使用1，正常写事务退休依赖verified。直接改0可能导致写事务无法退休与帧发布卡住。

若要删除逐写读回，需要以安装版原生DDR接口的真实完成语义另建可靠写可见性栅栏，并验证错误、取消、迟到返回及消费者读到新数据的顺序。它可能减少带宽和逻辑，但属于内存一致性重构，不属于题目未要求就可删除的测评模块。现阶段不放入首批裁剪。

## 6 推荐的取舍

建议先形成“功能基本不变的精简版”，再评估需要改变项目承诺的版本：

1. 保留当前单相机、基础ISP、镜头矫正、动态参数、双线性、HDMI、S0和可信同帧证据，先去post增强对照、精简非必要遥测和过度通用的模式选择；同时按已确定refill/作业参数热点重构。
2. 单独生成仿射候选，测量相对当前透视核的LUT/APM/布线差异，明确倾斜处理限制。未经范围决策不替换生产默认。
3. 若上述仍不足，可研究低频快照的通路复用，但仍保留S0实时网络与HDMI结果。撤销HDMI-only版方向，不能把低频取证替代正常双流展示。

可用两个编译配置进行诊断，但不把“测评版”的图像精度和“精简版”的帧率/资源拼成同一版本成绩。最后提交版本应具备自身所需证据，并用自身源码、约束和位流哈希完成验收。

每个候选单变量比较：功能损失清单 → 独立参考和完整帧仿真 → 同一时钟的MAP → LUT/FF/APM/物理DRM与实际模块消除检查 → 局部和整机布线。快照结构改变还须重算客户端、帧槽引用和服务期限；只省外部DDR容量不能当作省片上LUT。

本次没有生成新候选或改变当前布线任务。原题已由用户提供并完成对照；候选裁剪尚未成为实施决策，双路回传明确保留，同帧取证实现若调整需同步项目基线与验收要求。

## 7 影响最终画面的开关清单

主测评设计第3.1节提出“三项算法独立开关”，没有在该表定义三个已实现的独立协议位。按设计职责可整理为镜头去畸变、角度/姿态变换、亮度增强三类，不能将规划界面误写成当前已上板验证的按钮。

| 控制 | 画面影响 | 当前层级 |
| --- | --- | --- |
| 镜头去畸变开/关 | 比较直线弯曲、边缘拉伸等；关闭仅去掉镜头模型，不应连带关闭姿态或增强 | 设计有旁路/矫正要求；现有协议通过整组几何参数提交，未见独立去畸变enable命令。零畸变系数是候选实现方式，须保留真实标定档与实际生效记录 |
| 旋转/姿态变换开/关或手动/姿态来源 | 改变画面方向、目标视角；固定参考、手动角度与动态跟随用于对照 | 几何实体支持变换参数；当前生产未接入MCU姿态补偿。关闭姿态应回到参考变换，保留镜头矫正，而不是盲设整个归一化矩阵为单位阵 |
| 增强模式 | 亮度、对比和暗部细节变化 | 当前0x92支持disabled/pre_resample/post_resample，RTL及host编解码已有；不等于当前Web已提供板端按钮，也不等于实板验证完成 |
| 固定/自适应Gamma及曲线档位 | 曲线固定或随亮度变化 | 主设计有规划；生产tone为参考曲线，不能声称自动选曲线已经接入 |
| 保留视场/固定裁剪/受限动态裁剪 | 改变黑边、缩放和保留视场 | 下一阶段规划，未列为当前已实现独立运行期开关 |
| 防抖、历史补全 | 分别影响抖动、边缘缺失/历史来源 | 下一阶段规划，不是当前生产可切换功能 |
| 相机自动/固定曝光及增益 | 从源头改变亮度、噪声和运动模糊，原图与结果都会受影响 | 设计与相机专项控制，不能与Gamma开关混为一项 |
| PC原图RAW灰阶/基础彩色/平均灰度 | 改变左窗呈现方式，不改变保存的RAW字节 | 当前Web已有 |
| PC计算机矫正开/关 | 对HDMI回采再做软件参考变换，改变右窗预览 | 当前Web已有，明确标注PC软件参考；不能作为FPGA矫正开关或正式结果替代品 |
| 像素标记显示/隐藏 | 只增加观察用叠加标记 | 当前Web已有，不改变板端图像或原始证据 |

展示用主控建议保留“镜头矫正”“角度/姿态变换”“图像增强”三类独立控制；“全部算法旁路”作为组合预设，而非第四套处理流水。旁路结果是基础ISP后的RGB，并非S0 Bayer原始字节。开关按源帧原子生效，左侧S0保持传感器原始来源；普通HDMI帧身份未证明时仍标unverified。所有开关状态、实际参数版本和增强位置应随对应帧记录。
