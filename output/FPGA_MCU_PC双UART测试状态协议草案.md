# MCU→FPGA／上位机双 UART 测试状态协议草案

状态：**接口设计，尚未实现或上板验收**。本草案落实“MCU 将当前云台角度、三种预设颜色之一、龙门架 XYZ 位置分别通过 UART 回传 FPGA 和上位机”的六项要求。它扩展 [FPGA–MCU V1](FPGA_MCU通信协议V1.md) 的帧包络，不改动已存在的 `0x10 SUBMIT_ENVIRONMENT` 含义。机械与坐标依据 [STM32F407ZGT6 测试系统方案](STM32F407ZGT6_三轴龙门架与二维无刷云台黑箱测试系统设计方案.md) 和 [光照黑箱方案](光照黑箱详细设计方案.md)；三种颜色的具体名称、光谱/灯路配方和接线仍需实物配置确认。

## 1. 两个接收端与同一采样

```text
云台实际反馈、龙门架位置来源、已应用的灯光预设
              ↓ MCU 在同一采样周期冻结 TestState
              ├─ UART_A（独立端口）→ FPGA 协议端点
              └─ UART_B（独立端口）→ USB–UART → 上位机接收器
```

两条 UART 发送**同一份 72 字节 TestState 载荷**，各链路使用独立发送队列、重试和 ACK；不得先后重新读取传感器再分别封包。上位机凭 `mcu_boot_id + sample_seq` 比对两端记录，而非凭报文到达顺序推断同帧。两路只传状态，**不传视频像素**。初始采用 115200 bit/s、8N1、TTL 电平（具体电压与引脚待核对）、无流控；MCU 到 FPGA、MCU 到 PC 分别使用独立 UART，不能把两个 RX 或现有 CP2102/云台控制器串口无仲裁并接。STM32F407 有多个串口，但此处**不预先指定引脚或外设实例**。

某一路断开时，另一路继续上报。发送队列有界，实时预览优先保留新状态；被丢弃的 `sample_seq` 必须可见地计数/告警，不能把旧状态伪装成最新值。FPGA 端如未建立有效 epoch/session，可停止向 FPGA 发送，同时继续向 PC 发送并标记 FPGA 链路未就绪。

## 2. V1 包络上的新命令

两链路均采用以下逐字节格式，多字节字段小端：

```text
55 AA | version=01:u8 | cmd=11:u8 | seq:u16 | length=0048:u16 |
TestState[72] | CRC16/CCITT-FALSE:u16
```

`0x0048` 为十进制 72，在线路上是 `48 00`。CRC 参数沿用 V1：poly `0x1021`、init `0xFFFF`、不反射、xorout 0，覆盖 `version` 至载荷，不覆盖 `55 AA` 与 CRC 自身；CRC 小端发送。完整报文 82 字节。外层 `seq` 为该 UART 链路的 16 位请求/应答关联号，允许回绕；可取 `sample_seq` 的低 16 位，但业务去重必须使用完整的 `mcu_boot_id + sample_seq`。

新命令暂定 `0x11 SUBMIT_TEST_STATE`；它是**待实现扩展**，现有 `mcu_protocol.v` 只接受至多 32 字节请求，当前 PC 上位机也没有该二进制接收器。旧固件可能返回 `BAD_LENGTH` 或 `UNSUPPORTED`；不能向旧端点发送新包后把 NACK 当作板卡故障。正式启用前，FPGA 的 `GET_CAPABILITIES` 必须新增能力 bit7=`TEST_STATE_72` 并报告本端请求上限至少 72 字节，PC 接收器也须明确声明同一载荷版本。未经能力确认不发送 `0x11`。保留 `version=01` 表示沿用帧包络，不表示旧实现已支持新命令。

## 3. TestState 载荷布局（固定 72 字节）

| 偏移 | 字段 | 类型 | 单位与说明 |
|---:|---|---|---|
| 0 | `fpga_epoch` | u64 | 从 FPGA 能力查询取得的当前非零代次；PC 镜像记录同值，FPGA 校验同值 |
| 8 | `session_id` | u32 | 本次 FPGA 会话，非零；PC 镜像记录同值 |
| 12 | `sample_seq` | u32 | MCU 同一启动内严格递增、不回绕的采样号，两条链路相同 |
| 16 | `mcu_boot_id` | u32 | MCU 每次复位都不复用的启动代次；生成方法需固件落实并验证 |
| 20 | `mcu_time_us` | u64 | MCU 单调微秒时间，代表本次状态快照时刻，不是 FPGA 曝光时刻 |
| 28 | `roll_mdeg` | i32 | Roll 当前反馈角度，毫度，二补码；不是目标角 |
| 32 | `pitch_mdeg` | i32 | Pitch 当前反馈角度，毫度，二补码；不是目标角 |
| 36 | `x_um` | i32 | 龙门架 X 当前位置，微米，二补码 |
| 40 | `y_um` | i32 | 龙门架 Y 当前位置，微米，二补码 |
| 44 | `z_um` | i32 | 龙门架 Z 当前位置，微米，二补码 |
| 48 | `light_preset_id` | u8 | `0` 已确认关灯；`1..3` 三种颜色预设；其他值保留 |
| 49 | `light_state` | u8 | `0` 已关、`1` 切换中、`2` 已稳定、`3` 故障；其他值保留 |
| 50 | `valid_mask` | u16 | 见下文；未有效的数值不得用于控制或测评 |
| 52 | `source_mask` | u16 | 见下文；标明测量/估计来源，不能只报目标值 |
| 54 | `light_preset_version` | u16 | 三色预设映射/配方版本；为 0 时不能解释颜色 ID |
| 56 | `coordinate_version` | u16 | XYZ 原点、轴向、云台零位/正方向配置版本；为 0 时不能用于精度测评 |
| 58 | `reserved` | u16 | 必须为 0 |
| 60 | `max_field_age_us` | u32 | 有效字段中最旧反馈距 `mcu_time_us` 的年龄；未知时取 `FFFFFFFF` 并撤销相关有效位 |
| 64 | `state_flags` | u32 | 见下文，保留位必须为 0 |
| 68 | `reserved` | u32 | 必须为 0 |

`valid_mask` bit0=Roll、bit1=Pitch、bit2=X、bit3=Y、bit4=Z、bit5=已应用颜色预设；bit6..15 保留 0。每个字段分别判有效，不得用“云台有效”替代两个转轴，也不得在某个龙门架轴未回零/失步后继续宣称它的位置有效。数值分辨率 0.001°/1 μm **不等于**硬件测量精度。

`source_mask` bit0/1 表示 Roll/Pitch 来自编码器反馈；bit2/3/4 表示 X/Y/Z 来自独立位置传感器，否则可为已回零、无丢步证据的步数推算位置；bit5 表示灯光配方已由驱动侧确认应用；bit6..15 保留 0。若只有云台/龙门架目标值，相关 `valid_mask` 必须为 0；如果步数估计因限位、急停、失步或复位失去可信度，对应位置有效位立即清零。上位机必须展示来源，不把估计位置标为独立实测。

`state_flags` bit0=运动进行中、bit1=云台已停稳、bit2=龙门架已停稳、bit3=灯光已稳定、bit4=急停/安全联锁、bit5=设备故障；bit6..31 保留 0。`light_preset_id` 指**已确认应用**的颜色预设；切换中且不能确认当前输出颜色时，清除 `valid_mask.bit5`，不能提前填目标颜色并标有效。预设 1/2/3 的具体颜色、灯路和档位在版本化的 MCU/host 配置中一致冻结；它们不是现有 `NORMAL/NIGHT/BRIGHT` 照度场景的同义词，也不能由 ID 推出真实光谱或实测照度。现有四灯组合与三色预设之间须另行测量/标定映射。

机械坐标遵循现有方案：X 向右、Y 指向图卡、Z 向上；当前二维云台仅 Roll/Pitch，**没有已实现的 Yaw**。原点、零偏、Roll/Pitch 正方向和装配偏置通过 `coordinate_version` 对应的校准档冻结。零位改变后提高版本；未校准前字段可记录为诊断，但不能作为几何精度真值。

### 合成协议测试向量（不代表实测状态）

设 `fpga_epoch=0102030405060708`、`session_id=11223344`、`sample_seq=1`、`mcu_boot_id=A1B2C3D4`、`mcu_time_us=1000000`、Roll=`-45000`、Pitch=`12000`、XYZ=`100000/200000/300000` μm、颜色预设 2、灯已稳定、`valid_mask=source_mask=003F`、两个版本均为 1、`max_field_age_us=5000`、`state_flags=0000000E`，外层 `seq=1`。完整 82 字节报文如下，末尾 `A0 35` 是小端 CRC `0x35A0`：

```text
55 aa 01 11 01 00 48 00 08 07 06 05 04 03 02 01
44 33 22 11 01 00 00 00 d4 c3 b2 a1 40 42 0f 00
00 00 00 00 38 50 ff ff e0 2e 00 00 a0 86 01 00
```

## 4. 双端会话、ACK 与异常处理

1. MCU 从 FPGA 读取 `GET_CAPABILITIES`，确认新能力、非零 `fpga_epoch` 与 72 字节上限，再 `OPEN_SESSION`。上位机二进制接收器独立准备，但记录同一个 `fpga_epoch/session_id`。在 FPGA 未就绪期间，PC 可以接收带 `fpga_epoch=0` 的状态并标记“仅 MCU 本地状态”；**这些包不得发给 FPGA，亦不得与 FPGA 视频帧配对**。
2. MCU 冻结一个状态快照，分配一个 `sample_seq`，生成一份完整载荷，分别放入 UART_A/UART_B 队列。串口外层 `seq` 和 ACK、重试计时按链路管理；重试只能原样发送同一 `mcu_boot_id + sample_seq + payload`。两端各自按该身份去重，同号不同内容拒绝，旧号拒绝。`sample_seq` 达到 `FFFFFFFF` 前须重新建立不复用的 MCU 启动/会话代次，不从 1 静默回绕。
3. FPGA 延用 V1 响应包络 `cmd=0x80` 成功/重复、`0x81` 错误，响应 payload 32 字节。前 20 字节保持 V1 布局（其中偏移 16 的旧 `last_event_seq` 仍属于 `0x10`，**不是**本命令的 `sample_seq`）；对 `0x11`，后 12 字节建议为 `accepted_sample_seq:u32`、`mcu_boot_id:u32`、`receiver_flags:u32`（bit0=已接受并锁存，其他位保留）。PC 接收器采用同样回应语义，但其接收确认与 FPGA 确认独立。**ACK 只表示校验/入队成功，不代表电机到位、灯光稳定或几何矫正已经使用该数据**。
4. FPGA 重启、epoch 改变或 MCU 重启使原会话/旧状态失效；MCU 重新查询并建立会话。PC 以 `mcu_boot_id + sample_seq` 新旧关系维护状态，若 MCU 启动代次的唯一性尚无可靠持久化保证，必须在报告中标记来源身份不可靠，不能伪造跨重启严格配对。
5. UART CRC、长度、版本、保留位、valid/source/state 组合、位置和角度已配置范围均需检查；失败时不更新已发布状态。收到 NACK、超时或串口断开后，两路分别统计；某一路重试不得卡住另一条。接收方标注最后样本年龄，超时后状态变为“过期”，而非永久显示最后值为当前值。

建议测试初值 20 个状态快照/秒。每包 82 字节，单链路约 1640 字节/秒；50 Hz 约 4100 字节/秒，均未计入 ACK、重试和串口处理延迟，须实测负载后再提高。115200 8N1 名义单向上限约 11520 字节/秒，两路是**各自独立**的串口，而非共享同一 11520 字节/秒。重复发送要限速，避免接收 FIFO 被耗尽。实体急停仍走独立安全硬件，不依赖 UART ACK。

## 5. FPGA 与上位机如何使用状态

FPGA 接收有效快照后保留 `(fpga_epoch, session_id, mcu_boot_id, sample_seq, mcu_time_us)` 与各字段有效/来源。当前 [几何控制单元](../fpga/rtl/geometry/README.md)只预留旧 V1 `angle_mdeg` 接口，**还未解析 `0x11`，也未把 Roll/Pitch/XYZ/颜色送入板级视频链路**。将来几何处理按源帧曝光时间选择/插值姿态，并按帧原子锁存参数；Roll 的面内旋转与 Pitch 的透视效应应分别建模，XYZ 平移可能引起视差，不能把五个量简单相加成为单一角度。颜色预设用于实验元数据/必要的处理模式选择，不自动改变未经标定的像素算法。

上位机接收同一 `sample_seq` 的镜像状态，记录 MCU 设备时间、PC 接收时间、FPGA 确认/应用状态和 run_id。**PC 到达时间不等于图像曝光时间**；没有板端曝光时间映射、帧 ID 和同帧快照时，只能显示近似工况，不能声称“该 HDMI 帧对应这个角度/位置/颜色”。如果任一有效位为 0 或样本过期，预览 UI 必须显示未知/失效而非沿用旧数值。保存原始二进制报文及解码元数据；展示图像仅为派生可视化。

## 6. 实施与验收门槛

- MCU：从真实反馈形成快照，完成两 UART 独立队列、复位代次、版本化三色配方和坐标、重试/丢包计数；不能把目标角/目标位置/目标颜色冒充当前反馈。
- FPGA：扩展 `mcu_protocol` 的 `0x11` 解析、72 字节长度和能力协商，增加独立 MCU UART 与事件 CDC、帧关联及诊断；维持旧 `0x10` 的字节语义不变。旧 V1 端点只支持照度与单角度，**不能满足本草案的六项回传**。
- Host：在 `host/` 实现 MCU 第二串口的独占接收、CRC/去重/时间戳、状态失效和页面显示；不复用视频 UDP 端口，不将 PC MCU 串口与板载 CP2102 诊断口混淆。
- 联调：用相同 `mcu_boot_id + sample_seq` 验证两路内容一致；逐项覆盖 Roll、Pitch、X、Y、Z、三色预设、切换中无效、急停、MCU/FPGA 单独复位、单链路掉线与恢复。最后用独立量具/光谱或色温测量核验实物精度和颜色；未实测前只报告协议与仿真通过，不报告机械/光学精度或逐帧同步通过。

此文件是**设计草案**，不是已经烧录或已通过双 UART 板测的实现记录。冻结预设颜色、机械坐标零位、真实引脚和固件版本后，应再更新 V1 权威协议、FPGA/MCU/host 实现及相应测试向量。
