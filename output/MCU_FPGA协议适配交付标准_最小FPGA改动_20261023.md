# MCU↔FPGA 协议适配交付标准（最小 FPGA 改动版）

日期：2026-10-23。性质：供其他智能体直接执行的任务、修改边界与验收标准；本文不表示各项已完成。

> 后续用户授权覆盖：FPGA执行阶段必须严格LUT<70%，允许扩大资源重构并按需撤除组件，因此“最小改动”不再限制必要的等价存储/运算重构。当前板级候选保留MCU协议及姿态有效性规则，关闭自动图像控制、自定义LUT和独立C6视口变换，接口与实际执行证据见[执行记录](../fpga/reports/MCU板级接入执行记录_20261023.md)。任何后续智能体必须从当前冻结候选继续，不得回退到被常量禁用MCU而得到的旧低资源结果。任务边界止于位流生成之前；不得执行bitgen或烧录。

> **最新分工边界：用户要求本轮完成设计与布线前验证后停止，不启动布局布线；布线由其他智能体监控。** 本轮交付冻结源码、Compile/SYN/MAP、同源功能回归、资源整数门禁、综合报告内置时序审查及MAP例外继承检查。`whole_design_route_allowed=false` 与 `bitstream_generation_allowed=false` 保持；后续布线智能体在接到用户任务、复核交付后才可开启布线门禁。综合SNR的估计时序不替代完成布线后的STA；空Fast Corner表不得当成双corner通过，CLI不支持的SYN DB诊断不得伪称完成。

资源验收必须分别读取本候选原生MAP和完成布线后的PRR：两阶段均要求总LUT不超过46,619，不能仅看四舍五入百分比；PRR按CLMA+CLMS物理LUT计算，Distributed RAM是子集，不重复相加。内部STA与外部I/O时序分别报告；资料缺少的相机输出延迟、RGMII延迟状态或连接偏斜不得用猜测预算补成通过。保持`bitstream_generation_allowed=false`，即使内部时序和资源通过也不自动生成位流。

后续时序修复必须保持以下不变量：任务在目的时钟域完整捕获后才发布valid，返回统计在源域捕获后才发布done；不得恢复借用总线直接控制另一时钟域的ready/状态。宽捕获寄存器允许常量裁剪但禁止重定时，实际变量端点须在新SYN/CCR中核实。对异步复位的例外必须有可复核的assert-only证明，并限定到原生异步C/P支路；FSM重编码时须验证例外继承，不扩大到整个时钟、IP或数据/使能路径。

kind9参考实体的分拍校验仍检查原始完整正文；只有校验通过后才可把已知固定字段显式常量化入帧银行。内部等待标记不得上线，128周期未完成返回BUSY且保留幂等重试事务。首帧必须等待参考seed可用，关闭控制的模式不能被此等待卡住。验收同时覆盖精确有符号算术、非法保留字段、输入中途变化、复位、UART重试及源帧身份。

kind7相机实体的防闪烁校验同样采用有界分拍运算：原始line_ns/period精确绑定缓存结果，其它字段与版本、状态仍实时检查。kind7/9共享内部等待规则，不修改线上返回码和正文长度。相机按用户确认采用模组直接连接板卡，以reference资料为性能依据；直连不等于器件tCO和PCB偏斜为零，缺失的保证范围须在交付中明示。

ADS状态机重编码后，异步复位例外应在MAP阶段使用SCF，限定实际C/P引脚；本项目通过原始`i:`实例/`t:`引脚对象形式匹配，每一源/端点单独检查。要求原生正例保留全部旧时钟/例外、故意缺失源和端点负例明确拒绝，不接受仅CCR零错误或文本里存在命令作为继承证据。任何STA-3015均在进入物理任务之前阻止执行。

完整ADS工程可能已注册SCF但MAP静默漏载；必须核对最终DMR的实际十条命令和原生成功导入日志，并比对旧时钟、例外和PCF物理约束。必要时使用`fpga/scripts/map_postsyn_candidate.py`从已验证SYN数据库派生独立MAP候选，保留父候选原始证据；同源仿真须重新绑定最终候选。此方法不授权布局布线，不能把仅有SCF文件或原生退出0当作已消费证明。

缓存身份比较必须保持完整原始正文、任意位变化当周期失效及精确ABA语义。若工具将宽比较映成串行carry链，应采用有官方属性依据的分组组合比较，不能改成不检查保留位或增加未受协议约束的迟滞。验收新增逐位翻转、缓存/进行中ABA及旧新逐周期差分，并读取新综合报告确认逻辑链消除和资源门槛。

多个智能体可并行审查、修改独立模块和运行仿真；原生PDS须通过同一进程锁串行运行。每个候选重新冻结生产RTL/约束及哈希，仿真证据与该候选逐字节绑定；失败、未执行或空的用例集合不能当作通过。中间候选的面积、PLC布局估算和旧位流不能替代当前完整路由及min/max STA。

## 3. 冻结的线上协议

下列均保持不变：

| 项目 | 交付要求 |
| --- | --- |
| 物理协议目标 | FPGA独立口，460800、8N1；F4当前实现为USART6；不得借PC口逐包转发 |
| 外层 | `55 AA`、version=2、cmd:u8、seq:u16、length:u16、payload、CRC16，整数小端 |
| CRC | CCITT-FALSE，poly=0x1021、init=0xFFFF，覆盖version至payload，CRC小端 |
| Profile / tick | `0x4D32` / 1MHz |
| 请求长度 | INFO=0，OPEN=16，CONFIG=12，STREAM=16，SYNC=24，ACK_EVENT=16字节 |
| 回复长度 | INFO=64，OPEN=24，CONFIG=280，STREAM=20，SYNC=40，ACK_EVENT=20字节；均指payload |
| STATE / EVENT | 96B / 40B，现有字段偏移不变 |
| FPGA发送权限 | 仅现有0x40/41/42/43/45/49；不添加MOVE/HOME/标定/PC控制心跳 |
| 正常流 | 支持200Hz，保留100Hz及关闭；200Hz是发送目标，不代表测量更新率 |
| 重试 | 原seq、原载荷幂等；不将重复请求执行成新事务 |

不得升V3、增加线上长度、挪用保留字段、按客户端私自改同版本配置实体，也不得用“双方一起改”代替兼容现有FPGA的测试。

## 4. MCU侧必须完成的工作

### A1. 统一 GET_INFO 与 OPEN 的事件起点

必须消除已复现的“INFO提示下一事件6，OPEN却重放事件1”停滞。

验收使用以下不变量，不要求接收方改成接受任意跳号：

1. 记FPGA从成功GET_INFO计算的事件水位为 `E`：有首条可重放事件时为 `first-1`，否则为返回的 `latest`。
2. 对应新会话OPEN成功后，MCU的 `ack/sent_event` 起点必须与 `E` 一致，首次实际发送必须是 `E+1`（存在时）。
3. 同一OPEN精确重试不能二次回退水位、重复取消任务或重置已经运行的会话。
4. 已被重试缓存接受的事务保留原请求与回应语义；新的seq或session不得被当作旧事务。

**优先实现方式：在MCU的FPGA端口保存有界的握手快照。** GET_INFO确定一份事件起点及有效上下文，OPEN采用该快照，而非重新按旧会话ACK或实时oldest分别计算。按当前200ms请求超时及两次重试，为快照选择有依据的有效期，并测试边界；不要只改一个赋值而留下INFO→OPEN竞态。

必须处理以下竞态：INFO回复丢失、INFO/OPEN重试、期间产生事件、旧会话ACK在途、期间日志回卷、MCU重启。若起点所需记录已丢失，拒绝该OPEN并返回既有明确错误；不能返回成功后跳过事件ID。已有会话中发生不可恢复的日志缺口时，显式进入故障/失效流程并要求重新建会话；不承诺有限日志永不丢失。

发生无法交付的事件缺口时，不得继续呈现“姿态可用且事件正常”的假状态：保留故障/溢出证据，向FPGA提供一致的无效姿态状态，并使后续事务进入可观察的失败/重建路径。真实自动重建由阶段B的会话管理器负责；阶段A用测试端提供新的session验证恢复。

不修改PC运动租约含义，不让FPGA事件处理接管PC控制权。不能简单让新会话沿用旧ACK而忽略“全部事件已确认”和日志回卷场景。

### A2. 分开控制存活与视频姿态新鲜度

- 允许保留当前 `POSE_STALE_US=250000` 作为MCU控制反馈存活/容错窗口；不得全局退回20ms并重新引入已修复的运动误停。
- 为FPGA发布增加独立的姿态新鲜度策略，使用真实采样时间检查；基础预算不超过20000us。它只是MCU发送前筛查，最终仍由FPGA按源帧时刻和时间误差判断。
- FPGA口发布时，任一角轴过期、时间映射无效或采样来自旧boot/config，应将双角姿态标为不可用；同步维护有效位、angle_source和pose_status，不允许“无效位清了但来源/状态仍宣称有效”。保留真实故障与零位状态，不将旧值盖上新采样时间。
- 允许PC诊断继续看到控制窗口内的原始反馈；必须明确两个端口的有效性策略差异。不得让同一config_version的GET_CONFIG因查询端口不同而变成不同实体。
- GET_CONFIG现有body+80继续真实报告该字段约定的控制反馈失效门限；文档单独说明FPGA口20ms筛查与FPGA最终20ms预算，不能暗示FPGA会采用250ms。
- 角度时间戳仍是映射到F4时间域的真实两轴反馈保守时刻；双轴都有效时取最早值。不能用发布时刻、串口接收时刻或XYZ时间替代。
- 若MCU不能持续提供足够新鲜的反馈，先优化F1反馈调度、F4转发与排队，并保留失效状态。不得通过复制样本或伪造时间达到200Hz。

核心标准保持：`age_us + error_us <= 20000` 且 `error_us <= 1000`，具体标定实体可以更严格。MCU发布时通过筛查，不保证经过传输后或在任意视频帧上仍通过；两端各自基于真实时间判定。

### A3. 修正编码器方案的能力声明

补充发现：指定提交的GET_INFO仍写 `boot ? 0x3F : 0x1F`，data+31 `imu_type=1`；这会宣称MPU6050，虽然当前FPGA必要能力检查并不因此拒包。

本次MCU交付必须恢复现有编码器约定：

- feature_flags bit1清零；持久boot正常时为0x3D，失败分支按原故障语义保持0x1D，不用成功应答掩盖boot失效。
- imu_type=0；STATE bit5=0、IMU时间=0，不提供伪IMU采样。
- GET_CONFIG角轴state_source=2；真实有效双角STATE angle_source=0x05、pose_status=3。
- 核查指定提交新增F1诊断字段是否影响F4对旧IMU偏置/零位字段的复制；无效IMU字段按约定保持无效，不把诊断字节作为标定数据。
- 能力向量、实际C builder、测试断言和文档必须同步，不以旧测试“期待imu_type=1”作为保留错误声明的理由。

### A4. 保留标定保护，提供可信配置交付物

默认 `POSE_CONFIG_VERIFIED=0` 必须保留。协议软件验收应验证默认姿态被拒绝，而不是通过修改宏让测试通过。

交付时至少提供：完整GET_CONFIG二进制、字段解码、boot/config_version、配置文件/固件散列及标定状态。只有实物中心、轴向及该位承诺的配置内容经核验后，才交付单独可追溯的已验证配置。

FPGA端GET_CONFIG批准、MCU STATE bit7、kind8姿态到仿射标定、时间误差放行是四个不同条件，不能互相替代。生产路径不得将其中任何一个常量置1来实现“能用”。合成批准只允许存在于清楚标注的测试fixture中。

### A5. 校准测试框架与错误路径

- 基于真实目标提交的receive、configuration、make_snapshot、state_for和wire codec测试，stub仅替代硬件边界。
- 必须覆盖实际 `board_port_poll` 的发送排队及SYNC t3重写路径；仅调用receive生成SYNC不等于覆盖实际发出时间语义。
- 解析错误、忙、缓存冲突、超时、boot改变、config改变、sample序号回绕及session更换均应有确定结果。
- 更新旧测试桩以匹配新增DMA/UART诊断字段，但不得修改被测协议代码来适配陈旧stub。
- PC心跳、已有运动/回正、故障恢复应回归，确保FPGA口适配未破坏控制端。

## 5. FPGA 最小修改边界

### 阶段A：生产逻辑不修改

冻结以下模块的生产代码散列，新增测试不计入生产改动：

- `uart_v2_parser.sv`、`mcu_readonly_client.sv`；
- `pose_frame_selector.sv`、`pose_affine_model.sv`；
- 视频ISP、几何、DDR、帧池、网口、HDMI与现有PC控制逻辑。

阶段A验收必须证明MCU修复后通过**未修改的上述FPGA模块**。不能直接运行旧审查脚本得到通过就宣称修复完成：旧脚本的成功条件包含“复现事件死锁”。新回归必须对同一场景要求事件按序交付、ACK推进；原故障证据另存，不能覆盖。

### 阶段B：优先只新增适配层及必要顶层接线

建议新增 `fpga/rtl/control/mcu_link_adapter.sv`（名称可按现有命名调整），复用已有UART、CDC和核心字节接口；修改 `pango_video_system.sv` 的必要端口/连接及相关源清单、约束。只有无法通过边界连接完成时才变更核心接口，并说明必要性。

适配层必须负责：

| 职责 | 最低验收要求 |
| --- | --- |
| UART | 独立460800/8N1收发，ready表示实际接纳字节；错误和断流可观察 |
| CDC/复位 | 保留完整字节/握手，复位撤销旧上下文；不得用整域false-path掩盖问题 |
| session分配 | 非零、同一MCU boot内重连不复用旧session；处理reopen_required、序号耗尽及FPGA自身复位；计数器复位为1不算满足 |
| 配置批准 | 保存完整264B实体，与版本/批准清单核对；仅版本号相同不足以批准；未知或变化实体撤销批准 |
| EVENT消费者 | 在完整事件已由有界消费者接纳后给ready，避免event_ready长期为0；归档或按已定义只读消费规则记录，不伪称业务动作已完成 |
| 时间边界 | timing_valid仅在真实误差上界可用时有效；合并UART捕获、排队、F1→F4映射与漂移误差，不能只计F4↔FPGA往返 |
| 状态观测 | 至少能区分未连通、会话建立、配置未批准、未同步、姿态过期、待标定及事件故障 |

session可来自已有可信启动身份机制或明确的配置入口；选择方案时必须验证FPGA单独复位而MCU不复位的情况。不为此擅自新增复杂PC协议。

若确认只能修改 `mcu_readonly_client` 才能解决某项问题，先提供最小复现、MCU侧不可解决的原因和差异范围；将其列为独立变更评审项，不把它混入阶段A兼容通过。不得顺便重构协议核心或视频路径。

板级引脚/IO Bank/电平依据匹配板卡资料核验；PDS工程、IP、仿真、约束、时序及下载工作查阅 `E:\PDS_Pangu\PDS_2022.2-SP6.4\doc` 对应版本资料，只读。未获得实物依据时保持物理门控，不能猜引脚开启。

A阶段固定边界用例全部通过；另做至少100轮会话重连，覆盖上述事件起点组合，记录随机种子和失败输入。不得把永久拒包/永不批准当作全功能通过。

C阶段建议最少连续10分钟，并单列静止/运动/故障注入窗口。正常窗口目标：STATE发送200Hz且完整状态接收间隔不超过既定10ms目标；已完成标定与时间放行时，正常视频帧姿态可用比例至少99%。所有被接受姿态仍必须100%满足20ms/1ms门限。报告均值、P95、最大值和总样本数；不能用均值掩盖长间隔。达不到目标就报告差距，不能修改采样时间或门限。故障注入窗口单独统计安全降级与恢复，不混入正常性能口径。

完整实物UART未建立时，C不应执行或声称通过。视频30fps、光学矫正精度、功耗和HDMI源帧身份仍按原专项验收。

交付摘要必须包含：

1. `mcu_baseline`、`mcu_candidate`、`fpga_source_manifest`；是否修改FPGA生产代码，逐文件说明必要性。
2. 每个T项的 `PASS/FAIL/NOT_RUN/BLOCKED`、证据路径、合成/真实标记。
