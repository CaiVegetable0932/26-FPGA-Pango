## 2 仿射替代透视的能力边界

本次选择仿射是用户确认的资源与功能取舍，不把“题目更要求仿射”写成已经核实的规则结论。仿射可表达面内旋转、平移、缩放和剪切，不能精确表达一般俯仰／偏航造成的透视变化，也不能消除一般三维场景平移视差。

继续保留 `k1/k2/p1/p2` 与 `fx/fy/cx/cy`。仿射只是理想输出射线到输入归一化射线的前端，不是删除镜头模型。

定义像素中心为整数，u 向右、v 向下：

```text
[x y]^T = A × [u v 1]^T
A 为 2×3，输出理想归一化射线
之后执行现有镜头畸变模型，再用输入内参转换到源像素坐标
```

沿用六项 S(32,26)、内参 S(32,16)、源坐标及舍入规则。上位机界面使用角度、平移、尺度等易读参数，生成矩阵后预览其有效域，并显示实际量化矩阵；界面值不是 FPGA 已生效值。

### 2.1 当前代码改造

- 正式 `video_memory_core` 固定仿射路径，替换 `PROJECTIVE=1`，删除正式调用链中的深度递推、齐次除法和只为它们存在的寄存／总线。仅切参数不算清理完成。
- 复用 `affine_ray_stepper.sv`。`projective_ray_stepper.sv`、`perspective_divide.sv` 等专用实现退出活动工程；共享乘法器若仍被镜头映射使用必须保留。
- 调整 `geometry_rgb_pipeline.sv`、两类处理 domain／processor、集成接口和 source geometry 保留结构。检查未使用参考适配器是否仍为冻结工程所需，不修改历史副本。
- 全部几何参数仍按源帧原子生效。对旧帧锁存的实体不能因为新配置更新而重新解释。

### 2.2 旧几何协议兼容

保留 `0x94` 的 80 字节长度和 17 词布局，兼容成本比静默改变旧包长更低。新的仿射版本只接受第三行规范值：

```text
a20 = 0
a21 = 0
a22 = 1 << 26
```

非规范第三行拒绝并返回不支持／参数域错误，不静默忽略。内部可只保留 14 个有效词；`0x95` 读回时补回规范第三行，保留既有页布局。能力查询明确 `geometry_model=affine_lens`、`projective_supported=false`。

镜头校准模型与界面导入模型必须匹配。现有 PC 鱼眼 k1～k4 拟合不能直接当作板端 k1/k2/p1/p2；模型不支持时拒绝，不能截掉高阶项伪装兼容。

### 2.3 上位机控制仿射开启与关闭

本功能必须在 FPGA 内实现，并改变实际 HDMI 输出。上位机提供一个明确的“仿射变换”开关，显示开启、关闭、等待生效和失败状态；操作后通过 PC UART 发送指令，不在 PC 中旋转图像来代替板端效果。

这里的“关闭”定义为关闭附加的仿射视图变换，回到已确认的参考视图。仍需基础坐标归一化、镜头去畸变和插值，不是跳过全部几何流水，也不是显示 S0 RAW。

| 状态 | 实际几何参数 | HDMI 应显示的效果 |
| --- | --- | --- |
| OFF | 使用固定参考矩阵 `A_reference` | 无附加旋转／平移／缩放／剪切的参考视图，保留镜头去畸变及独立颜色、亮度设置 |
| ON | 使用当前已验证的 `A_effective` | 显示所配置的旋转／平移／缩放／剪切；启用跟随、防抖、动态视窗时按约定组合 |

`A_reference` 是该分辨率和输出内参下，输出像素到理想归一化射线的映射，必须与活动镜头标定一致。基础未旋转视图可按 `x=(u-cx_out)/fx_out`、`y=(v-cy_out)/fy_out` 构造；不能把六系数写成 `[1,0,0;0,1,0]` 当作关闭，因为该矩阵输出的是归一化射线而非源像素。

参考视图的输出内参和固定取景范围作为版本化 `AFFINE_REFERENCE` 实体，经统一实体接口提交；必须检查正焦距、坐标范围、定点格式及其与镜头模型的兼容性。首次启动使用明确记录的基线参考，不能从当前任意旋转矩阵反推“关闭值”。

镜头 `k1/k2/p1/p2`、输入 `fx/fy/cx/cy` 不因本开关清零；颜色矩阵、黑电平、增益和亮度策略不因本开关改变。S0 网络回传保持原始来源。关闭不清除已配置的 ON 矩阵，再开启恢复人工配置，或从新的有效源帧重新建立动态变换。

#### 命令与读回

新增候选 PC 命令 `0xA6 SET_AFFINE_ENABLE`，冻结前按第 5 节执行命令占用核对，不能复用已撤销的 0x93/96/97。外层仍为 PC V1。请求 payload 为 12 字节，小端：

| 偏移 | 字段 | 要求 |
| --- | --- | --- |
| 0 | `enable:u8` | 0=OFF，1=ON；其他值拒绝 |
| 1～3 | `reserved[3]` | 必须为零 |
| 4～7 | `control_version:u32` | 独立开关版本，合法范围 1～0x7FFFFFFF，正常更新递增 |
| 8～11 | `expected_geometry_version:u32` | 必须匹配板端当前已生效的几何实体，防止对过期参数启用 |

例如，在已生效 geometry_version=7 的前提下，关闭 payload 为 `00 00 00 00 01 00 00 00 07 00 00 00`；随后开启 payload 为 `01 00 00 00 02 00 00 00 07 00 00 00`。这只是待实现协议的载荷示例，发送端仍需添加外层长度、序号和 CRC16。

几何／参考实体提交与开关共用有界提交仲裁器；存在冲突待应用事务时返回 busy，先完成或明确取消原事务。保持同一序号与相同请求内容的重试幂等，不重复增加开关版本。版本不符、非法 enable、保留位非零或缺少有效参考／目标矩阵必须明确拒绝。

成功 ACK 表示 validated/queued。通过 `0xA4 READ_ENTITY` 的 `AFFINE_CONTROL` 状态记录读取 `requested_enable`、`applied_enable`、`control_version`、`geometry_version`、`reference_version`、实际六系数、pending／错误原因，以及实际应用的源 `epoch/frame_id`。新增能力查询提供 `affine_toggle_supported`，不占用旧快照 capability bit8。

#### 帧边界与显示语义

开关状态在合法源采集边界与对应矩阵版本一起锁存，每个源槽和处理作业携带自己的 enable、版本和实际矩阵。旧排队帧保持旧状态，新源帧使用新状态；不得在处理帧中途切换全局矩阵选择器。结果完整写入并在显示边界切换后，HDMI 才出现新效果。

上电默认 OFF，加载并校验有效参考后输出基线视图；host 读取实际状态，不自动假定上次界面开关仍生效。正常 PC 断开不改变已生效状态；板卡复位后重新查询能力与版本。软件界面分别显示“源帧已应用”和“板端显示帧已采用”状态，后者需由显示槽描述符确认；这仍不等于采集卡回调已有可信源帧号。

第 6.3 节的 `A_effective=S×M×V` 只在 ON 时应用。OFF 时 MCU 跟随、防抖补偿和动态裁边的附加变换不进入结果，保留其用户配置并显示“受仿射总开关旁路”。历史补全在 OFF 参考显示模式中暂不应用。开关切换时清理不兼容的轨迹／历史引用；重新开启只使用新的有效状态和已验证历史，不叠加旧补偿产生突跳。主视频旧事务照常排空，不能为开关直接清空在途 DMA。

本开关用于画面对比，不承诺关闭后停止全部几何计算或产生指定功耗差。无需第二套视频流水，使用帧级矩阵选择与元数据即可；新增寄存、控制和读回资源计入现有预算。

#### 实现与验收

- FPGA：修改 PC 命令解析、帧参数保留、调度／几何作业描述符及显示状态读回；开关选择放在帧参数层，不做逐像素宽总线广播。
- host：增加命令编解码、串口发送／重试、能力检查、开关控件、版本和生效读回；OFF 时仍允许编辑／提交待启用的仿射参数，但必须显示尚未应用到当前画面。
- 用不对称静态图卡和已知非零旋转、平移、缩放分别验收 OFF→ON→OFF：ON 符合参考模型，OFF 回到相同参考；镜头和颜色／亮度参数保持相同。
- 覆盖帧中发命令、多个源帧排队、版本冲突、CRC 错误、重复请求、串口重连、FPGA 复位，以及跟随／防抖／裁边／补全组合。不能出现半帧混合、旧帧被新状态重解释或帧槽泄漏。
- 比较图像时固定 AE/AWB 和自动 Gamma，或完整记录其变化，避免把曝光／颜色波动当作仿射效果。动态场景的两次显示不是同一源帧，不声称同帧对比；不恢复已删除的同源快照。
- 完成标准包含两种实际 HDMI 效果、板端生效版本／源帧证据及新版本资源／时序检查；仅 UI 开关变化、串口 ACK 或 PC 软件效果不算完成。

## 3 精简后的亮度方案

只保留一个可选的前置曲线模块，位置仍为“S1 四邻域读出后、双线性插值前”。S1 保持基础 ISP 输出，S0 不受 FPGA 曲线影响。不增加 CLAHE、直方图均衡、独立 RGB 三曲线或后置增强通路。

| 模式 | 上位机操作 | FPGA 行为 |
| --- | --- | --- |
| OFF | 关闭增强 | 跳过曲线，直接插值 |
| MANUAL | 选择内置曲线，或输入 Gamma 生成 256 项 LUT 后上传 | 对 R/G/B 使用同一 LUT，按实体版本应用 |
| AUTO | 设置目标亮度区间、阈值、迟滞、最小保持帧数和允许曲线集合 | 用已完成的 S1 统计选择内置曲线，应用于后续采集帧 |

保留 3 档初始调试曲线，例如 gamma=0.7、1.0、1.3；这些仅为调试初值，后续依据实测修改，不能称为已标定增强。Gamma 的指数运算在上位机离线生成或构建时完成；FPGA 不增加浮点幂函数。

自动选择使用 S1 ROI 的亮度和、样本数、暗部／饱和计数。通过 `sum < threshold × count` 等比较避免逐像素除法；统计只在帧完成且源帧合法后提交。当前帧结束得到的统计不得标成已影响该帧。

### 3.1 LUT 实体与页寿命

保留 256×8 bit 单曲线和 12 路读表副本，以满足四邻域 RGB 的吞吐；删除 post 地址选择和结果查表路径。主要精简来自功能与控制，不能宣称 12 路表可以直接合并为单读口而不降低吞吐。

使用两页版本化表。每个采集源槽绑定 `tone_entity_id/tone_version/page_id`，几何作业使用源槽绑定页。队列中的旧源帧仍引用旧页；新曲线只能覆盖引用数为零的页。读表副本必须整组写满并校验后才发布。

当前 `rgb_enhance` 的写表许可和全局活动页不足以直接支持这个队列语义，必须改造：

1. 上传先进入小型暂存区；旧页使用期间不能原地写入。
2. 在几何空闲边界向空闲页复制全部 256 项，保持实际 RAM 同址读写语义安全。
3. 完整发布后，新采集源帧绑定新页，旧源帧继续用旧页。
4. 两页都被占用时维持旧曲线，延后提交或返回忙；不阻塞不可暂停的 DVP，不为换曲线隐式丢帧。
5. 自动选择请求可以合并为最新目标，人工已接受的事务必须报告 applied、rejected 或 superseded，不能无记录丢弃。

自动档位的曲线数据本地存放，切换不依赖 PC 每次上传。曲线切换频率受迟滞和最小保持帧数限制，避免持续页等待。历史补全读取原始历史 S1，使用当前输出帧所绑定的同一曲线，不要求无限保存旧增强页。

### 3.2 曝光与增强的职责

曝光／传感器增益改变 S0；Gamma 只改变结果显示。先用受约束 AE 保持信号质量，再用较慢的自动 Gamma 调整显示；设置稳定等待、死区和速率限制，避免两个闭环相互追逐。

上位机必须显示“相机曝光／增益”和“FPGA 曲线”两个独立状态。几何和颜色测评提供固定曝光、固定增益、固定白平衡、增强关闭的可复现配置。

## 4 颜色矫正与基础 ISP 参数接口

保留 `rgb_colour_matrix.sv` 的 12 bit 线性输入，先完成矩阵乘加，再按现有规则量化／钳位到 RGB888。禁止先量化到 8 bit 再冒充 12 bit 色彩校正。

新增统一的 ISP_COLOR 实体，至少包含：

| 字段 | 格式／语义 |
| --- | --- |
| `schema_version`、`entity_id`、`version` | 可回读，版本递增 |
| `black_level[4]` | R/Gr/Gb/B，各 u8 |
| `channel_gain[4]` | R/Gr/Gb/B，各 U(16,12) |
| `ccm_enabled` | 关闭使用单位阵，并保持量化／流水时序一致 |
| `ccm[9]` | 行优先，有符号 S(18,14)，线上以 i32 符号扩展传输 |
| `wb_mode` | FIXED／AUTO_BOUNDED，及实际采用的通道增益 |
| `calibration_id`、CRC | 指向真实标定来源和完整实体内容 |

上位机提供 3×3 编辑框、导入／导出、单位阵恢复、启停、四通道黑电平与增益、标定来源和生效版本显示。界面只编辑草稿，点击应用后才提交整组；不能每个输入框修改都导致半套矩阵生效。

校验系数范围、矩阵行和的数值上界、乘加位宽及截断／饱和规则。不能只检查单个系数落在 18 bit 内就认定整组不会溢出。Bayer 相位不作为随手可改的颜色参数，变更需走相机模式／epoch 重建流程。

颜色实体在采集帧边界整体锁存；源帧记录实际 `isp_version`，处理结果继承该源帧颜色实体。运行时 CCM 会使原来单位常量的优化失效，不能沿用当前 78 LUT／3 APM 作为最终资源承诺。

## 5 上位机统一控制协议

保留 PC UART V1 外层、115200 8N1、CRC16、序号和启动机制，与 MCU V2 独立。新命令以下作为本方案分配的候选编号，编码前须检查整个 PC 命令注册表并在权威接口文档冻结；如已有占用则改编号，不能覆盖旧语义。这些命令当前尚未实现。

| 候选命令 | 名称 | 作用 |
| --- | --- | --- |
| `0xA0` | GET_CAPABILITIES | 分页读取 profile、支持实体／版本、容量与当前启用能力 |
| `0xA1` | BEGIN_ENTITY | 建立一个有界上传事务 |
| `0xA2` | WRITE_ENTITY_CHUNK | 按偏移上传最多 64 字节 |
| `0xA3` | COMMIT_ENTITY | 完整 CRC／语义验证后排队应用 |
| `0xA4` | READ_ENTITY | 读取活动、待应用或指定保留实体，含版本及实际生效边界 |
| `0xA5` | CONTROL_ACTION | 防抖参考重置、历史清空、查询事务／明确取消等离散动作 |
| `0xA6` | SET_AFFINE_ENABLE | 独立开启／关闭 FPGA 仿射变换，12 字节载荷见第 2.3 节 |

载荷采用小端，保留位必须为零。初版 BEGIN_ENTITY 为 `kind:u16, schema:u16, txid:u32, version:u32, entity_id:u32, length:u16, reserved:u16, crc32:u32`，共 24 字节；CHUNK 为 `txid:u32, offset:u16, count:u8, reserved:u8, data[count]`。单实体上限 1024 字节，单个 CHUNK 不超过 72 字节，不通过扩大 PC 单包长度来绕开当前解析器限制。

COMMIT 至少携带 txid、整体 CRC32 和应用策略。所有 payload 的最终字节布局、回复页及动作枚举必须写入 `fpga/config/integration/PC_RGB_CONTROL.md` 并配套固定字节向量后再实现，禁止各端自行补字段。整体 CRC32 与外层 CRC16 各司其职。

初版只允许一个未完成上传事务，分块必须连续；相同 txid、offset 和相同字节重试可以幂等确认，内容冲突则拒绝。只记录已接受字节前沿和有界重试状态，不增加无界事务队列。超时清除暂存，正在使用的实体不受影响。

实体种类包括 TONE_CONFIG、TONE_LUT、ISP_COLOR、STABILIZATION_CONFIG、VIEWPORT_CONFIG、COMPLETION_CONFIG、CAMERA_CONFIG、POSE_AFFINE_CALIBRATION、AFFINE_REFERENCE，以及用于开关状态读回的 AFFINE_CONTROL。AFFINE_CONTROL 的状态更新只通过 SET_AFFINE_ENABLE 和内部生效记录完成，不允许通用实体上传覆盖其状态。新增内容不得塞入现有保留字节或擅自改变 S0 PRAW V1 头。

### 5.1 兼容与应用语义

- `0x71/0x90/0x94/0x95` 保留；`0x94` 按仿射兼容规则限制第三行。
- `0x92 mode=0` 表示关闭；mode=1 表示启用已提交的前置曲线策略；mode=2 返回不支持。新 tone 实体与旧 0x92 经同一提交仲裁器处理，活动状态只有一个权威来源。
- `0x93/0x96/0x97` 按快照删除交接撤销，不复用为新功能。
- 增加 profile/schema 能力协商。新实体读回使用独立布局标识，旧 RGB1 页保持既有含义。
- ACK 表示校验／排队成功，不等于生效。读回至少区分 received、validated、queued、applied、rejected、superseded，并提供实际 epoch/frame_id、版本和原因。
- 短期需要几何、颜色、曲线同时改变的预设，首版先由上位机逐实体提交并明确过渡帧；不宣称多个独立 ACK 等于跨实体原子应用。严格测量只取全部预期版本已生效后的数据。
- 断开 PC 后，FPGA 使用最后有效配置和本地闭环继续运行。恢复连接先读能力、版本和设备代次，再决定是否重发；不盲目恢复旧事务。

上位机新增板端算法页，分为几何、亮度、颜色、防抖／裁边／补全、相机、MCU 跟随。各区显示请求值和实际值、来源、版本、生效状态及降级原因。PC 软件参考预览保留明确标签，不将其按钮当作板端生效证明。

## 6 C 系列剩余功能实现

### 6.1 C3 MCU 姿态到受限仿射

接入现有 `mcu_readonly_client`、`pose_frame_selector` 与 MCU_POSE_V2。保留独立 MCU→FPGA UART、会话／boot/config 核验、时间映射误差及曝光参考选取。PC 不逐包转发姿态；FPGA 不下发运动命令。

C7 的删除只排除相机 IMU 防抖和逐行补偿，不删除 F1 既有 MPU6050 与舵机优先的机械姿态融合。pitch/yaw 仍为机械相对角；yaw 不能当画面 roll；归一化 XYZ 不能当毫米平移。

新增 POSE_AFFINE_CALIBRATION：参考机械角、参考六系数、针对 pitch/yaw 的局部系数变化率、有效角域、误差上限、模型来源和版本。首版使用固定点局部线性模型，由 FPGA 按有效姿态生成六系数。标定可由 PC 离线完成，但在线矩阵生成不依赖 PC。

局部模型约定为 `A = A_ref + J_pitch × Δpitch_rad + J_yaw × Δyaw_rad`，变化率单位为每弧度；机械角线上单位仍按 MCU V2 转换，不改变旧协议。模型定点格式、角域和中间乘加上界在实体定义中冻结，并用独立浮点基准核验，不用相同定点实现充当参考答案。

该模型只是经验证的小范围近似，不称为透视等效。目标场景、安装位置、焦距或图像裁剪改变时重验。超域、无效角、时间映射不可信或标定缺失时降级到最后确认的手动参考，不伪造动态补偿成功。XYZ 只做设备位置记录，除非另有物理标定模型，不进入像素映射。

### 6.2 C4 视觉防抖

由 FPGA 从 S1 分出经低通缩小的亮度图，用有界块匹配／多区域背景运动估计得到平移和小角度旋转／尺度变化，再做因果轨迹平滑、补偿限幅。首版比较低分辨率候选，按资源与误差选择，不直接承诺 480×270 或任意运动范围。

运动估计与补偿在明确的坐标域完成；强畸变下不能把未校正图全局仿射直接当作理想射线变换。可以对稀疏匹配点应用离线生成的校准坐标关系，再求受限模型，具体误差须验证。

同一帧的运动结果必须在其几何作业开始前准备好；按 source id 对齐，不用“最新完成的运动”代替该帧运动。超时使用明确旁路／减弱策略并计数，不借用未来帧。

用户界面支持关闭、参考重置、平滑强度、最大补偿及质量阈值。MCU 跟随控制目标视图，视觉防抖消除残余抖动；两者同时启用必须通过组合测试，防止把有意云台运动抵消或重复补偿。

### 6.3 C6 视窗与联合映射

提供保留视场、固定裁剪、受限动态裁剪三种模式。固定最大缩放、变化速率、迟滞与最小有效面积；用户能看到保留视场比例和当前缩放。

固定矩阵组合定义：输出像素先经视窗映射 V，再经参考／机械跟随映射 M，最后应用定义在理想源射线域中的防抖补偿 S，即 `A_effective = S × M × V`，均按 3×3 仿射形式相乘后保留前两行。运动估计模块若采用其他正逆方向，必须先显式转换为这里的 S，不能调整乘法顺序来凑画面。

用非对称图案、单轴正负变换和已知位移验证方向。全部变换与镜头模型合并到一次当前帧重采样，不增加完整“先矫正、再防抖”的帧级二次插值。

裁剪有效性须涵盖非线性镜头映射和插值邻域，不能只验四角。若采用网格近似，须给出保守边界和全像素离线验证；不能保证全域时明确显示剩余无效区域。

### 6.4 C5 一帧历史补全

历史仅保存真实 S1，首版最多一帧。对当前合法帧的几何视场外区域尝试历史对齐采样，优先当前有效像素；没有可信历史则保持无效／黑边或由受限裁边处理。

不递归使用上一次已补全结果作为新观测，不用历史内容掩盖 DMA、算术或输入坏帧。检查历史年龄、配准置信度、遮挡／前景运动、曝光与颜色实体兼容性；场景变化和模式／epoch 切换必须清空历史。

历史帧引用包含源 epoch/frame_id、颜色／相机／几何实体和配准版本。界面提供关闭、最大历史年龄、置信度阈值及清空；首版一帧深度固定，不展示未实现的多帧选项。

首选复用现有 SRC 中一个额外受控历史引用，先证明三个源槽在目标吞吐下可周转；保留槽不足时允许本帧跳过补全并统计，不能卡住采集或假报补全开启有效。若持续无法满足，分配一块新的 8 MiB 历史区并计量复制读写，另行冻结地址布局。不得把已经删除的两个快照银行原样恢复。

内部“当前像素／历史像素／无效”掩码与结果同路，保留每帧历史引用和覆盖计数。历史结果是多源派生图像，不把其全部像素称为单一源帧原始结果。正常 S0 网络仍仅输出 RAW_LIVE，不重新引入视频快照导出。HDMI 来源未验证时仍为 unverified。

上位机提供测量预设和视频增强预设。测量预设关闭历史补全，冻结或完整记录实际几何／颜色／曲线参数；视频增强预设允许补全，但图像质量指标必须区分当前有效区域与历史填充区域。预设仍遵守跨实体应用的过渡帧规则。

### 6.5 C8 相机 AE 与 AWB

完成固定曝光／增益与受限自动曝光，曝光上限受实际 30fps 行时序及余量限制，禁止通过增加 VTS／夜间模式偷偷降帧。150 Hz 灯光条件优先比较其整数周期曝光档位，寄存器值按实测行时间换算；不把模型值当成防条纹实测。

颜色自动控制优先采用 FPGA 四通道增益的受限 AWB，与 CCM 职责分离。统计使用增强前信号，可增加抽样 RGB 和／有效计数以及暗、饱和排除；有限变化率、增益上下限和中性区域适用性必须显式配置。相机侧白平衡保持明确固定配置，避免传感器与 FPGA 双重闭环。

相机曝光写入沿用 SCCB 所有权、掩码、回读与错误边界。当前寄存器服务只允许 quiesced 写，不能仅去掉保护就宣称在线 AE。实施须基于 OV5640 官方资料验证安全组写／生效时刻和旧新曝光帧归属；若不能证明，需要单列停流配置过渡模式，在线连续 AE 仍标未完成，不能以此代替最终功能。

AE 算法在 FPGA 控制侧按已完成统计运行，PC 只传目标、模式和限制。相机参数、实际回读、有效生效区间、失败原因都可回读；不确定的过渡帧不冒充精确曝光绑定帧。

## 7 帧身份与实体统一

每个源帧在采集边界绑定几何、ISP 颜色、曲线策略／页、相机配置以及姿态选择结果。处理作业另绑定防抖与视窗最终矩阵、历史引用和质量状态。实体采用有界版本／句柄，不把所有大矩阵逐像素携带。

源槽、作业和历史消费者释放前，对应实体不能被覆盖。通用引用、generation、64 bit ticket、错误处理和取消排空继续保留；不能为了资源目标删除这些机制。

元数据扩展同步 FPGA package／生成布局／host 解码与协议文档。保留现有 RAW PRAW 头，新增参数关联采用版本化控制记录。PC 不根据串口消息先后或 HDMI 到达时间推断逐帧绑定。

同源快照删除后，仿真使用内存观察／记分板验证同源像素。实板可以分别验证标定、图卡、显示质量和吞吐，但在没有独立来源证明前，不能发布严格 S1／结果逐像素同帧实测结论。新功能完成不自动补回该取证能力。

## 8 资源和性能预算

当前已核实 MAP：41,477 / 66,600 LUT，即 62.28%；当前目标严格低于 70%，整数上限 46,619。详细依据见[资源评估](../fpga/reports/功能裁剪与LUT资源评估_20261020.md)。

旧基线上的规划差值：删除快照约 3,200～5,000 LUT，透视替换仿射约 2,000～2,600，删除 post 约数十～200。基础版预算约 33,700～36,300 LUT，仅是旧报告推算，必须重新 SYN/MAP。不得把这个值当作加入 C 系列后的最终占用。

以下是新增能力的分配上限目标，不是已有模块面积或保证能实现的估算：

| 新增／扩展区域 | LUT 增量目标上限 |
| --- | ---: |
| 动态 CCM、ISP 参数与版本保留 | 900 |
| 自动 Gamma、上传与页管理 | 700 |
| MCU V2 接入及局部仿射模型 | 1,000 |
| 低分辨率视觉防抖 | 2,500 |
| 有效视窗／自动裁边 | 400 |
| 一帧历史补全与缓存／引用扩展 | 1,700 |
| 相机 AE/AWB、共享扩展控制及其余统计 | 800 |
| **新增总预算** | **8,000** |

基础版若为 36,300，加上 8,000 为 44,300，约 66.52%，距离严格 70% 上限还剩 2,319 LUT。真实共享成本、跨域、总线和控制集都计入预算，不能只统计算法模块。APM、DRM、FF 和 DDR 混合带宽另设并跟踪预算，不能仅守 LUT。

任一阶段超预算：先优化复用、低分辨率、匹配区域／搜索范围、顺序控制和数据布局；不得默删用户保留功能，也不得降低主视频真实 1080p30目标或放宽时序。若仍冲突，提交准确资源／吞吐证据及可选取舍，标明该功能未完成。

性能验收分别记录真实源帧率、完整 RAW 网络帧率、处理新帧率、HDMI 新帧及重复帧。防抖／补全开启组合必须独立通过，不能拿关闭这些功能的结果替代最终组合。LUT 低于 70% 不保证布通。
