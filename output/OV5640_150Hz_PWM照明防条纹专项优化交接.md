- 版本：V1.0
- 日期：2026-10-12
- 文档性质：专项设计、开发交接与验收方案；不是实测报告。

## 1. 专项目标与边界

在现有 OV5640 单路摄像头链路中，降低测试箱 150 Hz PWM 照明引起的横向明暗条纹和帧间亮度波动，保留可重复的曝光、增益、白平衡、灯光和时间证据。

本专项应交付：

1. 摄像头配置与实际行时间核验结果。
2. 固定曝光、固定增益的可重复测试模式。
3. 必要的 SCCB 寄存器读取、写入与回读验证能力。
4. 多占空比条件下的原始采集证据、条纹指标及源帧率记录。
5. 自动曝光是否适配 150 Hz 的独立结论，或无法满足的明确范围。

当前可用的代码入口是 `mini_camera_diag` 的 720p RGB565 诊断路径。本专项对它的改进不能当作正式 RAW8/1080p30、FPGA ISP、几何矫正或网络回传验收。正式 RAW8 模式建立后，必须重新测量行时间并重算曝光与防闪烁参数。

PC 可用于测试控制、采集和离线测评；主视频仍由 FPGA 处理，PC 不转发主视频、不承担实时几何矫正。

## 4. 防条纹原理与曝光候选

### 4.1 已知频率条件下的曝光匹配

OV5640 采用卷帘曝光，各行曝光窗口起点不同。稳定周期照明下，如果每行积分相同的整数个完整光强周期，积分结果理论上与曝光起始相位无关。

设实际光强周期为 T_light，曝光时间为 T_exp：

- 标称 150 Hz 对应 T_light = 1/150 s = 6.666666… ms。
- 目标条件为 T_exp = N × T_light，其中 N 为正整数。
- 分析假设：各行曝光时长一致，照明在曝光窗口内保持稳定周期，PWM 占空比不在窗口中途改变。
- 这不是“曝光超过一个周期即可完全消条纹”；非整数周期仍可能产生残余条纹。

| N | 标称曝光时间 | 优先场景 | 约束 |
| --- | --- | --- | --- |
| 1 | 6.667 ms | 动态、云台和运动测评 | 150 Hz 下最短整数周期档位 |
| 2 | 13.333 ms | 较弱光照或较慢运动 | 运动模糊增加 |
| 3 | 20 ms | 静态图卡 | 需满足实际帧周期与曝光余量 |
| 4 | 26.667 ms | 更暗的静态场景 | 不适合需要更短曝光的运动测试 |

不要直接采用 33.333 ms 作为30 fps模式的曝光上限，它接近整个帧周期，须另核对传感器要求的行余量。若以后使用真60 fps模式，20 ms和26.667 ms不能沿用为固定60 fps的曝光档位。

150 Hz 是 PWM 重复频率时，光强周期按1/150 s计算，不因 PWM 同时存在上升沿和下降沿而改成300 Hz。若驱动器有额外包络、跳脉冲或环境光混入，应按实测光强波形重新分析。

### 4.2 帧率与相位不能替代曝光匹配

150/30=5仅说明标称帧周期包含5个 PWM 周期。它不说明单行曝光窗口覆盖整数周期，也不说明相机和 MCU 时钟锁相。只设置30 fps或只在 VSYNC 上同步灯光，不能保证卷帘全画面无条纹。

整数周期积分在理想稳定条件下不要求 PWM 与各行起点锁相；频率误差和曝光量化会破坏精确匹配。测试必须覆盖漂移和低占空比，不能只验证一个相位。

### 4.3 普通50/60 Hz防闪烁的限制

常规电网50/60 Hz防闪烁通常按光强100/120 Hz周期计算约10/8.333 ms的曝光步长。两者分别为150 Hz周期的1.5倍和1.25倍，并非本专项的通用消条纹档位。

20 ms同时是100 Hz光强和150 Hz PWM周期的整数倍，但不能据此假设混合光源已经解决：120 Hz或其他驱动频率要另行分析。

## 5. 开发路线A：固定曝光与固定增益

这是专项的第一阶段和正式几何测评的优先模式。

### 5.1 先补齐可计算输入

1. 读取芯片 ID `0x300A/0x300B`，验证模组身份，禁止向只读 ID 寄存器写入。
2. 核对实际 XCLK 来源及频率，读取时钟、HTS、VTS和曝光扩展相关寄存器。
3. 按手册建立内部时序时钟计算，不把 FPGA 控制时钟、DVP 字节时钟或 HDMI74.25 MHz误作同一个时钟。
4. 实测相邻有效行 HREF 起点的间隔，并结合本模式裁剪/抽样关系核对行时间。
5. 实测 VSYNC 间隔和有效帧尺寸。HDMI输出节拍及采集卡协商帧率只能作为各自链路指标。
6. 用光电探头核验光强重复频率、抖动、占空比及跳脉冲；仅测 GPIO PWM 不能证明驱动后光强相同。

### 5.2 曝光编码与量化

设内部时序时钟频率为 f_timing，HTS为实际寄存器值：

- t_row = HTS / f_timing。
- E = round(16 × T_exp / t_row)。
- E为20位曝光编码，单位为1/16行；实际曝光 T_actual = E × t_row / 16。
- `0x3500`承载 E[19:16]，仅低4位为曝光值；`0x3501`承载 E[15:8]；`0x3502`承载 E[7:0]。

每个档位都需报告 T_target、E、T_actual、时间误差及与实际光强周期的偏差。曝光寄存器分辨率与硬件实际响应也需核验。不能只输出“6.667 ms”标签，不保存编码和计算输入。

对整数倍档位分别计算完整曝光 E_N，不简单把已经舍入的一周期行数反复相乘。低占空比时，微小时间失配的相对影响可能更大，最终以图像指标判定。

### 5.3 寄存器职责与配置顺序

| 寄存器/位 | 固定测评模式要求 | 注意事项 |
| --- | --- | --- |
| `0x3503[0]` | 置1，手动曝光 | 读改写，保留其他位 |
| `0x3503[1]` | 置1，手动增益 | 与手动曝光分别确认 |
| `0x3500～0x3502` | 写入计算后的 E | 核对20位范围及实际曝光上限 |
| `0x350A～0x350B` | 写入固定增益 | 可从1倍对应编码`0x0010`开始，按手册和回读确认；不把数字增益当作补回欠曝信息 |
| `0x3A00[2]` | 清0，关闭夜间模式 | 保留其他位；同时检查模式是否还有扩帧路径 |
| `0x350C～0x350D`、VTS | 核对额外曝光行与帧周期 | 不继承旧自动曝光产生的扩展而不检查；上限须留本模式要求的行余量 |
| `0x3406`及`0x3400～0x3405` | 几何/色彩测评使用可重复白平衡 | 若从自动切手动，先核对并保存实际 RGB 增益，再提交手动模式；仅关 AWB 不保证保留此前颜色 |

推荐流程：初始化成功 → 读取并核对当前值 → 停止采集或执行已验证的参数组提交 → 设置手动模式与曝光/增益 → 回读校验 → 恢复采集 → 丢弃受过渡影响的帧 → 发布稳定有效帧。

初版可在停止采集期间更新整组寄存器。运行期原子更新若采用 OV5640 group access，应按手册验证 group hold、结束与 launch，不凭经验承诺恰好下一帧生效。模式切换不得导致帧内混用曝光、输出格式或标定参数。

几何测评保持固定曝光、增益、白平衡。改变灯光时允许图像真实变亮/变暗，不应自动补偿掉被测光照差异。画面过曝时应调低照明或选择合适光学条件；不要为消除过曝而自动退回任意短曝光。

## 6. 开发路线B：受约束的自动亮度

自动亮度适合日常演示及单独的系统测试，不替代路线A的几何测评条件。

### 6.1 优先策略

控制器只在满足帧周期的整数 PWM 周期曝光档位之间切换，档位间用增益补偿，并加入迟滞和最小保持时间。记录每个有效源帧的曝光档位、增益、参数版本及变更状态。

当前 FPGA 尚无完整亮度统计反馈与运行期摄像头服务，因此这是一项新增实现，不应标为现成能力。自动反馈应由板端负责；PC可配置目标和读取状态，不承担逐帧主视频处理。

如果最短6.667 ms档位在最低增益下仍过曝，则该光照条件不能通过受约束自动曝光解决，应降低照明或改变光学条件。若最长允许曝光及增益上限仍欠曝，应报告能力边界，不通过无限扩帧维持画面亮度。

### 6.2 可选实验：自定义传感器 banding 步长

OV5640有可编程 banding 步长，但手册的常规模式和频率检测针对50/60 Hz。以下是需要回归的实验性参数化方向，不是官方已验证的150 Hz工作模式：

- B150约为 T_light / t_row，单位为行；banding参数的有效位宽和舍入方式按手册核对。
- 若选择50 Hz参数槽，可研究将`0x3A08/0x3A09`写为 B150，并相应重算`0x3A0E`的最大 bands；若选择60 Hz槽，则对应`0x3A0A/0x3A0B`和`0x3A0D`。
- 通过`0x3C01[7]`强制手动选择，再用`0x3C00[2]`选择已配置的参数槽。参数槽名称不代表本次实际光源变成50/60 Hz。
- 最大 bands需满足实际曝光上限、VTS行余量和有效位宽，不能沿用厂商默认值。
- 核对`0x3A00`中的 banding、短于一 band、短于一行及夜间选项。必须验证亮场时 AEC 会不会绕过步长而缩短曝光，不能只证明暗场采用了整数步长。
- 回读曝光实际值并覆盖亮场、暗场、占空比突变和长稳。整数行步长的量化误差与手动曝光的1/16行编码不同，需单独评估。

如无法证明内部 AEC 在整个工作范围内遵守所需档位，退回路线A，或实现板端受约束控制器。不因写入 banding 参数就宣称自动防条纹完成。

## 7. SCCB与跨端接口要求

FPGA应提供有界的寄存器读取/写入服务：锁存事务参数，忙时拒绝或有限排队，返回成功、NACK、超时及回读不一致状态。初始化与运行期访问应有明确所有权，不能同时驱动总线。

需至少可查询：芯片 ID、时钟参数、HTS/VTS、曝光编码、曝光扩展行、增益、AEC/AGC模式、AWB模式/RGB增益、配置版本及生效状态。

建议配置与状态语义包括：

| 语义 | 必要内容 |
| --- | --- |
| 灯光设置 | 标称/实际 PWM 频率、占空比、通道、设置版本、变更事件 |
| 摄像头设置 | 工作模式、曝光档位或编码、增益、AWB模式、参数版本 |
| 摄像头回读 | 实际寄存器值、事务状态、回读时间与模式 |
| 帧元数据 | 源身份、可用源帧号、格式、参数生效版本、过渡/有效标志 |

以上仅定义专项所需语义，不分配或覆盖现有 UART 报文编号。PC配置口与 MCU_POSE_V2独立回传不能混用，也不得恢复已撤销的全系统 STOP 约定。未确认的灯光 MCU、引脚、电平和驱动器型号保持待核验。

回读寄存器的时刻不自动等于被保存帧的曝光时刻；不能把“读回当前值”冒充每帧参数的精确身份。无法关联时，明确标为未验证。新增元数据或跨端格式时同步相关主设计、`output/host/`和整机测评文档。

## 8. 验证计划与判定

### 8.1 离线验证

- SCCB：正常读写、地址NACK、数据NACK、拉伸/超时、最后读取字节NACK、复位和忙时请求；保留现有244项初始化回归。
- 曝光计算：20位编码边界、分数行舍入、VTS余量、无效时钟/零HTS、各档位量化误差；无测量输入时不得输出标为已验证的参数。
- 参数组：读改写保留无关位、回读不一致、错误时不发布新版本、配置过渡帧处理。
- 视频链路：模式变更后FIFO/帧池的清理和恢复；传感器寄存器模拟器不能替代真实光学响应。

若涉及 PDS构建，执行项目现有工程审计与时序流程，保留警告和未约束接口范围。通过综合或时序报告不等于光学防条纹通过。

### 8.2 测试矩阵

| 维度 | 建议条件 |
| --- | --- |
| 灯光占空比 | 5%、10%、25%、50%、75%、95%、100%；实际使用更低占空比时必须追加 |
| 曝光 | 6.667、13.333、20、26.667 ms中满足本模式帧周期的档位 |
| 对照 | 原自动配置、匹配后的手动配置；自定义AEC另列实验组 |
| 图卡 | 静态均匀灰面用于条纹测量，真实运动/网格图用于模糊与几何影响 |
| 增益 | 固定并记录实际编码；自动增益实验另列，不能混入固定条件比较 |
| 变化 | 占空比上跳/下跳，亮到暗/暗到亮，曝光档位切换 |
| 光源 | PWM单独照明优先；存在环境光时追加混合光源组 |
| 时长 | 硬件条件获准后，稳定组建议连续不少于30 s；长期验证单独安排 |

100%占空比应作为连续发光对照，但必须确认驱动器没有内部跳脉冲或其他调制。不同组记录实际照度；占空比不是 lx。几何、白平衡或增强参数保持一致，避免其他自动处理遮蔽结果。

### 8.3 指标与建议门槛

在中心及边缘的多个均匀灰面ROI分别计算，不仅展示主观截图：

1. 每帧每行ROI亮度均值 L(y)，保留行亮度曲线及空间周期分析。
2. 匹配连续光照参考以分离图卡不均匀、镜头渐晕与PWM条纹。参考需同几何、曝光、增益和ISP条件，并避免饱和及噪声底。
3. 可用归一化行比值 r(y) = [L_PWM(y)/mean(L_PWM)] / [L_REF(y)/mean(L_REF)]，定义 R_band = [P95(r)-P5(r)] / median(r)。参考噪声过大或分母接近零时，指标无效并报告原因。
4. 帧间波动 R_temporal = std(每帧ROI均值) / mean(每帧ROI均值)，另报告峰峰值、过渡过程和有效样本数。
5. 记录源 VSYNC帧间隔、有效尺寸/完整帧率、重复显示、丢帧、FIFO错误和实际曝光/增益；不能用静态图像哈希相同判定重复帧。

建议将稳定组 R_band≤1%、R_temporal≤1%作为初始工程目标，均须结合连续光照基线、测量噪声和使用场景确认。它们不是OV5640官方指标，也不是已经达到的结果。严重欠曝、饱和或来源未确认的数据不能标为完整系统验收通过。

若本模式目标为真实30 fps，源端帧率需独立达标且暗光不通过扩帧降速。当前720p诊断结果与正式1080p30分开记录；HDMI30 fps或采集卡30 fps不能证明源端30 fps。

### 8.4 原始证据与限制

摄像头原始格式、未压缩RGB采集及元数据按项目规则保存为`.raw`/`.rgb`及对应描述；PNG仅为派生展示。当前RGB565诊断路径不能标为S0 RAW8，采集卡转换结果应记录实际像素格式和转换过程。

元数据至少记录：源码/位流版本、源身份、模式、时钟核验输入、HTS/VTS、目标与实际曝光、编码与回读、增益/AWB、PWM电气/光学频率、占空比、照度、时间与ROI、过渡帧、采集格式及来源关联状态。

既有报告记录采集后`over_temp=1`，且HDMI源身份仍为`null/unverified`。本交接不解除告警、不授权下载或压力测试。硬件验证须按项目现有放行条件安排，不能屏蔽告警或把该位解释为实测温度值。

## 9. 不满足时的处理

- 无回读或时钟证据：先完成 SCCB读取、时序核验与测量，不给出“已验证”的固定曝光字节。
- 低占空比仍有条纹：检查光学频率漂移、脉冲包络、量化误差与亮场短曝光退让；不要只调 Gamma 掩盖条纹。
- 6.667 ms导致过曝：降低照明/光学通量或改用连续光照；不能要求整数周期方案同时支持任意强光及任意短曝光。
- 动态场景需要短于6.667 ms：考虑提高实际灯光PWM频率、连续电流调光或经验证的其他采集方式。提高PWM频率仍须检查驱动器带宽、最小脉宽、实际光强和最短曝光下的残余条纹，不承诺某个频率必然完全无条纹。
- 混入不同频率光源：隔离环境光或分析共同周期，不能把单一150 Hz方案外推。
- 自动模式无法约束曝光：交付固定模式并说明自动模式未完成，保留实验数据。
