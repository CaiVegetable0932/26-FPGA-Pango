# Jetson 本机 host 环境

配置日期：2026-10-02。机器：Ubuntu 22.04.5 LTS、Jetson ARM64、5.15.148-tegra。已完成本机 Web 上位机的软件环境安装与实际浏览器检查。验证记录见 [本机报告](../reports/environment_20261002/README.md)。

## 日常启动

在仓库根目录运行：

```bash
sh host/scripts/start_workbench.sh
```

入口自动使用 `host/build/environment/venv/bin/python`，启动或复用已安装的用户后台服务，核对当前仓库的 HTTP 身份后打开 Chromium。访问地址为 http://127.0.0.1:8765/。命令结束和关闭终端不会停止后台服务。重复执行会激活已有工作台标签页，不重新加载；已有重复工作台页会保留正在采集的一页。标定页及其他网址保持独立。登录自启动也使用相同的浏览器打开逻辑。

从任意目录也可以运行本机绝对路径：

```bash
sh /home/cai/26-FPGA-Pango/26-FPGA-Pango/host/scripts/start_workbench.sh
```

建议先连接 FPGA、HDMI 采集卡和网线并上电，再运行命令。若 FPGA 在页面启动后才上电，点击“启动 / 重连板卡链路”使用保存参数连接。后台服务启动和页面打开成功不等同于板卡出图成功；以页面中的实际预览和链路状态为准。

仅启动服务、不打开页面：`sh host/scripts/start_workbench.sh --no-browser`。检查启动选项：`sh host/scripts/start_workbench.sh --help`。原 `start_web.sh` 保留给前台开发运行，其进程生命周期依赖所在终端。

标签页复用使用原有浏览器配置和随机本机回环 CDP 端口，按 [Playwright 官方接口](https://playwright.dev/python/docs/api/class-browsertype#browser-type-connect-over-cdp)连接现有浏览器；不关闭浏览器、不切换采集卡、不改动系统电源管理。升级前已打开的旧浏览器若没有控制接口，需正常关闭一次再执行新命令；脚本会明确提示，不会强制终止它。

## 1080p30 接收与预览

2026-10-04：本机接收器使用 Linux `recvmmsg` 批量收包和本地 C 校验/组帧模块。每个分包继续校验 CRC、来源、布局、重复冲突和截止时间；仍只发布完整帧。按 [Linux recvmmsg 官方手册](https://man7.org/linux/man-pages/man2/recvmmsg.2.html)使用非阻塞批量接收，避免阻塞超时陷阱。模块位于 `host/build/udp-fast/`，加载前核对当前源码、二进制 SHA-256 与机器架构。

本地二进制随项目目录保留，正常启动自动加载。更新 C 源码或迁移主机后重建：

```bash
host/build/environment/venv/bin/python -B host/scripts/build_udp_fast.py
```

缺失或校验不匹配时安全回退 Python；不能将回退后的吞吐视为已达到 30 FPS。没有升级 JetPack、改变全局电源管理、提升时钟或修改 FPGA 位流。

两路预览分别显示实测显示帧率；网口还显示完整接收帧率。HDMI 默认请求原生 1920×1080/30，实际协商尺寸单独显示，必要时可在连接设置明确选择 720p30。`协商 30 FPS` 不是实测指标。网口使用持续的本机二进制连接跟随最新完整帧；缩小界面的 Bayer 2×2 基础预览可先产生明确标记的 GRAY8/RGB888 派生显示数据，原始 `/api/frame` 和 RAW 归档保持完整 1920×1080、字节不变。HDMI 源帧配对仍未验证。

复验工具：`host/scripts/check_preview_performance.py`，测量两个浏览器预览、完整组帧和内核 UDP 丢包；`--save-evidence` 在测量结束后保存原始 RAW 和原生解码 RGB。帧率证据及持续运行验收见 优化报告（本机留存：`../reports/preview-performance-20261004/README.md`）。

命令行开发、测试及采集工具使用项目环境：

```bash
source host/scripts/env.sh
python --version
node --version
ffmpeg -version
v4l2-ctl --version
```

`PANGO_PYTHON` 可显式选择其他 Python 3.12+；`BROWSER` 可显式选择其他浏览器。项目启动器依次查找显式解释器、准备好的项目虚拟环境、可选标定虚拟环境、`python3.12`、`python3`，并检查版本。

合并标定工作台后，已有环境需执行 `source host/scripts/env.sh` 和 `python host/scripts/setup_calibration.py` 补齐 OpenCV/NumPy；安装器复用 `host/build/environment/venv`，不新建一个启动器不会选中的环境。新环境依赖锁定清单已引用 `host/requirements-calibration.txt`。下文的 Jetson 实测记录来自提交 `931f2da6`，新合并版本的 Linux 测试由用户独立执行。

## 系统准备

已通过本机管理员授权完成：

- `/etc/sysctl.d/90-pango-host.conf` 设置 `net.core.rmem_max=16777216`，当前值已生效；接收器请求 8 MiB 时，Linux 返回的含记账开销缓冲值为 16 MiB。
- `cai` 已加入 `dialout` 组。当前桌面会话的旧进程仍保留旧组列表，重新登录后串口组权限生效。
- 本机已在 `video` 组中。

截至检查时，USB 未枚举到 CP2102 或 Hagibis，`/dev/video*` 与 USB 串口均为空，`enP8p1s0` 有线网口为 DOWN。设备接入后重新枚举物理身份、网卡地址与链路；不要复用旧 Windows COM 号、MAC/IP 或冷启动 epoch。

浏览器视频预览走跨平台 `getUserMedia`。现有 `comms_uart.ps1` 和 `hdmi_diag_capture.py` 的 PowerShell/DirectShow 路径仍属于 Windows 工具；安装 pyserial、FFmpeg 并不会自动把这些工具变为 Linux 后端。Linux 上的实际板端启动控制及 HDMI 原始证据采集需按后续平台适配验收。

```bash
systemctl --user status pango-host --no-pager
```

```bash
source host/scripts/env.sh
```
