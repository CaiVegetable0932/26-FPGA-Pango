# Web 上位机一键启动

开发板上电后的 UART、网口及 HDMI 联动入口见[板卡上电一键启动](板卡上电一键启动.md)。首次配置后可勾选“下次启动 host 自动连接”；下面的启动命令保持不变。

Jetson Ubuntu 22.04 ARM64 的本机环境已于 2026-10-02 配置并验证；安装与服务管理见 [本机环境配置](本机环境配置.md)。原启动命令会自动使用项目 Python 与独立浏览器。

2026-10-04：本机 Jetson 已安装后台服务，日常手动启动使用：

```bash
sh /home/cai/26-FPGA-Pango/26-FPGA-Pango/host/scripts/start_workbench.sh
```

该入口启动或复用服务、等待当前仓库的 HTTP 就绪并激活已有工作台标签页，执行后可以关闭终端；默认地址 http://127.0.0.1:8765/。先连接设备并给 FPGA 上电。若板卡较晚上电，点击“启动 / 重连板卡链路”。仅启动后台服务时加 `--no-browser`。重复执行和桌面登录入口已验证不会新增工作台标签页。下面的跨平台 `start_web.sh` / `start_web.cmd` 仍是前台开发入口。

Windows 与 Ubuntu 共用 host/src 下的核心和 host/web 下的界面，两份入口只负责找到 Python 并传递参数。运行需要 Python 3.12 或更高版本及本机浏览器；核心无需第三方 Python 包，标定功能需先安装 OpenCV/NumPy。启动本身不需要 npm、Qt、PDS 或管理员权限。

## Windows：双击启动

在资源管理器中双击 [start_web.cmd](../scripts/start_web.cmd)。启动后自动打开 http://127.0.0.1:8765/，并保留服务终端。终端必须保持运行；页面中点击“开始模拟”或配置实板接收后再开始采集。

脚本优先使用显式 PANGO_PYTHON，其次使用项目 `host/build/calibration-venv/Scripts/python.exe`，再尝试 py -3.12、py -3、python，选取满足版本要求的解释器。缺少 Python 时会显示原因并等待按键，便于双击启动时阅读。安装 Python 时启用 Python launcher 或将 python 加入 PATH，再次双击即可。PANGO_PYTHON 的值只包含可执行文件路径。

在项目根目录的 PowerShell 中，也可以运行：

~~~powershell
.\host\scripts\start_web.cmd
.\host\scripts\start_web.cmd --port 8766
.\host\scripts\start_web.cmd --no-browser
~~~

自选 Python 的例子（请替换为实际路径）：

~~~powershell
$env:PANGO_PYTHON = 'C:\Python312\python.exe'
.\host\scripts\start_web.cmd
~~~

PANGO_NO_PAUSE=1 仅用于自动化调用，使 Windows 入口出错后直接返回退出码；日常双击无需设置。正常运行无需提权。

## Ubuntu 24.04：一条命令启动

进入项目目录，在终端执行：

~~~bash
sh host/scripts/start_web.sh
~~~

服务就绪后会在本机桌面会话中打开浏览器。入口依次使用显式 PANGO_PYTHON、项目 host/build/environment/venv/bin/python、项目 host/build/calibration-venv/bin/python、系统 python3.12、系统 python3，并检查版本。已准备项目环境时使用独立 Chromium；BROWSER 可显式指定其他浏览器。系统已有 Python 3.12 时核心不需要其他包。没有兼容解释器时安装 Python 3.12 或更高版本后重试。

已有 Jetson 项目环境更新标定功能时，执行 `source host/scripts/env.sh` 后运行 `python host/scripts/setup_calibration.py`，将 OpenCV/NumPy 安装到启动器实际使用的环境。Windows 或普通 Ubuntu 可用 Python 3.12+ 运行同一安装脚本，创建项目内标定虚拟环境；不会修改系统 Python。新建 Jetson 环境的 `setup_environment.sh` 已包含同一份标定依赖清单。

脚本在 Git 中带可执行权限；如果通过 ZIP 或跨系统复制后丢失权限，可以只在首次执行时设置：

~~~bash
chmod +x host/scripts/start_web.sh
./host/scripts/start_web.sh
~~~

Shell 入口保留在终端运行，方便查看错误和正常停止。不同桌面环境对直接双击 .sh 文件的行为不同，因此这里统一使用上面的启动命令，不依赖文件管理器的脚本执行设置。可选指定已有解释器：

~~~bash
PANGO_PYTHON=/usr/bin/python3 ./host/scripts/start_web.sh --port 8766
~~~

无桌面环境或通过 SSH 使用时，可显式加 --no-browser；服务仍只监听所在机器的 127.0.0.1，不会自动对外开放端口。

## 参数与正常退出

两个平台的参数完全相同，也可直接运行 python -X utf8 -B host/scripts/web.py（Ubuntu 用 python3）。所有入口均按自身位置查找源码、配置和页面，可从任意工作目录运行，支持带空格和中文的项目路径。

| 参数 | 作用 |
| --- | --- |
| 无参数 | 使用 8765 端口，就绪后打开本机页面 |
| --port 8766 | 使用指定 HTTP 端口；不改变采集的 UDP 端口 |
| --port 0 | 由系统选择空闲 HTTP 端口，实际地址打印在终端 |
| --no-browser | 启动或复用服务，不自动打开浏览器 |
| --help | 显示帮助后退出 |

重复执行时，如果同一端口已经运行本项目同一目录的服务，会打开或激活工作台，保留既有配置和采集会话；本机 Jetson 独立浏览器会复用已有标签页。如果该端口被其他程序、另一个项目副本或旧版服务占用，会显示失败原因；可选择其他端口，或先在原服务终端正常停止后重启。脚本不会终止占用端口的其他进程。更改源码后，需要先停止原服务再重新启动，复用服务不等于重新加载代码。

浏览器打不开时，终端保留访问地址，可手动复制到本机浏览器。浏览器关闭会释放当前页面打开的视频采集卡，但不会停止 Python 后台 RAW8 采集。正常退出时先在页面点击“停止”，再在原服务终端按 Ctrl+C，等待采集与归档收尾。Ubuntu 收到 SIGTERM 也执行相同收尾；直接强制结束进程或关闭 Windows 终端窗口可能来不及收尾。

服务不会自动开始模拟。未配置板卡自动连接时，默认接收参数来自 host/config/receiver.mock.json；保存板卡配置并勾选“下次启动 host 自动连接”后，服务按 host/config/board-link.json 恢复真实链路及运行记录。本机 Jetson 已启用该选项，晚于工作台给 FPGA 上电时需点击重连按钮。采集证据位于 host/data，报告位于 host/reports。启动脚本不改变系统网络配置，也不执行 Git 上传。

退出码 0 表示正常停止、成功复用已有服务或输出帮助；2 表示环境、参数、启动或收尾失败。默认端口仅供本机浏览器访问，不能通过浏览器页面直接完成板端硬件连接验收。

## 移植与验证

迁移时保留完整 host 目录结构，至少包含 scripts、src、web 与 config；只复制启动脚本不能独立运行。Windows 与 Ubuntu 使用相同协议、接收器、会话与页面，通过 pathlib、标准库 socket/http.server 和 webbrowser 处理平台差异。Shell 入口固定 LF 换行，Windows 入口为 CRLF。

本次 Windows 软件验证与 Shell 兼容检查见[一键启动验证记录](../reports/Web_UI一键启动验证.md)。Ubuntu 24.04 目标机器尚未实测，Git Bash 下的脚本运行不能代替 Ubuntu 验收。迁移到目标机后可执行：

~~~bash
python3 -B host/scripts/test.py --report host/reports/webui-launcher-tests-ubuntu24.04.json
sh host/scripts/start_web.sh
~~~

在 Ubuntu 桌面上继续检查默认浏览器弹出、页面交互、Ctrl+C/SIGTERM 停止及实际采集环境。真实千兆网、HDMI、UART和1080p30性能仍按各自方案验收。界面操作与现有功能边界见[Web界面与核心接入说明](Web界面与核心接入说明.md)。

视频采集卡可在连接设置中选择并保存，之后单独打开预览；步骤见[视频采集设备接入说明](视频采集设备接入说明.md)。
