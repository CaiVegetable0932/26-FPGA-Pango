# 板卡上电自动恢复矫正参数

2026-10-11。基于 GitHub `fd3335ab` 实现 host 后台恢复，不改 FPGA RTL、位流或 MCU；使用现有 CP2102/UART 接口。软件测试使用模拟串口，尚未在 Jetson ARM64 或真实板卡复验。

## 一次配置，以后启动服务即可

1. 更新代码并重启旧 host 服务。启动脚本会复用已有服务，单纯重复启动不能把已运行的 Python 换成新代码。
2. 按[板卡连接说明](板卡上电一键启动.md)配置直连网卡、CP2102，成功连接一次。确认当前固件有几何 `0x80` 和显示 `0x100` CAPS；保存的 USB 序列号用于跟随串口编号变化。
3. 在首页“上电自动恢复 FPGA 矫正”勾选“后台检测上电并自动下发参数”。默认文件为 `config/calibration/fpga-fisheye-rgb33-20261010.json`，相对于 **host/**，不是仓库根目录。
4. 确认旋转、增强、启动 HDMI 模式、标记开关/直径，再点击“保存自动恢复设置”。默认：旋转 0°、增强开启、FPGA 矫正图、标记关闭、直径 10。只有保存才启用；仅打开网页或填入审校文件不上传。
5. 后续 Jetson 执行已有 `sh host/scripts/start_workbench.sh`。可以先开 host 再给 FPGA 上电，也可以反过来。后台检测无需保持浏览器打开；HDMI/UVC 预览仍由浏览器授权并打开。

使用前仍需串口权限、可用直连网卡和项目 Python/pyserial 环境；程序不自动改系统网络、防火墙、USB 设置或 Flash。Jetson 环境见[RGB33 接入说明](Jetson_RGB33标定接入说明.md)。

### 配置文件

网页写入 `host/config/board-autoload.json`，通用示例见 [board-autoload.example.json](../config/board-autoload.example.json)。示例默认 `enabled=false`，复制后须显式改为 true 才启用参数恢复。文件最大 64 KiB，仅允许 `host/config/calibration/` 内 JSON，不接受绝对路径、越界路径或指向外部的符号链接。

```json
{
  "enabled": true,
  "preset_path": "config/calibration/fpga-fisheye-rgb33-20261010.json",
  "rotation_deg": 0,
  "enhance": true,
  "mode": "corrected",
  "markers": false,
  "diameter": 10
}
```

恢复使用已有 `GeometryProfile.from_preset()` 编码器：读取浮点 `parameters`，使用这里的旋转/增强控件，不把记录中的历史 `hardware_applied` 标签当作板上状态。当前 RGB33 为 1920×1080、model=2、100°输出；参数文件原件不改写。

文件不是实时监视器。改文件后，在网页重新“保存自动恢复设置”、重启服务或等待新的板卡冷启动以重新读取；稳定会话不每两秒重复上传/读取全部参数。

## 后台流程与成功含义

后台约每两秒执行一次检查，出错按 1/2/4/8/16/30 秒退避（不计 UART 事务和启动等待耗时）。串口由现有 `BoardLink.uart_lock` 独占，忙时稍后检查，不与手动上传、显示控制或遥测交叉发送。

| 步骤 | 使用现有接口 | 成功依据 |
| --- | --- | --- |
| 检测 FPGA 在运行 | CAPS `0x01` | 校验后的 32 字节应答；不是 USB 枚举存在 |
| 冷启动建立链路 | `0x71 RAW8`、OPEN `0x02`、STATUS `0x03` | 先绑定 UDP，再写本轮 epoch；复用既有启动器 |
| 热启动恢复 | CAPS、已保存端点/epoch | 无匹配启动记录时拒绝覆盖，提示冷启动 |
| 等待源图 | 既有状态/完整帧接收状态 | 摄像头就绪并发布完整帧，或已收到实时完整网络帧 |
| 检查/装载参数 | `0x30` BEGIN、`0x31` WORD、`0x32` COMMIT、`0x33` STATUS、`0x34` READ | 14 字及模型/增强回读一致，版本已在帧边界激活 |
| 恢复 HDMI 模式 | `0x35` 与 bank=2 显示头部 | 模式/标记/直径一致，已显示参数版本等于活动版本 |

若重开 host 时活动参数完全相同，仅回读确认，不重复 BEGIN/WORD/COMMIT、不重新冷启动。已确认的稳定会话只轮询 CAPS；串口失联后撤销缓存证明，再恢复时完整回读，避免错误保留“就绪”。

保留 `fd3335ab` 的显示头部验证：关闭标记时，独立标记映射失败不会阻止无标记 HDMI 模式确认；LUT/模型错误仍失败。开启标记时必须有可信、完整的标记元数据。

“活动参数与 HDMI 显示版本已确认”只证明协议/寄存器状态，不证明 UVC 已锁定、画面精度、同帧身份或 30 FPS。HDMI `source_frame_id=null`、`pairing_status=unverified`；网口协议和像素不改变，当前 RENH v2 仍是 FPGA 增强 RAW8，不是原始 S0 或网络矫正图。Jetson GPU 软件参考保持独立。

## 手动操作优先级

- “停止接收”或停止板卡链路：暂停后台恢复，下一次轮询不会重新启动。点击“启动/重连板卡链路”、以太网默认重连、保存恢复设置或重启服务才继续。
- 手动上传参数/切换显示：撤销正在执行的自动操作，本次 epoch/session 保持手动设置；下一次真正冷启动再装载保存的预设。想立即回到保存预设，重新保存自动恢复设置。
- 手动模拟/其他来源采集：不被后台替换；显式开始手动采集会暂停自动恢复。
- 单次事务已发送时不能撤回。取消发生在事务间，未发送的 COMMIT 不会再发；若 COMMIT 已生效，后续只查询真实板上状态，不声称回滚。
- Ctrl+C/服务退出：先取消并等待恢复线程释放 UART，再停止既有启动器与接收器。独立 CLI 或 MCU 不得同时占用/并接此 UART。

浏览器跨标签页看的是同一个后台状态，打开新页不会触发上传。已打开的旧页可能保留旧 JS，更新后刷新。Windows 加入端口独占绑定，避免第二个服务争抢同一端口；Linux 保留原监听方式。

## HTTP 接口

| 接口 | 行为 |
| --- | --- |
| GET `/api/board/autoload` | 恢复设置、阶段、暂停/重试、活动/显示版本、文件 SHA 等；只读 |
| POST `/api/board/autoload` | 保存上述七个设置并重新授权恢复；同源和 `X-Pango-Token` 保护 |
| GET `/api/board/autoload/preset` | 读取已保存的恢复文件、SHA、旋转/增强设置供审校；不访问 UART |

状态阶段包括 disabled/waiting/connecting/loading/ready/error/manual/paused。失败保留具体原因和重试秒数，不用模拟图代替真实链路。文件 GET 返回的 `uploaded=false` 是“此 GET 未上传”，不是板卡是否存在活动参数。

恢复日志为 `host/reports/board-autoload-<UTC>-<随机串>.jsonl`，记录每次恢复或错误的实际 UART 事务、epoch/session、参数 SHA、编码值和回读；不逐次写空闲探测。既有启动日志 `board-link-*.json` 保留。参数回读日志不包含图像证据；文件路径、地址、设备身份属于本机运行信息，提交前审查。
