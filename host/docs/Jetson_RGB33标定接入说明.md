# Jetson 最终上位机与控制器：RGB33 标定接入

2026-10-10。本次发布数据和接入说明，未开启采集、串口下发、烧录或板级测试。以下操作由 Jetson 端后续执行，成功状态以实际回读与图像证据为准。

## 1. 分工及当前边界

Jetson（Ubuntu 22.04 / ARM64）是最终版本的上位机软件运行平台和试验控制协调器，不是临时视频转发机。Windows PC 仅用于开发、生成标定记录及备份；正常运行不要求 PC 给 Jetson 或 FPGA 转发主视频。

| 设备 | 职责 |
| --- | --- |
| FPGA | 摄像头启动与 DVP 采集、板侧 ISP、实际定点几何矫正与采样、HDMI 末端标记；网口按固件声明输出 RAW8 阶段 |
| Jetson | 参数档案、UART 控制与真实状态回读、网口接收、HDMI 回采显示、标定、独立 GPU 软件参考、试验编排与证据归档 |
| MCU | 云台/龙门架/光照设备执行及遥测；Jetson 的设备控制按现有 MCU 协议及已实现能力接入 |

“Jetson 是最终控制器”不表示所有 MCU 自动试验编排、XYZ/pitch/roll 闭环补偿已实现。本次不改 MCU/FPGA 功能代码，也不新增物理连接协议。Jetson 不能和 MCU 将两个 UART TX 并接同一个 FPGA RX；共用端口必须有明确仲裁，现有 CP2102 控制口先由 host 独占。

## 2. 本次推荐参数

以 [RGB33 交付包](../reports/rgb33-calibration-20261010/README.md) 为原始证据；以 [FPGA 联调记录](../config/calibration/fpga-fisheye-rgb33-20261010.json) 为板端上传入口。本组替代之前手填参数作为后续推荐基线，但不会隐式替换页面 localStorage、已保存连接配置或板上活动参数。旧近似记录保留用于回退。

| 参考图尺寸 | 1920×1080，原样本为紧密 RGB888 |

K/D 保留完整精度。先固定 K/D，只调输出 FOV；改变焦点、镜头、采集裁剪、镜像或采集模式需重新核对/标定。物距是采集记录，不是改变静态内参的直接控制量；原报告的板姿态和距离是软件估计，不是 MCU/IMU 实测真值。

33 张均用于拟合，留一折还用于选模，没有额外独立最终测试图。图卡平整度、格宽精度、焦点稳定及采集 RGB 与板端 S1 的几何等价性仍需核验。软件 RMS 不是 FPGA 定点误差，100% 可采样率也不是全图精度证明。

## 3. 报告与现有固件的版本差异

原 PDF/YAML/JSON 的鱼眼 `fpga_compatible=false` 保留原样；报告中的“不兼容”按旧针孔 k1/k2/p1/p2 接口写成，不应据此将鱼眼 k3/k4 强行装入 p1/p2。

当前 main 的 `fpga/rtl/geometry/geometry_lens_lut.v` 已实现 `theta=atan(r)`、`theta_d=theta*(1+k1*theta²+k2*theta⁴+k3*theta⁶+k4*theta⁸)`，host 编码器显式选择 model=2。本次用现有编码器离线生成 14 字，未溢出、未更换模型或截断系数；只证明参数可以表达。

目标恢复/联调镜像为 `fpga/release/geometry_20261007_e4dd5bbb06e6/mini_raw8_geometry.sfc`，SHA-256：`E4DD5BBB06E659C55ECB87B7A4F66385D0680A2D1C4DE46F838830B7AFA180A2`。Jetson 运行时仍须读取 CAPS 的几何 0x80、显示 0x100，并核对实际固件。未具备接口时停止下发，不能向旧位流猜测寄存器地址。

前十字（六个逆映射仿射值与四个 D）为 signed Q26，末四字（fx/fy/cx/cy）为 signed Q16，线上 LE32。记录中的 signed_words 是比对值，上传器从 parameters 重新生成，不读取该数组。单个系数量化的舍入上限分别是 0.5×2^-26、0.5×2^-16；这不是完整坐标误差上限，LUT、DSP 舍入及插值误差还需单独验证。

输出相机使用 `f=W/(2*tan(HFOV/2))` 与中心 `(959.5,539.5)`，不是直接把输入 fx/fy 当输出 f。缩放 K 时沿用像素中心 `(c+0.5)*scale-0.5`，D 不随分辨率乘比例。网页 UVC 1280×720 与板端 1920×1080 必须先核实确为等比例缩放而非裁剪，不能仅凭尺寸声明相同采集模式。

## 4. 拉取与启动

在 Jetson 仓库根目录执行。先保存本地未提交工作；有分叉则人工正常合并，不强制覆盖。

```bash
# 获取 main 中的数据、参数和说明；不覆盖本机运行配置。
git fetch origin
git switch main
git pull --ff-only origin main

# 校验本次交付原件；出现 FAILED 时停止使用。
(cd host/reports/rgb33-calibration-20261010 && sha256sum -c SHA256SUMS)

# 使用 Jetson 已安装的项目运行环境，启动/复用最终工作台。
sh host/scripts/start_workbench.sh
```

首次没有项目环境时，先按[本机环境配置](本机环境配置.md)安装；`start_workbench.sh` 要求项目 `host/build/environment/venv/bin/python`，不要拷贝 Windows venv/AMD64 二进制到 ARM64，也不要把 Ubuntu 系统 Python 3.10 当作项目 Python 3.12+。已有环境需要标定依赖时执行 `source host/scripts/env.sh`，再运行 `python host/scripts/setup_calibration.py`。不要盲目部署绑定其他 Jetson 内核 ABI 的 UVC 补丁。

服务默认 `http://127.0.0.1:8765/`，以启动输出为准。默认保留本机回环监听；异机浏览器不是本次默认使用方式，因为浏览器采集设备属于浏览器所在机器。

直连网卡可沿用 Jetson `192.168.80.2/24`、FPGA `192.168.80.3`，先核对本机网卡名称和 MAC；连接配置、boot epoch 是本机运行状态，不从 Windows 复制。核对 CP2102 唯一身份和 Hagibis 名称 + `VID_1DE1/PID_F105` + 唯一物理路径。占用由本项目会话释放，外部程序须先停止，不任意杀无关进程；不回退到集成摄像头。

## 5. 控制 FPGA 实际输出

1. 板卡上电后，在主工作台“启动 / 重连板卡链路”，等待摄像头/网络状态和完整帧就绪，获得有效 epoch/session；参数上传不替代初次 0x71 网络启动配置。
2. “FPGA 几何与显示控制”的参数框粘贴 `host/config/calibration/fpga-fisheye-rgb33-20261010.json` 全文，核对 model=2、1920×1080、FOV=100、旋转=0、增强开启。上传时只使用 parameters 与显式控件，不根据附带元数据推断已经应用。
3. 点击“上传并验证 FPGA 参数”。UART 在现有 host 互斥锁内执行 0x30 BEGIN、0x31 WORD、影子回读、0x32 COMMIT、0x33 STATUS 和 0x34 活动回读；版本使用递增值，epoch/session 从运行时查询，不能固化旧机数值。
4. 选择“FPGA 矫正图”并“应用板端显示”；0x35 控制原图/矫正图、标记开关和直径，默认约 10 原生图像像素。参数在源帧边界生效，显示切换还须等待 HDMI 已显示 revision/参数版本，不把 COMMIT ACK 当成已经显示。
5. HDMI 面板才是 FPGA 的实际矫正输出。对比时在同一 ISP 阶段切换“原图”，记录实际参数版本、模式、标记可见性、时间和来源状态。映射失败、构表错误或元数据不一致时停止判定，不用软件画面代替硬件结果。

参数是易失配置，冷启动后由 Jetson 再次显式下发。本次没有新增自动恢复标定参数功能；开机只启动网络链路不会自动装载 RGB33。网页优先，因为同一服务负责 UART 仲裁，独立 CLI 与它同时访问端口会冲突。

离线编码命令（不开串口，不改变板卡）：

```bash
# 在已有项目环境中确认编码与交付记录一致。
source host/scripts/env.sh
python -B host/scripts/fpga_geometry.py host/config/calibration/fpga-fisheye-rgb33-20261010.json
```

仅在已完成会话初始化、暂停其他 UART 操作且端口身份已核实后，才可给同命令增加 `--port /dev/ttyUSB0 --timeout 10`（换为实际端口）。CLI 不配置网络 boot、不烧 Flash，也不自动切换显示模式；日常操作推荐网页。

## 6. Jetson 独立软件参考

在 `/calibration#manual-preview` 的“导入调参 JSON”选择交付包中的 `fisheye-preview-rgb33.json`。不要选择结构不同的 `fisheye_equidistant.json`，也不要随后点击旧“用户审校 · 200°鱼眼”预置恢复旧值。保留原件：页面导出通用手调记录可能改写来源标签，不能冒充真实拟合证据。

这里的 WebGL/Jetson GPU 矫正仅是独立软件参考。其导入不会下发 FPGA；冻结同一输入可用于检查数学模型，但普通 UVC 与网口不能按到达顺序宣称同帧。软件重采样图不能重新作为原始标定输入。

100° 为本次起点，可单独试 90°/110°；原软件扫描分别为 100%/97.8215% 可采样比例。120°开始超过报告的 62.07°最大已观测光线角，139°仅约63.5476%可采样；不能延用旧139°且假设本次全幅已验证。调FOV不需要更换鱼眼模型或修改K/D，调后另存版本。

## 7. 网络、来源和证据

当前 E4DD…固件网口是 FPGA 增强 Bayer RAW8 / RENH v2，不是矫正后的网络 RGB，也不是未处理 S0。Jetson 解码必须按实际协议和来源阶段标注；此标定包不改变网口字节、RAW8 协议或数据归档。

20点坐标、颜色及可见性以 FPGA 元数据为准，Jetson 只绘制 UI 叠加；HDMI 实际彩色标记由 FPGA 末端完成，不污染摄像头输入或原始存档。具体接口见[几何与显示 Web 接口](FPGA几何与显示Web接口.md)。

没有可信像素身份时，HDMI `source_frame_id=null`、`pairing_status=unverified`。参数首个应用源帧号和显示元数据不等于采集卡各帧身份。严格精度需要板侧 S1 与 S2/S3 同帧快照证据，不能靠软件到达顺序或截图相似性补出配对。

Jetson 每次运行保存本机代码 SHA、参数文件 SHA、浮点与编码值、实际活动/显示版本、epoch/session、帧来源、设备身份和错误日志到 `host/data/<run_id>/`；结果报告放 `host/reports/<run_id>/`。原证据保存 `.raw/.rgb` 与元数据，PNG/JPEG 仅作派生显示。本机地址、设备路径和运行日志另行脱敏，不把通用标定文件写成某次已成功运行。

## 8. Jetson 端下一步验收

- 核对镜头/焦点/裁剪/镜像一致，确认 RGB 标定坐标与板侧 S1 的几何关系；至少另采3张未参与拟合/选模的独立图，补四角/边缘和平整硬板。
- 实际下发后逐字回读14字，确认活动及已显示参数版本，分别审校原图/FPGA矫正图/独立GPU参考和标记裁剪。
- 测量定点坐标误差、真实图像直线度和有效域；必要时再做斜边MTF/SFR。软件RMS不能替代这些结果。
- 分别实测源DVP帧率、完整网络帧率、FPGA有效输出帧率及Jetson显示帧率，再测延迟；不以30FPS协商值、预算或浏览器刷新率代替实测。
- 参数断电重下发、异常链路恢复与MCU设备控制按实际能力逐项验证。失败项保留日志，不声称整个最终系统已验收。
