# 以太网视频预览

2026-09-22 对接 `main` 的 `331f6078` 通信版本。依据
`fpga/rtl/network/praw_packetizer.v`、`comms_test_source.v` 以及
`host/reports/comms_ethernet_20260922/README.md`（上述文件在 main 中）。
PRAW V1 报文格式没有改变，沿用 64 字节头、1400 字节分片、逐包 CRC 和完整帧重组。

## 目前能看到什么

当前板端通信镜像输出 **1920×1080 RAW8 形状的合成 TEST 图**，descriptor
为 `0x54534554`，图案随帧号移动。它不是 OV5640 图像，该镜像也不输出 HDMI。
host 能实时接收、显示、按需归档；TEST 身份显示在画面、记录和元数据中。
未来真实 RAW8 只要遵循同一 PRAW 契约，可按实际宽高/Bayer/epoch接入，
但当前测试不能代替真实摄像头视频的验收。

## 操作

1. Windows 双击 `host/scripts/start_web.cmd`；Ubuntu 运行
   `sh host/scripts/start_web.sh`。若旧服务仍在运行，请先在旧终端 Ctrl+C
   关闭后重启，使新增后端生效。也可指定 `--port 8768` 单独启动新服务。
2. 在“连接设置 → RAW8 网络来源”点击“填入 MINI 以太网示例”。
   示例为 PC `169.254.81.186:50000`、FPGA `169.254.81.187:50001`。
   这些是本机本轮实际地址，不是固定板卡出厂地址；换网卡/主机要按实际连接改填。
3. 点击“探测当前板端流并应用”。只在指定 PC 地址上被动监听3秒，
   只采信指定 FPGA 地址/端口的 CRC 有效 RAW_LIVE 包；至少观察3个不同分片。
   读取当前 epoch、宽高、Bayer 和 TEST descriptor；epoch 使用十进制字符串
   传给浏览器，避免64位整数精度丢失。该操作是数据面观察，不冒充 UART 回读。
4. 探测成功后切到实时采集，点击“开始接收”。左框显示以太网原图，
   彩色是 PC 基础 Bayer 可视化，灰度可观察 TEST 条纹；两者都不做几何矫正。
5. 完整帧率与浏览器预览帧率分开显示。原始接收是1920×1080，前端派生
   预览为960×540；HTTP轮询间隔125ms，不承诺浏览器以30FPS刷新。
6. 默认不保存图像。需要时点击保存原图或选择归档间隔，写入 `.raw` 与元数据；
   结束点击停止，端口释放。断线时旧图标记过期，不冒充继续更新。

一次只能有一个接收程序占用UDP50000。探测时需要先停止本页接收。
探测不改 IP、路由、防火墙、板卡寄存器或 Flash，不进行全网扫描。
板卡复位后当前通信镜像不会自动发包，需要按 main 的通信联调说明生成新 epoch
并下发启动配置，再回到本页探测；不要重放已经使用过的启动报文。
运行中不会自动接受不同 epoch，板卡重启后需停止、重新探测、重新开始。

## 复测

在项目根目录执行（先停止网页接收以释放端口）：

```powershell
host/build/calibration-venv/Scripts/python.exe -B host/scripts/check_ethernet_preview.py --hardware --seconds 10
```

Ubuntu 可用 `python3` 或已有的 host 虚拟环境；测试还需要 Node.js 来执行
网页使用的像素转换器。测试从同一个 WebSession/HTTP 接口获取真实接收帧，
检查 TEST 全帧字节并调用 `host/web/pixels.js`。只保存统计与哈希，不写视频载荷。
结果在 `host/reports/ethernet-preview-<时间>.json`。

后端接收只依赖 Python 标准库，不需要 OpenCV；现有标定虚拟环境可以共用。
配置参考：`host/config/receiver.ethernet.example.json`，其中 epoch=0 仅是占位，
应通过探测或有效控制回读替换后再开始接收。
