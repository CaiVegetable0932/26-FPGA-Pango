# FPGA 算法控制

运行 `python host/scripts/web.py --page algorithms`，或从视频工作台进入“FPGA 算法控制”。新版控制依赖 AFG1 能力查询；旧位流不会被当作新版协议使用。页面不自动恢复旧开关或提交保存的配置。

1. 选择 CP2102，读取板端状态。串口与启动流程共用同一把锁，启动期间不抢占。
2. 仿射开关直接发给 FPGA。OFF 选择独立参考视图并保留镜头、颜色和亮度；ON 使用手动/MCU 姿态仿射与固定视窗。
3. 编辑参考内参，或用旋转、平移和缩放生成 ON 草稿。绿色有效域是离线采样估计，不改变主视频、不证明 RTL 全像素有效。提交完整草稿后读取源帧应用与板端显示采用，不能以 ACK 代替 applied。
4. 从模块列表选择颜色、亮度、LUT、固定裁边、补全禁用配置、相机或姿态标定；能力未开放时按钮禁用。示例填入关闭状态草稿，不会立即下发。完整实体字段和单位见 [字节布局](../../fpga/config/integration/ENTITY_CONTROL.md)。

LUT 的 `{"gamma": 0.7}` 会离线生成单调 256 项曲线；也可提供 `values` 数组。上传只保留新曲线，读取实际版本后，再提交亮度配置 `mode=1, curve=3, lut_version=该版本` 才启用。LUT 等待被选择时 pending 不表示像素已使用它。自动亮度 `mode=2` 在 FPGA 内依赖合法 S1 统计运行，PC 断开不会停止控制。

ISP 的 `channel_gain` 为 R/Gr/Gb/B 的 Q12；`ccm` 是线性 RGB12 上的行优先 Q14 矩阵。固定白平衡 `wb_mode=0`，受限 AWB 为 1。提交整组配置，不能把未经标定的矩阵称为颜色精度改善。

颜色选择项提供十进制 3×3 CCM、单位阵恢复、四通道黑电平/增益、CCM 启停、白平衡模式和标定来源 ID。先载入或编辑，再点击“量化整组颜色参数到草稿”；只有“提交完整实体”发送。导入/导出使用 `{schema:1, kind, draft}` JSON，类型必须匹配当前选择，文件仅作为草稿。受限 AWB 范围和保持帧仍在完整 JSON 中编辑。

相机 `mode=0` 为固定曝光，1 为停流受限 AE：暂停新采集、排空、寄存器写入和回读、等待稳定再采集。mode=1 会中断采集连续性。mode=2 为连续 AE 候选：在前置寄存器状态通过后仅使用官方group0更新曝光和增益，主视频保持运行；白名单以外的运行中寄存器写仍拒绝。group异常锁定失败并需板复位，不能假定部分组缓存已撤销。150Hz 档位必须提供真实行时间与标定ID；没有这些值时用 flicker=0。曝光生效帧未实测，状态 `exposure_binding_unverified=true`，读回源身份仅指恢复后的首次采集。

MCU 姿态标定是机械 pitch/yaw 的有限域局部仿射模型；当前板级独立 UART、时钟误差和标定尚未放行，因此核心显式降级。XYZ 归一化步数不作为相机米制平移。C4 视觉防抖于 2026-10-22 撤销；kind 4 和 A5 action 3 返回不支持（6）。kind 5 仅 mode 0/1，mode 2 返回不支持；kind 6 enabled=1 返回不支持，读回 error=6 表示视觉配准不可用。历史缓存/DDR/清空与引用释放框架保留，零偏移与零置信度不代表配准。kind 8 姿态标定保留。固定裁剪仍可能有无效像素，不承诺任意镜头下黑边全消。

“实际运动帧”是只读的最近完成 job：完整六系数、源身份、配置版本、历史来源和像素覆盖计数一起发布。外部 HDMI 采集卡的源身份继续为 null/unverified，不能根据显示读回或到达先后给采集卡帧补写源号。

错误或超时后先重新读取状态。客户端重试保持相同序号和字节，不自动递增版本重复提交；上传未提交时可取消，已排队的帧实体不靠取消回滚。

“重置视觉参考”已禁用；“清空历史引用”在下一源采集边界执行；在途DMA继续排空。动作pending、实际执行epoch/frame/seq从实际运动帧的runtime_action独立读回，不能把动作ACK当执行完成。
