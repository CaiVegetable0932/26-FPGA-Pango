# 图像实体与受限曝光实现验证

日期：2026-10-21。本文记录本机 RTL／软件验证；不构成实板光学、真实 1080p30、资源或时序签核。

## 已接入的实现

- `ISP_COLOR` schema 1，64 字节。四通道黑电平／U16.12 增益在源采集边界锁存；九个 S18.14 系数真实接入 `rgb_colour_matrix` 的 RGB12 输入。关闭矩阵使用单位阵，保持相同流水与量化。系数符号扩展、范围以及每行绝对值和不超过 8.0 均被验证。S1 存储校正后像素，因此旧源不会被新的 ISP 实体重解释。
- `TONE_CONFIG` schema 1，32 字节，OFF／MANUAL／AUTO。R/G/B 共用单调曲线，只在四邻域读取之后、插值之前处理。三档调试曲线由离线幂运算生成，指数为 0.7、1、1.3，不代表已标定曲线。
- `TONE_LUT` schema 1，256 字节，整曲线非递减校验。外层 CRC／连续分块由统一上传网关处理。接受后进入一个有界暂存，随后由 MANUAL／curve 3／匹配 LUT version 的策略提交选择。未应用的人工上传不能被另一上传静默覆盖。
- 两页 LUT 各有 12 个同步读表副本。页复制经过独立的 DDR→processing 请求／完成握手，完整写入和提交之后才能由后续源帧绑定。旧源槽按 LUT generation 解析保留页；只有无源引用的非活动页可覆盖。两页被占用时返回 busy；采集不等待 LUT 复制。历史只拥有原始 S1，不持有旧 tone 页。
- 旧 `0x92` 与新 tone 实体共用一个 pending 仲裁器。OFF 后重新 ON 保留最后提交的 AUTO／MANUAL 策略；mode 2 仍是旧命令不支持值。新实体 `TONE_CONFIG.mode=2` 则是 AUTO。
- AUTO Gamma 使用帧完成、合法 EOF、ISP writer 完成之后的 S1 亮度统计，只影响后续源。带目标区间、迟滞、允许曲线集合、最小保持帧数；断开 PC 后仍由 FPGA 运行。
- 受限 AWB 使用 pre-CCM、中性采样的 RGB 和。固定规则为通道均在 32～239、最大最小差不超过最大值的四分之一、至少 16 个样本；不把强色场景假定为灰世界。R/B 按有界步长接近绿色参考，保留 Gr/Gb 校准比例、上下限、保持帧数与 1/32 死区。实际增益改变产生新 ISP 版本，死区无变化不产生版本。

## 相机 C8 的明确边界

`CAMERA_CONFIG` schema 1，48 字节，支持 mode 0 固定值、mode 1 **停流受限 AE**、mode 2 **连续 group AE 工程候选**。mode 2 已有 RTL 与协议模型实现，尚无实板曝光帧绑定或连续帧率验收。

mode 0/1 提交后先暂停 DVP 接纳，通过 `camera_frame_cdc.source_quiesced` 确认 PCLK 侧停止、旧上下文释放、两队列排空，再通过同一 SCCB 所有者执行 12 个带掩码读改写／回读的寄存器操作：standby、手动 AE/AGC、关闭夜间延帧、extra lines 清零、曝光三字节、模拟增益两字节、传感器手动白平衡、stream-on。该停流路径不写 HTS、VTS、PLL 或 0x3212 在线 group launch。失败保持上一成功实体并暂停采集；重试不能覆盖仍在跨域借用的请求。

mode 2 使用独立 `ov5640_group_exposure` 状态机和同一 SCCB 物理所有者。预读要求 0x3213 无活动组、手动 AE/AGC、关闭夜间延帧、extra lines=0、sensor ISP AWB 关闭、VTS=1120；随后保存曝光／增益保留位，只执行 group0 的 start 0x00、五个曝光／增益字节、end 0x10、launch 0xA0。缓冲写仅确认 SCCB ACK；启动后轮询组状态并回读全部五字节，不能对缓冲期的旧寄存器值做错误的逐字节校验。事务有期限，正常更新期间不暂停 DVP。受信入口固定白名单拒绝 VTS／任意地址，通用寄存器接口仍保留 quiesced 限制。

连续分组错误可能留下未取消的传感器组缓存；官方资料没有提供本实现可依赖的 abort 恢复语义。因此错误后停止接纳、保留 last-good、拒绝进一步运行期请求，要求板复位。预读失败也采用同样保守的隔离边界。不能通过普通停流重试伪称已清除未知组。

曝光采用 sensor line/16 单位，硬上限 `(1120-4)*16=17856`；这只是本版固定 VTS 配置的寄存器安全边界，不是实际行时间或真实帧率测量。AE 带死区、曝光／增益上下限、有限步长、恢复稳定等待和最小保持帧数。Gamma/AWB 在相机稳定等待或 AE 仍有待校正步进时不推进；同一统计帧不能同时触发曝光步进与这两个闭环。150 Hz 档需用户明确提供实测行时间、标定 ID 和对应曝光周期代码，通过乘法比较校验一至四周期档；测试中的行时间是合成输入，不能作为实板标定。

相机状态 header 的 flags bit2 恒为 1，表示 **曝光与源帧的精确绑定尚未验证**。header epoch/frame 是寄存器组回读后首次接纳的源帧，仅用于配置关联，不宣称该帧所有行已采用新曝光。恢复初期帧也不能作为精确曝光测量证据。连续在线组写生效时刻、真实 30fps、不同占空比 150 Hz 灯光效果仍需实板验证。

相机 mailbox、SCCB owner 与内存侧共同接受 `fabric_async_reset_n`，各时钟同步释放，防止旧 reply 进入新代次。返回错误在 DDR 域等待同步 done 后锁存，再以本域 done/error 交付。新增 CDC 约束只作用于明确的首级同步和持有数据端点；没有整域 false-path。

## 板级 LUT 单调性校验的资源专门化

`pc_reference_upload` 在原有逐字节 CRC 扫描时累计 LUT 单调性证明，比较跨 64 字节分块的相邻值。只有完整长度、CRC 正确、未发现下降的 kind 2 能进入 COMMIT。精确 chunk 重试不改变前字节或累计失败标志；取消／新事务才重新初始化。A3 遇正确 CRC 的下降 LUT 返回 11，不能触发 consumer submit。

`tone_entity_control.LUT_PREVALIDATED` 默认 0（完整并行验证）。`video_memory_core.TONE_LUT_PREVALIDATED` 也默认 0。只有 `pango_video_system` 的唯一 `pc_reference_upload` 提交路径显式置 1，删除重复的并行校验。任何新增旁路／DMA／测试提交入口必须保持默认 0，或者先实现同等完整校验；不能把这个参数当作通用性能开关。

`run_20261021_191703_228410/tb_pc_tone_gateway.run.log` 是实际 UART 位流→CRC／单调校验网关→`LUT_PREVALIDATED=1` tone 消费者的组合证据：跨 chunk 下降、有效 CRC、A3 重试仍拒绝、取消后合法曲线上传、COMMIT 幂等均通过。默认 0 的 standalone tone 坏 LUT 拒绝仍由同次原有测试覆盖。
