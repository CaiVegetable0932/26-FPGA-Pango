# PC 动态控制精简与布线优化

本轮从 Git `22dfcb06` 保存的正式版本出发，按用户指令精简回读、取消 MCU 自动姿态并保留 PC 动态控制。LUT 目标为严格低于 39,960 / 66,600（60%）；实际布通和布线后时序须分别用 PnR 与 STA 证明。

旧版已独立冻结并形成[不限时布线交接](当前保存版本不限时布线交接_20261026.md)，没有启动旧版 PDS。以下为新设计的验证记录，不改变旧版 MAP。

## 功能范围

| 功能 | 本轮处理 |
|---|---|
| 单路 OV5640 RAW8 与 S0 千兆网 | 保留 |
| 基础 ISP、仿射/镜头矫正与唯一 HDMI | 保留 |
| PC 几何参数、参考矩阵与仿射 ON/OFF | 保留完整上传、校验、帧原子生效和完整回读 |
| PC 手动曝光、色彩/CCM、预设曲线 | 保留动态写入；回读改为状态摘要 |
| MCU UART 协议、时间映射、姿态选择、自动矩阵计算 | 从当前板级实例中移除；MCU 固件和历史通用 RTL 保留 |
| kind 8/12、运动诊断 kind 11 | 不再宣告；不能通过旧命令重新启用 |
| 已停用历史补全的 kind 6 配置/清理 | 撤销空功能控制入口，实际历史补全此前已不可用 |
| DDR、帧池所有权、像素 CDC、缓存容量、125/150 MHz 时钟 | 保留 |

`PC_ONLY_CONTROL=1` 直接将调度器持有的源帧几何参数送入原有 job mailbox，不读取当前可变 PC 配置，也不以默认矩阵替换冻结矩阵。源帧归属与生效/显示确认继续由既有帧池和 CDC 控制。

`SUMMARY_READBACK=1` 将普通图像实体只读状态收敛为 32 字节身份头和 16 字节零填充，共两页；schema=2、body_length=0。capability bit 3 宣告该格式，kind mask 为 `0x068a`。page 0 冻结、精确重试、复位所有权和帧原子规则保留。PC 返回 `values=null`，不能把本地草稿当成板端实际回读；完整草稿仍可上传。参考、仿射、0x90 与 0x95 保持四页完整状态，支持 PC 持续控制与显示确认。

## 功能验证

- [RTL 协议回归](../build/pc_only_20261026/proof_131210_278858/result.json)：8 项通过，包含实际精简配置下 40 条 PC 动态控制响应，几何/参考上传、ON/OFF、CRC、精确重试；摘要冻结、page 2 拒绝、复位撤销快照，以及 MCU 上传拒绝。
- [上位机冻结测试](../../host/reports/pc_only_controls_20261026_131653_825603.json)：23 项通过，覆盖新摘要协商、完整草稿提交、采用硬件版本号、ACK 不冒充应用、旧 schema 1 兼容。
- [完整帧仿真](../build/full_integration_20261013/verilator_20261026_130539_595293/result.json)及[原始日志](../build/full_integration_20261013/verilator_20261026_130539_595293/run.log)：3 帧 RAW 共 6,220,800 字节，处理 3 帧；HDMI 校验 8,294,400 像素，failed=0、underflow=0。geometry_cycles 为 3,949,268 / 3,972,636 / 3,963,327，125 MHz 计数域最慢 31.781088 ms。
- 完整帧仿真使用冻结的 `PC_ONLY_CONTROL=1` 核心；板级顶层由 PDS 编译核对。仿真吞吐不等于实际摄像头、网络、DDR、HDMI 的实板时序或帧率验收。

## 原生实现与当前状态

当前重新验证约束的构建为 `fpga/build/full_integration_20261013/board_20261026_134708_527115`，由 `fpga/build/pc_only_20261026/pipeline_134708_306466` 串行驱动。只有新构建通过原生约束、显式 SCF 映射和来源绑定审查后才进入不限时 PnR/STA；当前没有宣称已布通或生成位流。

首轮 `board_20261026_130509_075155` 保留了两个已删除 MCU 同步器端点的旧 CDC 命令，CCR 报 4 个错误，不能用于布线。已从正式约束仅移除这两个失效端点的 `set_max_delay` / hold `set_false_path`；其他 CDC、时钟、引脚和 10 条 post-SYN reset SCF 不变。首轮仿真冻结的核心 RTL 与最终核心相同，重新生成原生工程时保留哈希绑定。

中间构建 `board_20261026_131504_581900` 已完成原生 SYN/MAP，测得下表资源；但两个 `core.processor.job_mailbox.source_result*` 约束出现 STA-3015 无路径诊断，因此该构建不能进入布线。网表确认运动诊断是三个回传计数器的唯一消费者，删除消费者后计数器捕获路径被优化掉。已仅移除该不存在端点的两条 CDC 命令，保留真实 job 数据、完成/失败握手、其他 CDC、时钟及 reset SCF。正在重新生成完整原生证据，不能复用中间构建宣称约束通过。

新设计通过功能、资源和约束审查后，使用 `review_pc_only_design.py` 生成输入与选项绑定的 review，再启动一次 monitor-only PnR/STA。原生和主机时间上限均为 0，停滞仅观察，不自动换种子或重试；用户停止文件仍有效。没有位流生成或下载授权。本轮资源目标为尽量低于 60%；原有实际布线资源低于 70% 的安全门槛仍保留，两个门槛分别记录。

## 后续交接

以 [campaign.json](../build/pc_only_20261026/campaign.json) 中的精确运行路径为入口，不用“最新目录”替换另一版本。布线期间检查日志、每轮未布通数、布局线长、复制数、CPU/内存与静默时间。最终必须保存完整 PRR、routed DB 和 min/max STA；源文件变更后不能借用本轮物理结果作为新版本签核。

原每 10 分钟监控（自动化 `pc`，名称“PC动态控制精简版布线监控”）已因用户改用其他智能体监控而暂停，后台流水线继续运行。接手入口见[PC 精简版布线任务监控交接](PC精简版布线任务监控交接_20261026.md)。原生 PnR 继续保留本地监控日志；SYN/MAP 的构建超时设置与后续不限时 PnR 分开记录，不将前者误写成已启动布线。

当前取消的是 FPGA 自动姿态路径，不改 MCU 电机/编码器固件，不让 PC 转发主视频或执行实时几何矫正。HDMI 源身份未验收时仍为 null/unverified，像素精度、吞吐和功耗不写成实测通过。
