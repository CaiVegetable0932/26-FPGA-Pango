# 外部 IO 时序约束审查（2026-10-23）

## 结论与边界

当前不能签核“整板外部 IO 时序已完成”。DVP、RGMII 的板级 min/max 模型确实缺失，HDMI/TMDS 和 DDR 的外部电气、采样窗口也没有本轮验收证据。内部 PnR/STA 可以继续用于验证已建模的 FPGA 内部路径，但其 `All Constraints Met` 不能扩大为整板接口时序通过，更不能据此宣称位流前全部工作已放行。

本报告初始审查只读检查 E 候选 `board_20261023_174853_591836` 的日志、冻结 RTL/IP/约束和参考资料；当时F候选 `board_20261023_180615_764649` 正在原生流程中。该审查未修改冻结工程，未运行PDS、未生成位流、未添加猜测约束；下文E告警数保留为历史证据，不推定为后继候选的实测数量。此前相机FSM CDC例外修复的审查独立见 `fpga/build/core_area_20261023/final_constraint_review/CDC与配置释放后续复核.md`。

用户后续明确将布局布线交给其他智能体。本轮只完成布线前工作，不启动PnR、位流生成、下载或烧录；本文件关于内部实现检查的说明不构成启动布线授权。最终候选和交接门禁以[布线前交接](布线前验证与智能体交接_20261023.md)为准，当前不能把已知未命中的路径例外写成约束审查通过。

## DVP：可以确认的边沿，尚缺的保证值

2026-10-23 用户补充：**相机模组直接与板卡连接，器件性能与指标以 reference 中资料为依据**。据此，连接模型不再包含未知的外接延长线；直连仍包含模组、连接器与板内走线。对 `reference/OV5640双目摄像头资料` 与 MINI 开发板资料中的三份 OV5640 PDF 已逐份比较 SHA256，内容一致。重新目视核对的原理图、时序表、极性页及源文件哈希见 [直连资料核查](../build/mcu_link_20261023/camera_direct_reference_review/manifest.json)。本补充是用户确认的连接条件与资料复核，不是实板测量。

1. `ov5640_reference_profile.v` 写 `0x4740=0x20`；`ov5640_raw8_mode.v` 的 `0x4740` 读改写 mask 为 `0x03`，保留 bit5。OV5640 DVP Application Guide **PDF27，4.2节**明确 bit5=1 为数据在 PCLK 下降沿输出（此前页码28有误，此处已更正）。当前 `dvp_frame_receiver.v` 在 PCLK 上升沿取样。因此软件配置采用半周期采样策略，有文档依据。
2. 参考 profile 以模块24 MHz输入和 PLL/分频配置推算84 MHz系统时钟，HTS=2500、VTS=1120对应目标30 fps；这个推算依赖实际 XCLK、PLL/模式寄存器读回与模组版本，不能作为实测 PCLK。FDC 的10 ns/100 MHz是明确标注的内部保守分析预算，不能据此声称外部数据有效窗口为10 ns或5 ns。
3. OV5640 datasheet v2.01 PDF94–95 的 DVP表是以像素周期计数的行/场时序，且说明随寄存器设置变化；PDF166给出时钟特性，PDF167给出SCCB规范。本次提供的资料未找到当前RAW8模式下 D[9:2]/HREF/VSYNC 相对输出PCLK的 **保证 tCO_min/tCO_max**，不能把行场计数或典型频率当作该保证值。
4. `DOUBLE-DVP-OV5640-1113.pdf` 可以核对模组连接、信号/电源和器件：J17 为40针2.54 mm连接器，U27为24 MHz晶振，两路摄像头使用对应DVP信号。按用户确认采用模组直连，不增加延长线预算。该原理图未提供模组、J10/连接器及MINI板到FPGA的时钟/数据布线偏差、信号完整性和负载下的有效阈值窗口。

需要补齐：当前器件/模式完整的输出 AC 保证值，实际 XCLK/PCLK与0x4740等读回；直连条件下数据/HREF/VSYNC相对PCLK在FPGA焊盘处的最早/最晚到达（含各线偏差、负载、上升下降沿和必要PVT裕量）。用户已明确连接方式，不再将外接排线型号/长度列为待答问题。重新核对的表8-5给出时钟频率与输入边沿规格，但没有数据相对PCLK的保证tCO范围；其中4–5 ns脚注描述PLL旁路时输入时钟到输出时钟，不能用作DVP数据输出延迟。若厂商资料没有保证范围，需要工程可接受的板级测量/裕量方法，不能把单次室温示波器图等同全条件签核。

## RGMII：TX策略明确，RX模式与PCB偏斜仍缺证

MINI V1.3 **PDF28–29** 标明 RTL8211F-CG 及RGMII管脚。图是连接框图，不能代替strap电阻原理图或PCB走线长度。当前 `3_Hardware` 仅有管脚表、点位图和机械DXF，未见可用于提取电气走线偏斜的PCB/电气原理资料。

- 当前顶层 `mini_phy_startup #(.PHY_TX_DELAY(1),.SCAN_ADDRESSES(1))`；初始化对page0xD08/reg0x11 bit8读改写置1并精确读回。FPGA TXC由与TX数据同相的ODDR转发，RTL不另加2 ns移相。这能确认配置意图及软件失败关闭路径；不构成当前实物读回或板级偏斜证据。
- RX初始化没有读取/写入RX时钟延时配置。不能将器件内部PU、默认strap推断为已确认的RXDLY=1；还需核对实际strap/寄存器及PHY型号、封装、复位采样条件。

## 预算公式：只定义变量，不伪造常数

对同一个已确定的传感器/PHY输出参考边沿，令 `tCO` 为器件引脚数据相对该源时钟边沿的保证延迟，`Ddata`、`Dclk` 为从器件引脚到FPGA引脚的数据与时钟板级延迟：

- `input_delay_min = tCO_min + Ddata_min − Dclk_max`
- `input_delay_max = tCO_max + Ddata_max − Dclk_min`

DVP应使用已确认的下降沿作为输出参考，并保留FPGA上升沿采样；RGMII须对两个边沿分别建立窗口。jitter/duty-cycle/测量及PVT裕量须另行明确如何计入，不重复计入。已带时钟延时的器件输出窗口须使用对应规格，不能再叠加同一名义2 ns。

输出源同步预算可写为以下通用形式：以FPGA实际转发时钟为参考，`Bdata`、`Bclk` 表示到接收端所选数据/采样参考点的外部延迟，`tSU`、`tH` 是同一参考点定义下的接收要求：

- `output_delay_max = tSU + Bdata_max − Bclk_min`
- `output_delay_min = Bdata_min − Bclk_max − tH`

采用引脚规格还是器件内部延时后的参考点必须一致；PHY内部延时只能计一次。此公式不提供缺失的板长、延时模式、边沿和容差，不能直接替换成0、1或2 ns以消除warning。

## DDR、TMDS与管理接口

**DDR。** 冻结IDF为PDS 2022.2-SP6.4生成的PG2L100H/FBG676 HMIC_S DDR3 x32、1000 Mb/s配置，保留IP注册、DDR生成时钟、固定PHY位置及优先布线约束。IP原始 `/pnr/ddr_test.fdc` 的Inputs/Outputs段本来为空；本次没有发现一份已存在、应加载却漏加载的DDR通用I/O延迟文件。安装版 `UG042003_Logos2_HMIC_S_IP.pdf` **p59–60** 要求按IP时钟、固定位置、电气和RCF处理；当前约束结构与此一致。DDR专用PHY/训练承担接口时序机制，但不能据此把32输入/71输出告警全部声明为已豁免或外部保证。仍需对匹配颗粒、PCB条件、初始化/校准完成、DDR读写压力与裕量提供实际证据。摘录：[HMIC_S说明](../build/core_area_20261023/io_timing_review/UG042003_Logos2_HMIC_S_IP.selected.txt)。

**TMDS。** 当前设计是FPGA原生OSERDES+TMDS差分输出；不能套用板上MS7210并行输入端的setup/hold表。内部serial/pixel时钟、同源关系、原生级联和IO打包可由PDS检查；端口侧的眼图、抖动、时钟到数据及差分对内偏斜仍需针对当前板/线缆/接收端及相应规范验收。现有文件不能支持一个通用“HDMI output_delay=某值”的正式常数。

**UART。** PC/MCU RX是异步输入，两级同步；约束只对端口到首级采用6 ns datapath-only和hold例外，级间及协议逻辑正常计时。TX没有与外部接收方共享的同步时钟。这些4086/4087不能用伪造的DDR/系统时钟输入输出延迟消除；需波特率误差、采样裕量、实际电平/边沿与接线验收。

**SCCB/MDIO、复位/LED。** SCCB的器件规范可核对400 kHz及低/高时间、建立保持等（OV5640 PDF167），MDIO也须按PHY管理接口规范和实际divider核对。但SCL/SDA/MDIO的双向、上拉、负载及ACK采样不等于普通流水线同步端口；必须明确协议时序模型，不能直接整口false-path后宣称通过。reset_n异步置位/同步释放、ref_clk_n差分补端已有结构模型；LED/复位输出需功能和最小脉宽/电气要求，不应冒充视频数据口缺时钟。
