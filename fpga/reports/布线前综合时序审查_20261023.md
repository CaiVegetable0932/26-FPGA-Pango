### 必须处理的参考配置比较链

J 最差的三个 setup 样本位于 SNR 行 1032、1904、2776，起点均为 `core/reference_seeded_copy_4/CLK`，终点分别为 `boot/upload/response_code[4]/D`、`[5]/D`、`[6]/D`，裕量均为 -1.935 ns。

路径经过 `affine_reference_guard` 中完整 512 位 `frozen == entity` 比较。综合将它实现为 `N60.eq_0` 至 `N60.eq_255` 的长进位链，再经过上传响应的选择逻辑。报告显示 69 个逻辑级，逻辑延迟 6.489 ns、估计线延迟 2.830 ns，估计时钟偏斜 -0.330 ns。它是正常同域同步路径，不能通过 false-path、多周期例外或降低约束要求隐藏。

安装版《ADS Synthesis User Guide》印刷页 21（PDF 页 22）说明，综合时序报告默认将 4 个 carry instance 计为一个逻辑级。因此“69 级”不能简单解释为 69 个普通 LUT；本路径的 256 级 carry 已贡献约 64 个报告逻辑级。完整样本保存在 [J_worst_setup.txt](../build/core_area_20261023/J_final_review/J_worst_setup.txt)。

修复采用保持边界的平衡比较树：171 组 3 位相等比较，随后按 29 组、5 组、1 组进行 AND 归约。输入高位补 0；归约不足部分补 1，覆盖全部 512 位，包括最高两位。每个比较叶最多 6 个输入，各归约节点最多 6 个输入，预期形成约 4 层 LUT，而不是串联整段进位链。K 已验证中间边界保留和原长进位链消失；完整设计仍存在其他 setup 违例，不能把这项修复写成整板时序通过。

比较仍为组合逻辑，不新增寄存周期。`result_valid` 仍要求缓存对应当前完整实体；任一字节变化须立即使旧结果失效，不能让旧配置的合法结果授权新配置。重新计算检测复用同一比较结果。对于精确恢复到原实体的 ABA 情况，只能复用与 `frozen` 完全一致的结果。独立结构审查见 [reference_comparison_tree_review.json](../build/core_area_20261023/J_final_review/reference_comparison_tree_review.json)。

平衡树专项回归已通过：512 次逐位失效、512 次缓存 ABA、64 组随机请求、4789 次逐周期检查，并覆盖 seed/upload 切换、busy ABA 和四态语义。对照是 J 的旧 guard，仅重命名模块。证据为 [专项 result.json](../build/pose_storage_20261023/reference_match_tree/regression_20261023_214949/result.json) 与同目录 `run.log`。专项记录的 guard SHA256 与 K 冻结文件独立复核一致：`7a613a6187eb259524fa143a93c8268848b303d21c13a7b53fa8bce448e95940`。这证明功能语义与延迟的测试一致性，不证明实际综合网表层数或物理时序。

安装版《ADS Synthesis User Guide》§5.11，印刷页 83–84（PDF 页 84–85），规定 `syn_keep=1` 用于保持已连接 net，防止该 net 被优化掉并保留名称；没有实际连接的 net 仍可能被删除。当前只在比较树的局部中间 net 上使用该属性，避免综合重新合并为长比较链。该属性不直接保证时序通过，不保证 LUT 减少，也不等同于时序例外。官方资料只读；摘录副本保存在 `fpga/build/core_area_20261023/J_final_review/ADS_syn_keep_page_84.txt` 和 `ADS_syn_keep_page_85.txt`。

### DDR IP 的 hold 与复位 removal

J 的三个 hold 类别的代表路径均为零逻辑级：DDR 控制器 FF 到分布式 RAM 数据/地址，PHY FF 到 OSERDES 数据输入，以及 DQS gate FF 到 DDC 控制引脚。这些路径属于厂商控制器/PHY 和生成时钟相位关系，不能仅凭综合延迟估计认定用户 RTL 存在长组合缺陷，也不能据此删除 hold 检查。应保留原约束，在后续获准执行的物理实现中核查实际时钟、放置和最小延迟。

另外五个 removal 端点属于已定位的复位例外问题：`processing_safety.fault_latched` 发往 phase-adjust 的一个 preset 和四个 clear 引脚。J 仍报告 `STA-3015`，重编码后的五个 FSM FF 在 SYN VM 中没有对应 SDC 注释。独立追踪证明这些 FF 的 D 锥只到本域 FF/常量、没有 CE，指定两个安全源只通过异步复位分支影响目标；但**结构安全性不等于工具已经应用例外**。必须检查 K 中精确 C/P 端点及实际约束继承，不能用整个时钟组的例外替代。详见 [J_review.json](../build/core_area_20261023/J_final_review/J_review.json) 与 [fsm_cone_proof.json](../build/core_area_20261023/J_final_review/fsm_cone_proof.json)。

## L 最终 MAP 继承结论（2026-10-24）

L=`board_postsyn_20261023_221908_913042` 在独立目录显式读取 K 的相同 SYN DB 和冻结 SCF 后重新 MAP，返回0，资源保持 **46,152/66,600 LUT（69.2973%）**。[独立最终约束清单](../build/mcu_link_20261023/camera_reset_L_review_20261024/final_map_constraints.json)确认179条时序命令、15个时钟定义、10条精确源到 C/P 例外及其原生成功导入记录，零 STA-3015。K 完整工程漏载 SCF 的问题由这份实际 L MAP 关闭，不能回写或改称 K 原 MAP 已通过。

[继承证据](../build/mcu_link_20261023/camera_reset_L_review_20261024/source_synthesis_ccr_pcf_inheritance.json)确认321个源文件、SYN DB、SNR、CCR 与 K 逐字节相同，PCF 的117个端口及3个实例定位命令全部保留。因此上面的 K 综合结构与时序分析适用于 L 使用的同一综合网表；SNR 不是在 L 再次生成，也不是 SCF 叠加后的 STA，CCR 同样是继承证据。

最终交付已完成布线前资源、结构与约束继承审查，**SNR 仍为 Some Constraints Violated，DDR setup −1.337 ns 尚未签核**。厂商 hold、五个后综合复位例外的实际时序、Fast Corner 缺少数据及外部 IO 限制不因 MAP 成功自动消失。下一智能体应以 L 的实际 MAP 数据库开始另行授权的布局布线及 min/max STA；本轮未执行该阶段或生成位流。
