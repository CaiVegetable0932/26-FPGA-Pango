# 摄像头采集门控定位固件

## 当前事实

用户反馈：上轮帧尾修复固件仍黑屏；旧诊断页11的摄像头配置/DDR均亮，页01完整帧亮，页10像素/显示就绪均灭。因此不能宣称此前仿真复现就是实物根因，也不能把旁路曾见完整帧解释为持续完整帧。

本轮保持摄像头寄存器、十帧预热、DDR和HDMI协议不变，增加直接观察采集端内部条件的能力，并调整输入结构。目标是用实物证据区分复位/跨域就绪、预热未推进、异常行及帧准入，不继续凭灯态猜测后修改寄存器。

## 实现及边界

- 新增 `rtl/mini_camera_diag/mini_dvp_input.v`：PCLK上升沿将VSYNC/HREF/data作为同一组寄存一次，供旁路观测与采集共用，增加一拍延迟。消除两组逻辑直接采样外部控制信号的差异；不是外部时序已签核的证明，也不声称它一定解决实物黑屏。
- `camera_data.v`/`camera.v` 增加8位采集状态：实际采集复位已释放、同步后的cfg/DDR就绪、预热计数非零、预热完成、配置后帧开始曾出现、帧曾被准入、异常行曾出现。后三项事件为粘滞位，复位清除；就绪位是当前值。未放宽尺寸/预热要求。
- Top诊断状态逐位2FF同步到sys_clk，原有`diagnostic_meta*`首级CDC约束覆盖扩宽的总线。这不是多位计数器跨域快照，每位均为独立状态。
- LED2改为诊断页最高位，取消原DDR心跳驱动，避免一个端口由两个时钟域驱动。每页2秒、8页16秒。LED0为最低位，顶部reset指示不计入编号。

## LED解码（1=亮）

| LED2 LED1 LED0 | LED3 | LED4 |
| --- | --- | --- |
| 000 | VSYNC活动曾出现 | HREF活动曾出现 |
| 001 | 正确2560字节行曾出现 | 完整720行几何帧曾出现 |
| 010 | 像素曾放行 | 帧池有可显示帧 |
| 011 | 摄像头ID和配置回读通过 | DDR初始化完成 |
| 100 | 采集域复位已释放 | 采集域cfg_sync就绪 |
| 101 | 采集域ddr_sync就绪 | 预热计数非零 |
| 110 | 预热已完成 | 配置后帧开始曾出现 |
| 111 | 帧曾准入 | 异常行曾出现（故障标志） |

LED2高时应观察最后四页，而不是按旧版把它视作心跳。若仍无画面，冷启动后等待5秒，录制至少20秒完整LED视频即可读取全部页；须保留启动后状态，不在录像中再次按复位。
