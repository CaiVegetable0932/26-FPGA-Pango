## 另一台Windows电脑：准备与启动

安装PDS **2022.2-SP6.4 build 146967**（含PG2L100H-6FBG676支持及有效许可证）、Python 3.10或更新版本、Git。使用本机合法许可证，不从交付包寻找许可证文件。PDS官方资料在该电脑安装目录doc中只读查看。

在新的本地目录执行；不要覆盖已有工程。以下示例假定工作目录为 `D:/FPGA/gray-route`，PDS在 `E:/PDS_Pangu/PDS_2022.2-SP6.4`，按实际位置替换：

```powershell
git clone --depth 1 --single-branch --branch codex/gray-optimized-portable-20261031 https://github.com/CaiVegetable0932/26-FPGA-Pango.git D:/FPGA/gray-route
Set-Location D:/FPGA/gray-route
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
python -m pip install psutil
python -B fpga/scripts/portable_gray.py --audit
python -B fpga/scripts/portable_gray.py --prepare --pds-root E:/PDS_Pangu/PDS_2022.2-SP6.4
```

`--audit`只校验发布manifest、327项源码、MAP资源、CCR及10条SCF实际加载。`--prepare`在此电脑调用一次目标器件help检查版本/PLC入口，然后复制到新的运行目录、重定位flow注册路径、验证全部设计和约束引用存在、创建新一次性scope并运行check-only。不会运行PnR。旧输入保持原字节；不得手动批量替换source或二进制文件中的字符串。

`--prepare`只执行一次。成功后读取：

```powershell
Get-Content fpga/build/portable_gray/dispatch.json
```

其中`build`是本次唯一运行目录（下称RUN）。可用PDS GUI打开RUN/flow.pds查看，但不要从GUI点Run或修改项目。实际启动只有以下一个入口：

```powershell
python -B fpga/scripts/portable_gray.py --run
```

保持此终端开启。若需要关闭交互终端仍继续运行，可**改用一次**后台启动（两种方式选一种，不能都执行）：

```powershell
$pythonExe=(Get-Command python).Source
Start-Process -FilePath $pythonExe -ArgumentList @('-B','fpga/scripts/portable_gray.py','--run') -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
```

默认一次原生PnR180分钟、主机单阶段185分钟；布通后独立min/max STA，之后停止。不会生成位流/下载。CLI使用匹配MAP+PCF+PLC及原IP/约束；旧规划/打包已经属于PLC，不重新开启新布局规划参数。记录完整congestion输出；不因单独改善变慢自动中止，只执行原生/主机预算和显式stop请求。

若任何检查失败，先反馈具体错误。不要删除锁、清除attempt_claim、修改dispatch使它重复启动；没有自动失败重试。输入引用或二进制检查点加载错误不能通过关闭约束门禁解决。

## 外部智能体监控要求

用户已经授权另一台电脑启动此旧版一次有界PnR和监控；不需再次询问是否运行上述入口。授权不含位流、下载、修改源码或无界延长。另一台电脑与原电脑各用独立本地副本，不能共享可写RUN。

1. 只以 `fpga/build/portable_gray/dispatch.json` 定位RUN；启动后其`resume`给出本次精确证据目录，不能按整个build树最新目录猜测。
2. 有界检查约每5～10分钟一次；正常运行保持静默，只在阶段重要变化、异常、结束或需要行动时回复。
3. 读取RUN/launch.log、launch_exit.json、result.json，以及dispatch.resume下place_route_monitor.jsonl、place_route.log和result.json。根result在阶段结束前可能仍是旧MAP，不据此判成功。PnR完成后同目录检查report_timing.log和对应monitor。
4. 进程必须核对PID、创建时间、命令行；受限查询为空不等于退出。确认没有其他本机PDS native任务再启动；不要终止其他任务。界面标题不是状态依据。
5. 90/120/150分钟记录末5轮未布通、净改善、单轮CPU、CPU/净清除、剩余规模、总拥塞及高拥塞格数量。总数用日志的Total ... subnets，不能用网数作分母。全局布线局部步骤的Unrouted=0不等于细化布线完成。
6. 本轮180分钟已固定，修改磁盘policy/Tcl不改变运行中的预算；不要无界延长或自行开第二轮。低改善或反弹时保存证据并报告，未获新指令不提前终止健康进程。
7. 超时/失败：保存最后5轮、末轮CongestionPlot/NetInfo、原生退出码、result和检查点哈希；不自动再跑，不覆盖旧结果。
8. 成功：确认_pnr.adf存在、非空PRR与实际路由完成、min/max RTR明确结果、源哈希完整。逐项核查setup/hold/recovery/removal及异常诊断；综合setup余量不能替代布线后STA。即使成功仍停止在位流之前。

预算与PID等以目标电脑实际dispatch/monitor为准。本交付仅在原电脑做无PDS的完整性/迁移/门禁测试，不能声称异机PnR已成功启动或PLC已被异机加载。
