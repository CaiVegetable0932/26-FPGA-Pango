# Git 版本管理指南

## 1. 当前约定

- `main`：保留可追溯、经过相应检查的阶段结果。
- `feat/<主题>`：新功能；`fix/<主题>`：修复；`docs/<主题>`：文档；`chore/<主题>`：工具和维护。分支名用英文和连字符。
- 完成一个独立改动就提交一次；合并前检查差异并记录验证结果。
- 初始基线标签为 `baseline-2026-09-06`，仅表示设计文档和仓库配置快照。
- 硬件里程碑使用 `v0.1.0`、`v0.2.0` 等注释标签；已经交付的标签不移动、不覆盖。

仓库使用本机已有 Git 姓名和邮箱，不另造提交身份。换行、长路径及中文路径显示配置仅在本仓库生效。由于初始化进程与桌面用户不同，已在用户 Git 配置中添加仅针对 D:/XDU/concept/26-FPGA-Pango 的 safe.directory 信任条目。需要更换身份时在项目目录执行 `git config user.name "你的姓名"` 和 `git config user.email "你的邮箱"`。

## 2. 纳入与排除

| 内容 | 规则 |
| --- | --- |
| `output/`、文档、RTL、约束、测试、构建脚本 | 纳入 Git |
| PDS 工程、IP 配置、必要生成源码和初始化数据 | 纳入 Git，确保依赖齐全 |
| `build/`、各级 `compile/`、PDS 自动备份、仿真波形 | 忽略，可重新生成 |
| `PDS/` 和原始 `reference/` 资料 | 本地单独备份，仅保留参考资料索引 |
| License、`.env`、`*.local.json`、`*.local.ps1` | 忽略；共享配置使用不含本机信息的模板 |
| `reports/`、`release/` | 不整体忽略，按里程碑挑选报告和记录 |

构建输出统一放 `build/`。不要把唯一的源码或约束放在 `compile/`、`ip_backup/` 或 `constraint_backup/`，这些目录会被忽略。保留必要 IP 生成源码，因为重新生成可能依赖特定工具和 IP 版本。

大位流、长视频和完整波形应保存在单独的制品存储中；仓库提交其路径、SHA-256 和生成条件。当前未配置 Git LFS；若后续确需直接管理大文件，应在首次提交大文件前配置。

## 3. 日常开发

```powershell
git status
git switch main
git switch -c feat/video-input
# 开发、仿真，检查修改
git diff
# 按实际文件选择暂存范围，以下仅为示例
git add -- rtl/video sim/tb
git diff --cached
git commit -m "feat(video): 添加视频输入模块"
# 功能完成且相关验证通过后
git switch main
git merge --no-ff feat/video-input -m "merge: 集成视频输入模块"
```

上例中的 RTL 和仿真目录尚未创建，按后续实际文件使用。合并前应保证工作区干净；有冲突时解决并复核，无法完成可用 `git merge --abort` 取消本次合并。

提交格式：`类型(可选模块): 具体改动`。类型使用 `feat`、`fix`、`docs`、`test`、`refactor`、`chore`。对 RTL 改动在提交正文注明验证命令、结果及尚未验证项，不能把文档检查写成硬件验证通过。

## 4. 查看与恢复

```powershell
git log --oneline --graph --decorate --all -20
git show baseline-2026-09-06
# 取消暂存，保留文件修改
git restore --staged -- output/README.md
# 从基线创建独立分支查看或继续开发（先提交/暂存当前工作）
git switch -c review/baseline baseline-2026-09-06
```

撤销已经提交的改动优先使用 `git revert <提交号>`，它保留历史并生成反向提交。合并提交需另行指定正确的主线父提交，不照搬普通提交的撤销命令。

不要把 `git reset --hard` 或 `git clean -fdx` 当作常规清理；后者会删除被忽略的本地资料、License 和构建结果。Git 无法恢复未跟踪且被删除的资料。

## 5. 阶段版本

在 `main` 上完成相应检查后，更新 `CHANGELOG.md`，记录器件/板卡修订、PDS/IP 版本、测试结果、时序和资源报告、已知问题，以及位流位置和 SHA-256。

```powershell
# 以下只在真实完成该里程碑后执行
git tag -a v0.1.0 -m "首个通过既定验收的硬件里程碑"
git show v0.1.0
```

每个里程碑都应说明验证覆盖范围。记录位流对应的源码提交号，避免只按文件名判断版本。

## 6. 远程仓库与备份

当前只建立本地仓库，没有配置远程仓库或上传文件。取得自己的远程仓库地址后，将下面的占位符替换为实际地址：

```powershell
git remote add origin <远程仓库地址>
git push -u origin main
git push origin baseline-2026-09-06
# 后续只推送需要交付的具体标签
git push origin v0.1.0
```

多人协作时通过合并请求集成到 `main`，在托管平台配置主分支保护；这些服务端规则尚未启用。

无远程仓库时，可将已提交历史导出到项目外已存在的备份目录（替换示例路径）：

```powershell
git bundle create "E:\Backups\26-FPGA-Pango-2026-09-06.bundle" --all
git bundle verify "E:\Backups\26-FPGA-Pango-2026-09-06.bundle"
# 恢复到一个新的目录
git clone -b main "E:\Backups\26-FPGA-Pango-2026-09-06.bundle" "D:\Restore\26-FPGA-Pango"
```

bundle 包含引用可达的已提交历史，不包含未提交修改、被忽略的资料或本地 Git 配置。恢复后需单独恢复外部资料，并按需要重新设置远程地址。本次没有创建上述外部备份。
